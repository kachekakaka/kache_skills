## 1. 两条治理路线

本规则只支持单一上下文项目，不建立项目级骨架版本、profile、manifest、隐藏状态或跨 Skill 运行依赖。

- **标准骨架路线**：新项目或用户明确选择的结构迁移采用第 3 至第 9 节的固定主干和条件模块。
- **等价既有治理路线**：成熟项目保留自己的路径、schema、导航和门禁；按第 2 节证明全部适用结构维度达到
  相同职责和必要安全结果。

发现 `CONTEXT-MAP.md`、多个领域 `CONTEXT.md` 或明显独立业务上下文时保持只读，报告边界，不自动压平。

## 2. 等价既有治理与完整结构检查

### 2.1 冻结有限范围

只有开始处理一个新骨架问题且尚不存在对应活动方案时，才启动新的完整检查。同一问题已有活动方案时，先读取
方案、状态和当前直接证据，报告已有交接位置；不要实施、验证或关闭方案。只有用户明确要求仅修订方案时，才复核
会影响既有决定的漂移并更新方案本身；不要按对话或 Skill 调用次数重置流程，也不要把旧结论直接当作当前证据。

新问题的完整检查按以下方式冻结范围：

1. 完整读取适用 `AGENTS.md`，再从用户范围、根入口、文档和测试入口、活动/历史索引及其直接治理链接建立
   初始文件集合。
2. 列举活动 Markdown、结构目录和条件模块以核对未接线材料；列举结果只证明存在性和位置，不按文件名猜职责。
3. 对集合内文件充分读取完成结构判断所需的正文，不限制标题、Markdown token、固定行数或 fenced code。
4. 只有直接链接、结构冲突来源或会改变某一维结论的机械实现才能追加；在范围账本记录路径和理由。
5. 不为补洞无限遍历产品源码、全部测试、全部 workflow 或 Git 历史。证据不足时列缺少的证据角色和最小补证条件。

可以读取 Registry、suite、CI、安全规则和直接相关脚本，但目的只限结构职责、默认接线和机械结果。不要借此
持续核对产品事实、评价测试覆盖与经济性，或认证整个项目的攻击面和安全状态。

### 2.2 检查全部维度

一次检查完成下列全部适用维度，不在任何缺口处短路：

| 维度 | 当前证据角色 | 必须证明的结构结果 |
| --- | --- | --- |
| 上下文与路线 | 协作规则、项目入口、上下文入口 | 边界是单一上下文，并能解释采用标准或等价路线的依据 |
| 结构与职责 | 活动文档清单、职责索引、条件模块入口 | 必要事实和治理职责有唯一承接；结构不同不等于职责缺失 |
| 入口与导航 | 用户、协作、文档和测试入口及实际链接 | 活动材料可达，当前权威入口不互相争夺职责 |
| 活动与历史生命周期 | 当前入口、归档/历史入口、替代关系 | 当前、临时、被替代和历史材料有明确边界及退出条件 |
| 待办、方案与记录 | backlog 或等价入口、方案链接、记录承接位置 | 未完成事项能登记和退出，检查、保存与普通任务接手边界清楚 |
| 测试治理结构 | 测试入口、Registry/选择清单、suite 入口 | 验证层级和测试选择职责可解释，活动测试入口可达 |
| 机械门禁与授权边界 | 门禁入口及自测试、授权/安全规则、直接相关默认接线 | 结构规则可机械验证；受限操作有唯一规则入口且没有直接相反接线 |

每一维只使用 `满足`、`存在缺口`、`证据不足`、`不适用`；`不适用` 需要当前证据。完成全表后再给总体结论，
不综合打分，不用一维成功抵消另一维缺口。

全部适用维度均为 `满足` 才能判为等价既有治理。存在缺口或证据不足时保留现状，列出所有已经发现的结构
问题、影响和修复条件，不自动改用标准骨架。等价结论只说明结构治理可原样保留，不说明产品事实、测试设计或
全项目安全已经通过。

等价不要求：

- `docs/README.md`、`archive/docs/README.md` 或其他标准路径；
- 四列 Registry、固定列名或 `full`、`affected_only`、`explicit` 这些字面类别；
- 通用 T-DOC、两跳导航或相同脚本实现。

但现有机制必须能映射到相同结构职责和必要安全结果。已证明等价时保留原路径、schema、类别词汇和项目专用
门禁；标准化迁移只作为待保存、待裁决的独立选项。

## 3. 标准骨架的固定与条件结构

只有已经选择标准骨架路线时，以下主干固定：

```text
/
├── AGENTS.md
├── README.md
├── docs/
│   ├── README.md
│   ├── 需求文档.md
│   ├── 设计文档.md
│   ├── 已知问题与待做需求.md
│   └── 软件测试.md
├── SoftwareTesting/
│   ├── README.md
│   ├── PROTOCOL.md
│   └── SAFETY.md
└── archive/
    └── docs/
        └── README.md
```

按需创建：

```text
CONTEXT.md
docs/字段契约.md
docs/adr/
docs/方案/
docs/运维/
SoftwareTesting/<suite>/
SoftwareTesting/manual/
archive/SoftwareTesting/
```

空条件目录不落盘。条件后来满足时可再次显式调用本 Skill 检查；调用本身仍不授权保存或施工。

## 4. 标准导航

协作入口：

```text
AGENTS.md
├── CONTEXT.md（存在时）
├── README.md#构建与交付
├── docs/README.md
└── SoftwareTesting/README.md
```

用户入口：

```text
README.md
├── docs/README.md
└── SoftwareTesting/README.md
```

专题入口：

```text
docs/README.md
├── 核心文档
├── 条件专题
└── archive/docs/README.md

SoftwareTesting/README.md
├── PROTOCOL.md
├── SAFETY.md
├── docs/软件测试.md
└── 每个活动 suite README
```

根 README 不反向链接 `AGENTS.md`。每份活动文档通过实际 Markdown 链接在两跳内到达：

- 核心文档从 `docs/README.md` 直接到达；
- 活动方案从 `docs/README.md → 已知问题与待做需求.md → 方案` 到达；
- ADR 从 `docs/README.md → 当前设计或相关真源 → ADR` 到达；
- 多份运维文档可以由 `docs/运维/README.md` 二级索引；
- 活动测试 suite README 从 `SoftwareTesting/README.md` 直接到达。

根 README 只保留简介、当前能力简要边界、最短使用入口、唯一构建与交付入口及文档和测试总入口，不复制
`docs/README.md` 的专题清单。活动索引不直接枚举归档正文。机器入口使用普通行内相对链接。

## 5. 标准协作规则与文件职责

`AGENTS.md` 保存跨任务长期红线、语言、修改与 Git 授权，以及 CONTEXT、构建、文档和测试入口；不保存专项
命令、产品现状、字段、任务进度或重复规则。

没有既有约定的新项目默认：

- 与用户交流、文档、代码注释和提交说明使用简体中文；标识符、公开 API 和协议字段使用生态惯例；
- 本地只读操作默认允许，包括文件读取、搜索，以及不改变工作区、索引、引用或远端状态的 Git 查询；命令按实际
  副作用分类，不因使用命令行而自动成为受限操作；
- 未获明确修改授权时保持只读；用户明确授权“按已确认方案实施”时，该次授权覆盖确定范围内的文件新增、修改、
  重命名和删除、方案列明的普通验证及结果记录，以及完成条件满足后的待办状态更新、方案归档、索引更新和精确
  任务清理；
- 方案保存不构成实施授权；验证升级、新增副作用、候选实质漂移或需要新的语义决定时停止并只申请授权差额。
  方案关闭不以 commit、push 或 PR 为前提，也不推定这些操作；
- commit（含 amend）、push、PR、发布和安装，以及会覆盖工作区、丢失修改、改写历史或改变远端状态的 Git 操作
  必须明确授权。commit 授权包含确定变更的必要暂存；未请求 Git 交付时不主动改变索引、分支或历史；
- 未列明的联网、产品进程、真实数据、全量测试和正式认证仍不授权。确认方案列明的仓库内精确删除及本任务创建
  且所有权可验证的精确临时产物清理随实施授权覆盖；方案未列明、超出确定范围、使用宽泛匹配或未解析路径、仓库
  外非任务产物、所有权不明或涉及真实数据的删除必须取得精确授权；
- 构建入口和交付产物明确，普通验证为默认层级；
- 不把 Cookie、Token、Key、密码、真实用户数据或原始运行现场写入仓库。

文件职责：

- `README.md`：项目目的、当前能力简要边界、主要目录、最短运行入口和唯一“构建与交付”入口。
- `CONTEXT.md`：仅有项目专属术语时存在于根目录；骨架只检查位置和入口，不编辑内容。
- `docs/README.md`：活动文档总入口、职责索引、事实分流、生命周期、项目级收尾模板、条件模块和归档入口。
- `docs/需求文档.md`：当前已交付、用户可观察且可验收的行为和支持边界。
- `docs/设计文档.md`：当前实现结构、入口、调用链、数据流和适配边界，并链接必要 ADR。
- `docs/已知问题与待做需求.md`：只保存未完成事项。
- `docs/软件测试.md`：只保存稳定 Registry。
- `docs/字段契约.md`：存在数据库、API、跨进程、配置 schema、事件或多层序列化边界时创建。
- `docs/运维/`：存在部署、安装、代理、证书、备份、恢复、升级或当前故障处理时创建。

其他专题只有在职责独立、长期有效、有实际入口和明确退出条件时新增。事实内容是否正确不由本规则裁决。

## 6. 标准待办、方案与检查记录

待办格式：

```markdown
## FEATURE-001：标题

- 状态：待确认
```

ID 使用大写字母、数字和连字符，至少一个连字符；不得复用当前文档、归档和可发现 Git 历史中的既有 ID。
活动状态只允许 `待确认`、`待实施`、`实施中`、`暂缓`。

活动方案路径：

```text
docs/方案/<待办ID>-<名称>.md
```

活动方案必须是当前 Skill 的主责方案，正文聚焦自身职责内的证据、决定、目标、目标路径、动作边界、完成条件和
验证要求。不要在方案中预写精确脚本或命令，不预定由哪个 Skill、agent 或其他实现者施工，也不把跨职责问题
并入同一方案。方案保存并自审后，本 Skill 即退出执行链。

标准路线的 `docs/README.md` 必须在生命周期中提供以下项目级稳定模板；每份主责方案只实例化任务值，不复制本段：

```markdown
### 收尾与联合复核

- 本方案主责与完成证明：
- 关闭时的状态消费者：
- 关联方案、共享文件与对方职责状态：
- 联合只读复核触发条件：
- 验收停点：
- 关闭边界与未运行验证：
```

没有关联职责时，第三项写“不适用”及当前依据。关联方案未完成时只能报告本方案主责范围；最后一个关联方案只能
触发联合只读复核，不能自动调用其他 Skill、继承授权或结论、宣称全项目闭环或自动关闭。等价既有治理保留自己
的生命周期真源和字段组织，不因路径或 schema 不同迁移；缺少同等收尾职责时作为结构缺口处理。

生命周期关系：

| 待办状态 | 活动方案数量 | 说明 |
| --- | --- | --- |
| `待确认` | 0 或 1 | 普通未决待办可以无方案；用户明确保存后允许一份方案，但保存不授权施工 |
| `实施中` | 恰好 1 | 差异已裁决且用户另行授权普通实施任务施工，方案必须由待办实际链接 |
| `待实施` | 0 | 尚无活动施工方案，不得用该状态绕过保存与再次授权阶段 |
| `暂缓` | 0 | 方案必须退出活动目录和活动入口 |

同一待办在任何状态最多一份活动方案。活动方案必须：

1. 文件名与唯一待办 ID 对应；
2. 由对应待办实际链接；
3. 恰好各记录一次“测试层级、验证影响域、具体验证项”；
4. 保存阶段记录证据、影响、处理选项、推荐理由和用户决定；未裁决项保持待决；
5. 按项目生命周期真源实例化“收尾与联合复核”，不存在的关联职责使用有依据的“不适用”；
6. 完成、取消、暂缓、被替代或退出活动列表后移除活动文件和链接。
7. 按 [`testing-baseline.md`](testing-baseline.md) 第 7 节区分初始检查证据、完成条件和实际实施或关闭结果；状态变化
   不得把保存时快照冒充当前结果。

检查没有可施工问题时，不创建待办或空方案。用户选择保存记录时，优先写入项目现有检查记录、工作记录或
历史记录位置；没有承接位置时保存前询问用户指定，不新增标准目录。

机械门禁只检查可机械证明的状态、数量、链接和字段关系，不判断方案事实或用户决定是否正确。

## 7. 标准归档与活动分类

`archive/docs/README.md` 始终存在，使用：

```markdown
| 归档文档 | 历史职责 | 当前承接真源 |
| --- | --- | --- |
| [旧方案](旧方案.md) | 当时承担的职责 | [当前设计](../../docs/设计文档.md) |
```

每份归档 Markdown 恰好登记一次；历史职责不能为空；当前承接必须链接项目内活动 Markdown，确实没有时写
“无，仅保留历史证据”。退役测试资产进入条件目录 `archive/SoftwareTesting/`，使用相同三列逻辑的索引。

迁移或完整结构检查时按结构证据分类：

- **当前长期真源**：持续承接当前事实，同类事实没有并列主入口；
- **当前可执行手册**：当前仍使用，有入口和退出条件；
- **活动方案**：只服务一个 `待确认` 或 `实施中` 待办；
- **临时交接材料**：有明确承接和退出条件；
- **历史阶段记录**：记录已完成批次、审查、原型、工作过程、动态结果或被替代方案；
- **重复或职责消失材料**：没有独立当前职责，或有效内容已有承接。

分类需要职责声明、当前入口、状态或替代关系及当前承接位置。无法判断正文应由谁承接时保持待决，不要为了
减少文件数丢失未承接事实。

## 8. 标准测试治理

标准测试结构、Registry、验证层级、安全声明和通用 T-DOC 见 [`testing-baseline.md`](testing-baseline.md)。

通用资产只服务标准骨架。等价既有治理保留自己的测试目录、Registry schema、类别词汇和机械门禁，只需在
第 2 节的适用维度证明结构职责、直接接线和必要安全结果；不要要求机械复制标准实现。

## 9. 新建、迁移与内容交接

新项目只生成标题、路径职责、必要导航和用户明确确认的“不适用”，不推导产品能力、实现、测试或构建事实，
不生成大段 TODO 或目标架构。没有项目专属术语时不创建 `CONTEXT.md`。

既有项目先完整检查第 2 节全部维度：

- 等价已证明：保留现有结构；
- 等价未成立：列全部已发现结构缺口和修复条件，不自动迁移；
- 用户明确选择标准迁移：先保存并裁决完整方案，再由普通任务在新的施工授权下实施。

标准迁移方案先识别当前长期真源和有效手册，再确定历史、临时和重复材料的当前承接；要求后续实施先建立承接和
入口，再移动、归档或退出旧正文。无法确定承接时保持待决。

方案按当前证据记录可恢复性：可以从 Git 或其他可靠来源精确恢复时不要求额外备份；未跟踪、已有未提交修改、
无版本控制或其他不可恢复内容，在移动、合并、覆盖、归档或删除前必须由实施者确定可恢复方式。不得把产品代码、
配置、构建脚本或产品测试列为删除目标。

事实错误、内容缺失、测试实现缺口、术语和领域边界不由骨架处理。交接包包含问题类别、目标、声明与证据、
实际影响、建议动作、职责边界、所需授权和完成条件；不自动调用后续工具或 Skill。

## 10. 方案交接与结构完成

### 10.1 方案最低完备性

保存的方案必须让没有参加检查对话的普通任务能够继续，至少包含：

1. 初始检查证据、证据不足和未覆盖范围，事实、推断、建议和未来条件分开；
2. 每项差异的影响、处理选项、推荐理由、用户决定及尚待补证或裁决的项目；
3. 目标与非目标、确定修改路径、可能修改路径、明确不修改范围及重新冻结触发条件；
4. 动作边界、完成条件，以及按 [`testing-baseline.md`](testing-baseline.md) 第 3、7 节形成的验证要求；
5. 实施前置条件和授权边界，并按 [`testing-baseline.md`](testing-baseline.md) 第 3 节说明标准路线的一次实施授权、
   高风险操作和差额停止条件，但不写精确命令、脚本、临时 Git 技巧或指定执行者；
6. 目标项目生命周期要求的任务特定收尾字段。

确定修改路径必须有当前证据证明需要变化；仅可能受影响或要到实施阶段才能判断的路径进入“可能修改”，不能用
候选清单冒充最终写入范围。缺少证据或用户决定时保留待决，不写占位结论。

### 10.2 可关闭交接

标准路线按第 6 节由项目 `docs/README.md` 提供稳定收尾模板；等价路线引用项目自己的生命周期真源，不要求迁移
路径、状态词或 schema。每份方案实例化：

- 本方案主责与完成证明；
- 关闭时的状态消费者；
- 关联方案、共享文件与对方职责状态；
- 联合只读复核触发条件；
- 验收停点；
- 关闭边界、最终状态门禁和未运行验证。

方案明确要求普通实施任务只记录实际结果。标准路线的一次实施授权在完成条件和方案列明的验收要求满足、没有
授权差额时，覆盖退出活动待办、归档方案、更新索引、处理方案列明的精确条件清理及验证最终状态；需要新的语义
决定、用户明确验收或高风险清理时仍在对应停点等待。方案关闭与 commit、push、PR 相互独立。文件修改或中途
门禁通过不等于完成，完成条件不得预写成实施或关闭结果；这些字段只保证方案可交接，方案保存本身不授权本 Skill
或后续任务执行任何动作。

### 10.3 Skill 终点与结论边界

本 Skill 在方案保存和静态自审后停止，不实施、验证、验收或关闭。后续普通任务依据项目规则和当轮授权接手；
已有方案时不重新启动完整流程，除非用户明确授权仅修订方案。

分别判断结构检查结论和整体治理闭环。标准结构清单只是拟实施目标，既有结构等价只说明对应结构结果；内容一致性、
测试充分性和全项目安全仍需各自证据。遗留只使用 `待事实同步`、`待结构处理`、`待语义决策`、`待实现或验证`，
任一类仍有未承接项目时明确报告，不用机械门禁结果替代更高层结论。
