## 1. 适用条件

只在项目采用标准骨架（含新建和日常检查）、用户明确选择迁移，或用户要求与标准结构比较时读取本文件。成熟项目
走等价既有治理路线时，以 `SKILL.md` 的核心维度和当前项目证据判断，不因存在文档、测试目录或结构差异而加载或
套用本标准。

本标准只支持单一上下文项目，不建立项目级骨架版本、profile、manifest、隐藏状态或跨 Skill 运行依赖。发现
`CONTEXT-MAP.md`、多个领域 `CONTEXT.md` 或明显独立业务上下文时保持只读并报告边界。

项目级 Skill 工具资产、测试资产信息架构调查、检查／保存阶段和有限证据规则以 `SKILL.md` 为唯一运行时说明，本
文件不重复定义。

## 2. 固定与条件结构

标准主干固定为：

```text
/
├── AGENTS.md
├── README.md
├── docs/
│   ├── README.md
│   ├── 需求文档.md
│   ├── 设计文档.md
│   ├── 已知问题与待做需求.md
│   └── 软件测试.md
├── SoftwareTesting/
│   ├── README.md
│   ├── PROTOCOL.md
│   └── SAFETY.md
└── archive/
    └── docs/
        └── README.md
```

按需创建：

```text
CONTEXT.md
docs/字段契约.md
docs/adr/
docs/方案/
docs/运维/
SoftwareTesting/<suite>/
SoftwareTesting/manual/
archive/SoftwareTesting/
```

空条件目录不落盘。条件后来满足时可以再次显式调用本 Skill 检查，但调用本身不授权保存或施工。

## 3. 标准导航

协作入口：

```text
AGENTS.md
├── CONTEXT.md（存在时）
├── README.md#构建与交付
├── docs/README.md
└── SoftwareTesting/README.md
```

用户入口：

```text
README.md
├── docs/README.md
└── SoftwareTesting/README.md
```

专题入口：

```text
docs/README.md
├── 核心文档
├── 条件专题
└── archive/docs/README.md

SoftwareTesting/README.md
├── PROTOCOL.md
├── SAFETY.md
├── docs/软件测试.md
└── 每个活动 suite README
```

根 README 不反向链接 `AGENTS.md`。除 `SKILL.md` 已排除的项目级 Skill 工具资产外，每份活动文档通过实际
Markdown 链接在两跳内到达：

- 核心文档从 `docs/README.md` 直接到达；
- 活动方案从 `docs/README.md → 已知问题与待做需求.md → 方案` 到达；
- ADR 从 `docs/README.md → 当前设计或相关真源 → ADR` 到达；
- 多份运维文档可以由 `docs/运维/README.md` 二级索引；
- 活动测试 suite README 从 `SoftwareTesting/README.md` 直接到达。

根 README 只保留简介、当前能力简要边界、最短使用入口、唯一构建与交付入口及文档和测试总入口，不复制
`docs/README.md` 的专题清单。活动索引不直接枚举归档正文。机器入口使用普通行内相对链接。

## 4. 协作规则与文件职责

`AGENTS.md` 保存跨任务长期红线、语言、修改与 Git 授权，以及 CONTEXT、构建、文档和测试入口；不保存专项命令、
产品现状、字段、任务进度或重复规则。

没有既有约定的新项目默认：

- 与用户交流、文档、代码注释和提交说明使用简体中文；标识符、公开 API 和协议字段使用生态惯例；
- 本地只读操作默认允许，包括文件读取、搜索，以及不改变工作区、索引、引用或远端状态的 Git 查询；按实际副作用
  而不是命令工具分类；
- 公开只读联网默认允许，但必须无需认证、不上传本地或非公开内容、不收费、不发布或改变外部状态；
- 未获明确修改授权时保持只读；用户明确授权按已确认方案实施时，覆盖确定文件变更、方案列明的普通验证和结果
  记录，以及完成条件满足后的待办退出、方案归档、索引更新和精确任务清理；
- 方案保存不构成实施授权；验证升级、新副作用、候选实质漂移或新语义决定只申请授权差额；
- commit（含 amend）、push、PR、发布、安装、破坏工作区或改写历史的 Git 操作必须明确授权；
- 认证或私有访问、上传、外部写入、费用、明显大规模下载、产品进程、真实数据、全量测试和正式认证必须明确授权；
  方案未列明、超出确定范围、宽泛或未解析、所有权不明、仓库外非任务产物或真实数据删除也需精确授权；
- 普通验证为默认层级，构建入口和交付产物明确；
- 不把 Cookie、Token、Key、密码、真实用户数据或原始运行现场写入仓库。

文件职责：

- `README.md`：项目目的、当前能力简要边界、主要目录、最短运行入口和唯一“构建与交付”入口；
- `CONTEXT.md`：仅有项目专属术语时存在于根目录；骨架只检查位置和入口；
- `docs/README.md`：活动文档总入口、职责索引、生命周期、任务级收尾模板、条件模块和归档入口；
- `docs/需求文档.md`：当前已交付、用户可观察且可验收的行为和支持边界；
- `docs/设计文档.md`：当前实现结构、入口、调用链、数据流和适配边界，并链接必要 ADR；
- `docs/已知问题与待做需求.md`：只保存未完成事项；
- `docs/软件测试.md`：只保存稳定测试 Registry；
- `docs/字段契约.md`：存在数据库、API、跨进程、配置 schema、事件或多层序列化边界时创建；
- `docs/运维/`：存在部署、安装、代理、证书、备份、恢复、升级或当前故障处理时创建。

其他专题只有职责独立、长期有效、有实际入口和明确退出条件时新增。事实内容是否正确不由本规则裁决。

## 5. 待办、方案与检查记录

待办使用：

```markdown
## FEATURE-001：标题

- 状态：待确认
```

ID 使用大写字母、数字和连字符，至少一个连字符；不得复用当前文档、归档和可发现 Git 历史中的既有 ID。活动
状态只允许 `待确认`、`待实施`、`实施中`、`暂缓`。

活动方案路径为：

```text
docs/方案/<待办ID>-<名称>.md
```

生命周期关系：

| 待办状态 | 活动方案数量 | 说明 |
| --- | --- | --- |
| `待确认` | 0 或 1 | 普通未决待办可以无方案；用户明确保存后允许一份，但保存不授权施工 |
| `实施中` | 恰好 1 | 已获普通任务实施授权，方案必须由待办实际链接 |
| `待实施` | 0 | 尚无活动施工方案，不得绕过保存和实施授权 |
| `暂缓` | 0 | 方案必须退出活动目录和入口 |

同一待办始终最多一份活动方案。活动方案必须：

1. 文件名与唯一待办 ID 对应，并由对应待办实际链接；
2. 恰好各记录一次“测试层级、验证影响域、具体验证项”；
3. 记录当前证据、影响、选项、推荐理由和用户决定；未裁决项保持待决；
4. 按项目生命周期真源实例化任务级收尾字段；
5. 完成、取消、暂缓、被替代或退出活动列表后移除活动文件和链接。

检查没有可施工问题时不创建待办或空方案。用户选择保存记录时，使用项目已有检查、工作或历史记录位置；没有承接
位置时先询问。机械门禁只检查可机械证明的状态、数量、链接和字段，不判断方案事实或用户决定是否正确。

## 6. 归档与活动分类

`archive/docs/README.md` 始终存在，使用：

```markdown
| 归档文档 | 历史职责 | 当前承接真源 |
| --- | --- | --- |
| [旧方案](旧方案.md) | 当时承担的职责 | [当前设计](../../docs/设计文档.md) |
```

每份归档 Markdown 恰好登记一次；历史职责不能为空；当前承接必须链接项目内活动 Markdown，确实没有时写
“无，仅保留历史证据”。退役测试资产进入条件目录 `archive/SoftwareTesting/`，使用同样三列逻辑的索引。

迁移或标准结构检查时按证据分类：

- **当前长期真源**：持续承接当前事实，同类事实没有并列主入口；
- **当前可执行手册**：当前仍使用，有入口和退出条件；
- **活动方案**：只服务一个 `待确认` 或 `实施中` 待办；
- **临时交接材料**：有明确承接和退出条件；
- **历史阶段记录**：记录已完成批次、审查、原型、过程、动态结果或被替代方案；
- **重复或职责消失材料**：没有独立当前职责，或有效内容已有承接。

分类需要职责声明、当前入口、状态或替代关系及当前承接位置。无法判断正文应由谁承接时保持待决。项目级 Skill
工具资产不进入分类、归档登记或两跳导航检查。

## 7. 标准测试治理

标准测试结构、Registry、验证层级、安全声明、结果语义和通用 T-DOC 见
[`testing-baseline.md`](testing-baseline.md)。只在 `SKILL.md` 指定的标准测试治理或标准验证规划条件满足时读取。

测试资产信息架构调查以 `SKILL.md` 为唯一方法说明。等价既有项目保留自己的测试目录、Registry schema、类别词汇
和机械门禁，不要求复制标准实现。

## 8. 新建、迁移与内容交接

新项目只生成标题、路径职责、必要导航和用户明确确认的“不适用”，不推导产品能力、实现、测试或构建事实，也不
生成大段 TODO 或目标架构。没有项目专属术语时不创建 `CONTEXT.md`。

标准迁移先识别当前长期真源和有效手册，再确定历史、临时和重复材料的当前承接；后续实施先建立承接和入口，再
移动、归档或退出旧正文。无法确定承接时保持待决。

方案按当前证据记录可恢复性：可从 Git 或其他可靠来源精确恢复时不要求额外备份；未跟踪、已有未提交修改、无版本
控制或其他不可恢复内容，在移动、合并、覆盖、归档或删除前必须由普通任务确定可恢复方式。不得把产品代码、配置、
构建脚本或产品测试列为删除目标。

事实错误、内容缺失、测试实现缺口、术语和领域边界不由骨架处理。交接包含问题类别、目标、声明与证据、实际影响、
建议动作、职责边界、所需授权和完成条件。

## 9. 标准方案交接与关闭

标准路线的 `docs/README.md` 提供以下任务级收尾模板，每份方案只实例化当前值：

```markdown
### 收尾与联合复核

- 本方案主责与完成证明：
- 覆盖与残余：
- 确定切片与就绪证明：
- 关闭时的状态消费者：
- 关联方案、共享文件与对方职责状态：
- 联合只读复核触发条件：
- 最终范围与漂移复核：
- 验收停点：
- 关闭边界与未运行验证：
```

没有关联职责时写“不适用”及当前依据。关联方案未完成时只报告本方案主责；最后一个关联方案只能触发联合只读
复核，不能自动调用其他 Skill、继承授权或结论、宣称全项目闭环或自动关闭。

标准方案还要按 [`testing-baseline.md`](testing-baseline.md) 记录验证层级和实际结果语义。完成条件与方案列明验收均
满足、没有授权差额时，目标项目的一次实施授权可以按其规则覆盖待办退出、方案归档、索引更新、精确条件清理和
最终机械门禁；关闭不依赖 commit、push 或 PR。文件修改或中途门禁通过不等于完成，未执行动作不得预写为结果。
