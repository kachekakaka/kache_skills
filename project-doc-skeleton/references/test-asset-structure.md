## 1. 适用条件与职责边界

存在活动测试治理入口或测试根，或者冻结结构清单发现可能未被活动入口承接的测试资产时读取本文。本文同时适用于
标准路线和成熟等价路线；项目可以使用自己的路径、Registry 等价物、类别词汇和正式选择机制。

本调查只回答当前资产、生命周期、执行暴露、结构身份、所有者、直接消费者、执行入口和正式选择之间的关系。不要
评价覆盖率、断言质量、测试经济性或实现重构，不要求项目新增 manifest、固定目录树、共享层或“一项测试一目录”。

## 2. 建立当前资产候选集合

需要声称测试资产盘点完整时，先冻结查询根、排除项和当前工作区来源，再建立候选集合。Git 可用且当前仓库以 Git
管理时，候选集合由以下成员构成：

1. 已跟踪且当前仍存在的文件；
2. 未跟踪、未被 ignore 且当前存在的新文件；
3. 排除索引中已经删除但磁盘不再存在的旧路径；
4. 排除明确的缓存、报告输出、生成残留、空目录、仅含忽略文件的残留，以及主 Skill 已排除的项目级 Agent Skill
   工具资产。

使用能同时表达已跟踪文件和未忽略新文件的有界只读 Git 查询，再以当前存在性过滤。只记录上述集合语义，不把某个
shell、平台命令或项目路径写成通用要求。未暂存移动可以同时表现为旧路径已不存在和新路径未跟踪；两端必须按当前
存在性分别判断，不能只读取 index 或只遍历磁盘。

Git 不可用、目标并非 Git 项目或适用规则禁止依赖 Git 时，优先读取项目明确维护的资产清单或等价版本控制查询。
替代证据必须说明来源、边界、完成状态和排除语义。没有 Git 感知集合或等价完整清单时，将“当前资产完整性”标记为
证据不足；不得退化为把所有物理目录猜成活动资产。

普通目录枚举可以用于验证候选路径是否存在、理解已冻结根的边界，不能单独证明活动身份。一个目录有 README、构建
文件或缓存，也不自动说明它是活动独立测试项。

## 3. 判断生命周期与执行暴露

为每个会改变结构结论的候选分别记录生命周期和执行暴露。两轴相互独立，允许项目使用等价词汇。

生命周期至少区分：

- **活动独立项**：可以被任务直接选择，拥有当前唯一身份和可达入口；
- **活动附属项**：只补充一个明确活动所有者，不重复建立独立身份；
- **隔离保留项**：仍被构建、合同或其他当前消费者使用，但不再作为普通直接入口；
- **历史项**：只用于追溯，位于历史承接位置，不出现在活动选择入口，也不提供当前运行指引。

执行暴露至少区分：

- **纯静态**：只读取和比较仓库内合成或声明证据；
- **合成本地**：使用虚构、离线输入并只影响受控本地现场；
- **真实数据或产品进程**：读取真实输入、启动产品或占用前台／设备，即使没有外部写入；
- **外部只读**：访问外部资源但不认证、不上传、不收费且不改变外部状态；
- **外部写入**：会发布、上传、修改远端、触发真实业务或产生其他外部状态变化。

同一资产可以在一个生命周期下暴露多种执行路径，记录当前实际可达路径中最高相关副作用和对应入口。外部写命令即使
安全说明齐全，只要其路线已停止却仍作为活动指引暴露，就形成直接结构影响；但不要用固定严重度等级替代实际影响。

## 4. 分开身份、所有者、消费者和选择范围

对会改变活动、归档、删除、替代或正式选择结论的资产，分别检查以下关系：

- **Registry 或等价身份**：当前治理清单是否把它作为独立活动项登记；
- **唯一所有者**：哪一个活动职责直接承担它，附属项是否只有一个所有者；
- **直接消费者**：哪些当前构建、配置、脚本、文档或测试直接使用它；
- **执行入口**：任务实际从哪里直接运行或选择它；
- **正式／完整／Release 选择范围**：项目声明的正式候选或完整检查是否选择它。

这些关系不得互相反向推导：未独立登记可能是合法附属项；存在构建或测试 target 不证明旧脚本仍是活动入口；不在正式
选择范围不证明它不是活动普通测试；归档脚本不自动授权删除产品合同或构建消费者；清单包含身份也不证明实现存在。

从当前测试总入口和 Registry 或等价入口建立映射。集中治理或跨 suite 组织根列出候选集合中的完整受管路径；模块内
测试根只核对入口、模块所有者和选择映射。只有职责或一层直接依赖会改变上述关系时，才读取必要 runner、fixture、
fake、helper、构建或配置证据。

## 5. 使用有界三态证据

关键关系只使用三种证据状态：

- **已证明存在**：有精确当前命中且能定位关系；
- **已证明不存在**：有界查询范围完整、查询成功且没有命中；
- **证据不足**：范围、入口、查询完成状态或解码不完整，不能形成存在或不存在结论。

“已证明不存在”必须同时记录查询根、精确种子或关系、排除边界和完整成功状态。搜索无输出、命令失败、只查一个
目录、未包含未跟踪新文件或无法解释 ignore 时，都不能写成项目中不存在。

只为会改变当前归档、删除、替代、所有权或正式选择的关键关系保留负证据，不创建庞大的全项目“不存在”账本。搜索
从精确路径、标识或职责声明开始，只展开一层会改变结论的直接消费者；不要从新命中递归扩张。

## 6. 形成发现、阻断和唯一归宿

每项发现至少记录：

1. 当前证据及三态结论；
2. 用户可理解的实际影响；
3. 生命周期与执行暴露；
4. 唯一归宿：当前确定切片、待决切片、跨职责交接、后续待办或明确不处理；
5. 是否阻止相关切片进入确定实施范围；若阻止，写明最低解除条件。

不要增加固定“高／中／低”字段，也不要创建持久发现账本。同一根因可以合并描述，但调用内发现集合、报告、矩阵和
方案处置仍须成员一致。无入口、链接不可达和仍暴露外部写命令的实际影响不同，应以结果和副作用说明，而不是只标
统一严重度。

## 7. 报告与方案交接

只报告路线把当前候选集合来源、范围、排除项、生命周期／执行暴露、关系证据、发现归宿、阻断和残余直接写入对话
报告，然后停止。

方案路线还要把确定根、实际路径、保留例外、一层消费者、关键负证据、完成条件和解除条件物化到主责方案。目录混放、
导航脱节、历史命名和跨职责依赖只是调查信号；最终目标必须来自项目当前证据。无法证明候选集合完整或关系唯一时，
保持现状并标记证据不足，不把移动、删除、归档或正式选择列为确定切片。
