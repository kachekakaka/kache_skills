# 项目文档骨架检查与方案

## 坚守职责与独立性

只支持单一上下文项目，并独立处理两条路线：

- **标准骨架**：为新项目或用户明确选择的结构迁移建立固定主干和适用条件模块；
- **等价既有治理**：成熟项目使用不同路径、schema 或机械实现，但当前证据证明结构职责和必要安全结果等价时原样保留。

只处理文件、目录、入口、导航、职责归属、活动与历史生命周期、测试治理结构和机械门禁。为完成结构判断，
可以读取当前文档和直接相关的治理证据；不要持续核对产品事实，不要审计测试设计经济性，也不要把结构检查
扩张为攻击面扫描或全项目安全认证。

不要调用、依赖或假定其他 Skill 已安装。发现内容事实冲突、正文重复或膨胀、内容放置不当、测试实现缺口或
真实语义取舍时，输出包含目标、双方证据、影响、建议动作、授权需求和完成条件的精确交接。

## 只执行检查与落方案

把一个新骨架问题分为两个阶段：

1. **检查**：始终只读。完整检查结构、报告结论并询问是否保存方案；即使请求包含“修复”“施工”或 `apply`，
   也不修改目标项目。
2. **落方案**：只有用户明确说“保存方案”或“落方案”后，才写入一份集中方案及必要活动待办。项目缺少活动方案
   位置时，可以在同一明确保存授权下建立；保存结果保持 `待确认`，完成静态自审后立即停止。

本 Skill 没有 `apply`、施工、验证、重试、归档、删除或关闭阶段。保存后的方案由普通实施任务按目标项目规则和
当轮授权接手，不需要再次调用或安装本 Skill。对应活动方案已经存在时，默认只报告交接位置；只有用户明确要求
“仅修订方案”并授权方案文件修改时，才更新方案本身，随后仍然停止。

标准路线的方案按 [`testing-baseline.md`](references/testing-baseline.md) 第 3 节支持一次明确实施授权：用户授权
“按已确认方案实施”时，普通任务可在同一批次完成确定范围内的文件变更、方案列明的普通验证和结果记录，以及
完成条件满足后的生命周期关闭；方案列明的仓库内精确删除和本任务精确临时产物清理包含在其中。验证升级、新增
副作用、候选实质漂移或需要新的语义决定时停止并只申请授权差额。这是方案交接后的普通任务授权语义，不是本
Skill 的执行授权包，也不会恢复 `apply` 或让本 Skill 继续运行。

没有可施工问题时仍询问是否保存检查记录。用户选择保存后，优先使用项目现有检查记录、工作记录或历史记录
位置；项目没有承接位置时，保存前询问一次精确位置。不要创建统一记录目录，也不要用空活动方案冒充记录。

## 检查适用性与授权

1. 完整读取目标路径适用的全部 `AGENTS.md`。
2. 检查阶段不写文件、不运行命令。保存阶段的授权只覆盖方案及必要活动待办，不推定目标文件施工、非只读 Git、
   安装、联网、产品进程、真实数据、高风险删除或生命周期关闭；本地只读操作不需要从保存授权中推定。
3. 发现 `CONTEXT-MAP.md`、多个领域 `CONTEXT.md` 或明显独立业务上下文时停止，不要压平多上下文结构。
4. 发现既有语言约定时保留原规则并展示冲突；修改语言规则不包含批量翻译授权。
5. 不自动运行构建、测试、产品程序、真实数据操作、联网、Git 操作或正式认证。
6. 不修改产品代码、产品行为断言、`CONTEXT.md`、ADR 正文或任何方案目标文件，不覆盖用户已有工作区修改。
7. 不把凭据、真实用户数据或原始运行现场写入仓库或交接。

## 按需读取资源

- 每次完整读取 [`references/skeleton-rules.md`](references/skeleton-rules.md)。
- 新建、迁移、测试治理变化或方案验证范围适用时，再完整读取
  [`references/testing-baseline.md`](references/testing-baseline.md)。
- 只有用户已经选择标准骨架，且方案需要判断通用门禁资产的安装边界时，才读取
  `assets/SoftwareTesting/doc_consistency/` 下对应源码。只记录整文件逐字节一致、既有冲突和停止条件，不安装资产、
  不选择复制机制，也不以片段补丁代替整文件结果。
- 不把参考文件复制到目标项目，不创建 profile、manifest、版本号或隐藏治理状态。

## 冻结有限范围并充分读取

先记录本轮结构检查维度和文件集合，再形成结论：

1. 从用户指定范围、适用协作规则、项目公开入口、文档与测试入口、活动/历史索引，以及它们指向的直接治理
   证据建立初始集合。可以列举活动 Markdown 和结构目录以核对完整性；不要只按文件名猜职责。
2. 冻结的是结构问题边界和本轮文件集合，不是理解能力。对集合内文件完整读取完成判断所需的正文，不限制为
   标题、链接 token、固定行数或 fenced code。
3. 只有新发现的直接链接、结构冲突来源或会改变某一维结论的机械实现才能加入集合；记录新增路径和理由。
4. 不为寻找替代答案无限遍历产品源码、全部测试、全部 workflow 或历史。证据仍不足时明确写出缺少的角色和
   最小补证条件。

既有未提交修改属于当前证据。方案必须要求实施者施工前重新冻结拟改文件；发现冲突或不可恢复覆盖风险时停止。

## 完整检查全部结构维度

一次 `check` 必须完成全部适用维度，不在首个缺口处停止：

1. **上下文与路线**：确认单一上下文边界，判断是新建标准骨架、标准骨架日常检查，还是等价既有治理检查。
2. **结构与职责**：核对必要事实、协作规则、测试治理、待办和条件专题是否有唯一承接职责；标准路线同时核对
   固定与条件路径，等价路线不要求相同文件名或 schema。
3. **入口与导航**：核对用户入口、协作入口、专题入口、实际 Markdown 链接和适用可达性，识别重复权威入口。
4. **活动与历史生命周期**：核对当前、临时、被替代和历史材料的结构归属、退出条件、归档入口与当前承接关系。
5. **待办、方案与记录生命周期**：核对状态、活动方案数量、实际链接、检查—保存—普通任务接手边界，以及无问题检查记录
   的现有承接位置。
6. **测试治理结构**：核对验证层级、Registry 或等价选择入口、suite 职责和活动入口；不要据此评价覆盖是否充分、
   测试是否重复或实现是否正确。
7. **机械门禁与授权边界**：核对适用门禁入口、自测试、结构规则，以及命令、Git、真实数据、进程、输出和删除的
   权威规则入口。只读取与这些结构声明直接相关的接线，不认证整个项目安全。

每一维使用 `满足`、`存在缺口`、`证据不足` 或 `不适用`，并附当前证据；`不适用` 必须有当前依据。完成所有
维度后再给总体路线结论，不综合打分，不用一项成功抵消另一项缺口。

成熟结构只有全部适用维度均为 `满足` 时才能判为等价既有治理。未成立时保留现状，完整列出所有已发现结构
缺口及各自修复条件，不自动套用标准骨架。已证明等价时保留现有目录、导航、Registry schema、类别词汇和
项目专用门禁；标准化迁移只能作为另一个待保存、待裁决的选项。

## 输出检查结论并停下

检查结束只输出便于裁决的摘要，不在对话中展开完整施工方案：

- 路线结论和冻结范围；
- 全部结构维度的结论、关键证据和未检查原因；
- 按共同根因合并的结构差异及其影响；
- 内容、语义、测试实现或其他职责的交接项；
- 未运行验证和未获授权操作；
- 是否保存方案或无问题检查记录的问题。

不要因为用户已经表达修复意愿而跳过停点。只有用户随后明确选择保存，才进入保存阶段。

## 保存一份可裁决方案

按 [`skeleton-rules.md`](references/skeleton-rules.md) 第 6、10 节保存可裁决且可关闭的方案，并按
[`testing-baseline.md`](references/testing-baseline.md) 第 3、7 节记录验证范围和证据语义。方案只实例化当前任务值，
不要复制参考文件规则，也不要写精确命令、脚本、临时 Git 技巧或绑定某个执行者。

保存方案至少区分初始检查证据、证据不足、用户决定、确定与可能路径、动作边界、完成条件、验证要求和未覆盖范围；
再按目标项目当前生命周期真源写明完成证明、状态消费者、关联方案、验收停点、关闭动作和未运行验证。标准路线
使用项目 `docs/README.md` 的收尾模板；等价路线保留现有等价生命周期，不要求迁移路径或 schema。

写入后静态自审：

- 方案与全部结构维度证据一致，没有夸大、遗漏或把推断写成事实；
- 目标、路径、动作边界、完成条件和验证要求互相一致；
- 确定修改路径、可能修改路径、待用户决定和实施阶段补证清楚分开；
- 标准路线的确定文件变更、列明普通验证、结果记录和满足条件后的关闭可由普通任务在一次明确实施授权中完成，
  差额停止条件和高风险操作边界没有遗漏；
- 保存不等于施工授权，完成条件不冒充结果，方案明确要求满足验收要求后退出活动生命周期，且关闭不依赖 Git 交付。

## 交接并退出

方案保存和静态自审完成后立即停止。后续普通任务负责补齐决定、复核漂移，并按目标项目规则实施；标准路线按
上述一次实施授权语义执行确定文件变更、普通验证、结果记录和满足条件后的关闭，只对新增副作用或高风险动作申请
差额。本 Skill 不生成执行授权包、不跟随实施结果，也不因用户说“继续”“验证”或“关闭”而恢复执行阶段。

最终只报告本次结构检查与方案保存结果、未获授权操作和未覆盖范围。机械门禁只能证明对应机械规则，不能替代
内容一致性、测试充分性、项目安全或整体治理闭环结论。
