# 项目文档结构建议审计

## 职责

只发现会妨碍读者找到当前信息或判断权威来源的真实结构问题：

- 入口或导航链接失效，当前文档无法从项目入口合理到达；
- 同一主题存在竞争所有者，无法判断哪份是当前真源；
- 活动内容与历史内容边界不清，旧材料可能被误当成当前合同；
- 当前项目明确声明的结构职责没有实际承接者。

成熟项目已有等价入口、命名、生命周期或测试治理时直接复用。缺少某个标准文件、路径与示例不同、没有 Registry、没有
自动门禁或没有固定方案目录，本身都不是问题。不要提出迁移到统一骨架，也不要携带、安装或要求 T-DOC、测试套件、
证据 schema、运行账本或其他治理资产。

本 Skill 只读并只交付报告。即使用户同时说“修复”“落方案”或“实施”，也不写文件、不保存方案、不登记待办、不改变
生命周期、不运行测试或构建；报告后说明建议可由普通任务另行实施并停止。不要调用或假定其他 Skill 已安装。

## 范围与证据

1. 先读取目标路径适用的项目规则和当前文档入口。用户指定文件或主题时只检查该范围；未指定时，从项目自己的入口和
   活动声明识别并完整读取全部活动文档。
2. 当前入口不足以可靠界定活动范围时，报告范围不明、已有证据和未覆盖内容；不要退化为全仓 Markdown 扫描，也不要
   自行规定标准路径。
3. 只为判断入口、所有者或活动／历史边界读取一层直接证据，例如直接链接、所有权声明、当前索引或直接机械消费者。
   不从命中继续递归，不自动扫描全部源码、测试、CI、配置、历史或归档。
4. 历史材料默认只提供语境；只有当前入口明确把它继续定义为现行内容时才纳入。项目级 Agent Skill 文件默认是工具资产，
   除非项目明确把其中某项声明为本次结构证据。
5. 不用标题、固定文案、文件白名单、源码 Token、固定数量、行数或耗时替代正文判断。

## 反过度治理门

建议新增规则、文档或测试前，先确认：

- 它保护的具体行为或合同是什么；
- 谁会实际消费它；
- 已发生或合理预期的失败是什么；
- 为什么现有入口或测试不能证明；
- 什么条件下可以删除。

任一项没有答案，只把想法标为可选建议，不建议形成长期项目资产。若治理设施明显重于被治理内容，直接指出成本并优先
建议收缩。安全、协议、合规或其他高风险发现只建议相应专业审查，不把本次结构审计扩张成专项治理。

## 报告

保持简短，包含：

- 实际检查的活动文档范围和一层证据边界；
- 每个真实问题的位置、证据、实际影响和最小建议；
- 因证据不足而无法判断的内容及未覆盖边界；
- 若无问题，明确“在已检查范围内未发现真实结构问题”。

不要输出编号审计分片、覆盖矩阵、评审轮次、方案候选或实施就绪结论。建议不等于修改授权。
