# 项目文档骨架检查与方案

## 职责与路线

只支持单一上下文项目，并独立处理两条路线：

- **标准骨架**：新项目、采用标准骨架的现有项目，或用户明确选择的结构迁移；
- **等价既有治理**：成熟项目可以保留不同路径、schema、导航和门禁，但必须用当前证据证明全部适用结构职责。

只检查文件、目录、入口、导航、职责、活动与历史生命周期、测试治理、测试资产信息架构和机械门禁。可以读取直接
相关的治理证据，不持续核对产品事实，不评价测试覆盖、重复、断言质量或成本，也不把结构检查扩张为安全认证。
内容事实冲突、正文膨胀、产品或测试实现缺口和真实语义取舍只形成精确交接。

不要调用、依赖或假定其他 Skill 已安装。

仓库任意层级的 `.agents/skills/**`、`.cursor/skills/**`、`.claude/skills/**`、`.codex/skills/**`、
`.opencode/skills/**`、`.opencode/skill/**` 和 `.github/skills/**` 是标准项目级 Agent Skill 工具资产。用户、适用
项目规则或本轮已进入范围的精确配置还可以声明其他项目级 Skill 根。默认不把这些资产纳入活动文档、导航、历史
分类或覆盖矩阵；不要为发现自定义根扫描全部工具配置。只有活动结构声明精确要求某个 Skill 的存在、入口或职责时，
才读取必要文件作为一轮实现证据，不审计其正文。显式 Skill 审查交给专项任务；不要宽泛排除整个工具目录或其他
位置的 `SKILL.md`。

## 只检查与落方案

1. **检查**：始终只读。即使请求包含“修复”“施工”或 `apply`，也要完整检查、报告并询问是否保存方案。
2. **落方案**：只有用户看到结果后明确要求保存，才写一份主责方案及必要待办；按项目生命周期保持待确认，完成
   静态自审后立即停止。

本 Skill 没有施工、验证、重试、归档、删除或关闭阶段。已有对应活动方案时只报告普通任务接手位置；只有用户明确
授权“仅修订方案”时才更新方案本身。保存方案不授权目标文件修改或命令执行；后续普通任务遵守目标项目规则和当轮
实施授权，出现新语义决定、候选实质漂移、验证升级或新增副作用时只申请差额。

没有可施工问题时仍询问是否保存检查记录。优先使用项目现有记录位置；没有承接位置时保存前询问，不创建统一记录
目录，也不用空活动方案冒充记录。

## 按路线读取参考

先完整读取目标路径适用的全部 `AGENTS.md`，再判定路线：

- 采用标准骨架的项目检查（含新建）、明确迁移或用户要求标准结构比较时，完整读取
  [`references/skeleton-rules.md`](references/skeleton-rules.md)；成熟等价项目不因存在文档或测试目录而读取它。
- 标准测试治理、标准 T-DOC 或标准验证规划适用时，完整读取
  [`references/testing-baseline.md`](references/testing-baseline.md)；成熟等价项目保留自己的测试治理。
- 只有标准路线方案需要判断通用门禁资产的安装边界时，才读取 `assets/SoftwareTesting/doc_consistency/` 下对应整
  文件；只记录字节一致、冲突和停止条件，不安装资产或选择复制机制。

不要把参考复制到目标项目，也不要创建 profile、manifest、版本号或隐藏治理状态。

## 冻结有限范围

先写明结构维度、文件集合和排除项，再建立覆盖／残余矩阵：

1. 从用户范围、适用规则、公开入口、文档与测试入口、活动／历史索引及其直接治理链接建立初始集合；列举活动
   Markdown 和结构目录核对完整性，但精确排除项目级 Skill 工具资产。
2. 对集合内文件充分读取完成结构判断，不以标题、固定 token、固定行数或 fenced code 代替正文。
3. 只有直接链接、结构冲突来源或会改变某一维结论的机械实现才能加入集合；记录路径和理由。
4. 不遍历无关产品源码、全部测试、全部 workflow 或历史来寻找替代答案。证据不足时记录缺少的角色和最小补证条件。

拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，以精确旧路径、标识或职责声明为种子，只读取会改变
退出结论的一层直接消费者，包括直接引用、默认配置、启动接线、自动化触发、运维入口和结构机械断言。不要从命中
继续递归。结构断言进入结构实施切片，产品行为断言留给相应职责；无法分离或边界不足时保持待决。

既有未提交修改属于当前证据。保存方案时要求普通任务施工前重新冻结拟改文件，存在覆盖风险时停止。

## 调查测试资产信息架构

存在活动测试治理入口／根，或结构清单发现未被活动入口承接的顶层测试目录时：

1. 从测试总入口与 Registry 或等价选择入口建立活动项的入口、所有者和实现根映射；
2. 对集中治理或跨 suite 组织根列出完整受管路径，对模块内部测试根只核对入口、模块所有者和选择映射；
3. 把未接线顶层测试目录列为所有权待确认候选；
4. 只有职责或一层直接依赖会改变结构结论时，才读取必要 runner、fixture、fake、helper、构建或配置证据。

目录混放、导航脱节、职责含糊、历史命名和跨职责依赖只是调查信号。根据当前证据形成项目特定结论，并把实际根、
映射、推荐目标、保留例外、影响和残余写入方案；不要固定目录名、层数、共享目录、一项测试一目录或 runner 拆分。

## 检查全部结构维度

一次检查完成全部适用维度，不在首个缺口停止：

1. **上下文与路线**：单一上下文边界及采用标准或等价路线的依据；
2. **结构与职责**：必要事实、协作规则、测试治理、待办和条件专题的唯一承接；
3. **入口与导航**：用户、协作、专题和测试入口、实际链接、可达性及重复权威入口；
4. **活动与历史生命周期**：当前、临时、被替代和历史材料的归属、退出与承接；
5. **待办、方案与记录**：状态、数量、实际链接及检查—保存—普通任务接手边界；
6. **测试治理结构**：验证层级、选择入口、suite 职责、活动入口及适用测试资产信息架构；
7. **机械门禁与授权边界**：门禁、自测试、结构规则和受限操作的权威规则入口及直接接线。

矩阵逐项记录维度、精确范围、状态和证据／残余。状态只使用 `已覆盖`、`无法验证`、`需要决策`、`未覆盖` 或
`不适用`；已覆盖项再注明 `满足` 或 `存在缺口`。内容事实与测试经济性据实标为未覆盖或不适用。

成熟结构只有全部适用维度均满足时才能判为等价；否则保留现状，列出全部已发现缺口和修复条件，不自动套用标准
骨架。总体结论只限本次冻结范围，不能扩写为内容一致、测试充分、安全认证或工作区全部 Markdown 已审计。

## 报告、保存并退出

检查结束报告路线、冻结范围、排除项、已填矩阵、按根因合并的结构差异、跨职责交接、未运行验证和未获授权操作，
然后询问是否保存。不要因为用户表达修复意愿而跳过停点。

保存的一份方案必须让没有参加检查对话的普通任务独立接手，并物化：

- 活动文件、所有者、排除项、已填矩阵、初始证据和未覆盖范围；
- 每项差异的影响、选项、推荐理由、用户决定和最小补证条件；
- 确定与可能路径、动作边界、完成条件、验证要求、可预见验证副作用及无落盘调用／受控输出／精确清理办法、授权
  差额和生命周期收尾；直接证据声称验证只读而默认调用会落盘时必须在方案内解决；
- 拟退出内容的一层消费者证据及结构／产品断言分流；
- 最终范围与漂移复核：普通任务只核对最终入口与所有者、确定切片、方案已列直接消费者，以及本次修改路径新产生
  的一跳直接链接或消费者；不递归、不扫描整个工作区、不重做内容或测试设计审计。

标准路线按所选参考实例化当前任务值；等价路线保留目标项目自己的生命周期、门禁和授权语义。内容事实、产品或
测试设计问题只形成精确交接，不扩大 skeleton 主责方案。

写入后静态自审证据、矩阵、路径、动作、验证及其可预见副作用处理、授权、收尾和保留能力是否一致，确认完成条件
没有冒充结果。随后立即停止；最终只报告检查与方案保存结果、未获授权操作和未覆盖范围。
