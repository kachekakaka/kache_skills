# 项目文档骨架与结构治理

## 坚守职责与独立性

只支持单一上下文项目，并独立处理两条路线：

- **标准骨架**：为新项目或用户明确选择的结构迁移建立固定主干和适用条件模块；
- **等价既有治理**：成熟项目使用不同路径、schema 或机械实现，但当前证据证明结构职责和必要安全结果等价时原样保留。

只处理文件、目录、入口、导航、职责归属、活动与历史生命周期、测试治理结构和机械门禁。为完成结构判断，
可以读取当前文档和直接相关的治理证据；不要持续核对产品事实，不要审计测试设计经济性，也不要把结构检查
扩张为攻击面扫描或全项目安全认证。

不要调用、依赖或假定其他 Skill 已安装。发现内容事实冲突、正文重复或膨胀、内容放置不当、测试实现缺口或
真实语义取舍时，输出包含目标、双方证据、影响、建议动作、授权需求和完成条件的精确交接。

## 严格分离检查、保存与施工

把一个新问题的生命周期分为三个阶段：

1. **检查**：新一轮首次调用始终只读。即使用户说“检查并修复”“建立骨架”或直接写 `apply`，只要没有已保存、
   已裁决且无漂移的活动方案，就完整检查结构、报告结论并询问是否保存方案；不要在同一次运行继续施工。
2. **保存**：只有用户明确说“保存方案”或“落方案”后，才把一份集中方案写入项目现有活动方案位置。项目缺少
   该位置时，可以在同一明确保存授权下建立；保存后的待办和方案保持 `待确认`，保存不授权施工。
3. **施工**：只有差异已经裁决，用户再次明确选择 `apply` 或其他施工方式，并且方案与当前项目没有实质漂移时，
   才把待办转为 `实施中` 并按方案写入。施工授权不继承检查或保存阶段的授权。

`check` 表示检查阶段，未指定阶段时默认 `check`。`apply` 只表示按满足上述条件的活动方案施工，不是跳过检查和
保存的捷径。用户可以选择其他施工方式；本 Skill 不把方案绑定到自身执行。

没有可施工问题时仍询问是否保存检查记录。用户选择保存后，优先使用项目现有检查记录、工作记录或历史记录
位置；项目没有承接位置时，保存前询问一次精确位置。不要创建统一记录目录，也不要用空活动方案冒充记录。

## 检查适用性与授权

1. 完整读取目标路径适用的全部 `AGENTS.md`。
2. 分别核对文件修改、命令、commit、push、PR、发布和安装授权；不要相互推定。
3. 发现 `CONTEXT-MAP.md`、多个领域 `CONTEXT.md` 或明显独立业务上下文时停止，不要压平多上下文结构。
4. 发现既有语言约定时保留原规则并展示冲突；修改语言规则不包含批量翻译授权。
5. 不自动运行构建、测试、产品程序、真实数据操作、联网、Git 操作或正式认证。
6. 不修改产品代码、产品行为断言、`CONTEXT.md` 或 ADR 正文，不覆盖用户已有工作区修改。施工授权内可以最小
   修改只约束已确认路径、入口、生命周期或自动化副作用的结构机械断言；与产品断言无法可靠分离时停止并交接。
7. 不把凭据、真实用户数据或原始运行现场写入仓库或交接。

## 按需读取资源

- 每次完整读取 [`references/skeleton-rules.md`](references/skeleton-rules.md)。
- 新建、迁移、测试治理变化或验证层级问题适用时，再完整读取
  [`references/testing-baseline.md`](references/testing-baseline.md)。
- 只有用户已经选择标准骨架，且准备安装或审查通用门禁资产时，才读取
  `assets/SoftwareTesting/doc_consistency/` 下对应源码。安装只约束整文件逐字节一致和冲突停点，不预设复制命令
  或常驻 helper；不能保证整文件复制时停止，不以片段补丁代替。目标已有不同内容时停止并展示冲突。
- 不把参考文件复制到目标项目，不创建 profile、manifest、版本号或隐藏治理状态。

## 冻结有限范围并充分读取

先记录本轮结构检查维度和文件集合，再形成结论：

1. 从用户指定范围、适用协作规则、项目公开入口、文档与测试入口、活动/历史索引，以及它们指向的直接治理
   证据建立初始集合。可以列举活动 Markdown 和结构目录以核对完整性；不要只按文件名猜职责。
2. 冻结的是结构问题边界和本轮文件集合，不是理解能力。对集合内文件完整读取完成判断所需的正文，不限制为
   标题、链接 token、固定行数或 fenced code。
3. 只有新发现的直接链接、结构冲突来源或会改变某一维结论的机械实现才能加入集合；记录新增路径和理由。
4. 不为寻找替代答案无限遍历产品源码、全部测试、全部 workflow 或历史。证据仍不足时明确写出缺少的角色和
   最小补证条件。

既有未提交修改属于当前证据。施工前重新冻结拟改文件；与方案冲突或出现不可恢复覆盖风险时，只暂停受影响项。

## 完整检查全部结构维度

一次 `check` 必须完成全部适用维度，不在首个缺口处停止：

1. **上下文与路线**：确认单一上下文边界，判断是新建标准骨架、标准骨架日常检查，还是等价既有治理检查。
2. **结构与职责**：核对必要事实、协作规则、测试治理、待办和条件专题是否有唯一承接职责；标准路线同时核对
   固定与条件路径，等价路线不要求相同文件名或 schema。
3. **入口与导航**：核对用户入口、协作入口、专题入口、实际 Markdown 链接和适用可达性，识别重复权威入口。
4. **活动与历史生命周期**：核对当前、临时、被替代和历史材料的结构归属、退出条件、归档入口与当前承接关系。
5. **待办、方案与记录生命周期**：核对状态、活动方案数量、实际链接、检查—保存—施工阶段，以及无问题检查记录
   的现有承接位置。
6. **测试治理结构**：核对验证层级、Registry 或等价选择入口、suite 职责和活动入口；不要据此评价覆盖是否充分、
   测试是否重复或实现是否正确。
7. **机械门禁与授权边界**：核对适用门禁入口、自测试、结构规则，以及命令、Git、真实数据、进程、输出和删除的
   权威规则入口。只读取与这些结构声明直接相关的接线，不认证整个项目安全。

每一维使用 `满足`、`存在缺口`、`证据不足` 或 `不适用`，并附当前证据；`不适用` 必须有当前依据。完成所有
维度后再给总体路线结论，不综合打分，不用一项成功抵消另一项缺口。

成熟结构只有全部适用维度均为 `满足` 时才能判为等价既有治理。未成立时保留现状，完整列出所有已发现结构
缺口及各自修复条件，不自动套用标准骨架。已证明等价时保留现有目录、导航、Registry schema、类别词汇和
项目专用门禁；标准化迁移只能作为另一个待保存、待裁决的选项。

## 输出检查结论并停下

检查结束只输出便于裁决的摘要，不在对话中展开完整施工方案：

- 路线结论和冻结范围；
- 全部结构维度的结论、关键证据和未检查原因；
- 按共同根因合并的结构差异及其影响；
- 内容、语义、测试实现或其他职责的交接项；
- 未运行验证和未获授权操作；
- 是否保存方案或无问题检查记录的问题。

不要因为用户已经表达修复意愿而跳过停点。只有用户随后明确选择保存，才进入保存阶段。

## 保存一份可裁决方案

每项差异记录当前结构证据、目标规则、影响、可选处理、推荐理由和用户决定。方案同时记录所有拟新增、修改、
移动、归档和删除路径，以及验证层级、验证影响域和具体验证项。

同一待办最多一份活动方案：

- `待确认` 可以没有方案，也可以有一份已保存方案；
- `实施中` 必须有且只有一份方案；
- `待实施`、`暂缓` 及退出活动状态不得保留活动方案；
- 完成、取消、暂缓、被替代或转出活动列表后，移除活动入口和活动方案文件。

保存后停止，等待用户裁决差异并重新选择施工。无法由当前证据决定的职责、承接位置、不可恢复变化或语义冲突
保持待决，不写占位结论。

## 按方案实施结构变化

施工前重新读取适用规则、活动方案、待办状态和全部拟改文件。只实施已裁决、已授权且无漂移的项目；新增差异
回到检查或裁决，不扩大原授权。

先建立承接位置和入口，再移动或退出旧位置。退出旧入口前核对其直接消费者闭包：引用、默认配置、启动接线、
自动化触发、运维入口和结构机械断言。只沿会改变退出结论的直接证据展开；发现部署或产品行为选择时停止裁决，
保留上游入口，不先退出。未跟踪、已有未提交修改、无版本控制或无法可靠恢复的内容，在移动、覆盖、归档或
删除前先确定可恢复方式；不得删除产品代码、配置、构建脚本或产品行为测试。

涉及自动化、外部副作用或授权选择时，在裁决前用三行白话分别说明“会发生”“不会发生”和“既有状态”，不要
只展示 workflow、权限或参数。

新项目只写标题、路径职责、必要导航和用户明确确认的“不适用”，不要虚构产品能力、实现、测试、构建产物或
大段 TODO。既有文档一对一迁移时保持事实正文原样；内容错误、重复正文和位置不当只形成交接。

通用 T-DOC 只在标准骨架路线从资产逐字节安装。等价既有治理保留项目专用门禁，不安装、不替换也不要求改名。

## 验证、review 与交接

命令需要独立授权。每次申请前在对话中建立本次临时验证执行账本，列出实际运行器、工作目录、现有依赖、输出
位置，以及可预见的 Git、联网、产品进程、真实数据、安装或其他嵌套副作用；账本不写入仓库，也不跨任务继承。

获准后按实际路线选择最小普通验证：标准骨架运行规则夹具、目标 T-DOC 并比较资产；等价既有治理运行项目自己
的结构门禁和自测试。两条路线都静态复核入口、链接、意外文件、绝对本地路径、工作区差异和未授权修改。

规范验证没有执行时记为 `not_run`；替代静态证据单独报告，不能把原验证写成 `passed`。施工中途门禁通过只
绑定当时状态，不能替代生命周期关闭后的最终状态门禁。

只有用户验收并另行授权关闭后，才按固定顺序：记录已授权验证结果，退出活动待办入口，归档方案并更新索引，
确认适用条件目录是否为空，执行已在账本中列明并单独授权的精确空目录清理，再对最终状态运行适用 T-DOC。
最终命令未获授权时报告 `not_run`，不得把方案视为已经退出。

未运行适用验证时，只能报告静态结果和未验证项。最终分别报告：

- 本 Skill 范围为 `完成`、`部分完成` 或 `未实施`；
- 路线与全部结构维度结论；
- 实际结构变化、验证结果、review 发现、备份状态和未获授权操作；
- `待事实同步`、`待结构处理`、`待语义决策`、`待实现或验证`。

机械门禁通过只证明对应机械规则。不要用它替代内容一致性、测试充分性、项目安全或整体治理闭环结论。
