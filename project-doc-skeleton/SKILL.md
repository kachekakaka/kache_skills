# 项目文档骨架检查与方案

## 职责与路线

只支持单一上下文项目。先按当前请求确定交付路线，再独立判断结构路线：

- **路线待确认**：只显式调用本 Skill 或意图不足以可靠分流时，先询问只要检查报告还是检查后形成方案；回答前不得开始
  实质项目调查；
- **只报告**：用户只要求检查、审计、review 或报告且没有同时要求方案时，完成同等严格的只读检查并在对话中交付结果后停止；
- **形成方案**：用户明确要求形成、保存或修订方案时，进入候选评审与最终保存停点。

结构路线为：

- **标准骨架**：新项目、采用标准骨架的现有项目，或用户明确选择的结构迁移；
- **等价既有治理**：成熟项目可以保留不同路径、schema、导航和门禁，但必须用当前证据证明全部适用结构职责。

只检查文件、目录、入口、导航、职责、活动与历史生命周期、测试治理、测试资产信息架构和机械门禁。可以读取直接
相关的治理证据，不持续核对产品事实，不评价测试覆盖、重复、断言质量或成本，也不把结构检查扩张为安全认证。
标准完整测试和正式认证只描述最小充分能力选择，不得解释为全部测试资产、平台或环境的机械并集。
内容事实冲突、正文膨胀、产品或测试实现缺口和真实语义取舍只形成精确交接。

不要调用、依赖或假定其他 Skill 已安装。

仓库任意层级的 `.agents/skills/**`、`.cursor/skills/**`、`.claude/skills/**`、`.codex/skills/**`、
`.opencode/skills/**`、`.opencode/skill/**` 和 `.github/skills/**` 是标准项目级 Agent Skill 工具资产。用户、适用
项目规则或本轮已进入范围的精确配置还可以声明其他项目级 Skill 根。默认不把这些资产纳入活动文档、导航、历史
分类或覆盖矩阵；不要为发现自定义根扫描全部工具配置。只有活动结构声明精确要求某个 Skill 的存在、入口或职责时，
才读取必要文件作为一轮实现证据，不审计其正文。显式 Skill 审查交给专项任务；不要宽泛排除整个工具目录或其他
位置的 `SKILL.md`。

## 请求分流、只读检查与最终保存

1. **分流请求**：明确只要报告时直接进入只报告路线，不询问轮次、不形成方案候选、不询问保存；明确要求方案时直接
   继续后续方案步骤，不重复询问路线。请求只有 `$project-doc-skeleton` 或意图不足以可靠分流时，在实质调查前用一个
   白话问题询问“这次只要检查报告，还是检查后形成方案”，推荐先只要报告，并说明形成方案会继续取得自查轮数和反哺
   报告选择。允许回复“按推荐”或“只要报告”、“形成方案”或“暂缓”；“按推荐”只接受已展示的报告路线，沉默或
   模糊回复不构成选择。取得回答前只读取本 Skill 和为遵守安全边界所必需的适用 `AGENTS.md`，不得读取活动文档入口、
   枚举项目文档、搜索实现、检查 Git 或联网取证。已有活动方案的普通施工、验证或关闭请求只报告普通任务接手位置。
2. **联合取得方案选择**：方案路线在实质调查前用同一个白话问题询问“交付方案前需要我自查几遍”和“实施完成后
   是否生成反哺报告”，推荐“两轮、不生成”。用户已经明确给出的项直接采用；回复“按推荐”只在该联合问题中同时
   接受两项推荐，随后用一句白话复述。反哺报告若被选择，只是普通实施任务在项目修改和验证完成后的独立历史交付物，
   本 Skill 不生成报告，也不修改目标 Skill。
3. **检查**：始终只读。即使请求包含“修复”“施工”或 `apply`，也要完整检查并报告，不写方案、待办或检查记录。
   只使用文件读取、搜索和只读 Git 等静态证据；不运行测试、构建、产品、门禁或其他验证命令，即使调用可做到无落盘。
   候选中列明的全部动态验证保持 `not_run`，交给后续普通任务。
4. **候选与评审**：只在方案路线于报告后形成当前调用内的未保存候选，围绕冻结证据完成指定轮次的自我评审、自我修订和
   变更后复核。每轮检查证据、用户决定、确定／可能路径、验证副作用、授权、完成条件和收尾字段，不重新执行完整检查，
   也不因轮次数量扩大范围。各轮过程只存在于本次调用，不把逐轮意见、修订轨迹或评审日志写入最终方案。
5. **最终保存**：完成轮次后展示目标、保存路径、用户决定、确定范围、残余和完成轮次，再用白话询问是否“只保存
   方案，不开始实施”。只有最终确认后才一次写入主责方案及必要待办，按项目生命周期保持待确认；项目没有定义精确
   候选状态时使用 `待确认`，不自造近义状态。随后只机械核对写入结果与候选一致并立即停止。

用户回复“确认”“接受”“按推荐”“就这样”只确认当前问题明确展示的语义结果。当前问题没有明确询问写文件、登记
待办、保存方案、转换生命周期状态或开始实施时，不产生相应动作授权；较早授权只绑定原范围，不能扩展到后来出现的
新需求。进入任何生命周期状态也必须由当前明确动作请求和项目规则共同支持，不能从方案存在或单项语义确认推导。

能够直接调查的事实自行查明。提问前先使用允许的只读证据、适用项目规则和已确认决定消解选择；证据能够唯一裁决时，
直接说明依据和用户可感知结果，不再请求确认技术实现。纯实现细节由 Skill 选择，但用户可观察契约、真实治理取舍、
风险／成本偏好和不可逆结果不得伪装成实现细节。

不是每项不一致都构成语义决定。当前活动所有者、适用项目规则或已确认决定已经唯一给出结果时，冲突的旧实现、旧配置、
旧测试和历史记录只用于证明缺口、影响与改动成本，不是同等级候选；把它们列为修复项，不让用户重新拍板。只有当前
权威本身明确留白，或多个同等级当前权威互相冲突时，才进入语义决定。当前实现不能仅因改动较少而成为默认推荐；尚未
发布且会造成用户可见歧义的契约，优先推荐消除歧义。已有规则或决定还必须贯穿后续路径、目录、字段和生命周期安排，
不得把同一结果拆成新的实现问题再次询问。

证据无法唯一裁决的语义决定，或目标已明确但副作用超出当前授权的授权差额，一次只用一张用户决策卡询问，不混写
两类停点。卡片先标明“需要你决定的结果”或“需要你允许的动作”，再用日常语言给出推荐及理由、各选项的实际结果与
主要代价、可回退性和简短回复方式。内部字段、测试分类、路径、哈希、manifest、marker、pack 等只在确实帮助复核时
进入末尾的“技术备注（可跳过）”，且备注不得承载作出决定所必需的信息。容易混淆的概念先说明“这不是 X，而是 Y”；
沿用用户使用的流程名称，必要术语首次出现时用白话解释，不自行创造近义流程。授权差额涉及外部副作用时，在选项
影响中复用副作用效果摘要，明确会发生、不会发生和既有状态。

发送决策卡前先临时移除“技术备注（可跳过）”自检：标题、消歧、推荐、选项标签、实际结果、代价、可回退性和回复
方式必须仍能让不了解实现的用户独立作答。这些正文不得出现内部字段名、精确路径、内部 ID、Registry、suite、
manifest、Git、命令、代码格式，或用户没有使用过的组件、模块、服务与包名；确需复核的原名只放技术备注。决定名称时，正文写成“采用专门表达业务含义的名字”
与“沿用当前共用名字”等结果，不用标识符充当选项。每张卡明确给出“按推荐”、一个或多个白话备选和“暂缓”的回复
方式；任一条件不满足就先改写卡片，不向用户发送。

用户回复“按推荐”只表示明确接受当前卡片已陈述的推荐项；记录后用一句白话复述结果。不得把沉默、模糊回复或其他
问题的历史推荐当作确认；新问题、推荐改变或概念发生漂移时必须重新询问。用户明确暂缓的事项可以进入 `待确认`
方案，但受影响切片不得进入确定实施范围，必须记录最小解除条件和残余，且不能宣称对应评审已完成。

一旦识别语义决定，立即在当前轮计数前停下并只询问第一项；不得继续完成其余轮次、把问题留到最终摘要，或直接进入
保存停点。只有用户明确选择“暂缓／待确认”时才可不裁决保存；此时明确标出受影响切片的评审未完成，不能用候选整体
轮次掩盖它。

冻结检查完成后在当前调用内维持发现清单，并为每项发现分配仅在本次调用内使用的稳定标识。最终报告和候选必须逐项
承接全部冻结发现，分别标为已决定、确定、待决、跨职责交接、不适用或排除并给出依据；后续决定和评审不得静默删除、
合并掉或遗漏早先发现。提出最终保存问题前执行集合对账：发现清单、最终报告和候选处置的标识集合与数量必须完全相等，
并在最终摘要中逐项展示归宿；任一成员缺失、重复或无归宿时，本轮评审作废，回到候选修订并重做受影响评审，不得询问
保存。该清单、临时标识和对账过程不持久化为独立日志或账本，只用于保证本次最终输出闭合。

标准路线、参考中的默认做法和本 Skill 的推荐都不是用户决定。改变项目已声明的自定义 Skill 根、工具可发现性、
所有者或路径职责，或者在“迁移现有根”与“调整本地门禁”等多个有效治理结果之间选择时，必须作为语义决定逐项询问；
确认前只保留为可能路径，不得写成确定切片。已有项目规则或已确认决定能够唯一裁决时，才直接采用并列出证据。

项目规则明确要求“保留现有路径”时，本次范围内每条已经存在的路径都已获得位置裁决，包括尚未接线、尚无所有者或
名称不理想的路径；规则没有明确列出例外时，不得把所有者、纳管方式或完整检查关系的决定再次拆成“迁移还是原地”
问题。后续只补负责人、导航、选择关系和必要说明。只有项目规则明确把该路径排除，或用户主动要求迁移时，才另行评估
移动及其直接消费者。

同一测试资产的“以后由谁长期负责”和“完整项目检查是否默认覆盖”是两个独立治理结果。当前证据同时把两者留白时，
先逐项询问所有者；用户选择后只重新判断尚未裁决的完整检查关系。若它仍有多个有效结果，必须在当前轮计数前另发一张
白话决策卡，不能让所有者选择顺带代表检查范围，也不能以测试质量、覆盖率不在本 Skill 职责为由标成未覆盖或范围外。
这里裁决的是治理入口的默认选择关系，不是评价测试够不够好。第二项决定仍只补选择关系；适用规则已要求保留路径时，
不得借此重新询问移动方式。

形成方案候选时，把验证入口的调用方式作为就绪证据。对会读取文本的新增 Python 验证入口，必须声明 `-X utf8` 或由
当前证据证明等价的显式 UTF-8 运行模式；`-B` 只负责禁止默认字节码缓存，不能替代运行编码。缺少显式模式是可机械
查明的就绪缺口：自行修订候选，修订前不计受影响评审轮次，也不要把该事实作为用户语义决定。

正确启用显式 UTF-8 后仍发生 `UnicodeDecodeError` 或等价严格解码错误时，把验证结果规划为失败；不得猜测本地编码、
使用替换字符继续或用宽泛文件迁移掩盖错误。成熟等价项目已有的权威命令不自动改写；若当前证据表明它依赖 locale，
只记录可移植性残余、影响和可能修订路径，等待对应决定与授权。本检查不运行命令，也不扩大通用 T-DOC 的文件范围。

本 Skill 没有施工、验证、重试、归档、删除或关闭阶段。已有对应活动方案时默认只报告普通任务接手位置；只有用户
明确要求修订方案时，才按同一未保存候选流程处理，原文件在最终保存确认前保持不变。保存方案不授权目标文件修改
或命令执行；后续普通任务遵守目标项目规则和当轮实施授权，出现新语义决定、候选实质漂移、验证升级或新增副作用时
只申请差额。

没有可施工问题时不创建待办或空方案。对话检查报告仍直接输出；用户选择保存检查记录时，先按所选轮次复核未保存
记录候选，再在最终停点询问，只使用项目现有记录位置。没有承接位置时在最终保存前询问，不创建统一记录目录。

最终保存新建了此前不存在的活动方案容器、且项目规则要求关闭后清理空容器时，保存方案必须记录“保存前不存在、由
本工作保存阶段创建、归档后为空即可由后续普通实施任务精确删除”。这里的工作所有权跨越检查任务与实施任务，不因
换用全新普通任务而丢失；普通任务凭该记录和实施授权即可清理。保存前已存在、归属不明或关闭后非空的目录不得这样
标记或删除。

## 按路线读取参考

先完整读取目标路径适用的全部 `AGENTS.md`，再判定路线：

- 采用标准骨架的项目检查（含新建）、明确迁移或用户要求标准结构比较时，完整读取
  [`references/skeleton-rules.md`](references/skeleton-rules.md)；成熟等价项目不因存在文档或测试目录而读取它。
- 标准测试治理、标准 T-DOC 或标准验证规划适用时，完整读取
  [`references/testing-baseline.md`](references/testing-baseline.md)；成熟等价项目保留自己的测试治理。
- 存在活动测试治理入口／根，或冻结结构清单发现可能未被入口承接的测试资产时，完整读取
  [`references/test-asset-structure.md`](references/test-asset-structure.md)；标准与等价路线都使用该有界证据方法。
- 只有标准路线方案需要判断通用门禁资产的安装边界时，才读取 `assets/SoftwareTesting/doc_consistency/` 下对应整
  文件；只记录字节一致、冲突和停止条件，不安装资产或选择复制机制。

不要把参考复制到目标项目，也不要创建 profile、manifest、版本号、持久评审日志或隐藏治理状态。

## 冻结有限范围

先写明结构维度、文件集合和排除项，再建立覆盖／残余矩阵：

1. 从用户范围、适用规则、公开入口、文档与测试入口、活动／历史索引及其直接治理链接建立初始集合；列举活动
   Markdown 和结构目录核对完整性，但精确排除项目级 Skill 工具资产。
2. 对集合内文件充分读取完成结构判断，不以标题、固定 token、固定行数或 fenced code 代替正文。
3. 只有直接链接、结构冲突来源或会改变某一维结论的机械实现才能加入集合；记录路径和理由。
4. 不遍历无关产品源码、全部测试、全部 workflow 或历史来寻找替代答案。证据不足时记录缺少的角色和最小补证条件。

拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，以精确旧路径、标识或职责声明为种子，只读取会改变
退出结论的一层直接消费者，包括直接引用、默认配置、启动接线、自动化触发、运维入口和结构机械断言。不要从命中
继续递归。结构断言进入结构实施切片，产品行为断言留给相应职责；无法分离或边界不足时保持待决。

既有未提交修改属于当前证据。形成方案候选时要求普通任务施工前重新冻结拟改文件，存在覆盖风险时停止。

单一上下文判断按以下证据优先级收敛：用户在当前任务中的明确声明；项目长期规则和公开入口；实际所有权、发布节奏、
术语与变更闭环；只有前三层都不能裁决时，目录、语言、产品形态和外部上游才作为调查信号。最后一层不能单独证明
必须拆分或合并上下文，证据仍不足时记录最小残余。

读取目标项目生命周期时，分别记录当前待办状态、该状态是否允许存在方案、是否已经取得实施授权，以及方案存在能否
证明已经开工。标准路线遵守标准表；成熟等价项目服从自己的明确规则。四项不得相互反向推导。

## 检查全部结构维度

一次检查完成全部适用维度，不在首个缺口停止：

1. **上下文与路线**：单一上下文边界及采用标准或等价路线的依据；
2. **结构与职责**：必要事实、协作规则、测试治理、待办和条件专题的唯一承接；
3. **入口与导航**：用户、协作、专题和测试入口、实际链接、可达性及重复权威入口；
4. **活动与历史生命周期**：当前、临时、被替代和历史材料的归属、退出与承接；
5. **待办、方案与记录**：状态、数量、实际链接及检查—候选评审—最终保存—普通任务接手边界；
6. **测试治理结构**：验证层级、选择入口、suite 职责、活动入口及适用测试资产信息架构；
7. **机械门禁与授权边界**：门禁、自测试、结构规则和受限操作的权威规则入口及直接接线。

矩阵逐项记录维度、精确范围、状态和证据／残余。状态只使用 `已覆盖`、`无法验证`、`需要决策`、`未覆盖` 或
`不适用`；已覆盖项再注明 `满足` 或 `存在缺口`。内容事实与测试经济性据实标为未覆盖或不适用。

成熟结构只有全部适用维度均满足时才能判为等价；否则保留现状，列出全部已发现缺口和修复条件，不自动套用标准
骨架。总体结论只限本次冻结范围，不能扩写为内容一致、测试充分、安全认证或工作区全部 Markdown 已审计。

## 报告、评审、保存并退出

检查结束报告路线、冻结范围、排除项、已填矩阵、按根因合并的结构差异、跨职责交接、未运行验证和未获授权操作。
只报告路线在报告后停止。方案路线随后形成未保存候选并按本文件核心阶段完成评审；不要因为用户提前表达修复或保存
意愿而跳过最终保存停点。

保存的一份方案必须让没有参加检查对话的普通任务独立接手，并物化：

- 活动文件、所有者、排除项、已填矩阵、初始证据和未覆盖范围；
- 每项差异的影响、选项、推荐理由、用户决定和最小补证条件；
- 确定与可能路径、动作边界、完成条件、验证要求、可预见验证副作用及无落盘调用／受控输出／精确清理办法、授权
  差额和生命周期收尾；直接证据声称验证只读而默认调用会落盘时必须在方案内解决；
- 拟退出内容的一层消费者证据及结构／产品断言分流；
- 最终范围与漂移复核：普通任务只核对最终入口与所有者、确定切片、方案已列直接消费者，以及本次修改路径新产生
  的一跳直接链接或消费者；不递归、不扫描整个工作区、不重做内容或测试设计审计。

标准路线按所选参考实例化当前任务值；等价路线保留目标项目自己的生命周期、门禁和授权语义。内容事实、产品或
测试设计问题只形成精确交接，不扩大 skeleton 主责方案。

每轮评审静态核对证据、矩阵、路径、动作、验证及其可预见副作用处理、授权、收尾和保留能力是否一致，确认完成条件
没有冒充结果。最终确认后一次写入并机械核对，随后立即停止；保存正文最多记录用户选择的轮数、实际完成轮数和最终
决定／残余，不保留逐轮评语或修订轨迹。最终只报告检查、评审与方案保存结果、未获授权操作和未覆盖范围。
