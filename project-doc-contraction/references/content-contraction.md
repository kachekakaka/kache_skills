# 内容收缩审计参考

本参考只服务 `project-doc-contraction`。范围冻结、分片续跑、累计尾部、纠正和最终索引由共享长审计协议
承接；本文只定义怎样判断内容是否应删除、迁移、摘要加链接、合并、简化或保留。

## 自然收缩单元

内容覆盖必须穷尽每份长期文档的全部实质正文，但不建立固定逐段、逐行或项目级持久账本。

- 只有正文整体由同一角色、所有者和契约承接，且没有两个及以上稳定一级职责章节时，才可用一个单元覆盖全文。
- 有两个及以上稳定一级职责章节（通常是文档标题下的 `##`）时，每章至少一个单元，不得跨章合并。
- 同一章内若角色、所有者、消费者、内容类型或处置发生变化，继续拆分。
- 没有稳定标题时，在上述任一要素变化的位置分单元。

每个单元记录：

1. 当前内容和该位置应承担的文档角色；
2. 命名的唯一所有者、直接消费者、基线提交中的直接锚点或明确残余；
3. 收缩风险：重复、竞争真源、实现镜像、过程／快照、错位、摘要膨胀、复杂或不精准表达，或
   `consistency_blocked`；
4. 最小动作，或保留的具体依据。

“职责清楚”“属于核心真源”“已完整读取”“删除会损失能力”等概括只能作摘要，不能单独证明一个单元完成。

## 收缩检查轴

对每个单元检查：

- 同一当前事实、规则、决定或状态被完整重复或换一种措辞重复，形成竞争真源；
- 所有者正文被入口、摘要、方案、测试或运维文档复制成第二份长期正文；
- 源码、配置、schema、算法、测试实现或构建细节被逐段镜像到不应拥有它们的文档；
- 一次性设计讨论、施工步骤、排障过程、迁移轨迹或评审对话继续留在活动真源；
- 单次 PASS、日期化运行结果、机器快照、阶段证据或已经失效的历史结论冒充当前长期内容；
- 需求、设计、字段、测试、运维、待办或方案内容放在错误所有者；
- 聚合入口复制下级文档的命令、矩阵、默认值或专项步骤，而不是短摘要和链接；
- 摘要扩写成第二份正文，或默认入口加载了不理解项目也不需要的详细内容；
- 重复限定、嵌套说明、模糊指代、未定义术语、前提缺失或混合职责造成理解困难、歧义或不可验收结论。

措辞不同但含义、前提、例外和消费者义务相同不算事实冲突，可以作为重复候选。复杂度不按篇幅处罚；只有它造成
重复、职责负担、理解困难、歧义或维护漂移时才形成收缩发现。只对职责、链接、引用或正文复述已经表明直接相关的
所有者与消费者进行对照，不做全部活动文档两两比较。

## 一致性阻断

收缩只建立在用户明确指定、已经完成一致性整改和验证的基线提交上。出现以下任一情况时，当前单元必须标记
`consistency_blocked`：

- 两份当前来源对值、前提、例外、状态或适用范围给出互相冲突的含义；
- 当前所有者无法唯一裁决；
- 实现、配置或直接消费者表明一致性仍未关闭；
- 基线提交、完成证据或验证身份不足以证明当前事实稳定。

阻断记录写明冲突双方、最小证据缺口和应交给 `project-doc-consistency` 的精确内容种子。不得自行选择“看起来更新”
的一方，不得用删除或迁移掩盖冲突，也不得自动调用一致性 Skill。阻断单元不进入收缩动作和防误伤评审。

## 过时事实删除门

只要删除、迁移、合并或简化的理由依赖“已经过时”“当前已不是这样”“该事实已经错误”或“状态已经变化”，该单元
默认 `consistency_blocked`。收缩 Skill 不得通过删除当前错误表述来替代事实裁决。

只有同时满足以下条件，才可继续作为纯收缩：

- 一致性基线已经明确裁决当前事实、时态、状态和必要决定理由；
- 目标内容只是与该裁决重复的历史说明、过程快照或错位副本；
- 动作不会改变当前值、前提、例外、状态、决定理由或消费者理解。

阻断记录必须点名待裁决原句、当前权威和最小一致性交接种子。

## 删除优先的最小动作

按以下顺序选择：

1. 删除已经失效、重复、一次性或不再承担当前合同的内容；
2. 内容需要可达但不应重复时，只保留职责明确的短摘要和唯一所有者链接；
3. 内容仍有长期价值但所有者错误时，迁移到唯一所有者并删除原位置竞争正文；
4. 必要合同表达重复、含混或过度复杂时，在不改变值、前提、例外和义务的条件下合并或简化；
5. 只有当前职责需要、没有等价真源且删除会损害用户合同或实施闭环时，才有证据保留；
6. 真实价值取舍无法裁决时使用 `需要决策`；事实或所有权冲突使用 `consistency_blocked`。

加目录、拆文件、换文件名或把正文搬到另一活动文档本身不构成收缩。动作必须说明退出或澄清了哪些重复、镜像、
过程、快照、复杂表达或错误所有权。

## 证明无需收缩

判为 `无需收缩` 时，文档记录必须承接全部自然收缩单元，且任何单元都没有未解除残余，并说明：

- 文档角色、允许内容和相关事实的唯一所有者；
- 每个单元的直接消费者或基线锚点；
- 重复、竞争真源、镜像、过程／历史、错位、摘要膨胀和表达风险为何没有命中；
- 当前细节为何属于用户可观察合同、实现结构闭环、稳定测试职责、必要决定理由或操作步骤；
- 删除、迁移、只留链接、合并或简化会损失的具体当前能力。

“文档都重要”“职责就是承接这些内容”“已经分文件”“暂时不长”或“以后可能需要”不是充分依据。

## 两种内容足迹

分别报告：

- **活动真源总内容足迹**：全部活动真源中需要长期维护的唯一正文总量；只有删除重复、实现镜像、过程、快照或错位
  正文，才证明这一足迹下降；
- **默认入口加载量**：从默认入口理解项目时首先需要读取的内容；短摘要、路由和按需 reference 可以降低这一负担，
  但不能证明总内容足迹已经下降。

不得把第二种收益描述成第一种，也不得为了追求缩减比例删除唯一必要合同。

## 收缩方案评审

### 查漏轮

进入评审时固定全部 `无需收缩` 文档为复核集合，但不冻结其结论。逐份回看原始正文和原报告证据，每份记录：

- 路径；
- `改变` 或 `未改变`；
- 本轮复核的自然收缩单元和至少一个命名原始证据；
- 改变后的发现与动作，或未改变的具体理由。

只列新增发现、只补已有发现路径、只报告数量，或因预计输出不足提前结束，都不能证明查漏完成。评审不得新增活动
文档路径，但可以在冻结路径内新增、删除、拆分、合并或改变发现。新发现事实冲突时改为 `consistency_blocked`，
不继续设计收缩动作。

### 防误伤轮

对当前候选中的每一项删除、迁移、摘要加链接、合并和简化建立动作记录，包括第一轮后的变化：

- 动作和目标内容；
- 保留唯一事实的位置；
- 用户合同、必要决定理由、字段合同、测试特定义务或运维步骤是否仍完整；
- 直接消费者仍保留的必要摘要、链接和义务；
- 动作理由是否依赖尚未裁决的“过时／当前已不是这样”事实；
- 是否产生新的事实冲突、职责缺口或语义漂移；
- `通过`、`修改` 或 `撤销`。

任一轮发现遗漏、依据不足、阻断或误伤时，先修订候选并重做受影响记录；修订前结论不计入完成轮次。发现清单、
残余和候选的一一归宿只能防止已有项目丢失，不能证明没有漏项。

## 收缩完成条件

至少证明：

- 每份长期文档的全部自然收缩单元都有四项记录；
- 所有 `consistency_blocked` 单元已经从收缩动作中隔离并有精确交接；
- 没有以“过时事实”为理由绕过一致性裁决；
- 每类当前事实、规则、决定和状态仍有明确唯一所有者；
- 直接消费者只保留职责所需摘要、链接和特定义务；
- 一次性过程、动态快照和历史结果退出活动真源；
- 必要入口仍能到达唯一所有者；
- 总内容足迹和默认入口加载量分别陈述；
- 查漏与防误伤评审完整且不存在未修正失败。

不得使用统一行数、字数、页数、缩减百分比或集合数量作为跨项目完成门槛。
