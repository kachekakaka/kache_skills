# 项目文档收缩建议审计

## 职责

只寻找可以安全减少长期维护负担的内容：

- 完全重复或换措辞重复、竞争真源和实现／配置／测试细节镜像；
- 施工过程、单次结果、日期化快照或已经退出活动职责的过程残留；
- 聚合入口复制下级细节、需求夹带设计、术语说明越界或内容放错所有者；
- 不服务当前读者和直接消费者的细节、摘要膨胀、复杂或不精准表达；
- 明显比被治理内容更重的规则、证据设施和维护流程。

篇幅大本身不是问题；拆文件或加索引也不等于总内容已经收缩。只有能说明当前角色、唯一事实和消费者仍被保留时，才提出
删除、迁移、摘要加链接、合并或简化建议。

本 Skill 只读并只交付报告。即使用户同时要求清理、形成方案或实施，也不写文件、不保存方案、不登记待办、不改变
生命周期、不运行测试或构建；报告后说明建议可由普通任务另行决定和实施并停止。不要调用或假定其他 Skill 已安装。

## 范围与证据

1. 先读取目标路径适用的项目规则和当前文档入口。用户指定文件、章节或主题时只检查该范围；未指定时，从项目自己的
   入口和活动声明识别并完整读取全部活动文档。
2. 当前入口不足以可靠界定活动范围时，报告范围不明、已有证据和未覆盖内容；不要退化为全仓扫描，也不要自行规定标准
   路径。
3. 直接使用当前工作状态，不要求不可变 SHA、干净工作树、事先完成一致性整改或验证。未提交内容属于当前可见证据，
   但不把它误称为已发布事实。
4. 每项候选只读取一层直接所有者或消费者证据后停止；不自动扫描全部源码、测试、CI、历史或归档。
5. 事实、所有者或消费者不清时，把对应内容列为“保留项”，说明缺少的证据，不借收缩改写事实。一个保留项不阻断其他
   独立内容继续检查。

## 反过度治理门

建议新增替代规则、摘要、文档或测试前，先确认：

- 它保护的具体行为或合同是什么；
- 谁会实际消费它；
- 已发生或合理预期的失败是什么；
- 为什么现有内容或测试不能证明；
- 什么条件下可以删除。

任一项没有答案，只把想法标为可选建议，不建议形成长期项目资产。不要为了删除少量文字先建设更大的证据 schema、
保留策略、运行账本、评审流程或 GC 工具。高风险内容只建议相应专业审查，不把本次收缩审计变成事实认证。

## 报告

保持简短，包含：

- 实际检查的活动文档范围和一层证据边界；
- 每个收缩候选的位置、维护成本或风险、需要保留的唯一事实和最小建议；
- 因事实、所有者或消费者不清而保留的内容，以及未覆盖边界；
- 若无问题，明确“在已检查范围内未发现有证据支持的收缩项”。

不要输出不可变基线确认、长审计分片、评审轮次、方案候选或实施就绪结论。建议不等于修改授权。
