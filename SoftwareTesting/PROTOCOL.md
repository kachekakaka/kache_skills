# 测试协议

## 验证层级

- 普通验证：默认层级，按实际影响选择最小可证明范围。
- 全量测试：仅在用户明确开启后执行，覆盖所有 `full`、本轮受影响的 `affected_only` 以及用户明确加入的 `explicit` 测试项。
- 正式认证：仅在用户明确要求后执行，包含必要的全量测试、候选身份核对和结构化交接。

本地只读操作和只读 Git 查询默认允许。用户明确授权按已确认方案实施时，该次授权覆盖确定范围内的文件变更、
方案列明的普通验证及结果记录，以及完成条件满足后的状态更新、方案归档、索引更新和精确任务清理；验证升级、
新增副作用、候选实质漂移或新的语义决定只申请授权差额。commit、push、PR、发布、安装、破坏工作区或改写历史
的 Git 操作，以及未列明的联网、产品进程、真实数据、全量测试和正式认证仍须明确授权。方案未列明、超出确定
范围、使用宽泛匹配或未解析路径、仓库外非任务产物、所有权不明或涉及真实数据的删除也必须取得精确授权；方案
关闭与 Git 交付相互独立。

构建入口和交付产物以根 [README 的“构建与交付”](../README.md#构建与交付)为唯一入口。构建义务不自动提升验证层级，正式认证也不自动授权 commit、push、PR、真实数据操作、发布或分发。

## 影响域与测试类别

每次变更在实施前和交接时记录测试层级、验证影响域与具体验证项。

- `full`：每次全量测试必须执行。
- `affected_only`：相关能力受影响时执行。
- `explicit`：涉及真实数据、破坏性操作、联网费用或特殊环境时，仅在用户明确加入后执行。

## 结果语义

- `passed`：规范命令进入可判定阶段并完成，所有纳入范围的断言通过。
- `failed`：规范命令已进入可判定阶段，断言、收集或被检查项目明确报告错误。
- `blocked`：运行环境或前置条件不足，规范命令未进入可判定阶段。
- `inconclusive`：执行被中断或运行器内部异常，现有证据不足以形成结论。
- `not_run`：测试项没有执行。

跳过只作为测试项内部计数，不能代替总体结论。同一候选只重跑失败、中断、`blocked`、`inconclusive` 或证据失效的项目；产品输入、测试契约或候选身份变化后重新判断范围。

## 全量测试、认证与交接

全量测试先确认候选和范围，再按 Registry 执行并汇总结果。正式认证在必要全量测试通过后核对候选身份，并在仓库外保存结构化摘要。交接至少记录实际层级、影响域、具体验证项、逐项结果、未覆盖范围和未获授权的操作。
