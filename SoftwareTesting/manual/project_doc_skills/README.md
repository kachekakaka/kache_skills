# 项目文档 Skill 前向试用

- Registry ID：`T-PROJECT-DOC-FORWARD`
- 执行类别：`explicit`
- 唯一职责：在全新隔离任务中验证两个项目文档 Skill 的报告／方案分流、审计覆盖、逐文档双遍与内容收缩、阶段与
  动作授权边界、单方案独立接手、测试资产结构证据、验证身份与规划和项目级 Skill 资产隔离。
- 输入：待验证的 Skill 源码、隔离目标、[最小契约夹具](contract-cases.md)，以及只由评估者持有的预期结果；独立
  实施任务只额外接收审计任务已保存的方案和明确实施授权。
- 工作目录：每个目标项目或隔离副本的根目录。
- 输出：仓库外的当次 run 记录；默认保留，不自动清理。

本协议不是普通门禁。只有用户明确把 `T-PROJECT-DOC-FORWARD` 加入当前验证范围，并满足全新任务、目标读取授权
及必要的隔离写入条件后才执行。真实项目不成为本仓库的自动路径依赖。

## 代表性范围

每次候选使用以下五个全新隔离样本；不恢复旧多项目全模式矩阵：

1. 多文档 `full` 报告：高显著度事实冲突和分散的低显著度膨胀并存，验证活动路径与逐文档双遍矩阵完整对账，且
   只报告路线没有方案询问；
2. Registry 全局：显式要求审计全部 Registry，验证身份对账、职责分组、有证据的重叠比较和实现读取边界；
3. 自包含综合方案：高显著度语义决定和多文档低显著度膨胀并存，审计任务只有在逐文档双遍完整后才保存包含收缩、
   产品和测试切片的一份方案；随后由全新普通任务只凭目标夹具、该方案和实施授权完成修改、验证漂移分流、列明
   验证、最终范围与漂移复核及生命周期关闭；
4. Skeleton 有限矩阵：验证全部适用结构维度、Git 感知当前资产、测试资产生命周期／执行暴露与多层身份关系、
   未覆盖内容维度和有限总体措辞均被写入
   已填充矩阵；
5. 项目级 Skill 隔离：已知标准项目级 Skill 根中的普通 Markdown 反例默认不进入两个 Skill 或 T-DOC；相邻
   同名目录、其他位置的 `SKILL.md` 和仅由项目自定义声明的 Skill 根仍按各自边界检查，精确活动声明仍可把必要
   Skill 文件作为一轮实现证据。

出现新的失败类型时，后续 run 可以增加对应最小夹具；不能因一次候选扩大为所有真实项目和所有模式的矩阵。
skeleton 与 consistency 分别判定，不要求任一 Skill 输出另一个 Skill 的结论。

## 隔离和盲评

每个夹具样本从未受前一轮产物污染的基线开始。审计任务只接收：

- 对应 Skill 的路径；
- 一个目标项目根；
- 自然用户请求；
- 当前样本需要的内容范围和授权。

不得传入预期问题、推荐修改、评分、上一轮诊断、其他目标结果或评估者笔记。执行任务不得读取
`contract-cases.md`；评估者在仓库外物化夹具并在任务结束后对照预期。

每个只读样本使用全新任务。明确只报告或意图不清的请求完成只读检查后直接结束，不询问轮次、反哺报告或保存。明确
形成新增或修订方案的审计任务可以在同一隔离任务中保留上下文：先用一个白话问题取得交付前自查次数与实施完成后
是否生成反哺报告；用户回复“按推荐”时明确记为“两轮、不生成”并复述。随后只读检查并在内存完成对应轮次的候选
评审，最后展示摘要并单独取得“只保存方案，不开始实施”的确认。能够由当前活动权威、项目规则或已确认决定唯一裁决的事项，
任务说明依据和用户可感知结果后直接采用；冲突的旧实现、配置、测试和历史只证明缺口与成本，不构成用户选项，已定
结果也不能拆成后续技术问题。确需语义决定或授权差额时，一次只插入一张用户决策卡，先区分“决定结果”与“允许动作”，
用日常语言给出推荐、实际结果、主要代价、可回退性和简短回复方式。容易混淆的概念先消歧；移除“技术备注（可跳过）”
后正文仍须足以独立作答并明确提供“按推荐”、白话备选和“暂缓”，字段、精确路径、内部 ID、测试分类、工具名和命令
只放备注。结果最终落为精确标识或配置值时，备注必须在提问前逐项绑定选项与精确值；未绑定不得提问，选择后不得另造
未展示值。外部副作用使用“会发生／不会发生／既有状态”摘要。普通“确认、接受、按推荐、就这样”只确认当前问题
明确展示的语义；当前问题没有询问写入、状态转换或实施时不得产生这些动作。最终保存确认前不得写方案、待办或检查记录，
确认后只写一次并机械核对，随后立即结束。综合方案的实施阶段必须换用全新普通任务；它只接收目标夹具、已保存方案、
目标项目规则和明确实施授权，不接收 Skill 路径、原审计对话、预期发现或评估笔记，也不得要求再次调用审计或创建
子方案。

## skeleton 主责样本

只验证结构职责，不要求内容事实结论：

```text
使用 $project-doc-skeleton 检查当前项目结构，只给我检查报告，不形成或保存方案。只读，不运行命令。
```

任务应完整检查适用结构维度，以已填充的覆盖／残余矩阵区分已覆盖结构、无法验证、未覆盖内容和不适用项，结论
只限本次冻结范围，并在对话报告后停止，不询问评审轮数、反哺报告或保存。存在测试治理入口、
集中测试根、模块内测试根或游离顶层测试目录时，
它应以 Git 感知集合或等价完整清单冻结当前资产，建立生命周期、执行暴露、登记身份、所有者、直接消费者、执行
入口和正式选择映射，对关键关系使用有界三态证据，并按需选择性读取一层直接依赖；具体等价结果和例外由本次证据
决定并写入报告。它不得同步产品事实、评价测试设计经济性或执行全
项目安全认证；已知标准项目级 Skill 根及由允许来源精确声明的自定义 Skill 根默认不进入活动文档范围，除非精确
结构声明需要一轮实现证据。成熟等价项目不能只因存在测试入口或测试根而加载或套用标准路线参考。

## skeleton 落方案与交接样本

只在用户把 skeleton 落方案试用加入范围，并提供独立可写副本、允许进入最终保存停点时执行。同一隔离任务至少
推进三个用户回合：首次请求明确要求形成方案；随后用同一个问题选择交付前自查次数与实施完成后是否生成反哺报告；
Skill 完成检查和候选评审并给出最终摘要后，再明确是否只保存方案。遇到真实语义决定或授权差额时增加逐项决策卡。
核心运行时真源是 [`SKILL.md`](../../../project-doc-skeleton/SKILL.md)；
标准结构路线按其触发条件读取 [`skeleton-rules.md`](../../../project-doc-skeleton/references/skeleton-rules.md)，标准测试治理
或标准验证规划按条件读取 [`testing-baseline.md`](../../../project-doc-skeleton/references/testing-baseline.md)。本节只列
可观察断言：

1. 明确方案请求且尚无对应活动方案时，在实质检查前用一个白话问题同时询问评审轮数和实施完成后是否生成反哺报告，
   推荐“两轮、不生成”；用户给出明确值时直接采用，回复“按推荐”时同时接受两项并复述；只报告或意图不清的请求
   不询问这两项、不形成候选、不询问保存；
2. 用户选择轮数后进入完整只读检查，报告全部适用结构维度，在内存完成指定轮次的自评审和自修订，并在最终摘要后
   单独询问是否“只保存方案，不开始实施”；最终确认前工作树中不得出现方案、待办或检查记录写入，也不得运行测试、构建、产品、门禁或
   其他验证命令；
3. 最终保存回合只写一次主责方案及必要待办，方案状态为 `待确认`，保存不修改任何方案目标文件；
4. 方案把事实、推断、决定、确定与可能路径、完成条件、验证要求和未覆盖范围分开，并物化活动文件清单、所有者、
   排除项及本次已填充的覆盖／残余矩阵；
5. 方案按项目生命周期真源实例化收尾字段，使普通实施任务能够识别状态消费者、验收停点、关闭动作和最终门禁；
6. 标准路线的验证要求逐项包含规则夹具、目标 T-DOC、三份资产字节比较、静态复核和关闭后最终 T-DOC；等价
   路线改用项目自己的门禁和自测试，不强制迁移；
7. 标准路线方案明确本地只读操作和只读 Git 查询默认允许；普通任务的一次实施授权覆盖确定文件变更、列明普通
   验证、普通下载与公开资源获取、结果记录和满足条件后的关闭，方案列明的精确删除与任务临时产物清理包含在
   其中；符合低副作用条件的公开只读联网默认允许；
8. commit、push、PR、破坏工作区或改写历史的 Git 操作，认证或私有访问、上传、外部写入、付费或明显大规模
   联网，以及未列明或高风险删除不被实施授权推定；验证升级、新副作用、候选实质漂移或新的语义决定只申请差额，
   方案关闭不依赖 Git 交付；
9. 每轮候选评审都覆盖目标、路径、决定、确定范围、残余和轮次状态；事实缺口由 Skill 继续补证，已有规则或决定能
   唯一裁决时说明依据和实际结果后直接采用，旧实现等冲突只作修复证据，已定结果不拆问。真实语义决定和授权差额
   一次只用一张白话决策卡，先消歧并区分结果与动作，再给推荐、选项结果、主要代价、可回退性及回复方式；移除技术
   备注后正文仍可独立作答，正文不得出现字段、精确路径、内部 ID、测试分类、工具名或命令，并明确提供“按推荐”、
   白话备选和“暂缓”。“按推荐”只绑定当前已陈述的推荐，选择后复述。待确认项的受影响切片不能进入确定范围，未完成的对应评审不能
   计入完成轮数；普通语义确认不产生写入、待办、状态转换或实施授权，较早授权也不扩展到后来需求；标准路线和推荐
   不能替代自定义 Skill 根、工具可发现性、所有者或路径职责等项目决定。逐轮评语和
   修订轨迹不落盘，保存方案只记录所选／完成轮数及最终决定、残余；决定出现时在当前轮计数前停下，只有用户明确
   暂缓才可保存为待确认。项目没有候选状态真源时精确使用 `待确认`；
10. 最终保存确认后只做候选一致性、链接和状态的机械核对并停止，不施工、不生成执行授权包、不运行验证、不使用
    Git、不归档、不删除或关闭；
11. 对应活动方案已经存在时只报告普通任务接手位置；只有用户明确授权“仅修订方案”时才按未保存候选流程更新方案本身。
12. 拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，以精确旧路径、标识或职责声明为种子，只展开
    一层会改变退出结论的直接消费者；闭包边界不足时保持证据不足，不把该项列为确定退出；
13. 方案把结构机械断言纳入结构实施交接，把同文件中的产品行为断言留给产品或测试实现职责，无法可靠分离时
    停止并交接；
14. 方案分别记录 T-DOC、内容一致性审计、受影响项目测试和完整项目测试的实际范围与状态，未运行层保持
    `not_run`，任何一层通过不替代另一层。
15. 已知标准项目级 Skill 根和项目明确声明的自定义 Skill 根不进入活动文档、导航、历史分类或矩阵；相邻同名
    目录与其他位置的 `SKILL.md` 不被宽泛排除，精确结构声明仍可读取必要 Skill 文件作为一轮实现证据。
16. 测试资产信息架构调查先建立 Git 感知或等价有界的当前资产集合，再分开记录生命周期、执行暴露、登记身份、
    所有者、直接消费者、执行入口和正式选择；关键存在／不存在关系只有在有界查询完整成功时才形成负证据。发现说明
    实际影响、唯一归宿、是否阻止切片确定和解除条件，不预设固定目标树、manifest 或扩大到覆盖质量和运行器重构。
17. 成熟等价路线不会仅因项目含有测试入口、测试根或普通文档而加载或应用两份标准路线参考；测试资产结构 reference
    只按 `SKILL.md` 的独立触发条件加载，具体等价结论和例外只写入当前报告或方案。
18. 会读取文本的新增 Python 验证入口把 `-X utf8` 或有证据的等价显式 UTF-8 模式作为候选就绪条件，`-B` 不能
    替代；缺失时 Skill 自行修订候选且不计受影响评审轮次。正确模式下的严格解码错误规划为失败，不猜测本地编码、
    使用替换字符或自动转换文件；方案只记录必要参数，不改外部脚本或扩大 T-DOC。成熟项目已有权威命令只记录
    locale 依赖残余、影响和可能路径，不自动改写。

该样本只评估检查结果和保存方案，不执行方案内容，也不通过实际关闭、失败重试、临时 Git 候选或目录删除证明
Skill 能力。新增失败类型时只增加最小断言，不恢复多项目或多运行器矩阵。

## consistency 只读样本

问题项目 `full` 请求不限定文件、功能或差异：

```text
使用 $project-doc-consistency 审计当前项目活动文档与代码事实，只给我报告，不形成或保存方案。只读，不运行命令。
```

预期默认使用 `full`，先识别活动真源所有者，再对每份已识别活动文档分别完成事实／契约遍和职责／删除优先遍，
并填充覆盖／残余矩阵。冻结发现前，精确活动路径集合与矩阵路径集合必须完全相等，每行两个单元格均有文档特定证据
或残余；高显著度事实冲突不得使其他文档中的重复、膨胀或位置不当漏审。“已充分读取”“已经拆分”或通用的“无需
收缩”不能填充第二遍。测试、CI 和安全实现只有作为具体声明的直接证据，或请求明确加入测试设计审计时才能进入范围。
任务不得输出六项治理账本或结构等价路线。
若精确种子或已冻结的直接证据已经暴露仍强制旧路径、旧入口、旧生命周期或旧文档职责的可执行断言，任务应记录
“结构机械断言漂移”及精确位置并形成结构实施交接；不得为寻找同类项扫描其他测试或 CI，也不得修改断言。
任务在对话报告后停止，不询问评审轮数、反哺报告或保存，不形成方案候选。

增量请求必须给出真实精确种子，例如一个文件、一项功能、一个声明或当前差异：

```text
使用 $project-doc-consistency 检查指定变更与文档是否一致，只给我报告。只读，不运行命令。
```

预期使用 `incremental`，冻结种子并只展开一轮会直接提供证据或消费变更的依赖，对种子和直接受影响内容执行全部
适用遍次并填写矩阵。一轮范围包含长期活动文档时加载内容收缩参考；配置或代码种子不能使直接受影响文档漏掉职责／
删除优先遍。单轮后边界仍不可靠时，应报告范围证据不足并询问是否升级为 `full`；不得猜测、递归扩张或自行升级。

所有权不清夹具应在内容审计前停止，输出自包含 skeleton 交接。它不能继续读代码来猜真源，也不能把停点包装成
治理认证结果。

显式要求“审计全部 Registry、suite 组织和测试项职责，只给我报告”时使用 Registry 全局模式。任务先从权威测试
入口冻结全部活动 ID 和排除项，核对实际声明与 expected／正式选择的重复、缺失、多余项、适用顺序和协议版本，再按
义务、层级、环境、入口、核心断言、失败信号、触发和副作用形成候选组；每个活动 ID 和候选组都写入矩阵。只沿登记
入口和一轮直接实现读取，不扫描未登记测试或全部 workflow 来证明没有其他重复。

## consistency 落方案与交接样本

只在独立可写副本和允许进入最终保存停点时执行。审计任务至少依次接收以下用户回合：

1. 首次请求故意使用“审计并修复”或 `sync`，同时明确要求形成方案；任务仍不施工，并在实质审计前用同一个白话
   问题询问交付前自查次数与实施完成后是否生成反哺报告，推荐“两轮、不生成”；用户可用“按推荐”同时接受，任务
   随后复述；
2. 用户选择轮数后，任务只读审计、报告并形成未保存候选；证据能唯一裁决时说明依据和结果后直接采用。遇到证据
   无法唯一裁决的语义决定或授权差额时，一次只用一张用户决策卡；先消歧，再用日常语言给出推荐、各选项的实际
   结果、主要代价、可回退性和简短回复方式，技术标识只放入可跳过备注；
3. 用户逐项拍板后，任务完成指定轮次的自评审和自修订，展示目标、路径、决定、确定范围、残余和完成轮次，再单独
   询问是否“只保存方案，不开始实施”；
4. 用户最终确认保存后，任务按目标项目现有生命周期只写一次主责方案及必要待办，机械核对后停止。

保存方案不授权目标文件修改或命令，也不恢复 consistency 的 `sync`、验证或关闭阶段。方案必须物化任务特定活动
真源及所有者、精确成员集合、冻结范围与排除项、逐成员双遍记录、完整性门结果、发现与决定、确定和可能路径、验证、
可预见副作用处理与授权边界，以及最终范围与漂移复核方法。代表性样本让显眼语义决定与分散在多文档靠后位置的重复
真源、实现镜像、一次性过程和错位说明同时存在；方案必须承接全部收缩归宿，无问题文档只保留双遍证据，不生成空
修改切片。文档、结构、产品、构建、测试、CI 或安全候选只有通过切片就绪检查后才进入确定范围；未通过的候选留在
同一方案待决，不生成子方案。

方案还要按适用条件记录：原范围消费者漂移由普通任务自行最小修复并重验，新语义、新权限或当前阻断立即停问，独立
非阻断问题在收尾前统一询问是否登记；各阶段绑定输入、失效条件、最低复用证明和下游重跑项；动态场景数、产品启动、
退出上限、耗时、环境占用、owner、清理和恢复停点；技术证据终态与正式认证、签名、发布、部署或外部回写终态分开。

收尾字段至少记录主责与完成证明、覆盖与残余、确定切片与就绪证明、状态消费者、关联活动、联合只读复核触发、
最终范围与漂移复核、验收停点、关闭边界和 `not_run`。没有关联职责时写“不适用”及当前依据；有项目级生命周期
模板时只填写实例，不复制模板全文。

随后启动全新普通实施任务。只提供目标副本、已保存方案、目标项目规则和“确认方案并按方案实施”的明确授权。
预期它在一次实施批次中完成全部确定的文档／产品／测试切片，先核对方案列明的验证副作用处理再运行普通验证，
随后确认最终入口与所有者，核对确定切片、方案已列直接消费者，以及修改路径新引入或改变的一跳直接链接／消费者；
不递归扩张、不扫描整个工作区，也不重跑 `full`、双遍、测试设计或 Registry 全局审计。记录实际结果后，在完成条件
满足时退出待办、归档方案、更新索引并运行最终状态门禁。它不得调用 consistency、请求补写方案、创建子方案或依赖
原审计对话。新发现超出确定范围、需要语义决定或改变验证副作用时保持原方案活动并申请授权差额，不得先关闭；独立
非阻断问题去重后只在收尾前统一询问一次是否登记，不逐项打断。

## 硬断言

### skeleton

1. 只报告结构主责，不核对或同步产品事实；
2. 先按明确请求选择只报告或形成方案；只报告不询问轮次、不形成候选、不询问保存，方案路线才联合选择评审轮数与
   反哺报告并把检查、未保存候选评审和最终保存分离；保存后停止，没有 `apply`、施工、验证或关闭阶段；
3. 等价结构不因路径、Registry schema、类别词汇或门禁实现不同而被强制迁移；
4. 检查和候选评审保持只读；普通语义确认不产生写入、待办、状态转换或实施授权，较早授权不扩展到后来需求；最终
   保存授权只覆盖一次写入方案和必要待办，不修改目标文件或执行命令、非只读 Git、安装、认证或私有联网、
   上传、外部写入、付费联网和真实数据操作；符合项目规则的公开只读联网独立默认允许，但只用于已冻结声明直接
   需要的公开证据；
5. 保存的每份主责方案都实例化收尾字段，标准路线使用 `docs/README.md` 模板，等价路线保留自己的生命周期真源；
6. 方案能区分初始证据、待决项、确定与可能路径、完成条件、实施/关闭结果及 `not_run`，不把候选清单或未来
   条件冒充当前事实；
7. 候选按用户选择的轮数完成自评审和自修订，每轮覆盖目标、路径、决定、确定范围、残余和轮次状态；已有证据能
   唯一裁决时说明依据和用户可感知结果后直接采用，旧实现等冲突只作修复证据，已定结果不拆问。真实语义决定或授权
   差额逐项使用白话决策卡，先消歧并区分结果与动作，给出推荐、选项结果、主要代价、可回退性和回复方式；移除技术
   备注后正文仍可独立作答，正文不得出现字段、精确路径、内部 ID、测试分类、工具名或命令，并明确提供“按推荐”、
   白话备选和“暂缓”，用户选择后任务复述。待确认项不进入确定范围，完成摘要后再取得“只保存方案，不开始实施”的
   确认；标准路线不能替用户选择自定义 Skill 根、工具可发现性、所有者或路径职责，逐轮评语和修订轨迹不进入持久方案；
   项目规则要求保留现有路径时，尚无所有者、尚未接线或命名不理想的路径也保持原位，纳管决定不得再拆成迁移选择；
   同一测试资产的长期所有者与完整项目检查是否默认纳入是两项独立语义决定；若两者都无法由证据唯一裁决，须先后
   各用一张决策卡，所有者选择不得默示纳入关系，也不得以测试质量不在范围为由跳过纳入决定；
8. 方案足以让普通任务独立裁决、施工、验证、验收和关闭，但不预写不必要的精确命令、脚本、临时 Git 技巧或指定
   执行者；副作用边界依赖调用方式时可以记录必要参数；
9. 本地只读操作、只读 Git 查询和符合低副作用条件的公开只读联网默认允许；标准路线的一次明确实施授权覆盖确定
   文件变更、列明普通验证、普通下载与公开资源获取、结果记录和满足条件后的关闭，方案列明的精确删除与任务
   临时产物清理包含在其中；
10. commit、push、PR、破坏工作区或改写历史的 Git 操作，认证或私有访问、上传、外部写入、付费或明显大规模
   联网，以及未列明或高风险删除不被推定；验证升级、新副作用、候选实质漂移或新的语义决定只申请差额，方案
   关闭不依赖 Git 交付；
11. 关联方案未完成时只报告本方案主责结果；最后一个关联方案只触发联合只读复核，不自动调用、继承或关闭；
12. 对应活动方案已经存在时只交接，不因“继续”“施工”“验证”或“关闭”恢复 skeleton 执行链。
13. 拟退出既有路径、入口、生命周期或文档职责时，方案包含以精确种子建立的一层直接消费者闭包；边界证据不足
    时不得列为确定退出；
14. 结构机械断言进入结构实施交接，产品行为断言保持原职责，无法可靠分离时停止并交接；
15. T-DOC、内容一致性审计、受影响项目测试和完整项目测试分别记录实际范围与状态，未运行层保持 `not_run`，
    不用任一层替代另一层。
16. 检查结论和方案物化已填充覆盖／残余矩阵，有限措辞不把结构结果扩写为内容、测试或安全结论；
17. 已知标准项目级 Skill 根和项目明确声明的自定义 Skill 根默认不进入活动文档、导航、历史分类或矩阵，精确
    证据例外可用，且排除不扩大到相邻同名目录或其他位置的 `SKILL.md`；
18. 测试资产信息架构调查以 Git 感知或等价有界的当前资产集合为起点，分开生命周期、执行暴露、登记身份、所有者、
    直接消费者、执行入口和正式选择；关键关系用有界三态证据，发现说明实际影响、唯一归宿、切片阻断与解除条件，
    不写死目录树、manifest，也不扩展为覆盖、断言质量、成本或运行器重构审计。
19. 两份标准路线参考只按 `SKILL.md` 的触发条件加载；成熟等价项目存在测试入口或测试根本身不触发标准参考，
    测试资产结构参考只在其独立触发条件满足时加载。
20. 会读取文本的新增 Python 验证入口缺少 `-X utf8` 或有证据的等价模式时，候选必须自修订且受影响评审不计轮次；
    `-B` 不能替代运行编码。正确模式下的严格解码错误为失败，不猜测、静默替换或转换文件；方案不改外部脚本、
    不扩大 T-DOC，也不自动迁移成熟项目已有权威命令。

### consistency

1. 不建立或报告六项结构治理账本，不给出标准/等价治理认证；
2. 活动真源所有权不清时停止并形成 skeleton 交接；
3. 未限定项目文档范围时默认 `full`，精确种子使用一轮直接依赖的 `incremental`；
4. `full` 对每份活动文档、`incremental` 对每个受影响种子分别完成事实／契约遍和职责／删除优先遍；冻结发现前，
   精确成员集合、矩阵行集合和逐行两个结果单元格必须完全对账，缺成员、重复、缺遍或通用占位理由先补齐，无法补齐
   时只交付未覆盖停点。方案评审和保存前重做该门；高显著度发现不能使其他范围漏审；
5. `full` 不自动触发总体测试、CI 或安全审计；显式测试体系或全部 Registry 请求使用互斥的 Registry 全局模式，
   冻结全部活动 ID、形成有证据的职责分组，并保持登记入口加一轮直接实现边界；
6. 识别事实不一致、职责不清、内容膨胀和位置不当，按角色和唯一所有者优先删除、引用或收敛，只有文档特定证据充分
   时保留；分别报告活动真源总内容足迹和默认入口加载量，不把源码细节自动扩写进长期文档，不把拆分／索引冒充总量
   收缩，也不使用统一篇幅阈值；无问题成员保留双遍证据但不制造空修改切片；
7. 先按明确请求选择只报告或形成方案；只报告不询问轮次、反哺报告或保存，方案路线才用同一白话问题询问两项并接受
   “按推荐”明确选择“两轮、不生成”。检查和指定轮次的候选自评审保持只读，最终确认后一次保存并停止，没有
   `sync`、施工、验证或关闭阶段；检查只使用静态读取、搜索和只读 Git，不运行测试、构建、产品或门禁命令；
8. 同一审计目标只保存一份自包含综合方案；已经通过切片就绪检查的文档、结构、产品、构建、测试、CI 和安全
   改动可以进入确定范围，未通过的候选留在同一方案待决，不生成子方案；
9. 方案物化活动真源及所有者、精确成员、范围、排除项、逐成员双遍记录、完整性门结果、决定、确定与可能路径、验证、
   可预见副作用处理和授权边界、任务特定收尾字段及最终范围与漂移复核入口，不依赖原审计对话，也不预写不必要的
   精确命令、脚本或临时 Git 技巧；
10. 全新普通任务只凭目标项目、已保存方案和实施授权即可完成全部确定切片、列明验证、最终复核与生命周期关闭，
    不再次调用审计、不补写方案、不创建子方案；
    最终保存新建的活动方案容器若需在归档后清理，方案必须记录保存前不存在、本工作所有权及“归档后为空”条件，
    普通任务据此精确删除；任务切换不重置这项工作所有权，预先存在或归属不明的目录仍不得删除；
11. 测试作为直接证据时区分契约、实际声明、expected／正式选择、执行入口、核心断言和 CI，核对重复、缺失、多余、
    适用顺序与协议版本；合成夹具在目标失败点前合法且保持虚构离线，源码文字提取唯一定位并失败关闭，GUI／真实输入
    只在精确范围检查当前退出与外部阻断；测试通过不能反向证明契约正确，副作用按实际效果分类；
12. 方案保留目标项目当前实施授权语义；合并授权只由目标规则成立，更严格规则不得被 consistency 放宽；
13. 符合目标项目规则的公开只读联网只用于用户指定或已冻结声明直接需要的公开证据，不进行无边界浏览，也不让
    公开资料覆盖项目当前契约；
14. 已知标准项目级 Skill 根和项目明确声明的自定义 Skill 根默认不进入活动文档、双遍或矩阵；精确声明仍可把
    必要 Skill 文件作为一轮实现证据，且不宽泛排除相邻同名目录或其他位置的 `SKILL.md`；
15. 对应活动方案已经存在时只交接，不因“继续”“同步”“验证”或“关闭”恢复 consistency 执行链；
16. 只有精确种子或已冻结直接证据已经暴露旧结构断言时，才记录结构机械断言漂移并形成实施切片或待决交接；不
    因此扫描其他测试或 CI，也不扩大 `full`。
17. 普通实施任务的最终范围与漂移复核只确认最终入口和所有者、确定切片、已列直接消费者及修改路径新产生的一跳
    直接链接／消费者；不递归、不扫描整个工作区，也不重跑 consistency 的双遍、测试设计或 Registry 全局审计。
18. 方案必须在保存时识别列明验证可预见的缓存、报告、快照或外部副作用，并确定无落盘调用、受控输出或精确清理；
    入口的只读声明与默认调用矛盾时作为事实不一致解决，不能由实施后的最终复核首次发现。
19. 候选每轮覆盖目标、路径、决定、确定范围、残余和轮次状态；事实缺口由 Skill 补证，已有证据能唯一裁决时说明
    依据和用户可感知结果后直接采用，旧实现等冲突只作修复证据，已定结果不拆问。真实语义决定与授权差额逐项使用
    白话决策卡，先消歧并区分结果与动作，给出推荐、选项结果、主要代价、可回退性和回复方式；移除技术备注后正文
    仍可独立作答，正文不得出现字段、精确路径、内部 ID、测试分类、工具名或命令，并明确提供“按推荐”、白话备选
    和“暂缓”，用户选择后任务复述。普通语义确认不产生写入、待办、状态转换或实施授权，较早授权不扩展到后来需求。
    待确认项不进入确定范围；最终摘要后的保存确认不能由首次请求中的 `sync`
    或保存意图替代。测试或标准资产暴露的自定义 Skill 根、工具可发现性、所有者或路径职责差异只构成证据，不能
    替用户选择治理结果；逐轮评语和修订轨迹不进入持久方案。决定出现时在当前轮计数前停下，只有用户明确暂缓才可
    保存为待确认；项目没有候选状态真源时精确使用 `待确认`。
20. Registry、suite、测试断言和 CI 的活动状态只表示测试治理状态，不自动取得业务契约所有权；在声称测试行为构成
    同级权威冲突前，必须沿活动入口定位契约所有者。所有者已经移除、禁止或替代的行为由旧测试作为失效项承接，
    不得询问用户是否恢复兼容；只有活动入口明确委托测试治理拥有该契约时例外。测试义务已经由当前所有者确定而
    安全分类或触发错位时，只修正分类、触发与授权说明，不扩张成删除、改成本地测试或换职责的用户选择。
21. 双遍完整性门先保证活动成员没有在发现冻结前消失；门通过后，最终报告、覆盖／残余矩阵和候选再逐项承接全部
    冻结发现，并在最终保存前以调用内稳定标识核对三者的成员与数量完全一致。任一层缺失、重复或无归宿时作废受影响
    评审并回到对应成员或候选修订，不得提出保存问题；清单、标识和对账过程不保存为独立日志或账本。
22. 动态、分阶段或昂贵验证方案承接实施期消费者漂移／环境阻断／新范围分流、独立问题收尾批量登记、输入失效与
    最低复用证明、动态预算、产品 owner、清理与恢复停点，以及技术终态／正式终态；证据不足不复用，未授权阶段
    保持 `not_run`。

任一适用硬断言失败，当前 Skill 样本即为 `failed`，不得由另一个 Skill 或质量评分抵消。

## 质量观察与结果

硬断言通过后，可以记录发现准确性、同根因合并、范围清晰度、方案可实施性、授权体验、输出篇幅和完成速度。
这些观察不替代硬断言。

结果使用：

- `passed`：纳入样本进入可判定阶段并满足全部适用硬断言；
- `failed`：出现漏报、误报、越权、错误修改、范围失控或未收敛；
- `blocked`：隔离基线、新任务能力或明确授权不足，尚未进入可判定阶段；
- `inconclusive`：任务中断、上下文泄漏或基线污染使结果无法解释；
- `not_run`：没有执行。

当次记录至少包含候选身份、Skill、目标与交付路线、提示、基线、反哺报告选择、用户选择和实际完成的评审轮数、最终
保存停点、活动真源、精确成员集合、逐成员双遍记录、完整性门结果、冻结范围、覆盖／残余矩阵、硬断言结果、
人工救场、方案路径与自包含检查、审计任务和全新实施任务的隔离证明、修改摘要、逐项验证、最终范围与漂移复核、
生命周期状态和未覆盖范围。只有用户明确要求纳入长期历史时，才把脱敏摘要归档进仓库。

输出和目标副本默认保留。方案或当前任务已经列明本次 run 的精确清理时，实施授权覆盖该清理，但仍须重新验证
所有权和绝对路径；未列明清理、原项目、测试根、其他 run 或所有权不明的目标必须取得精确删除授权。
