# 项目文档 Skill 前向试用

- Registry ID：`T-PROJECT-DOC-FORWARD`
- 执行类别：`explicit`
- 唯一职责：在全新隔离任务中验证三个项目文档 Skill 的用户可观察合同，以及全新普通任务能否只凭自包含方案完成
  确定实施、列明验证、最终复核和生命周期关闭。
- 输入：待验证的 Skill 源码、仓库外隔离目标、[最小契约夹具](contract-cases.md)，以及只由评估者持有的预期结果。
- 工作目录：每个隔离目标项目的根目录。
- 输出：仓库外的当次 run 记录；成功关闭后精确清理，只有明确历史选择或带所有者和复查日期的未决现场才保留。

本协议不是普通门禁。只有用户明确把本测试加入当前范围，并满足全新任务、目标读取和必要隔离写入条件后才执行；
真实项目不成为本仓库的自动路径依赖。

## 标准五样本矩阵

每次完整候选固定执行以下五项；夹具文件中的其他 CASE 是补充回归，不计入默认五样本数量。

| 序号 | 精确夹具 ID | 主要证明目标 | 任务关系 |
| --- | --- | --- | --- |
| 1 | `CASE-CONSISTENCY-FULL` | 完整活动集合、逐文档核对、有界评审和只报告停点 | 一项全新审计任务 |
| 2 | `CASE-CONSISTENCY-REGISTRY-GLOBAL` | Registry 身份对账、职责分组、契约所有者和有限实现证据 | 一项全新审计任务 |
| 3 | `CASE-CONSISTENCY-PLAN-HANDOFF` | 决定、综合方案、显式保存意图及独立普通任务接手关闭 | 一项审计任务加一项全新普通实施任务 |
| 4 | `CASE-SKELETON-STRUCTURE` | 成熟等价治理的有限矩阵和测试资产结构证据 | 一项全新检查任务 |
| 5 | `CASE-PROJECT-SKILL-ISOLATION` | 标准／自定义 Skill 根边界及 T-DOC 隔离 | 两个 Skill 各一项全新任务，并按夹具核对 T-DOC |

补充回归夹具当前包括：

- `CASE-SKELETON-PLAN-HANDOFF`
- `CASE-SKELETON-EXIT-CONSUMERS`
- `CASE-CONSISTENCY-INCREMENTAL`
- `CASE-CONSISTENCY-OWNER-AMBIGUOUS`
- `CASE-CONSISTENCY-TEST-DIRECT`

出现新失败类型时可以增加最小补充夹具；只有项目明确修改标准矩阵时才改变上表五项。

## 隔离与盲评

评估者在仓库外为每项物化未受前一轮产物污染的基线。执行任务只接收：

- 对应 Skill 的路径；
- 一个隔离目标项目根；
- 自然用户请求；
- 当前样本需要的范围和授权。

执行任务不得读取 `contract-cases.md`，也不得接收预期问题、推荐答案、评分、上一轮诊断、其他目标结果或评估者笔记。
评估者在任务结束后才使用夹具预期判定结果。

只报告样本各使用一项全新任务。形成方案的样本可以在同一审计任务中完成必要用户回合和最终保存，但方案实施必须
换用全新普通任务；后者只接收隔离目标、已保存方案、目标项目规则和明确实施授权，不接收 Skill 路径、原审计对话
或预期发现。

每项失败后的诊断或修订不得复用为下一次候选的隐藏上下文。重新判定完整矩阵时，五项都从符合当前协议的干净基线
开始；单项诊断通过不能把完整 Registry 结果改写为通过。

## 契约与断言所有权

- 用户可观察合同由[需求文档](../../../docs/需求文档.md)唯一承接。
- 运行时规则由 [`project-doc-skeleton/SKILL.md`](../../../project-doc-skeleton/SKILL.md) 和
  [`project-doc-consistency/SKILL.md`](../../../project-doc-consistency/SKILL.md) 及各自按条件加载的 references 实现。
- 每个场景的输入、用户回合和评估者预期只由 [`contract-cases.md`](contract-cases.md) 承接。
- 本 README 只定义 suite 身份、标准选择、隔离、判定和结果记录，不复制上述合同或实现正文。

任一纳入样本违反对应夹具预期即为失败，不能由另一个 Skill、T-DOC、静态校验或质量评分抵消。质量、篇幅和速度
可以在硬性预期通过后作为观察记录，但不改变结果。

## 结果语义

- `passed`：五个标准样本均进入可判定阶段，并满足各自全部适用预期。
- `failed`：任一标准样本进入可判定阶段后出现漏报、误报、越权、错误修改、范围失控或未收敛。
- `blocked`：隔离基线、新任务能力或明确授权不足，尚未进入可判定阶段。
- `inconclusive`：任务中断、上下文泄漏或基线污染使结果无法解释。
- `not_run`：没有执行完整五样本矩阵。

当次记录至少包含候选身份、五项样本及任务关系、提示和基线、用户决定、保存动作、每项结果、人工救场、修改与验证
摘要、最终复核、生命周期状态和未覆盖范围。只有用户明确要求纳入长期历史时，才把脱敏摘要归档进仓库。

## 输出与清理

由本任务创建且所有权明确的成功输出和隔离目标在取证后精确清理。失败、阻断或不可判定现场只有确有复查价值时才
保留，并记录所有者和复查日期；长期历史留存必须明确选择。未列明清理、其他 run、测试根、原项目或所有权不明目标
必须取得精确删除授权，不设置后台或宽泛目录 GC。
