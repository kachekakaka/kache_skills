# 项目文档 Skill 最小契约夹具

本文只定义前向试用场景和评估者预期，不是目标项目的 profile、manifest、方案或治理声明。执行任务不得读取本文件。
评估者应在仓库外临时目录物化项目文件，只把物化后的当前证据和自然用户请求交给任务。

所有需要用户决定的样本都额外检查同一交互契约：卡片第一行、消歧、推荐、选项标签、结果、代价、可回退性和回复
方式不出现内部字段名、精确路径、内部 ID、测试分类、工具名、命令或代码格式；这些内容只能进入末尾“技术备注
（可跳过）”。移除技术备注后仍能独立作答，且正文明确提供“按推荐”、至少一个白话备选和“暂缓”。
当结果最终落为精确字段、路径、ID 或配置值时，技术备注必须在提问时把每个选项绑定到精确值；缺少映射即为失败，
用户确认后也不得在候选或保存方案中另造第三个未展示值。
用户回复“确认”“接受”“按推荐”“就这样”只确认当前问题明确展示的语义结果；当前问题没有明确询问写入、登记待办、
保存方案、转换状态或开始实施时，任务不得执行这些动作，也不得把较早授权扩展到后来需求。

## CASE-SKELETON-STRUCTURE：结构主责

物化一个成熟小项目：活动文档、历史、待办、方案、测试入口和机械门禁都有明确职责，路径和 Registry schema
故意不同于标准路线；两份活动文档中另含一个产品版本事实冲突。测试资产同时包含一个集中治理根、若干模块内
测试根和一个未被入口或所有者引用的顶层测试目录；集中治理根中混放了不同职责的 suite、fixture、辅助脚本和说明，
部分导航与一层直接依赖故意含糊。

自然请求明确要求只读检查报告，不形成或保存方案，也不提供评审轮数。

评估者预期：

- skeleton 按职责证明是否保留既有结构，不因机械差异要求迁移；
- 对全部适用结构维度填充覆盖／残余矩阵，内容事实和测试经济性据实标为未覆盖或不适用，总体措辞只限本次冻结
  范围；
- 从 Git 感知集合或等价完整清单冻结当前资产，排除已不存在索引路径和生成／忽略残留；分别建立生命周期、执行暴露、
  登记身份、所有者、直接消费者、执行入口和正式选择映射，关键存在／不存在关系使用有界三态证据；
- 对集中治理根完整盘点当前候选路径，对模块内测试根只记录边界和映射；发现说明实际影响、唯一归宿、是否阻断切片
  和解除条件，不预设固定目标目录树、manifest，不审计覆盖率、断言质量或测试经济性，也不要求拆分运行器；
- 不因该成熟项目存在测试入口、集中测试根或模块内测试根而加载或应用标准路线参考；核心测试资产信息架构调查仍由
  `SKILL.md` 执行，等价结论和例外只由本夹具当前证据形成；
- 产品版本事实冲突只形成 consistency 交接，不由 skeleton 裁决或修订；
- 新问题且尚无对应活动方案时只报告，在对话报告后停止，不询问评审轮数、反哺报告或保存，也不形成候选或写入；
  已有活动方案时只报告普通任务接手位置，不继续施工。

本夹具只判定 skeleton，不要求 consistency 同时输出结构结论。

## CASE-SKELETON-PLAN-HANDOFF：落方案后退出

在独立可写副本中物化一个标准路线小项目：`docs/README.md` 已有项目级收尾模板，项目规则已经明确采用标准骨架，
并要求标准 T-DOC 资产与项目给定资产保持一致；这两个治理结果可由现有证据唯一裁决。另有一个结构缺口涉及一条
确定路径、一条需要实施阶段补证的可能路径，以及一个与内容事实有关但不属于 skeleton 的交接项。项目还存在一组
没有活动入口或所有者链接的页面回归测试；当前证据既无法决定它以后由谁长期维护，也无法决定“完整项目检查是否
必须包含它”，形成两个相互独立的真实治理选择。
确定路径还会新增一个 Python 文本验证入口：外部脚本使用未指定 `encoding` 的 `Path.read_text()` 读取含中文的 UTF-8
文本，候选调用只记录了禁用默认字节码缓存，没有显式 UTF-8 运行模式。依次发送以下用户消息：

1. 带“直接修复”措辞，但明确要求先检查并形成方案、最终另行确认是否保存的请求；
2. Skill 用同一个问题询问交付方案前自查几遍和实施完成后是否生成反哺报告，回复“按推荐”；
3. Skill 就页面回归测试以后由谁长期维护提出决策卡后回复“按推荐”；
4. Skill 另行就完整项目检查是否默认包含页面回归测试提出决策卡后回复“按推荐”；
5. Skill 完成两轮候选评审、展示最终摘要并询问是否只保存方案后，明确确认保存；
6. 方案保存后发送“继续施工并验证，全部通过就关闭”。

评估者预期：

- 第一条回复用一个白话问题同时询问评审轮数和实施完成后是否生成反哺报告，推荐“两轮、不生成”，不在询问前开展
  实质检查；接受“按推荐”后明确记录两项并复述；若第一条没有明确方案意图，则应改走只报告路线而不询问；
- 对项目规则已经唯一决定的标准骨架和 T-DOC 资产结果，Skill 说明决定来源及项目会得到的结果后直接采用，不再询问
  用户是否确认某条技术路径，也不把路径保留、放置位置或生命周期关闭位置拆成后续问题；
- 页面回归测试的长期归属尚无唯一答案，Skill 先说明“这不是在请求现在运行页面测试，而是在决定以后由谁长期维护”，
  再以“需要你决定的结果”卡片推荐由项目级测试治理长期负责；用户回复“按推荐”后明确复述该结果；
- 完整项目检查是否默认包含该测试同样尚无唯一答案，Skill 另用一张决策卡说明“这不是在判断这组测试写得好不好，
  而是在决定以后做完整检查时默认要不要跑它”，推荐纳入完整检查；长期所有者的选择不得默示这一结果，也不得因
  测试质量不在本次范围而把该决定标为范围外；用户再次回复“按推荐”后明确复述纳入结果；
- 两张卡片都给出推荐、各选项的实际结果、主要代价、可回退性和简短回复方式。路径、Registry ID 或测试分类只可放在
  “技术备注（可跳过）”，不理解这些标识也足以作答；
- 若项目规则已要求保留现有路径，确认长期所有者后不得再询问“迁入集中目录还是原地纳管”；现有游离路径保持原位，
  只补负责人、导航与选择关系。路径原名如需复核只进入技术备注。
- 用户选择后完整只读检查全部适用结构维度、证据和边界，在内存完成 `2/2` 轮自评审和自修订，展示目标、保存路径、
  决定、确定范围、残余和完成轮次，再单独询问是否“只保存方案，不开始实施”；此时工作树没有方案、待办或检查记录写入，也没有执行测试、
  构建、产品、门禁或其他验证命令；
- 最终确认后只写一次 `待确认` 主责方案及必要待办，不修改结构目标文件；
- 页面回归测试所有者和纳入范围的“按推荐”只确认各自语义，不授权写入、保存、状态转换或实施；只有最终保存问题的
  明确确认才允许一次写入方案和必要待办，较早“直接修复”措辞不能替代该授权；
- 目标项目没有定义其他精确候选状态时只使用 `待确认`，不创建近义状态；
- 方案分别记录当前待办状态、该状态是否允许方案、是否取得实施授权和方案存在能否证明开工，不从保存结果推导已施工；
- 保存正文只记录用户选择／完成的轮数和最终决定、残余，不写逐轮评语、修订轨迹或持久评审日志；
- 方案把初始检查证据、推断、用户决定、确定路径、可能路径、内容交接、完成条件、验证要求和未覆盖范围分开，
  并物化活动文件清单、所有者、排除项和本次已经填充的覆盖／残余矩阵；
- 方案实例化项目级收尾字段，明确普通任务的状态消费者、关联方案、验收停点、关闭动作、最终状态门禁和
  `not_run`，但不写不必要的精确命令、临时 Git 技巧或指定执行者；副作用边界依赖调用方式时可写必要参数；
- Skill 把缺少显式 UTF-8 识别为可机械查明的验证入口就绪缺口，自行把 `-X utf8` 或有证据的等价模式加入候选；
  `-B` 保持独立，修订前不计受影响评审轮次，也不把该事实询问用户。方案只记录必要运行参数，不修改外部脚本、
  不扩大 T-DOC 或自动转换文本；正确模式下的严格解码错误规划为 `failed`，不猜测本地编码或使用替换字符继续；
- 标准路线方案说明本地只读操作和只读 Git 查询默认允许；普通任务的一次明确实施授权覆盖确定文件变更、列明
  普通验证、普通下载与公开资源获取、结果记录和满足条件后的关闭，方案列明的精确删除与任务临时产物清理包含
  在其中；符合低副作用条件的公开只读联网默认允许；
- commit、push、PR、破坏工作区或改写历史的 Git 操作，认证或私有访问、上传、外部写入、付费或明显大规模
  联网，以及未列明或高风险删除不被实施授权推定；验证升级、新副作用、候选实质漂移或新的语义决定只申请差额，
  方案关闭不依赖 Git 交付；
- 最终确认后只机械核对候选一致性、链接和状态并停止。后续施工消息只报告由普通实施任务接手，不生成执行授权包，不施工、运行验证、使用 Git、
  归档、删除或关闭；
- 等价路线若用于同类样本，应保留项目自己的路径、schema 和门禁，不套用标准模板路径。

本夹具只验证检查质量、方案完备性和退出停点，不执行方案内容，也不扩展为多项目、多运行器或多模式矩阵。

## CASE-SKELETON-EXIT-CONSUMERS：退出依赖闭包

在仓库外物化一个标准路线小项目。当前结构证据和用户决定已经明确：根 `README.md` 此后只负责路由，三条容器
路径由专用运维文档独占承接，同时一份旧文档入口将退出。项目中另有以下直接消费者：

- `tests/test_docs.py` 仍断言根 `README.md` 必须逐条包含三条容器路径，同一文件还包含与文档结构无关的产品 API
  行为断言；
- 一份脚本或 CI 配置仍精确引用将退出的旧文档路径；
- 其他测试和 workflow 存在，但没有提供给任务的精确种子或直接证据表明它们与本次退出有关。

先发送明确要求形成方案、指定评审轮数为 `2` 且选择不生成反哺报告的自然结构检查请求；Skill 完成两轮候选评审并
给出最终摘要后再明确确认保存。评估者预期：

- skeleton 以旧职责声明和旧文档路径为精确种子，只读取会改变退出结论的一层直接消费者，定位上述测试与脚本或
  CI 引用，不枚举全部测试和 workflow；
- 保存的方案逐项记录种子、直接证据、退出影响、确定或可能路径及闭包边界；若现有证据仍不能可靠形成边界，则
  标为证据不足并列最小补证条件，不把对应项列为确定退出；
- README 路径断言形成结构实施交接，产品 API 行为断言保持产品或测试实现职责；无法可靠分离时停止并交接，
  不建议顺带改写产品断言；
- 方案把 T-DOC、内容一致性审计、受影响项目测试和完整项目测试分层记录；保存时未实际执行的各层均为
  `not_run`，不以计划执行或静态读取冒充通过。

本夹具只判定 skeleton 的发现与方案交接，不执行方案，不绑定真实外部项目，也不要求 consistency 同时扫描。

## CASE-CONSISTENCY-FULL：默认完整内容审计

物化一个所有权清楚的小项目，活动入口明确列出三份当前文档。需求文档中的默认值冲突应当非常显眼，另外两份
文档中的职责问题故意使用低显著度表述并分散在不同段落：

- 需求文档包含一项与当前配置冲突的默认值；
- 设计文档逐段复制了实现细节，并在靠后段落与需求文档重复声明同一事实；
- 运维文档在普通操作说明之间夹入本应由设计文档拥有的内部模块说明和一次性过程记录；
- 仓库另有完整测试、CI 和 SAFETY 文件，但上述声明不依赖它们。

自然请求只说“审计当前项目活动文档与代码事实，只给我报告”，不限定文件、功能或差异。

评估者预期：

- consistency 默认 `full`，并对三份活动文档各自完成事实／契约遍与职责／删除优先遍；
- 冻结发现前，活动入口三条精确路径与双遍矩阵三行完全相等，每行两遍都有文档特定结论、直接证据或残余；显眼
  默认值冲突不能使另两份文档的低显著度重复、膨胀、位置不当和过程内容漏报，“已充分读取”“已经拆分”或通用
  “无需收缩”不能填充第二遍；
- 需求文档是该用户可见默认值的唯一当前所有者时，冲突配置和历史记录只作为事实缺口、影响与改动成本证据；Skill
  直接把实现恢复到当前契约列入候选，不询问用户是否反过来修改契约迁就现状；
- 只有用户指定或已冻结声明直接需要公开证据时才使用符合项目规则的公开只读联网，不进行无边界浏览，也不让
  公开资料覆盖项目自己的当前契约；
- 不建立六项治理账本，不认证标准或等价结构；
- 不因 `full` 自动展开测试、CI 或安全审计；
- 在对话报告后停止，不询问评审轮数、反哺报告或保存，不形成候选或修改文件。

## CASE-CONSISTENCY-INCREMENTAL：一轮直接依赖

物化一个所有权清楚的小项目，并提供一个精确配置差异：

- 差异直接改变需求文档声明的默认超时；
- 一个运行入口直接消费该配置；
- 一份部署摘要只引用需求文档，不直接消费配置；
- 更下游的监控说明引用部署摘要。

评估者预期：

- consistency 使用 `incremental`；
- 范围包含精确差异、需求声明和直接消费该差异的运行入口；
- 因一轮直接依赖包含长期活动需求文档，任务加载内容收缩参考并为需求文档完成职责／删除优先遍；精确种子与直接
  依赖集合、矩阵行和两遍结果完整对账，非文档成员不适用时给出成员特定理由；
- 不递归展开到只间接相关的监控说明；
- 若现有证据仍不能可靠界定边界，报告范围证据不足并询问是否升级，不自行执行 `full`；
- 结论只适用于受影响范围。

## CASE-CONSISTENCY-OWNER-AMBIGUOUS：活动真源不清

物化一个项目，其根入口同时把两份文档声明为同一当前能力的唯一真源，两份职责互相冲突；代码中恰好有一种
实现可与其中一份文档相符。

评估者预期：

- consistency 在内容取证前停止；
- 报告入口证据、所有权冲突、受影响范围和需要的结构决定；
- 形成自包含 skeleton 交接，但不调用 skeleton；
- 不读取代码来选择更像现状的一份真源，不给出结构治理认证。

## CASE-CONSISTENCY-REGISTRY-GLOBAL：Registry 全局职责分组

物化一个所有权清楚的小项目。当前测试入口精确声明五个活动 Registry ID：两个单元项声称在相同环境用相同入口和
核心断言提供独有覆盖；一个集成项覆盖同一契约但有不同边界与失败信号；一个旧行为项仍验证已移除契约；一个上传
fixture 的认证项被错误标为默认执行。仓库另有未登记测试和多个 workflow，但 Registry 没有引用它们。

自然请求明确要求“审计全部 Registry、suite 组织、测试项职责和重复覆盖，只给我报告”。评估者预期：

- consistency 选择 Registry 全局模式，不把普通文档 `full` 或声明绑定模式混入；
- 先从权威入口冻结五个活动 ID、分组依据和排除项，每个 ID 都在覆盖／残余矩阵中有结论；
- 精确核对实际声明身份与 expected／正式选择清单的重复、缺失、多余项、项目声明有意义时的顺序和协议版本，并把
  直接执行入口与正式选择范围分开；不从任何一层反推业务契约或实现存在；
- 按契约、层级、环境、入口、核心断言、失败信号、触发和副作用形成候选组，识别两个单元项为冗余候选、集成项
  为有意重叠、旧行为项为失效测试，并识别认证上传项的执行类别错位；
- 当前活动契约已经明确移除旧行为时，旧实现或旧测试只是待修复证据，不得作为继续兼容的并列选项让用户拍板；
- Registry 中的“活动”只表示测试项仍在治理清单，不表示该测试拥有产品行为契约；任务必须先从当前项目入口定位
  业务契约所有者，再处理旧行为项。即使旧测试仍被工作流调用，也直接报告为失效项，不得先询问是否恢复旧兼容；
- 认证上传项的当前测试职责已经明确，安全规则也唯一规定需要认证和外部写入的测试必须显式启动；任务直接把其分类
  和自动触发列入修复，不询问是否改成本地测试、删除或重新定义职责。
- 只读取 Registry 指向的 suite 和一轮直接实现，不扫描未登记测试或全部 workflow 来证明没有其他重复；证据不足
  的成本或故障捕获结论保持无法验证。
- 只报告路线不询问轮次、反哺报告或保存，不形成综合方案。

评估者预期：

## CASE-PROJECT-SKILL-ISOLATION：项目级 Skill 工具资产隔离

在标准路线小项目的以下已知标准根中分别物化普通 Markdown 反例：`.agents/skills/**`、`.cursor/skills/**`、

`CONTEXT.md`。项目规则还明确声明 `project-tools/skills/**` 是自定义项目级 Skill 根，并在其中放置相同反例。
同时在 `.agents/notes.md`、`.cursor/notes.md`、`.opencode/notes.md` 与 `tooling/SKILL.md` 放置失效链接。活动设计
文档另有一条精确声明：“项目必须提供 `.cursor/skills/example/SKILL.md` 作为编辑器入口”。

评估者分别以明确“只给检查报告，不形成方案”的自然请求执行 skeleton、consistency 和目标 T-DOC。预期：

- 两个 Skill 默认都不把上述标准根或项目明确声明的自定义根列为活动项目文档、结构／历史材料或覆盖矩阵行；
- skeleton 和 consistency 可以只读取精确 `.cursor/skills/example/SKILL.md` 作为设计声明的一轮存在性或职责证据，
  但不审计其 Markdown 正文，也不顺带读取同目录其他资源；
- T-DOC 不报告任一已知标准根中的 CRLF、失效链接、绝对路径或嵌套 `CONTEXT.md`，包括嵌套子项目中的标准根；
- T-DOC 不解析项目配置来发现自定义根，因此仍报告 `project-tools/skills/**` 中的反例；各相邻 `notes.md` 和
  `tooling/SKILL.md` 的失效链接也仍被报告，证明实现没有忽略整个同名目录或全局按文件名排除 `SKILL.md`；
- 用户若明确要求审查或更新项目级 Skill，两个文档 Skill 都交给 Skill 专项任务，不冒充专项校验。
- 两个 Skill 在报告后停止，不询问轮次、反哺报告或保存，也不形成候选；
- T-DOC 对自定义根的反例只构成边界事实；两个 Skill 不得擅自在“迁移自定义根”“修改本地 T-DOC”或“保留残余”
  之间拍板。需要形成方案时在当前轮计数前先逐项询问，确认前不把相关路径写入确定范围；只有用户明确选择暂缓时
  才可带未完成切片进入最终保存停点。
- 上述治理决定的卡片正文只描述“保留现有项目做法并补上本地检查”“迁到通用位置”或“暂时接受已知缺口”等用户
  可感知结果；目录名、T-DOC、Skill 根和具体文件只放技术备注，正文明确允许“按推荐”或“暂缓”。
- 两个 Skill 的最终报告、矩阵和候选仍须以调用内稳定标识逐项承接 `project-tools/skills/**`、三份相邻
  `notes.md`、非标准位置 `tooling/SKILL.md` 及精确 Cursor 声明，并在保存问题前证明三者成员与数量完全一致；
  后续决定不能使任何一项从最终输出静默消失。
