# 项目文档 Skill 最小契约夹具

本文只定义前向试用的最小场景和评估者预期，不是目标项目的 profile、manifest 或治理声明。执行任务不得读取
本文件；评估者应在仓库外临时目录物化对应项目文件，并只把物化后的当前证据交给执行任务。

> 阶段说明：本文件仍是职责收缩前的候选夹具，不用于当前 skeleton 第一阶段验收；代表性夹具将在 consistency
> 独立阶段与前向协议一并收敛。

## CASE-STANDARD：标准骨架正向样本

最小项目采用标准固定路径、四列 Registry、`T-DOC full`、活动/历史索引、待办生命周期及带正反样例的门禁。

评估者预期：两个 Skill 都识别标准骨架治理满足要求；骨架 Skill 不提出无价值迁移；一致性 Skill 仍分别
报告六项治理账本和本次内容范围。

## CASE-EQUIVALENT：机械不同但治理等价

最小项目故意使用：

- 根 README 直接承接文档导航，不存在 `docs/README.md`；
- `item_id | domain | trigger` 测试清单，而不是四列 Registry；
- 项目专用文档门禁和独立正反自测试，而不是 T-DOC；
- 不同目录名承接当前真源、历史索引、活动工作和安全规则。

所有六项职责均有唯一、可达、互相一致的当前证据。

评估者预期：判为等价既有治理；不得要求创建标准路径、改表格 schema、替换项目门禁或把该结构当成通用模板。

## CASE-MISSING-ONE：单项属性缺失

从 CASE-EQUIVALENT 派生，只移除机械门禁的正反自测试，其他五项保持完整。

评估者预期：机械门禁及自证为证据不足，整体等价治理未成立；保留现状并列精确缺口，不得用五项通过或
综合分数判等价，也不得自动迁移标准骨架。

## CASE-SAFETY-CONFLICT：安全声明与实现冲突

项目 SAFETY 声称真实数据测试仅 `explicit`，但 CI 的 push/PR 默认输入会调用该测试；脚本还把输出写到声明
测试根之外，删除逻辑没有 owner marker 或 containment 复核。

评估者预期：安全与授权结果未成立；必须引用 workflow 默认值和脚本实现，不能只因 SAFETY 文案完整而通过。

## CASE-TEST-DESIGN：测试重复、过度与契约偏离

项目包含：

- 单元与 E2E 对同一行为提供不同边界证据；
- 两个相同环境、命令、输入和断言的重复 CI 项；
- 超出支持契约且无风险依据的平台矩阵；
- 当前实现和测试共同接受权威契约明确禁止的行为。

评估者预期：分别识别有意重叠、冗余候选、过度候选及实现与测试共同偏离契约；不得自动删除测试，也不得
把契约文档简单判为过时。`sync` 只能修订允许范围内的文档或 Registry，并形成测试实现交接。
