## 1. 目标与已确认决定

本方案修复两个同根范围缺口：骨架检查能够核对测试治理入口，却不保证发现集中测试目录的物理职责混杂；项目级
Skill 工具资产又只精确排除 `.agents/skills/**`，会遗漏其他受支持位置。

已确认：

1. 测试资产信息架构归 `project-doc-skeleton` 主责，但 Skill 只规定调查方法，不写死目标目录、层数、`common/`
   或“一个 Registry ID 一个目录”；项目特定目标、例外和完成条件由当次审查得出并写入该项目的一份方案。
2. 对集中测试治理根建立完整路径清单；模块内测试根只核对入口、所有者和 Registry 映射。内容只按职责疑点选择性
   读取，依赖最多展开一层。
3. 不评价测试覆盖、断言质量或测试经济性，不因结构观感强制拆大型 runner；昂贵例外可作为有证据残余记录。
4. 项目级 Skill 隔离同时进入两个 Skill 与 T-DOC；只精确排除 Skill 子树，不排除整个工具目录或任意同名文件。
5. 通用 T-DOC 只内建标准路径；两个审计 Skill 可按项目活动入口或工具配置识别额外的明确 Skill 根，不建立新
   manifest 或多工具配置解析器。
6. 安装前执行完整 `T-PROJECT-DOC-FORWARD`；不增加真实项目矩阵，只扩充现有最小样本。

## 3. 确定实施切片

### 3.1 Skeleton 结构审查

- 在 `project-doc-skeleton/SKILL.md`、`references/skeleton-rules.md` 和 `references/testing-baseline.md` 中加入有条件的
  测试资产信息架构审查：从测试入口／Registry 建立入口—所有者—实现根映射；对集中治理根列全路径；对模块内根
  只核对边界；项目结构清单发现未被活动入口承接的顶层测试目录时，将其列为所有权待确认候选，但不因此递归审查
  模块内测试实现；只有职责或一层依赖会改变结论时读取实现证据。
- 把根部混放、导航脱节、职责不明、历史命名和跨职责依赖写成调查信号，不写成固定不合格结果。检查结果必须把
  当前项目的实际结构、推荐目标、保留例外和残余物化进该项目方案，不能要求实施者再次调用审计。
- 保持 skeleton 只检查与落方案，不增加施工、验证、内容事实或测试设计职责。

### 3.2 项目级 Skill 精确隔离

- 两个 `SKILL.md` 和 skeleton 参考把项目级 Skill 工具资产改为上述标准路径加项目明确声明路径；精确声明仍可读取
  必要文件作为一轮实现证据，显式 Skill 专项任务仍可审查正文。
- T-DOC 源实现只内建标准路径，并更新正反夹具：每类标准根均被排除；相邻工具目录 Markdown、非 Skill 路径中的
  `SKILL.md` 仍被检查。随后把说明、实现和规则夹具整文件同步到 skeleton 资产并比较字节一致。
- 不解析 Cursor、OpenCode、Copilot 等配置，不把自定义 Skill 根加入通用 T-DOC。

### 3.3 当前项目真源与前向契约

- 更新 `CONTEXT.md` 中“项目级 Skill 工具资产”，并增加不含实现细节的“测试资产信息架构”术语；同步根 README、
  需求、设计、测试 Registry 与测试入口中的当前能力和精确边界。不创建 ADR。
- 在现有 Skeleton 有限矩阵样本中加入集中测试根结构缺口；在现有 Skill 隔离样本中加入全部标准路径与相邻反例。
  不新增样本类别，不把 JA 或其他真实项目写成固定夹具。
