## 1. 问题、目标与边界

当前 Skill 已经要求 `full` 逐份读取活动长期文档、完成事实／契约遍和职责／删除优先遍，并为每份文档给出收缩处置。
但实际试用仍暴露出三个可以绕过这些要求的缺口：

1. `content-contraction.md` 使用“主要职责、主要章节”等表述，执行者仍可能以局部抽查或概括替代对全部实质正文的检查；
2. 重复声明、同一声明在所有者与消费者之间发生的语义漂移，以及过度复杂、不够精准的表达，没有被固定为逐文档必检项；
3. 候选的多轮 review 只要求通用的证据、矩阵和切片对账，没有要求独立挑战“漏掉了什么”和“是否收缩过头”。

实际失败表现为：一份较长需求文档曾以“抽查一致”和“职责就是用户可观察行为”为依据判为无需收缩；进一步检查后却
发现了跨职责正文和当前行为漂移。这证明“已完整读取”“已有逐文档结论”和集合对账都不能单独证明审计内容完整。

本方案只补强上述执行合同：

- `full` 中每份活动长期文档的事实／契约遍和职责／删除优先遍都必须覆盖全部实质内容，不得抽查；
- 每份文档都明确检查重复、漂移、职责、精确性、复杂度和收缩／保留依据；
- 两轮候选 review 分别承担查漏和防误伤职责，并在修订后重新取得有效结论；
- 保留当前请求分流、所有者发现、范围冻结、测试设计、验证规划、授权、保存停点和生命周期边界。

不把本次修订扩展为固定逐段落持久账本、全部文档两两比较、文风美化、测试体系重建或新的治理框架。

## 3. 确定实施切片

### 3.1 收紧主 Skill 的完整审计硬门

修改 [`project-doc-consistency/SKILL.md`](../../project-doc-consistency/SKILL.md)，在现有范围冻结、双遍审计和候选评审
流程中加入以下不可绕过的合同：

1. `full` 对每份活动长期文档、`incremental` 对冻结范围内每份长期文档，均须把全部实质性标题内容和无标题正文纳入
   两遍检查；可以稳定分块、合并相邻同职责内容，但不得抽样，也不得由“主要章节”“代表性片段”或文件级结论代表余下正文。
2. 事实／契约遍必须检查每个实质内容块中的事实、规则、契约、决定、前提、例外和状态，并沿已经确认的当前所有者与
   直接证据判断一致、漂移或残余；不能只检查最显眼声明。
3. 职责／删除优先遍必须对每个实质内容块检查重复声明、竞争真源、所有者／消费者之间的语义漂移、职责越界、实现
   镜像、过程或历史残留、动态快照，以及会掩盖合同或造成歧义的过度复杂、不够精准表达。
4. 文档级“无需收缩”必须由上述内容覆盖和风险检查共同支持，说明独有职责、必要消费者义务及删除、迁移、只留链接
   或简化会损失的当前能力；局部无问题不能推出整份文档无需收缩。
5. 任一内容块未检查、证据不足或所有权不清时，只能报告对应残余，不得通过完整性门、冻结完整发现或形成完整候选。

主 Skill 只承接这些核心门和 review 调用规则，详细识别与处置方法继续由现有 reference 唯一维护，避免在入口复制细则。

### 3.2 补强内容收缩 reference

修改 [`content-contraction.md`](../../project-doc-consistency/references/content-contraction.md)：

1. 将“主要职责、主要章节”改为“全部实质内容块”；先检查后才允许合并相邻且同职责的内容，不以固定标题、段落或
   行数作为跨项目模板，也不持久化逐段账本。
2. 为每份长期文档固定以下检查轴：
   - 同一事实、规则、决定或状态的重复声明和竞争真源；
   - 所有者与直接消费者对同一声明在措辞、值、前提、例外、生命周期或适用范围上的语义漂移；
   - 需求、设计、测试、运维、待办和方案之间的职责错位；
   - 源码、配置、schema、测试或构建镜像，以及过程、历史和动态结果残留；
   - 不必要的重复限定、嵌套说明、模糊指代、未定义术语或混合职责导致的复杂、不精准表达；
   - 删除、改为摘要加链接、迁移、合并、简化或有证据保留的最小处置。
3. 明确“表达复杂”不是按长度处罚：只有复杂度造成职责重复、理解负担、歧义或契约漂移时才形成收缩发现；唯一且必要
   的事实、用户可观察合同、决策、字段约束、测试职责和操作义务必须保留。
4. 对“无需收缩”要求可核验的负向证明；无法证明没有命中风险时使用 `无法核验`、`需要决策` 或 `未覆盖`，不默认通过。

### 3.3 为两轮候选 review 指定不同职责

在主 Skill 中定义 review 的有效语义，并由 `content-contraction.md` 提供收缩专项检查细则：

1. 第一轮是**查漏 review**：重新挑战全部长期文档的处置，尤其逐份复核“无需收缩”，检查是否遗漏低显著度内容、
   重复、语义漂移、职责错位、复杂或不精准表达；不能只给已经发现的收缩项补路径或落点。
2. 第二轮是**防误伤 review**：逐项复核删除、迁移、摘要加链接、合并和简化动作，确认没有丢失唯一事实、用户合同、
   决策、字段约束、消费者特定义务、测试职责或操作闭环；同时检查收缩后是否产生新漂移或职责缺口。
3. 每轮仍须完成现有证据、矩阵、切片、路径、验证、副作用、授权、完成条件和生命周期检查；收缩专项不能替代通用 review。
4. 用户只选择一轮时，该轮同时完成查漏和防误伤；选择两轮及以上时，前两轮分别承担上述职责，后续轮次复核前轮修订
   影响。任一轮发现问题后，先修订候选，受影响方向在变更后复核通过才计为完成，不能沿用修订前的轮次结论。
5. review 必须回看支撑处置的原始内容和所有者／消费者证据；发现集合与切片的数量对账只能证明已有发现未丢失，不能
   替代查找新遗漏或识别错误收缩。
