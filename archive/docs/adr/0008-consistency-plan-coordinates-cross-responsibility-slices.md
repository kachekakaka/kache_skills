# 一致性方案统一协调已就绪的跨职责实施切片

真实试用表明，把一致性审计发现的结构、产品、构建、测试、CI 或安全问题一律移交到后续方案，会让同一根因被拆成
多次裁决、多个方案和再次审计。审计已经确定所有者、契约、路径、直接消费者、验证义务、副作用、授权和完成条件时，
这种拆分不再提供额外安全性，反而使普通实施任务依赖原审计对话。

现决定 `project-doc-consistency` 对同一审计目标只保存一份自包含综合方案。现有文档内容以及通过切片就绪检查的文档
结构、产品、构建、测试、CI 和安全改动，都可以进入该方案的确定实施范围；证据不足、候选漂移或需要语义取舍的
事项继续作为同一方案中的待决项或精确交接。方案必须物化活动真源及所有者、冻结范围、已填写的覆盖／残余矩阵、
确定与可能路径、验证和授权边界，并要求普通任务从最终活动入口执行发现集外复核后再关闭。

这一决定只改变 consistency 方案可以协调的实施范围，不改变 Skill 的执行终点。`project-doc-consistency` 仍然只读检查，
只在用户明确要求时保存方案，完成静态自审后立即停止；它不施工、不验证、不关闭，也不自动调用其他 Skill。后续普通
任务依据目标项目规则和实施授权，一次完成全部确定切片、列明验证、最终复核和满足条件后的生命周期关闭。

本 ADR 替代 ADR-0003 中“consistency 不修改任何可执行测试代码、所有实现问题只能形成交接”和 ADR-0006 中“结构、
产品实现和测试实现问题不并入内容方案施工”的方案范围决定。ADR-0003 关于 skeleton 独占结构治理与两个 Skill 不互相
调用的决定、ADR-0006 关于 consistency 保存方案后退出执行链的决定，以及保存不构成施工授权的边界继续有效。
