# 方案候选先评审后一次保存

> 状态：部分被替代。方案路线的未保存候选评审、逐项决定和一次性持久化继续有效；只有明确方案请求才进入该路线，
> 按 [ADR-0010](0010-route-report-plan-and-separate-action-authorization.md) 执行。固定预问评审轮数和无条件再次确认保存由
> [ADR-0014](0014-honor-explicit-save-intent-and-remove-feedback-report.md) 替代。

两个项目文档 Skill 原先在用户同意保存后才写入方案并静态自审，使持久化方案可能在评审期间反复变化，也混淆了保存确认与评审修订。现决定两个 Skill 在调用开始先询问方案评审轮数并推荐两轮；检查报告完成后，它们只在当前调用内生成方案候选，围绕已冻结证据自行完成指定轮次的评审和修订，最后展示目标、路径、决定与残余，并仅在用户确认后新增或覆盖活动方案。

能够直接调查的事实由 Skill 自行查明；评审发现语义决定或授权差额时，一次只询问用户一个问题并提供推荐答案。用户明确暂缓的事项可以保存在 `待确认` 方案中，但受影响切片不得进入确定实施范围，且不能宣称对应评审已经完成；修订既有方案时，原文件同样保持不变，直到最终保存确认。

这一次保存确认只产生最终活动方案，不授权目标产品、长期文档、验证或生命周期修改。保存后两个 Skill 仍然停止，由普通任务按项目规则实施；普通需求不会仅因曾使用两个 Skill 而自动生成方案，但已有方案完成时必须更新受影响的长期真源并按目标项目生命周期归档。该决定替代 ADR-0004 至 ADR-0006 中“先保存再静态自审”的阶段顺序，其余显式调用、保存不构成实施授权、同一待办最多一份活动方案及保存后退出执行链的决定继续有效。
