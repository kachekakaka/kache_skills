## 1. 目标与确定结果

修复两个项目文档 Skill 的共同交互回归：用户只显式调用 Skill、没有用自然语言说明“只要报告”或“形成方案”时，
Skill 不得替用户选择只报告并开始实质检查，而应先停在交付路线选择问题。

确定采用以下行为：

1. **裸调用先问路线**：只出现 `$project-doc-skeleton` 或 `$project-doc-consistency`，或者请求内容不足以可靠区分交付路线时，
   先用一个白话问题询问“这次只要检查报告，还是检查后形成方案”。取得回答前，不读取活动文档入口、枚举项目文档、
   搜索实现、检查 Git 或联网取证；读取 Skill 自身和为遵守安全边界所必需的适用 `AGENTS.md` 不算实质检查。
2. **明确报告不多问**：用户已经明确只要检查、审计、review 或报告且没有同时要求方案时，直接走只报告路线，不询问路线、
   方案自查轮数、反哺报告或保存。
3. **明确方案不重复问路线**：用户已经明确要求形成、保存或修订方案时，直接进入方案路线，并在实质检查前联合询问
   交付前自查轮数和实施完成后是否生成反哺报告。
4. **路线确认不产生动作授权**：选择报告或方案只决定本次交付形式；不授权写文件、登记待办、保存方案、转换状态、
   实施、安装或 Git 写操作。方案路线仍须在候选完成后单独取得最终保存确认。
5. **两个 Skill 同步修复**：Skeleton 与 Consistency 共享同一用户可观察合同，不保留一个询问、另一个默认的分叉。
6. **触发策略不变**：两个 Skill 继续只允许显式调用，`policy.allow_implicit_invocation` 保持 `false`；本方案不把 Skill
   变成会话级常驻模式，也不改变各自的结构／内容职责、只读边界或保存后退出执行链。

路线问题推荐“先只要报告”，理由是它不产生方案候选或保存停点；同时必须平等说明“形成方案”会在下一步取得自查轮数
和反哺报告选择。用户可以回复“按推荐”或“只要报告”、“形成方案”或“暂缓”；“按推荐”只接受已展示的报告路线，
Skill 不得因用户沉默或其他模糊回复而自行采用推荐。
