# 骨架 Skill 职责收缩施工方案

- 原待办：`DOC-SKELETON-RESPONSIBILITY-REFACTOR`（已退出活动列表）
- 状态：已完成
- 性质：由原职责收缩总待办拆出的 skeleton 独立施工方案
- 决策依据：[ADR-0003](../../docs/adr/0003-separate-structure-governance-from-content-consistency.md)、[ADR-0004](../../docs/adr/0004-separate-review-plan-and-construction.md) 与 [`CONTEXT.md`](../../CONTEXT.md)

## 拆分结论

- 按 D-09 至 D-12，skeleton 与 consistency 使用独立待办、独立方案、独立复核和独立验收；先施工 skeleton，
  普通门禁和 review 后暂停。
- 原总待办及总方案被本方案和 consistency 方案共同替代并退出活动入口。
- 按 D-07，旧 `VALIDATION-EQUIVALENT-GOVERNANCE` 待办退出活动列表；其中 skeleton 验证责任由本待办承接，
  consistency 验证责任由后续独立待办承接，不改写旧 ID 的含义。
- 按 D-08，无可施工问题但用户选择保存时，优先写入项目现有检查记录、工作记录或历史记录位置；不存在承接
  位置时在保存前询问，不创建固定标准目录，也不使用空活动方案。
- 本方案只记录 skeleton 主责范围内的目标、目标路径、动作边界、完成条件和验证要求，不预写具体脚本或命令；
  是否由 Skill 自身施工、采用何种实现机制以及是否执行验证，均由用户另行选择和授权。
- 骨架阶段若发现旧真源仍含未承接事实，只能把它保留为带退出条件的临时材料。当前 skeleton 方案在结构落位并
  验收后正常退出；内容同步由 consistency 的独立方案处理，之后仍需归档临时材料时重新发起 skeleton 周期。

## 目标行为

1. `project-doc-skeleton` 只处理文件、目录、入口、导航、职责归属、活动与历史生命周期、测试治理结构和机械门禁。
2. 新项目建立职责清晰、导航可达、生命周期完整且具有适用机械门禁的标准骨架；成熟既有项目按治理职责和
   必要安全结果判断结构等价，等价时保留现有路径、schema 和实现。
3. 检查先冻结有限的结构维度和本轮文件集合，再在范围内充分读取；不使用标题 token、固定行数、入口围栏或
   首缺口短路限制理解能力。
4. 一次检查覆盖全部结构维度并给出完整结构结论。内容事实冲突、测试设计经济性和全项目安全认证不属于本 Skill。
5. 首次运行只检查并报告，随后询问是否保存方案；明确保存后形成 `待确认` 方案，完成裁决且再次选择施工后才
   转为 `实施中` 并允许 `apply` 或其他施工方式写入。
6. 主责方案只保存目标、路径、动作边界、完成条件和验证要求，不包含具体脚本或命令，也不预先决定施工者。
7. 在施工授权内，可以最小修改可明确分离的结构机械断言；产品行为断言保持不变，职责无法可靠分离时停止交接。
8. 每次申请命令授权前，在对话中建立验证执行账本；涉及自动化、外部副作用或授权选择时，先给出三行白话效果摘要。
9. 退出旧入口前检查引用、默认配置、启动接线、自动化触发、运维入口和结构机械断言组成的直接消费者闭包；
   直接证据出现部署或产品行为选择时停止，由用户决定，不先退出上游入口。
10. 标准资产只约束整文件逐字节一致、既有冲突停点和字节比较完成条件；不增加永久复制 helper，不能保证整文件
    复制时不得退化为片段补丁。
11. 最终关闭顺序固定为：记录已获授权的验证结果，退出活动待办入口，归档方案并更新索引，确认适用条件目录
    是否为空，执行已在账本中列明并单独授权的精确空目录清理，再对最终状态运行适用 T-DOC。

## 施工顺序

1. 先拆分待办和方案，建立 skeleton `实施中`、consistency `待确认` 的独立生命周期。
2. 更新 skeleton 主契约、参考和默认提示，删除入口冻结规程。
3. 更新共享长期文档；只在机械规则实际变化时同步方案生命周期门禁、规则夹具与骨架资产副本。
4. 若需要运行验证，先形成临时验证执行账本和适用副作用效果摘要，再申请独立命令授权。
5. 执行获准的普通门禁并静态 review 本阶段差异，检查 consistency 文件零修改且结构机械断言没有越过产品边界。
6. 暂停等待用户验收；不自动开始 consistency，也不提前退出本活动方案。
7. 用户验收并授权关闭后，先核对退出依赖闭包，再按“记录验证结果 → 退出活动待办 → 归档方案并更新索引 →
   确认条件目录为空 → 执行已预授权的精确空目录清理 → 对最终状态运行 T-DOC”的顺序完成关闭。

## 完成条件与停点

1. skeleton 不再引用入口冻结规程，不在首个缺口短路，并能完整报告全部结构维度。
2. skeleton 的首次检查、保存方案和施工授权是三个可观察阶段；无问题检查记录遵守 D-08。
3. T-DOC 接受合法的“待确认可选方案”和“实施中必需方案”，拒绝其他非法组合，仓库实现与骨架资产一致。
4. 方案、Skill 和参考均不预设永久复制 helper 或其他施工脚本；命令只存在于当次临时执行账本。
5. 结构机械断言修改保持最小且可与产品断言分离；旧入口退出前已核对直接消费者闭包，真实行为选择均已停下裁决。
6. 普通门禁通过，review 未发现 skeleton 范围内的阻断问题，consistency 实现文件保持施工前状态。
7. 达到上述条件后仍保持本待办 `实施中`，停止施工并等待用户验收；不得自动开始 consistency。
8. 验收后的生命周期关闭完成且最终状态 T-DOC 通过，才允许把本方案视为已退出；未获最终命令授权时明确报告
   `not_run`，不得以中途通过结果代替最终状态门禁。
