## 3. 目标与非目标

### 3.1 目标

1. 让 skeleton 在删除、替代或收窄既有路径、入口、生命周期或文档职责时，形成有限且可交接的退出依赖闭包。
2. 用最小隔离夹具验证 skeleton 能发现测试、脚本或 CI 中仍固化的旧结构约束，并区分结构机械断言与产品行为断言。
3. 固化分层验证结论，禁止不同证据层互相替代。
4. 为 consistency 增加只在直接证据已经暴露时生效的结构交接兜底。

### 3.2 非目标

- 不恢复 skeleton 的 `apply`、施工、验证或关闭阶段，不增加两个 Skill 的自动调用或运行时依赖。
- 不让 skeleton 无限遍历全部源码、测试或 workflow，也不让 consistency 的 `full` 默认扩张为测试设计或结构审计。
- 不修改 T-DOC 源码、规则夹具或资产，不增加骨架版本、安装校验、profile、manifest 或隐藏状态。
- 不改变授权模型、生命周期、标准/等价治理路线、Registry schema、语言规则或既有 ADR。
- 不处理 `VALIDATION-LARGE-MIGRATION`、跨平台或自动化验证待办，不修改真实外部项目或其工作记录。

## 5. 拟定规则结果

1. 只有拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，skeleton 才以精确旧路径、标识或职责声明为种子核对退出依赖闭包；普通结构检查不因此变成全仓测试扫描。
2. 闭包包括直接引用、默认配置、启动接线、自动化触发、运维入口和结构机械断言。只有直接证据会改变退出结论时继续一轮；仍无法形成可靠边界时记录证据不足、可能路径或未覆盖范围，不猜测完成。
3. 同一测试文件中的结构机械断言可以作为结构实施交接；API、数据、业务行为或测试覆盖充分性继续保持产品或测试实现职责，无法可靠分离时停止并交接。
4. 最小夹具不进入 Skill 包，只由显式前向试用的评估者持有预期；它验证 skeleton 能发现旧结构消费者并生成可实施方案，不宣称大型真实项目迁移已经验证。
5. 结果分别记录 T-DOC、内容一致性审计、受影响项目测试和完整 T-PROJECT；任何未执行项保持 `not_run`，任一层通过不能替代另一层。
6. Consistency 不主动寻找结构消费者；只有当前精确范围已经暴露旧结构断言时，才记录证据与位置并形成结构实施交接，不修改测试或扩大内容方案。
