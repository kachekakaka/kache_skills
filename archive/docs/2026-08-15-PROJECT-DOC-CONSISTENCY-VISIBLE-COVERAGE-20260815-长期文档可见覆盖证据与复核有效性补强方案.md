## 1. 问题与目标

上一轮已要求每份长期文档建立内容覆盖图、禁止抽样并对 `无需收缩` 负向举证；实际试用仍出现以下绕过：

- 执行者完整读取了长需求文档，却没有在报告中展示它的内容组、双遍结果或保留依据；
- 最终用“其余 67 份无需收缩，包括核心真源”跨文档汇总，职责名称再次替代了逐文档证据；
- 第一轮 review 只证明 7 个发现都有归宿、78 个路径都有处置，仍是集合对账；第二轮只检查已有删除动作，未重新挑战
  没有进入动作清单的需求文档。

因此当前结论应当是“该文档未覆盖”，而不是“无需收缩”。本方案只把现有内部检查要求变成最终交付中不可省略的可见
证据，并让缺证据直接阻断候选和保存；不重新设计其他审计能力。

## 2. 确定实施切片

### 2.1 主 Skill：可见证据成为完整性硬门

修改 `project-doc-consistency/SKILL.md`：

1. 最终报告必须为范围内每份长期文档保留独立命名条目，不得用“其余 N 份”“其他核心真源”“同类文档均无需收缩”
   等跨文档汇总代替。
2. 每个条目至少展示：全部实质内容组的稳定锚点；各组事实／契约遍的结论与证据或残余；职责／删除优先遍命中的风险与
   处置；整份文档的收缩结论和依据。
3. 相邻且已经分别检查、职责和结论相同的内容可以紧凑合并；不能隐藏锚点，也不能把多份文档合并成一个结论。短文档
   可以只有一个内容组，长文档必须列出足以覆盖全部实质正文的多个内容组。
4. 任一长期文档缺少上述可见证据时标为 `未覆盖`，完整性门失败；只能交付不完整停点报告，不得冻结完整发现、形成
   候选、计算 review 轮次或询问保存。
5. 输出空间不足时宁可明确交付部分覆盖和剩余路径，也不得压缩成未经证明的项目级结论。

### 2.2 内容收缩 reference：禁止集合式“无需收缩”

修改 `project-doc-consistency/references/content-contraction.md`：

- 明确内容覆盖图不是只存在于推理中的自我声明，必须进入对话报告；方案路线还须把最终有效覆盖依据带入候选。
- 把“报告和方案可以紧凑合并”限定为同一文档内相邻内容组的合并，禁止跨文档合并收缩处置。
- 将“其余 N 份无需收缩”“核心真源天然无需收缩”“已完整读取所以无需收缩”列为无效反例。
- `无需收缩` 条目必须同时显示内容组覆盖、适用风险结果、唯一所有者、消费者义务，以及删除、迁移、只留链接或简化
  会损失的当前能力；缺一项即不能通过。

### 2.3 两轮 review 的可核验结果

在主 Skill 和内容收缩 reference 中收紧现有 review 合同：

1. 查漏轮必须逐份回看所有 `无需收缩` 文档的可见条目和原始证据；最终交付至少列明本轮改变了哪些处置，以及未改变
   处置已经由哪些文档条目支撑。只报告路径数量、发现数量或集合相等无效。
2. 防误伤轮逐项复核全部收缩动作；第一轮修订后新增、删除或改变的动作必须进入第二轮。没有进入动作清单的文档不能
   反过来作为其“无需收缩已经复核”的证据。
3. 任一轮发现条目缺失或依据不足，受影响 review 结论作废；修订并重新复核后才能计数。
4. 不保存逐轮推理日志；最终报告和候选只保留当前有效的逐文档证据、处置变化及 review 完成结论。

### 2.4 最小同步当前真源

- `docs/需求文档.md`：同步每份长期文档必须有可见独立条目、无证据即未覆盖，以及集合汇总不能通过 review。
- `docs/设计文档.md`：同步报告／候选的可见内容覆盖关系和两轮 review 停点，不复制 reference 细则。
