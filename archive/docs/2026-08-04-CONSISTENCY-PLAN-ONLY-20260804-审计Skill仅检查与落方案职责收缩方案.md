## 2. 已确认决定

1. consistency 只执行内容检查，以及用户明确授权后的方案保存与静态自审；保存后停止。
2. 删除 `sync`、施工、验证执行账本和生命周期关闭的运行时职责。
3. 保留内容审计、所有权停点、`full`/`incremental`、声明分类、问题分类和按需测试设计审计。
4. 保存方案必须让普通实施任务能够独立裁决、修改文档、验证、验收和关闭；执行规则不再复制进 Skill。
5. consistency 只保留和交接目标项目当前授权语义：目标规则明确合并确定修改、方案列明普通验证和结果记录时由
   普通任务按其执行，更严格的目标规则不得被 consistency 放宽；这不恢复 `sync` 或执行阶段。

## 3. 目标与非目标

### 3.1 目标

- 把 consistency 收缩为“完整内容检查 → 保存并自审方案 → 停止”。
- 让主入口只保留审计流程、硬边界和方案最低完备性，领域测试判据继续由现有 reference 按需承接。
- 让公开文档、默认提示和前向夹具只承诺检查与方案交付。
- 保留项目级收尾契约，使方案在普通任务实施后仍能退出待办、归档并验证最终状态。
- 让方案交接准确保留目标项目的一次实施授权或更严格边界，不复制或重定义授权规则。

### 3.2 非目标

- 不修改 skeleton Skill、其参考、资产或默认提示。
- 不改变 `full`、`incremental`、一轮直接依赖、内容问题分类或测试设计审计判据。
- 不改变标准骨架、T-DOC、Registry schema、项目级生命周期或 consistency 与 skeleton 的职责分界。
- 文件施工阶段不运行内容同步、Git、安装、联网、产品进程或生命周期关闭；只执行第 7 节获授权的普通验证，
  生命周期关闭另按后续明确授权处理。
