# 项目文档一致性

## 保持职责单一且运行独立

本 Skill 独立完成两件事：

1. 从当前项目证据证明六项文档治理属性是否成立；
2. 按文档职责核对当前事实，并在测试相关范围中审计契约、实现、测试断言、suite 和 CI 的一致性。

`sync` 只在现有治理拓扑内修订可直接证明的活动文档事实，以及受限待办和 Registry 内容。不得创建、移动、
重命名或删除文件，不得改变导航、路径职责、方案生命周期、归档关系或 Registry schema，也不得修改可执行
测试代码。

不得调用、依赖或假定其他 Skill 已安装。结构问题、语义取舍和测试实现缺口必须直接输出交接包，包含问题
类别、目标、声明与证据、影响、建议动作、授权需求和完成条件。

## 选择模式与写入授权

- `check`：只读检查并报告。未指定模式且没有事实修订意图时默认使用。
- `sync`：执行同一检查，形成可直接证明事实的集中变更清单，并在已有明确写入授权时实施。

“只检查、只审计、只读、不修改”进入 `check`。“同步、修订、修复可证明事实、检查并修复、审计后同步”
进入 `sync`。用户同时说“先别写”时仍完成 `sync` 所需检查，但只输出清单。

单独说 `sync` 只授权准备清单；明确要求“审计并修复”“直接同步”“全部修复”或同义动作，视为授权本次
范围内满足边界的文件修改。先集中说明精确清单后直接实施，不逐文件重复确认。只有真实语义取舍才一次
询问一个问题；全部取舍确认后只做一次共同理解确认。

文件修改不授权命令、commit、push、PR、发布、联网或真实数据操作。

## 先检查规则和安全边界

1. 读取目标路径适用的全部 `AGENTS.md`，遵守已有语言和授权规则。
2. 不把归档正文当成当前事实，也不因历史内容与现状不同而改写归档。
3. 不自动执行构建、测试、产品程序、真实数据、联网、Git 操作或认证。
4. 不把凭据、真实用户数据或原始运行现场写入仓库或报告。
5. 分别列明文件修改和验证命令；一类授权不得推定另一类授权。

## 按范围读取参考

每次完整读取 [`references/entry-freeze-procedure.md`](references/entry-freeze-procedure.md)，并用它执行 A 阶段。

用户要求 `full`、明确审计测试设计，或范围涉及测试、Registry、suite、CI、安全触发及测试脚本时，完整读取
[`references/test-design-audit.md`](references/test-design-audit.md)。其他纯文档增量检查不读取该参考。

不创建 profile、manifest、版本号、隐藏状态或持久化检查报告。每次结论都从当前项目证据重新建立。

## 使用不可交错的四阶段机

严格按 `A 入口冻结 → B 治理短路 → C 内容冻结 → D 单次取证与收尾` 执行。不得交错阶段，也不得先读细节
再补冻结账本。任一阶段无法形成要求的有限清单时，立即记录 `范围证据不足` 并前进到 D 收尾，不能返回发现。

### A. 只冻结入口和路径，不预读治理证据

严格按 [`references/entry-freeze-procedure.md`](references/entry-freeze-procedure.md) 完整读取适用
`AGENTS.md` 并建立入口图。禁止 glob、目录列举或宽搜索规则；禁止把 fenced code 内的 `#` 注释当标题。
除此之外，A 阶段只建立当前入口图：

1. 对根 `README.md`、它直接声明的当前文档索引和测试索引，先在该精确文件内只取排除 fenced code 后的
   Markdown 标题文本和 Markdown 链接 token，不返回链接所在整行，也不带正文上下文；不得在全文件扫描任意
   含 `/`、反斜杠、反引号或扩展名的正文/裸路径行。身份前言只读 1–4 行；导航只用标题上下文、链接 token
   和操作规程允许的单行结构记录，不读取章节 prose。
   不得因为文件较短就全文读取，也不得读取产品能力、版本结果、架构、API、运维步骤或其他事实段。
2. 对上述索引直接链接的治理 README/稳定入口，只取相同结构图；规范命令只读取操作规程允许的 fenced code
   block，不读取块前后说明。命令块中的精确路径算直接链接，可用于冻结门禁实现、自测试、CI 选择器或中央
   helper；A 阶段不读取这些被命名的实现正文。
3. 当前真源、backlog、归档/历史索引、Protocol、SAFETY、suite、CI、helper 及其他治理证据只冻结路径，不在
   A 打开；它们必须等 B 检查对应属性时才读取。`full` 的活动文件列表只由 Markdown 链接目标形成；规范命令
   路径只冻结治理实现，不自动成为活动内容文件，
   不得为了确认标题或存在性预读目标文件。

工具不能只返回标题/链接/精确段落时，跳过该次读取并把相应锚点记为 `证据不足`；不能退回全文读取。A 阶段
不得读取活动真源正文、ADR、运维正文、方案、归档正文、suite 正文、产品源码或测试代码。

继续前必须先写出一份有限的冻结声明：

- 六项治理属性各自的精确锚点路径、来源入口行/命令块、原文标签、唯一所属属性及留给 B 的允许证据类型；
  原文职责不明时写 `未归属`，找不到时写 `缺失`；
- 内容模式及 `full` 的精确活动文件列表，或 `incremental` 的精确变更对象；
- 当前导航以目录作为权威集合、但没有直接链接文件索引的内容边界；
- 明确不纳入的目录、历史和实现范围。

用户指定路径、当前差异和内容依赖只用于冻结内容范围，不能反向升级治理锚点。只有项目当前入口图已经直接
命名的路径，才能进入六项治理账本；即使用户本次精确指定了未接线的 CI、helper、方案或自测试，也只能在
内容阶段审计它，治理属性仍按入口锚点缺失处理。

目录名、目录职责或指向目录的链接不授权列举目录。当前职责图若明确把目录定义为唯一当前集合，并规定其内容
和生命周期，该目录可以证明治理归属；没有文件索引只使目录正文成为内容 `未覆盖边界`，不使治理属性自动
失败，也不会取消已经能够精确冻结的文件或跳过 B。只有连有限内容种子都无法形成时，才以空队列进入 D。
不得使用目录列表、仓库级文件枚举、宽泛 glob/grep、递归搜索或猜测文件名补齐冻结声明。

六项治理锚点固定为：

1. **当前事实归属**：当前文档索引或职责图，以及它直接链接的当前真源标题、职责、权威状态和导航前言；明确
   声明唯一职责和生命周期的目录可以作为集合真源，但不能据此审计目录正文。B 检查本项时，每份当前真源
   只读“标题 + 紧邻标题的职责/权威状态/导航前言”，最多 20 行，并在第一个事实性二级标题或事实清单前停止；
   前 20 行没有明确职责时直接记证据不足，不得继续向后读取。
2. **机械门禁及自证**：当前门禁 README/稳定入口，以及它直接链接的规则自测试或正反夹具入口。
3. **当前与历史分离**：当前生命周期规则和当前归档/历史索引；不读取归档正文。
4. **未完成事项生命周期**：当前 backlog/状态规则和适用的活动方案入口；不读取方案正文。必须先检查 B 本项
   定向读取的当前入口、导航和生命周期段是否明确声明“后续处理、迁移、合并、拆分、同步、裁决、待验证”等尚未
   完成的当前工作。存在这类声明时，它必须被 backlog 或等价生命周期入口承接并给出退出条件；backlog 为空或
   漏记时属于两份必需锚点直接违反治理结果，结论为 `未成立`。只有上述当前段落没有声明任何未完成工作，且
   backlog 的当前状态都按规则排除活动方案时，backlog 才能独立证明“当前无活动方案”，无需另建空索引。
5. **测试选择关系**：当前测试索引、稳定 Registry/选择清单和 CI 选择入口。
6. **安全与授权结果**：`AGENTS.md`/SAFETY、默认 CI 触发，以及由安全或选择入口直接链接的一份中央输出、
   进程或清理 helper。

### B. 按顺序完成治理短路

先创建六行治理结果表，固定依次检查上述六项。每项开始先检查该行必需证据角色；任一角色 `缺失` 或 `未归属`
时立即写 `证据不足`，不得打开该项任何证据正文。角色齐全时也只按冻结声明读取唯一归属于该行的锚点，禁止
试读、按文件名推断或借用其他属性路径。每项只使用 `已证明`、`未成立`、`证据不足`、`未检查`。第 4 项必须先执行“当前入口未完成声明 → backlog 承接 → 退出条件”的子检查，再判断
空 backlog 是否足以证明当前为空。每一行写定后不可回改，也不能把判断推迟到 C 或 D。
首个 `未成立` 或 `证据不足` 出现时，立即填写总体治理失败和后续 `未检查`，退出 B；不得读取后续治理锚点，
也不得以“还没形成完整六项报告”为由继续补证。属性内部只有两份冻结证据直接冲突时，才可额外读取一份由
冲突证据精确链接的来源；读取后必须结论。

A 冻结声明中任一必需锚点为 `缺失` 时，该属性直接记 `证据不足`，不得读取候选脚本来证明“不存在”。只有
必需锚点都存在，并且当前直接证据明确违反治理结果时，才使用 `未成立`。

六项全部 `已证明` 才能报告“标准骨架满足治理要求”或“等价既有治理已证明”。不综合打分，不允许单项
豁免；明确且有当前证据的“不适用”算 `已证明`。判断治理属性和安全结果，不要求路径、导航层数、表格列名、
Registry schema、测试类别词汇或门禁实现相同。项目自述和历史检查结果不能代替当前证据。

治理短路只终止 B，不取消用户要求的内容审计。无法证明等价时保留现有结构，只列首个决定性缺口和修复条件；
不得自动创建标准路径、替换项目专用门禁或安装通用 T-DOC。

### C. 冻结内容文件和声明组

内容范围默认使用 `incremental`。用户说“全量、全部、整仓、全面审计、审计当前项目文档事实”时使用
`full`。

`full` 的活动文件只能是 A 阶段当前导航直接链接的精确文件。导航只有目录职责而没有直接链接索引时，把该
目录记为 `未覆盖`，不得列举目录；继续完整处理其余已冻结文件，最终报告部分审计。先冻结文件列表，再把每份
冻结文件完整读取一次，仅用于提取声明；同根因或同一精确标识符合并后写出有限声明组队列。不得跟随正文链接
扩大活动文件列表。`full` 不设置固定文件数上限；只要冻结列表不增长，就处理完该列表后收尾。

Registry 整体只形成“选择声明”组；Registry 中每一行不得自动变成一个 suite 审计组。只有某行已经被冻结的
产品契约精确引用，或 Registry/选择器本身已给出一组精确重复/过度候选对时，才能把对应测试项加入声明组。
不得为寻找候选逐项打开 suite README。

`incremental` 只包含用户精确指定的文档、能力或当前差异，以及一次直接展开中被精确命名的契约、标识符和
消费者。导航链接的目标默认只定向读取标题、职责和目标存在性，最多 80 行；链接本身不使目标正文成为内容
依赖。范围内的目录若有明确集合职责，可以核对导航声明；没有文件索引只把目录正文记为 `未覆盖`，继续处理
其他冻结声明组。若变更涉及治理锚点，只允许为该属性读取直接证据。单轮后仍无法形成有限队列时记为
`范围证据不足`，不得猜小范围或静默升级 `full`。

“变更涉及治理锚点”只指该文件在 A 阶段已由当前入口图冻结为治理锚点；用户点名但入口未接线的文件不满足
此条件。

C 阶段只有两种出口：写出冻结声明组队列后进入 D；或记录范围证据不足、空队列后进入 D。不得一边提取声明
一边读取实现、suite、CI 或其他证据。

#### C1. 区分声明类型和权威来源

先按职责区分：

- 当前描述性事实：用代码、配置、构建、测试或可观察行为核对；
- 规则、决策和项目契约：以明确承接文档为权威，检查实现和其他文档是否遵守；
- 历史记录和动态结果：按时间语境检查，运行状态需要实际执行证据或用户确认；
- 待办与方案状态：以活动生命周期真源为准，没有完成证据不能把开放状态改成完成；
- 非穷举摘要：只有遗漏改变表述含义或违反其明确职责时才构成缺失。

ADR 和归档中的旧名称、路径或行为不自动构成当前不一致。它们仍明确充当当前契约且与现状冲突时标为
“需要决策”，不得在 `sync` 中静默改写历史决定。

核心文档只有标题、职责说明或旧文档链接时，识别为“空壳”或“兼容路由”，不是已完成的当前真源。
兼容路由必须有明确目标、收敛待办和退出条件；当前入口已经声明后续收敛动作而 backlog 未承接时，该矛盾应已
在 B 的第 4 项得出 `未成立`，不得到 C/D 才回改治理账本。

### D. 单次取证并强制收尾

只有 C 已写出冻结声明组队列，或明确写出“范围证据不足、队列为空”，才能进入 D。进入后不得再读取入口、
追加活动文件、重分声明组或返回 A–C。

进入 D 时先创建与冻结队列等长的编号结果表，每组固定记录：文档与声明、最多两条主证据、内容结论、一句
理由、影响或当前承接。初始结论为 `待处理`；不得另建无结论的证据草稿。

对冻结队列中的每个声明组，只能用以下方式定位证据：

1. 使用文档已经精确写出的路径或标识符；没有精确位置时，最多做一次该标识符的精确搜索。搜索必须限定在
   声明或当前设计已经命名的最小当前源码/配置根，先只返回匹配文件路径，再选定一个文件读取；不能以仓库根、
   工作区根或磁盘为搜索范围。
2. 最多读取一份直接实现/配置锚点和一份直接测试/CI 锚点；审计重复或过度时，一组已精确命名的候选对算
   一份比较锚点。搜索结果只用于选定这些锚点，不能继续枚举同类源码或全部调用方。
3. 两份锚点直接冲突时，最多再读取一份由冲突内容精确链接的来源；读完立即结论。
4. 超出预算才可能判断时使用 `无法验证`，不得扩大搜索词、遍历目录或把新发现追加为新的声明组。

`archive/`、`history/`、仓库外输出、测试 run、A 阶段未覆盖边界和任务禁读路径必须在搜索调用前排除，不能
依靠看到命中后再丢弃。工具无法把搜索限定在允许根时，跳过搜索并记 `无法验证`。

补写事实前先确认它属于该文档职责和抽象级别，且不会把长期文档变成源码镜像。源码存在某个细节，本身
不是文档必须记录它的证据。

证据优先级取决于事实类别，不采用“代码永远正确”：

- 构建与产物看构建配置、脚本、用户确认和获授权执行结果；
- 当前实现看代码、配置、schema 和调用关系；
- 可观察行为综合契约、实现、测试和运行证据；
- 术语与领域边界看当前术语真源和已确认决定；
- 难以逆转的取舍看当前 ADR 和已确认决定；
- 测试入口看实际 suite、命令、fixture、触发和断言；
- 运维事实看当前部署、配置和恢复入口。

明确权威契约存在而实现违反它时，结论是实现侧“不一致”。多个同等级权威来源冲突或优先级未定义时才是
“需要决策”。同时展示冲突证据，不自动让文档服从代码或让代码服从文档。

按冻结顺序把每个声明组处理恰好一次：读取允许的锚点后，必须立即把该行从 `待处理` 改成一种内容结论，
写入证据与一句理由；该行仍为 `待处理` 时禁止读取下一组。某组达到证据预算仍不能判断时写 `无法验证`，
不能继续发现证据。空队列直接跳过取证。

最后一行离开 `待处理` 后立即停止所有读取，只复用结果表组装报告，不得再次取证或重新逐组分析。最多详细
展开影响最高的八个非一致发现；其余非一致项用单行表列出，一致项只汇总数量与覆盖范围。即使仍有
`无法验证`、`需要决策`、`未覆盖` 或未获授权验证，也必须交付治理账本、内容范围账本和建议动作。`full` 只
表示完整处理冻结的活动范围；冻结范围不完整时只能报告部分审计。D 是每次运行唯一合法出口。

## 审计测试设计与安全结果

适用时按参考资料建立：

`权威需求/设计契约 → 当前实现 → 测试义务 → Registry/suite → 实际断言 → CI 选择`

分别识别：

- `覆盖缺口`：明确义务没有可信测试或核心断言；
- `声明错位`：Registry、suite、CI 或文档声称的覆盖与实际命令、实现或断言不符；
- `有意重叠`：覆盖相同能力但层级、边界、故障信号或独有证据不同；
- `冗余候选`：失败语义、层级、边界、断言与触发基本相同，没有新增独有证据；
- `过度候选`：矩阵、环境或触发成本超出支持契约且没有对应风险依据；
- `失效测试`：只验证已经明确移除、替代或不再支持的行为。

测试通过不能反向证明实现符合契约。测试固化了违反权威契约的实现时，报告“实现与测试共同偏离契约”，
并按实际情况归为声明错位或覆盖缺口，不能简单称为文档过时或失效测试。

安全结果必须检查实际接线，不只读声明，但只使用冻结锚点：

- SAFETY 中 `explicit`、真实数据和产品进程约束，对照 push、PR、schedule、workflow_dispatch 和默认输入；
- workflow 路径过滤，只对照 Registry、suite 或规范入口已经声明的真实输入；
- 一份由安全或选择入口直接链接的中央 helper，其输出根、owner marker、路径 containment、保留与删除实现；
- CI 是否漏触发必要验证，或让无关变更无条件触发昂贵、联网、破坏性或真实数据测试。

不得为证明安全遍历全部 workflow、测试脚本或清理实现；默认触发或中央 helper 没有从入口图接线时使用
治理属性 `证据不足`，内容项使用 `无法验证`。

静态证据不足以证明故障捕获、flaky、性能成本或恢复效果时使用“无法验证”。运行、故障注入、mutation
testing、删除或重构测试代码都需要独立任务和授权。

## 使用内容结论

每项内容声明只使用：

- `一致`：声明与相应证据相符；
- `不一致`：存在明确矛盾或会改变含义的缺失；
- `无法验证`：证据不足或未获必要运行授权；
- `需要决策`：同等级权威来源冲突或真实价值取舍未定；
- `未覆盖`：不在本次内容范围。

只有 `full` 中所有适用项均一致，且没有无法验证、需要决策或未覆盖，才能声明项目范围内容一致。治理
等价结论和内容一致性结论必须分开报告。

## 执行 check

在交流中报告，不创建项目内检查文件。输出顺序固定为：

1. 模式、冻结的治理锚点和内容范围；
2. 六项治理证据账本及总体治理结论，包括短路后的 `未检查`；
3. 内容范围账本：已检查、未检查及原因；
4. 按影响合并后的内容和测试发现；
5. 有边界的修复建议、交接和未获授权操作。

默认只展开不一致、无法验证、需要决策和治理缺口；一致项做简短范围摘要。每个问题包含声明与位置、证据
与位置、结论、影响、候选承接和推荐动作。报告后停止，不修改文件。

## 执行 sync

1. 完成与 `check` 相同的当前证据映射；不能复用失效的历史检查结论。
2. 核心文档为空壳或兼容路由时，可在其现有职责内首次填入源码直接证明的事实；未能承接的职责明确列为遗留。
3. 只保留证据充分、属于现有职责、修订维持准确性、符合抽象级别且不会制造重复真源的最小改动。
4. 非穷举摘要不因省略实现细节而扩写；不得把长期文档改成源码镜像。
5. 按受限规则处理待办和 Registry；结构问题、证据不足和语义取舍不得写入。
6. 集中列出每个现有文件、当前声明、证据和最小修订；明确列出不修改项及未覆盖范围。
7. 已有明确修复授权时说明清单后直接实施；否则取得一次集中确认。事实性修复不逐文件重复询问。
8. 修改后另行列出精确验证命令、层级、工作目录、输出和副作用，取得命令授权后才执行。

受限规则：

- 只有活动文档、契约或已确认决定明确承认某个未解决缺口时，才能在现有待办新增状态为 `待确认` 的条目；
  不能因源码缺少能力自行创造需求，ID 无法按项目规则确定时只交接。
- 只有现有 suite、稳定规范命令、触发条件和独有职责都有直接证据时，才能在现有 Registry 新增或修订行；
  不创建 suite，不猜执行类别，不改变 schema。
- 不改变既有待办状态，不创建活动方案，不修改 `AGENTS.md`、`CONTEXT.md`、ADR、导航、索引、路径职责或归档。
- 明确测试覆盖缺口可以同步其文档或 Registry 事实，并形成精确测试实现交接；不得创建、删除、合并、拆分
  或重构可执行测试代码。测试精简必须先证明没有损失平台、参数、边界或安全方面的独有证据，再由独立实现任务授权。

## 控制命令和最终交接

静态证据足够时不运行命令。必须运行才能判断时，先列出精确命令、工作目录、验证层级、输出目录、可能的
进程/联网/数据副作用和它要回答的问题。未获授权时将对应结论标为“无法验证”。

最终分别报告：

- 本 Skill 范围：`完成`、`部分完成` 或 `未实施`；
- 治理路线：`标准骨架满足治理要求`、`等价既有治理已证明` 或 `等价治理未成立`；
- 内容结论：项目范围、受影响范围或未形成总体结论；
- 实际修改、验证结果、未覆盖范围和未获授权操作；
- `待事实同步`、`待结构处理`、`待语义决策`、`待实现或验证`。

只有当前事实已有活动承接、历史退出当前权威入口、遗留进入明确生命周期且适用验证完成时，才能报告
“文档治理已闭环”。机械门禁通过或测试通过都不能替代总体结论。
