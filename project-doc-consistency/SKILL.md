# 项目文档一致性检查与方案

## 保持职责单一

本 Skill 只处理活动文档的内容一致性：

- 核对文档声明与当前代码、配置、构建或可观察行为；
- 判断内容是否属于该文档职责，识别职责不清、内容膨胀和位置不当；
- 在直接证据需要时，或用户明确要求时，审计相关测试设计声明；
- 把结构、语义决策、产品实现和测试实现问题交给对应任务。

不认证项目骨架是否标准或治理是否等价，不建立六项治理账本，不安装机械门禁，也不调用或依赖
`project-doc-skeleton`。发现结构所有权不清时输出自包含交接，不替用户调用其他 Skill。

归档和历史材料默认只提供历史语境，不作为当前事实。只有活动入口明确把某份历史材料继续定义为当前契约时，
才把它作为当前证据，并在冲突时标为需要决策。

## 只执行检查与落方案

1. **检查**：新问题始终只读。即使请求包含“修复”“同步”“直接改”或 `sync`，也只完成内容审计、报告结论、
   询问是否保存方案并停止。
2. **落方案**：只有用户看到检查结果后明确要求保存，才使用项目已有承接位置写一份主责方案及必要待办。方案
   状态按项目生命周期保持待确认，完成静态自审后立即停止。

本 Skill 没有 `sync`、施工、验证、归档、删除或关闭阶段。保存后的方案由普通实施任务按目标项目规则和当轮授权
接手，不需要再次调用或安装本 Skill。对应活动方案已经存在时，默认只报告交接位置；只有用户明确要求“仅修订
方案”并授权方案文件修改时，才更新方案本身，随后仍然停止。

方案交接不得重定义目标项目的授权规则。目标项目明确规定“按已确认方案实施”同时覆盖确定文件变更、方案列明
的普通验证、结果记录和满足条件后的生命周期关闭时，普通任务按该规则在同一实施批次执行；验证升级、新增副作用、
候选实质漂移或需要新的语义决定时只申请授权差额。目标项目规则更严格时以其为准。这只是普通任务的授权交接，
不会恢复本 Skill 的 `sync` 或执行阶段。

没有问题时优先使用项目已有检查记录位置；项目没有明确承接位置时，保存前询问用户，不创建固定目录或空方案。

## 先确认规则、授权和活动真源

1. 读取目标路径适用的全部 `AGENTS.md`，遵守项目语言、安全和授权约束，并识别实施授权是否已经明确包含方案
   列明的普通验证、结果记录与满足条件后的关闭。
2. 检查阶段不写文件、不运行命令。保存授权只覆盖方案及必要活动待办，不推定目标文档施工、非只读 Git、安装、
   认证或私有联网、上传、外部写入、付费或明显大规模联网、真实数据、产品进程、高风险删除或关闭；本地只读和
   符合项目规则的公开只读联网默认允许，不需要从保存授权中推定。
3. 公开只读联网只在用户指定或已冻结声明直接需要公开证据时使用；先固定声明和来源，不进行无边界浏览，也不
   让公开资料覆盖目标项目自己的当前契约。
4. 不把凭据、真实用户数据或原始运行现场写入仓库、方案或报告。
5. 不复用过去的审计结果代替当前证据，不保存 profile、manifest、版本号、隐藏状态或持久执行账本。
6. 检查当前文档入口和职责声明，只读取足以识别活动真源所有者的内容；不使用固定 token、固定行数或只读标题
   的入口冻结机制。

如果无法明确回答“本次声明由哪份活动文档拥有”，立即停止内容审计并报告：

- 已读取的当前入口和职责证据；
- 缺失、重复或冲突的所有权；
- 受影响的拟审计范围；
- 需要明确的结构决定；
- 建议交给 skeleton 的目标、授权需求和完成条件。

此停点不是结构治理结论。不得猜测真源、认证等价治理、创建标准路径或继续扩大内容读取。

## 冻结内容范围

在读取实现证据前写明模式、内容种子、直接依赖规则、活动文件清单和排除项。

### `full`

用户没有限定文件、功能或差异，却要求审计项目文档时默认 `full`。从项目当前活动入口和职责声明形成活动文档
集合，冻结后在本轮完整处理该集合。

`full` 表示完整审计已识别的活动文档，不表示遍历全部源码、测试、CI、安全实现、历史或归档。活动入口无法
形成完整集合时，报告未覆盖边界，不夸大为项目范围一致。

### `incremental`

用户明确指定文件、功能、声明、标识符或当前差异时使用 `incremental`。范围包括：

1. 精确内容种子；
2. 一轮直接依赖：会直接提供该声明证据，或会直接消费该变更并改变一致性结论的文档、代码、配置、构建或
   可观察行为锚点。

直接依赖只展开一轮，不递归跟随新发现。单轮后仍无法形成可靠边界时，报告范围证据不足并询问是否升级为
`full`；不得猜测小范围、静默升级或宣称全项目一致。

### 充分读取而非机械截断

范围内的活动文档应完整读取；大型文件可以稳定分块，但必须覆盖完冻结范围。证据锚点读取到足以理解相关声明
和直接上下文，不以固定 token、标题 token 或固定行数替代理解。

新发现只有会直接改变已冻结声明的判断时才能作为本轮直接证据；不得借机扩张为新的主题审计。

## 分类声明并选择权威证据

先区分声明类型：

- 当前描述性事实：对照代码、配置、schema、构建、调用关系或可观察行为；
- 规则、契约和决定：以明确承接它们的当前文档或已确认决定为权威，再检查实现和其他文档是否遵守；
- 历史记录和动态结果：按时间语境判断；当前运行状态需要实际执行证据或用户确认；
- 待办和方案状态：以活动生命周期真源及完成证据为准；
- 非穷举摘要：只有遗漏改变表述含义或违反文档职责时才是不一致。

证据优先级由声明类型决定，不能假定“代码永远正确”或“测试通过就证明契约正确”。多个同等级权威来源冲突，
或事实背后存在真实价值取舍时，使用“需要决策”。

为每个声明记录文档位置、直接证据位置、结论和理由。搜索只在当前声明已经命名的最小根中进行，并以精确路径、
标识符或当前差异为种子。不要遍历归档、历史、整个工作区或无关实现来证明不存在。

## 识别内容问题

除事实矛盾外，检查以下主责问题：

- `职责不清`：一个当前声明没有唯一活动所有者，或多个文档都自称权威且边界冲突；
- `内容膨胀`：文档复制易漂移的实现细节、重复其他真源，或记录超出自身职责且不影响使用者判断的内容；
- `位置不当`：内容本身可能正确，但位于错误的职责、生命周期或抽象层级；
- `事实不一致`：声明与相应当前证据明确冲突，或缺失会改变其明确含义。

源码中存在一个细节，本身不证明长期文档必须记录它。兼容路由、摘要和示例要按其明确职责判断，不能因不穷举
实现而自动扩写。

每项只使用以下内容结论：

- `一致`：声明与相应证据相符；
- `不一致`：存在明确矛盾或改变含义的缺失；
- `无法验证`：证据不足或必要验证未获授权；
- `需要决策`：同等级权威冲突或价值取舍未定；
- `未覆盖`：不在本次冻结范围。

只有 `full` 的活动范围完整，所有适用项都一致，且没有无法验证、需要决策或未覆盖时，才能报告项目活动文档
内容一致。`incremental` 只能报告受影响范围结论。

## 按需审计测试设计

以下任一条件成立时，完整读取
[`references/test-design-audit.md`](references/test-design-audit.md)：

- 用户明确要求测试设计、测试覆盖、Registry、suite、CI 或测试安全审计；
- 范围内的具体文档声明必须以测试、CI 或安全实现作为直接证据。

`full` 本身不触发测试设计或全项目安全审计。只因仓库存在测试目录、Registry、workflow 或 SAFETY 文件，也
不能把它们纳入范围。

测试、CI 或安全仅作为某项当前声明的直接证据时，只检查能回答该声明的一轮链路；不扩张为总体测试经济性、
CI 完整性或安全认证。静态证据不能证明故障捕获、flaky、性能成本或恢复效果。

## 交付检查结果

`check` 在对话中按以下顺序报告，不创建项目内报告：

1. 活动真源所有者及其证据，或所有权不清停点；
2. `full`/`incremental`、冻结范围、直接依赖和排除项；
3. 按影响合并的事实不一致、职责不清、内容膨胀和位置不当；
4. 适用时的测试设计发现；
5. 一致项摘要、无法验证项、未覆盖范围和未获授权操作；
6. 建议方案目标、目标路径、动作边界、完成条件与验证要求。

每个发现包含声明与位置、直接证据与位置、结论、影响、推荐承接和最小动作。报告后询问是否保存方案并停止。

## 保存可靠方案并退出

方案必须让没有参加检查对话的普通任务能够继续，至少写明：

- 活动真源、`full`/`incremental`、冻结范围、直接依赖、排除项和未覆盖边界；
- 初始检查证据、事实不一致、职责不清、内容膨胀、位置不当、无法验证和需要决策；
- 每项发现的影响、处理选项、推荐理由、用户决定和最小补证条件；
- 确定修改路径、可能修改路径、明确不修改范围、允许与禁止动作及重新冻结触发条件；
- 完成条件、验证要求和未运行项目，但不写精确命令、脚本、临时 Git 技巧或指定执行者；
- 目标项目的实施授权语义及差额停止条件；只引用或实例化当前规则，不复制、放宽或覆盖更严格的授权边界；
- 项目生命周期要求的完成证明、状态消费者、关联方案、联合复核条件、验收停点和关闭边界。

方案只把现有活动文档内容修订列为 consistency 可实施目标。创建、移动、重命名、归档或删除文档，改变入口、
导航、路径职责、生命周期、Registry、`CONTEXT.md` 或 ADR，以及修改产品、测试、CI 或安全实现，均形成精确交接，
不列为本方案确定写入。结构职责冲突、证据不足或语义取舍未决时保持待决。

项目已有生命周期真源时只实例化任务值，不复制模板全文。项目缺少收尾契约时仍填写最小字段，并形成 skeleton
交接；不创建结构入口，不自动调用 skeleton。关联方案未完成时只报告本方案主责，不能继承授权、结论或自动关闭。

写入后静态自审证据、范围、路径、动作边界、授权语义、完成条件、验证要求和收尾字段是否一致。完成条件不冒充
结果，未运行验证保持 `not_run`。随后立即停止，由普通任务负责裁决、实施、验证、验收和关闭。
