# 项目文档一致性检查与方案

## 职责与退出边界

本 Skill 只负责：

- 确认活动文档的当前所有者和有限审计范围；
- 核对文档声明与代码、配置、构建或可观察行为；
- 识别事实不一致、声明漂移、职责错位、内容膨胀和位置不当；
- 在条件成立时审计直接相关的测试设计，并为后续普通任务规划验证；
- 按用户明确要求交付只读报告，或保存一份综合实施方案。

本 Skill 不认证项目骨架，不安装门禁，不施工、不运行验证、不归档、不关闭目标项目生命周期，也不调用或依赖
`project-doc-skeleton`。已有活动方案的施工、验证或关闭请求只报告普通任务的接手位置。

归档和历史材料默认只提供历史语境；只有活动入口明确继续把它定义为当前契约时，才作为当前权威。

以下标准项目级 Agent Skill 根是工具资产，不是活动项目文档：

- `.agents/skills/**`
- `.cursor/skills/**`
- `.claude/skills/**`
- `.codex/skills/**`
- `.opencode/skills/**`
- `.opencode/skill/**`
- `.github/skills/**`

其他 Skill 根只有在用户、适用项目规则或本次范围内已读取的精确配置明确声明时才排除；不得为发现自定义根而扫描
配置。活动文档点名某个 Skill 的存在、入口或职责时，只把对应 `SKILL.md` 或必要资源作为该声明的实现证据，不因此
审计整个工具目录。

## 请求分流与只读边界

1. 明确只要检查、审计、review 或报告时，直接走只报告路线；报告后停止。
2. 明确要求形成、保存或修订方案时，直接走方案路线。
3. 请求只有 `$project-doc-consistency` 或意图不足以可靠分流时，在实质调查前询问“只要审计报告，还是审计后形成
   方案”，推荐先只要报告。取得回答前只读取本 Skill 和遵守安全边界所必需的适用 `AGENTS.md`。
4. 方案路线在实质调查前取得尚未明确的交付前自查轮数和实施后反哺报告选择，推荐“两轮、不生成”。反哺报告由后续
   普通任务在实施和验证完成后独立生成，本 Skill 不生成。
5. 新问题始终只读。即使请求中包含“修复”“同步”或 `sync`，也不写文件、不运行测试、构建、产品、门禁或其他动态
   验证；方案中列明的动态验证保持 `not_run`。

用户对语义结果的确认不自动授权保存方案、登记待办、转换状态或开始实施；确认只绑定当前明确问题，沉默、模糊回复
或旧问题的确认不授权新动作。方案保存必须在最终问题中单独确认，保存后立即停止。

## 活动真源与证据

先读取目标路径适用的全部 `AGENTS.md`，再从当前文档入口和职责声明识别活动所有者。若无法明确回答“本次声明由哪份
活动文档拥有”，停止内容审计并报告已读取入口、冲突或缺失、受影响范围和结构治理交接；不得猜测真源或创建标准路径。

按声明类型选择证据：

- 描述性事实：对照代码、配置、schema、构建、调用关系或可观察行为；
- 规则、契约和决定：以明确承接它们的当前文档或已确认决定为权威，再检查实现和消费者；
- 历史记录和动态结果：按时间语境判断；当前运行状态需要实际执行证据或用户确认；
- 待办和方案状态：以活动生命周期真源和完成证据为准；
- 非穷举摘要：只有遗漏改变含义或违反文档职责时才是不一致。

测试入口、Registry、suite、断言和 CI 默认是契约消费者与验证证据，不因仍在活动登记就取得业务契约所有权。只有活动
入口明确委托测试治理拥有相应契约时，测试声明才可作为同级权威。当前权威已经唯一裁决的旧实现、旧配置或旧测试直接
列为修复项，不让用户重新决定是否继续兼容。

只有当前权威留白、多个同级当前权威冲突或存在真实价值取舍时，才形成语义决定。能够由当前证据唯一裁决的事实自行查明。

公开只读联网仅在用户指定或冻结声明确实需要公开证据时使用，不进行无边界浏览。不得把凭据、真实用户数据、原始运行
现场或持久执行账本写入报告、方案或仓库。

## 冻结审计范围

在读取实现证据前记录模式、内容种子、直接依赖规则、排除项和精确活动文件路径。不得用“核心文档”或职责分组代替路径。

### `full`

用户未限定文件、功能或差异却要求审计项目文档时使用。由当前入口和职责声明形成活动文档集合，冻结后完整处理该集合。
`full` 不表示遍历全部源码、测试、CI、历史或归档；入口不能形成完整集合时报告未覆盖边界。

### `incremental`

用户明确指定文件、功能、声明、标识符或当前差异时使用。范围只包括精确内容种子和一轮直接依赖：直接提供该声明证据，
或直接消费该变更并改变一致性结论的文档、代码、配置、构建或可观察行为锚点。直接依赖不递归展开；边界仍不可靠时报告
证据不足并询问是否升级为 `full`，不得静默升级。

范围内活动文档必须完整读取；大型文件可稳定分块，但不得抽样。实现证据只读到足以理解声明和直接上下文。

**冻结的是文档路径和一轮依赖边界，不是问题发现集合。** 后续评审不得静默增加活动文档路径或递归扩大依赖，但必须
重新检查冻结路径中的原始正文，并可新增、删除、拆分、合并或改变发现及处置。

## 双遍审计与自然内容单元

对 `full` 中每份活动文档，或 `incremental` 中每个内容种子及其直接依赖，分别完成：

1. **事实／契约遍**：核对事实、规则、契约、决定、前提、例外和状态；
2. **职责／删除优先遍**：检查重复或漂移、职责错位、实现镜像、过程或历史残留、复杂或不精准表达、位置不当，以及
   删除、引用、迁移、合并、简化或保留的最小处置。

长期文档按自然职责单元审计：

- 只有正文整体由同一角色、所有者和契约承接，且没有两个及以上稳定一级职责章节时，才可用一个覆盖全部正文的单元；
- 有两个及以上稳定一级职责章节（通常是文档标题下的 `##`）时，每个一级职责章节至少一个单元；不得跨一级职责章节合并；
- 同一一级职责章节内若角色、所有者或契约发生变化，继续拆分；只有相邻内容已经分别检查且三者和处置均相同，才可
  合并，并列出全部被合并锚点；
- 没有稳定标题时，在角色、所有者或契约发生变化的位置分单元。

每个内容单元必须可见记录四项：

1. 被核对的具体声明或当前职责；
2. 命名的当前所有者，以及至少一个直接证据、直接消费者锚点或明确残余；
3. 事实／契约遍的结论与理由或残余；
4. 职责／删除优先遍命中的风险与处置，或该单元保留的具体依据。

“源码、配置和测试静态吻合”“职责清楚”“属于核心真源”“删除会损失能力”等概括只能作摘要，不能单独充当上述四项
证据。章节范围加一句统一结论不能证明其中各单元已经审计。

执行职责／删除优先遍前按以下条件完整读取
[`references/content-contraction.md`](references/content-contraction.md)：

- `full` 始终读取；
- `incremental` 的冻结范围包含长期活动文档，或已暴露重复、漂移、镜像、过程／历史、位置不当或删除候选时读取。

对范围内每份长期活动文档形成 `需要收缩`、`无需收缩`、`无法核验`、`需要决策` 或 `未覆盖` 之一。`无需收缩`
必须承接该文档全部自然单元的四项证据，且任何单元都没有未解除残余；不能从文档名称、总体职责或局部无问题推导。

## 完整性门

冻结当前发现和形成完整结论前，逐项核对：

1. 精确活动路径或内容种子与审计记录一一对应；
2. 每个长期文档的自然单元覆盖全部实质正文，没有跨一级职责章节隐藏内容；
3. 每个单元都有四项证据或明确残余；
4. 每份长期文档都有文档级处置和文档特定依据；
5. 高显著度发现没有终止其余成员、其余单元或另一遍。

任一项缺失时先补齐；仍不能补齐则标为 `未覆盖`，只交付不完整停点报告，不得宣称完整范围完成、形成完整方案候选、
计入已完成评审轮次或询问保存。输出空间不足时，优先在完整文档边界停止；单个文档本身超出时，在自然单元边界停止并
把该文档标为 `未覆盖`。列出已完成部分和剩余精确路径，不得降低证据密度换取 `N/N` 完成声明。

问题发现可以分配稳定标识以便方案承接，但标识和数量只用于防止已有发现丢失，不能证明没有漏项。评审改变发现后，以
最终有效发现清单为准重新核对每项只有一个归宿。

## 条件测试设计与验证交接

以下任一条件成立时完整读取
[`references/test-design-audit.md`](references/test-design-audit.md)：

- 用户明确要求测试设计、测试覆盖、Registry、suite、CI 或测试安全审计；
- 某项已冻结的产品或治理契约，必须评估测试义务、选择、核心断言、CI 或安全设计才能裁决。

核对测试文档自身点名的路径、命令、入口、当前分类或一处直接实现，属于普通事实一致性取证，可以精确读取证据而不加载
完整测试设计参考。`full`、测试文档进入活动集合，以及仓库中存在测试目录、Registry、workflow 或 SAFETY 都不会自动
触发该参考。若已冻结的直接证据暴露可执行断言仍强制已删除、替代或收窄的路径、入口、生命周期或职责，记录“结构机械
断言漂移”，但不搜索其他测试。

方案中的确定切片包含动态验证、昂贵阶段、产品／GUI／外部环境、证据复用、实施期消费者漂移或认证终态时，完整读取
[`references/validation-planning.md`](references/validation-planning.md)。该参考只为普通任务定义有界验证交接，不恢复
本 Skill 的执行阶段。

## 交付审计报告

报告至少包含：

1. 活动真源所有者及证据，或所有权不清停点；
2. 模式、精确路径或内容种子、直接依赖和排除项；
3. 每份长期文档独立命名的自然单元记录，逐单元展示四项证据，以及文档级处置；
4. 事实不一致、重复或声明漂移、职责不清、内容膨胀、表达不精准和位置不当等发现；
5. 无法验证、需要决策、未覆盖和未获授权操作；
6. 适用时的测试设计发现、结构机械断言漂移和验证交接建议。

每个发现写明声明与位置、直接证据与位置、结论、影响、推荐承接和最小动作。只报告路线在报告后停止。

## 形成与评审方案候选

方案路线只为真实发现和待决事项形成未保存候选；**不在方案中复制全部“无需修改”文档的内容覆盖图**。方案应自包含：

- 活动所有者、模式、完整性门结果和未覆盖边界；
- 每项发现的证据、影响、用户决定和最小补证条件；
- 确定修改路径、可能修改路径和明确不修改范围；
- 每个确定切片的责任、最小动作、一层直接消费者、验证义务、副作用、授权、完成条件和残余；
- 实施后的最终活动入口、确定切片和新产生一跳关系复核；
- 目标项目的生命周期承接位置和差额停止条件。

普通任务应能只凭项目规则和该方案执行确定切片；无需取得完整的“无需修改”审计证据，也不得重新运行本 Skill 的
`full` 审计。没有问题时不创建空方案。

### 收缩专项评审

用户只选择一轮时，同一轮完成查漏和防误伤，并同时满足下述两类记录；选择两轮及以上时：

1. **查漏轮**：以进入评审时所有 `无需收缩` 文档为固定复核集合，逐份回看原始正文和原报告证据。每份文档记录
   `改变` 或 `未改变`；改变时列出新增或修正的自然单元和处置，未改变时引用原报告单元并点名本轮复核的原始证据。
   不得只列新增发现。
2. **防误伤轮**：逐项检查当前候选中的全部删除、迁移、摘要加链接、合并和简化动作，包括查漏轮后新增、删除或改变
   的动作。每项记录保留的唯一事实、必要消费者义务、是否产生新漂移或职责缺口，以及 `通过`、`修改` 或 `撤销`。

评审可以在冻结文档范围内改变发现和动作。发现遗漏、依据不足或误伤时，先修订候选并重做受影响文档或动作；修订前的
结论不计入完成轮次。路径数、发现数、动作数或集合相等只能证明已有项目没有丢失，不能作为查漏或防误伤通过证据。

每轮同时核对方案范围、路径、用户决定、验证副作用、授权、完成条件和生命周期字段，但这些机械检查不能替代上述专项
复核。最终方案只保留有效结论和残余，不保存逐轮推理日志。

## 用户决定与最终保存

证据不能唯一裁决的语义决定，或目标明确但动作副作用超出当前授权时，一次只询问一项。用白话说明推荐、实际结果、
主要代价、可回退性和简短回复方式；内部字段、路径、ID 和命令只放在必要的技术备注中。用户选择“暂缓”时，受影响
切片保持待决并记录最小解除条件，不能宣称相应评审完成。

完成所选评审轮次后，展示方案目标、保存路径、用户决定、确定范围、残余和实际完成轮次，再询问是否“只保存方案，
不开始实施”。只有明确确认后才一次写入项目已有承接位置及必要待办；项目没有精确候选状态时使用 `待确认`，没有承接
位置时保存前询问，不自造目录或生命周期入口。保存后机械核对写入内容与候选一致并立即停止。
