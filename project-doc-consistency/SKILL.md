# 项目文档一致性检查与方案

## 职责与边界

本 Skill 只负责：

- 核对活动文档声明与当前代码、配置、构建或可观察行为；
- 识别事实不一致、职责不清、内容膨胀和位置不当；
- 在直接证据需要或用户明确要求时，按边界审计测试设计；
- 把同一审计目标中已经收敛的文档、产品、构建、测试、CI 或安全改动写入一份综合方案。

本 Skill 不认证项目骨架或治理等价性，不安装门禁，不调用或依赖 `project-doc-skeleton`。结构所有权不清时输出
精确交接，不替用户调用其他 Skill。

归档和历史材料默认只提供历史语境。只有活动入口明确把它继续定义为当前契约时，才把它作为当前证据。

仓库任意层级的以下七类标准项目级 Agent Skill 根是工具资产，不是活动项目文档：

- `.agents/skills/**`
- `.cursor/skills/**`
- `.claude/skills/**`
- `.codex/skills/**`
- `.opencode/skills/**`
- `.opencode/skill/**`
- `.github/skills/**`

其他项目级 Skill 根只接受三种精确来源：用户明确指定、适用项目规则明确声明，或本次冻结范围内已经读取的精确配置
明确声明。不得为发现自定义根而扫描配置。默认不把这些根中的 Markdown 纳入活动集合、双遍审计或覆盖矩阵；活动
文档精确声明某个 Skill 的存在、入口或职责时，只把对应 `SKILL.md` 或必要资源作为该声明的实现证据，不审计 Skill
正文。不要宽泛排除整个工具目录，也不要按文件名排除其他位置的 `SKILL.md`。

## 只有检查、候选评审与最终保存

1. **取得评审轮数**：新问题可能形成方案、或用户明确要求修订已有方案时，在实质调查前询问“交付方案前需要我自查
   几遍”；推荐两轮。用户给出正整数时直接采用，回复“按推荐”时明确记为两轮并用一句白话复述，不静默采用推荐值。
   已有活动方案的普通施工、验证或关闭请求只报告普通任务接手位置，不询问无用轮次。
2. **检查**：新问题始终只读。即使请求中包含“修复”“同步”或 `sync`，也只完成审计和报告结论，不写方案或待办。
   只使用文件读取、搜索和只读 Git 等静态证据；不运行测试、构建、产品、门禁或其他验证命令，即使调用可做到无落盘。
   候选中列明的全部动态验证保持 `not_run`，交给后续普通任务。
3. **候选与评审**：报告后只在当前调用内形成未保存的综合方案候选，围绕冻结证据完成指定轮次的自我评审、自我修订
   和变更后复核。每轮检查证据、矩阵、切片就绪、用户决定、路径、验证副作用、授权、完成条件、最终复核和收尾字段，
   不重跑完整审计，也不因轮次数量扩大范围。各轮过程只存在于本次调用，不把逐轮意见、修订轨迹或评审日志写入
   最终方案。
4. **最终保存**：完成轮次后展示目标、保存路径、用户决定、确定范围、残余和完成轮次，再用白话询问是否“只保存
   方案，不开始实施”。只有最终确认后才一次写入项目已有承接位置及必要待办，保持项目要求的待确认状态；项目没有
   定义精确候选状态时使用 `待确认`，不自造近义状态。随后只机械核对写入结果与候选一致并立即停止。

能够直接调查的事实自行查明。提问前先使用允许的只读证据、适用项目规则和已确认决定消解选择；证据能够唯一裁决时，
直接说明依据和用户可感知结果，不再请求确认技术实现。纯实现细节由 Skill 选择，但用户可观察契约、真实治理取舍、
风险／成本偏好和不可逆结果不得伪装成实现细节。

不是每项不一致都构成语义决定。当前活动所有者、适用项目规则或已确认决定已经唯一给出结果时，冲突的旧实现、旧配置、
旧测试和历史记录只用于证明缺口、影响与改动成本，不是同等级候选；把它们列为修复项，不让用户重新拍板。只有当前
权威本身明确留白，或多个同等级当前权威互相冲突时，才进入语义决定。当前实现不能仅因改动较少而成为默认推荐；尚未
发布且会造成用户可见歧义的契约，优先推荐消除歧义。已有规则或决定还必须贯穿后续路径、目录、字段和生命周期安排，
不得把同一结果拆成新的实现问题再次询问。

测试入口、Registry、suite、断言和 CI 默认是契约的消费者与验证证据，不因仍处于活动登记就成为业务契约所有者。
在把测试行为冲突判为“同等级当前权威冲突”前，必须沿当前项目入口查明该行为的一份活动契约所有者；只有活动入口
明确把对应契约所有权委托给测试治理时，测试声明才可作为同级权威。若契约所有者已明确行为被移除、禁止或替代，
仍登记的旧测试就是失效项，Registry 的“活动”只表示它尚在治理清单中；直接列为修复或退出，不询问是否继续兼容。

同样不得把一个已明确职责的修复扩张成职责重设计。当前测试治理所有者已经规定某项测试证明真实外部写入、需要认证
或承担其他精确义务，而安全规则又唯一规定其执行类别和触发边界时，只修正分类、触发和授权说明；不额外询问是否改成
本地测试、删除或换一种职责。只有当前测试职责所有者本身明确留白，或同等级当前职责声明冲突时，才让用户选择职责。

证据无法唯一裁决的语义决定，或目标已明确但副作用超出当前授权的授权差额，一次只用一张用户决策卡询问，不混写
两类停点。卡片先标明“需要你决定的结果”或“需要你允许的动作”，再用日常语言给出推荐及理由、各选项的实际结果与
主要代价、可回退性和简短回复方式。内部字段、测试分类、路径、哈希、manifest、marker、pack 等只在确实帮助复核时
进入末尾的“技术备注（可跳过）”，且备注不得承载作出决定所必需的信息。容易混淆的概念先说明“这不是 X，而是 Y”；
沿用用户使用的流程名称，必要术语首次出现时用白话解释，不自行创造近义流程。授权差额涉及外部副作用时，在选项
影响中复用副作用效果摘要，明确会发生、不会发生和既有状态。

发送决策卡前先临时移除“技术备注（可跳过）”自检：标题、消歧、推荐、选项标签、实际结果、代价、可回退性和回复
方式必须仍能让不了解实现的用户独立作答。这些正文不得出现内部字段名、精确路径、内部 ID、Registry、suite、
manifest、Git、命令、代码格式，或用户没有使用过的组件、模块、服务与包名；确需复核的原名只放技术备注。决定名称时，正文写成“采用专门表达业务含义的名字”
与“沿用当前共用名字”等结果，不用标识符充当选项。每张卡明确给出“按推荐”、一个或多个白话备选和“暂缓”的回复
方式；任一条件不满足就先改写卡片，不向用户发送。

用户回复“按推荐”只表示明确接受当前卡片已陈述的推荐项；记录后用一句白话复述结果。不得把沉默、模糊回复或其他
问题的历史推荐当作确认；新问题、推荐改变或概念发生漂移时必须重新询问。用户明确暂缓的事项可以进入 `待确认`
方案，但受影响切片不得进入确定实施范围，必须记录最小解除条件和残余，且不能宣称对应评审已完成。

一旦识别语义决定，立即在当前轮计数前停下并只询问第一项；不得继续完成其余轮次、把问题留到最终摘要，或直接进入
保存停点。只有用户明确选择“暂缓／待确认”时才可不裁决保存；此时明确标出受影响切片的评审未完成，不能用候选整体
轮次掩盖它。

冻结审计完成后在当前调用内维持发现清单，并为每项发现分配仅在本次调用内使用的稳定标识。最终报告、覆盖／残余矩阵
和候选必须逐项承接全部冻结发现，分别标为已决定、确定、待决、跨职责交接、不适用或排除并给出依据；后续决定和评审
不得静默删除、合并掉或遗漏早先发现。提出最终保存问题前执行集合对账：发现清单、覆盖／残余矩阵和候选处置的标识集合
与数量必须完全相等，并在最终摘要中逐项展示归宿；任一成员缺失、重复或无归宿时，本轮评审作废，回到候选修订并重做
受影响评审，不得询问保存。该清单、临时标识和对账过程不持久化为独立日志或账本，只用于保证本次最终输出闭合。

项目已声明的自定义 Skill 根、工具可发现性、所有者和路径职责不是实现细节；在“迁移现有根”“调整本地门禁”或
“保留已知残余”等多个有效结果之间选择时，必须作为语义决定逐项询问。测试或标准资产暴露差异只构成事实证据，
不能替用户选择治理结果；确认前相关路径保持待决，不得进入确定切片。

本 Skill 没有施工、验证、归档、删除或关闭阶段。已有活动方案时默认只报告位置；只有用户明确要求修订方案时，才按
同一未保存候选流程处理，原文件在最终保存确认前保持不变。普通任务按目标项目规则和确认授权接手，不需要再次调用
或安装本 Skill。

方案只记录目标项目已有的授权语义，不重新定义或放宽它。验证升级、新增副作用、候选实质漂移或新的语义决定仍须
在实施时申请授权差额。没有问题时先输出对话报告，不创建空方案或持久记录；用户在最终停点选择保存检查记录时，
只使用项目已有检查记录位置。没有明确承接位置时，保存前询问用户。

最终保存新建了此前不存在的活动方案容器、且项目规则要求关闭后清理空容器时，保存方案必须记录“保存前不存在、由
本工作保存阶段创建、归档后为空即可由后续普通实施任务精确删除”。这里的工作所有权跨越审计任务与实施任务，不因
换用全新普通任务而丢失；普通任务凭该记录和实施授权即可清理。保存前已存在、归属不明或关闭后非空的目录不得这样
标记或删除。

## 确认规则与活动真源

1. 读取目标路径适用的全部 `AGENTS.md`，遵守语言、安全、授权和生命周期规则。
2. 从当前文档入口和职责声明识别活动文档所有者；只读取足以判断所有权的内容，不用固定行数或标题截断替代理解。
3. 公开只读联网只在用户指定或冻结声明直接需要公开证据时使用；先固定声明和来源，不进行无边界浏览。
4. 不把凭据、真实用户数据、原始运行现场、profile、manifest 或持久执行账本写入仓库、方案或报告。

如果无法明确回答“本次声明由哪份活动文档拥有”，立即停止内容审计并报告：已读取的入口和职责证据、冲突或缺失、
受影响范围、需要明确的结构决定，以及建议交给骨架治理任务的目标和完成条件。不得猜测真源、创建标准路径或继续
扩大读取。

## 冻结内容范围

在读取实现证据前写明模式、内容种子、直接依赖规则、活动文件清单和排除项，并建立覆盖／残余矩阵。矩阵至少包含
审计维度、适用范围、状态、直接证据和残余；状态只使用 `已覆盖`、`无法验证`、`需要决策`、`未覆盖`、`不适用`。

### `full`

用户没有限定文件、功能或差异却要求审计项目文档时使用 `full`。从当前活动入口和职责声明形成活动文档集合，冻结后
完整处理该集合。`full` 不表示遍历全部源码、测试、CI、安全实现、历史或归档；入口不能形成完整集合时必须报告
未覆盖边界。

### `incremental`

用户明确指定文件、功能、声明、标识符或当前差异时使用 `incremental`。范围仅包括精确内容种子和一轮直接依赖：
直接提供该声明证据，或直接消费该变更并改变一致性结论的文档、代码、配置、构建或可观察行为锚点。

直接依赖只展开一轮，不递归跟随新发现。单轮后仍不能形成可靠边界时，报告证据不足并询问是否升级为 `full`，不得
静默升级或宣称全项目一致。

范围内活动文档完整读取；大型文件可稳定分块，但必须覆盖完。实现证据读到足以理解声明和直接上下文。新发现只有
直接改变冻结声明判断时才可作为本轮证据，不借机扩张新主题。

## 完成双遍审计

对 `full` 中每份活动文档、或 `incremental` 中每个内容种子及其一轮直接依赖，分别记录：

1. **事实／契约遍**：核对描述性事实、规则、契约、决定、状态与当前证据；
2. **职责／删除优先遍**：独立检查职责不清、重复真源、内容膨胀、位置不当，以及应删除、引用或收敛的内容。

某遍不适用时写明理由；未执行、证据不足或有语义取舍时留下残余。只有双遍矩阵填满，才能形成相应范围结论。

## 分类声明与证据

- 当前描述性事实：对照代码、配置、schema、构建、调用关系或可观察行为；
- 规则、契约和决定：以明确承接它们的当前文档或已确认决定为权威，再检查实现和其他文档；
- 历史记录和动态结果：按时间语境判断；当前运行状态需要实际执行证据或用户确认；
- 待办和方案状态：以活动生命周期真源及完成证据为准；
- 非穷举摘要：只有遗漏改变含义或违反文档职责时才是不一致。

证据优先级由声明类型决定。多个同等级权威来源冲突或存在真实价值取舍时，结论为 `需要决策`。为每个声明记录
文档位置、直接证据位置、结论和理由；搜索只在声明已经命名的最小根内进行，不遍历归档、历史或整个工作区来证明
不存在。

内容问题分为 `事实不一致`、`职责不清`、`内容膨胀`、`位置不当`。每项内容结论只使用 `一致`、`不一致`、
`无法验证`、`需要决策`、`未覆盖`。源码存在某个细节不等于长期文档必须记录它。

只有 `full` 的活动集合完整、所有适用项一致且没有残余时，才能报告项目活动文档内容一致；`incremental` 只能报告
受影响范围结论。

## 按条件审计测试设计

以下任一条件成立时，完整读取
[`references/test-design-audit.md`](references/test-design-audit.md)：

- 用户明确要求测试设计、测试覆盖、Registry、suite、CI 或测试安全审计；
- 冻结范围内的具体声明必须以测试、CI 或安全实现作为直接证据。

具体模式、范围、证据要求和停止条件只以该参考为准，本文件不重复。`full` 本身以及仓库中存在测试目录、Registry、
workflow 或 SAFETY 文件都不会触发测试设计审计。

若精确种子或已经冻结的直接证据暴露某项可执行断言仍强制已删除、替代或收窄的路径、入口、生命周期或文档职责，
记录“结构机械断言漂移”：列出当前结构决定、精确断言、直接影响和结构实施交接。此兜底不触发搜索其他测试、脚本
或 CI，不扩大范围，也不修改断言；证据不足或结构决定不明确时保持待决。

## 交付检查结果

`check` 在对话中依次报告：

1. 活动真源所有者及证据，或所有权不清停点；
2. 模式、冻结范围、直接依赖、排除项和覆盖／残余矩阵；
3. 按影响合并的内容问题；
4. 适用时的测试设计模式、范围与发现；
5. 结构机械断言漂移交接；
6. 一致项、无法验证、需要决策、未覆盖和未获授权操作；
7. 建议方案目标、路径、动作边界、完成条件、验证要求与最终范围和漂移复核边界。

每个发现包含声明与位置、直接证据与位置、结论、影响、推荐承接和最小动作。报告后形成未保存候选，完成指定轮次
评审和必要用户决定，再在最终停点询问是否“只保存方案，不开始实施”。

## 保存一份可独立实施的综合方案

方案至少写明：

- 活动真源、模式、冻结范围、直接依赖、排除项、未覆盖边界和覆盖／残余矩阵；
- 初始证据、各类内容问题、无法验证和需要决策；适用时写明测试设计模式及其参考要求的结果；
- 每项发现的影响、选项、推荐理由、用户决定和最小补证条件；
- 确定修改路径、可能修改路径、明确不修改范围、允许与禁止动作及重新冻结触发条件；
- 每个确定切片的责任与契约、精确路径或受控候选、一层修改链和直接消费者、验证义务、副作用、授权、完成条件和
  残余；未收敛候选保持待决；
- 每项列明验证的证明目标、入口或工作目录、可预见落盘或外部副作用，以及无落盘调用、受控输出或精确清理办法；
  直接证据声称验证只读而默认调用会生成缓存、报告或快照时，作为事实不一致在本方案内解决，不能留到最终复核才发现；
- 完成条件、验证要求、未运行项目、生命周期证明和关闭边界，但不写执行者、临时 Git 技巧或不必要的精确命令；
  只有副作用边界依赖调用方式时才记录必要参数；
- 目标项目授权语义及差额停止条件，只引用或实例化当前规则；
- **最终范围与漂移复核**：实施后确认最终活动入口和所有者，复核方案确定切片、已列直接消费者，以及修改路径新引入
  或改变的一跳直接链接／消费者。不得递归展开、扫描整个工作区，或重跑本 Skill 的 `full`、双遍审计、测试设计
  审计和 Registry 全局审计。发现范围外新问题时记录残余、保持方案活动，并按差额规则处理。

同一审计目标只保存一份综合方案。通过上述切片就绪条件的跨职责改动都可成为确定切片，不要求普通任务再次调用本
Skill、另起审计或按职责拆分子方案；未通过的保留为待决项或精确交接。普通任务取得实施授权后，应能仅凭目标项目
规则和该方案完成确定切片、列明验证、最终范围与漂移复核及满足条件后的生命周期关闭。

项目已有生命周期真源时只实例化任务值，不复制模板全文。缺少收尾契约时填写最小字段并形成骨架治理交接，不创建
结构入口。关联方案未完成时只报告本方案主责，不能继承授权、结论或自动关闭。
