# 项目文档一致性检查与方案

## 职责与边界

本 Skill 只负责：

- 核对活动文档声明与当前代码、配置、构建或可观察行为；
- 识别事实不一致、职责不清、内容膨胀和位置不当；
- 在直接证据需要或用户明确要求时，按边界审计测试设计；
- 把同一审计目标中已经收敛的文档、产品、构建、测试、CI 或安全改动写入一份综合方案。

本 Skill 不认证项目骨架或治理等价性，不安装门禁，不调用或依赖 `project-doc-skeleton`。结构所有权不清时输出
精确交接，不替用户调用其他 Skill。

归档和历史材料默认只提供历史语境。只有活动入口明确把它继续定义为当前契约时，才把它作为当前证据。

仓库任意层级的以下七类标准项目级 Agent Skill 根是工具资产，不是活动项目文档：

- `.agents/skills/**`
- `.cursor/skills/**`
- `.claude/skills/**`
- `.codex/skills/**`
- `.opencode/skills/**`
- `.opencode/skill/**`
- `.github/skills/**`

其他项目级 Skill 根只接受三种精确来源：用户明确指定、适用项目规则明确声明，或本次冻结范围内已经读取的精确配置
明确声明。不得为发现自定义根而扫描配置。默认不把这些根中的 Markdown 纳入活动集合、双遍审计或覆盖矩阵；活动
文档精确声明某个 Skill 的存在、入口或职责时，只把对应 `SKILL.md` 或必要资源作为该声明的实现证据，不审计 Skill
正文。不要宽泛排除整个工具目录，也不要按文件名排除其他位置的 `SKILL.md`。

## 只有检查与保存方案

1. **检查**：新问题始终只读。即使请求中包含“修复”“同步”或 `sync`，也只完成审计、报告结论，并询问是否保存
   方案。
2. **保存方案**：只有用户看到检查结果后明确要求保存，才写入项目已有承接位置。方案保持项目要求的待确认状态，
   静态自审后立即停止。

本 Skill 没有施工、验证、归档、删除或关闭阶段。已有活动方案时默认只报告位置；只有用户明确要求且授权“仅修订
方案”时才修改方案，随后停止。普通任务按目标项目规则和确认授权接手，不需要再次调用或安装本 Skill。

方案只记录目标项目已有的授权语义，不重新定义或放宽它。验证升级、新增副作用、候选实质漂移或新的语义决定仍须
在实施时申请授权差额。没有问题时优先使用项目已有检查记录位置；没有明确承接位置时，保存前询问用户。

## 确认规则与活动真源

1. 读取目标路径适用的全部 `AGENTS.md`，遵守语言、安全、授权和生命周期规则。
2. 从当前文档入口和职责声明识别活动文档所有者；只读取足以判断所有权的内容，不用固定行数或标题截断替代理解。
3. 公开只读联网只在用户指定或冻结声明直接需要公开证据时使用；先固定声明和来源，不进行无边界浏览。
4. 不把凭据、真实用户数据、原始运行现场、profile、manifest 或持久执行账本写入仓库、方案或报告。

如果无法明确回答“本次声明由哪份活动文档拥有”，立即停止内容审计并报告：已读取的入口和职责证据、冲突或缺失、
受影响范围、需要明确的结构决定，以及建议交给骨架治理任务的目标和完成条件。不得猜测真源、创建标准路径或继续
扩大读取。

## 冻结内容范围

在读取实现证据前写明模式、内容种子、直接依赖规则、活动文件清单和排除项，并建立覆盖／残余矩阵。矩阵至少包含
审计维度、适用范围、状态、直接证据和残余；状态只使用 `已覆盖`、`无法验证`、`需要决策`、`未覆盖`、`不适用`。

### `full`

用户没有限定文件、功能或差异却要求审计项目文档时使用 `full`。从当前活动入口和职责声明形成活动文档集合，冻结后
完整处理该集合。`full` 不表示遍历全部源码、测试、CI、安全实现、历史或归档；入口不能形成完整集合时必须报告
未覆盖边界。

### `incremental`

用户明确指定文件、功能、声明、标识符或当前差异时使用 `incremental`。范围仅包括精确内容种子和一轮直接依赖：
直接提供该声明证据，或直接消费该变更并改变一致性结论的文档、代码、配置、构建或可观察行为锚点。

直接依赖只展开一轮，不递归跟随新发现。单轮后仍不能形成可靠边界时，报告证据不足并询问是否升级为 `full`，不得
静默升级或宣称全项目一致。

范围内活动文档完整读取；大型文件可稳定分块，但必须覆盖完。实现证据读到足以理解声明和直接上下文。新发现只有
直接改变冻结声明判断时才可作为本轮证据，不借机扩张新主题。

## 完成双遍审计

对 `full` 中每份活动文档、或 `incremental` 中每个内容种子及其一轮直接依赖，分别记录：

1. **事实／契约遍**：核对描述性事实、规则、契约、决定、状态与当前证据；
2. **职责／删除优先遍**：独立检查职责不清、重复真源、内容膨胀、位置不当，以及应删除、引用或收敛的内容。

某遍不适用时写明理由；未执行、证据不足或有语义取舍时留下残余。只有双遍矩阵填满，才能形成相应范围结论。

## 分类声明与证据

- 当前描述性事实：对照代码、配置、schema、构建、调用关系或可观察行为；
- 规则、契约和决定：以明确承接它们的当前文档或已确认决定为权威，再检查实现和其他文档；
- 历史记录和动态结果：按时间语境判断；当前运行状态需要实际执行证据或用户确认；
- 待办和方案状态：以活动生命周期真源及完成证据为准；
- 非穷举摘要：只有遗漏改变含义或违反文档职责时才是不一致。

证据优先级由声明类型决定。多个同等级权威来源冲突或存在真实价值取舍时，结论为 `需要决策`。为每个声明记录
文档位置、直接证据位置、结论和理由；搜索只在声明已经命名的最小根内进行，不遍历归档、历史或整个工作区来证明
不存在。

内容问题分为 `事实不一致`、`职责不清`、`内容膨胀`、`位置不当`。每项内容结论只使用 `一致`、`不一致`、
`无法验证`、`需要决策`、`未覆盖`。源码存在某个细节不等于长期文档必须记录它。

只有 `full` 的活动集合完整、所有适用项一致且没有残余时，才能报告项目活动文档内容一致；`incremental` 只能报告
受影响范围结论。

## 按条件审计测试设计

以下任一条件成立时，完整读取
[`references/test-design-audit.md`](references/test-design-audit.md)：

- 用户明确要求测试设计、测试覆盖、Registry、suite、CI 或测试安全审计；
- 冻结范围内的具体声明必须以测试、CI 或安全实现作为直接证据。

具体模式、范围、证据要求和停止条件只以该参考为准，本文件不重复。`full` 本身以及仓库中存在测试目录、Registry、
workflow 或 SAFETY 文件都不会触发测试设计审计。

若精确种子或已经冻结的直接证据暴露某项可执行断言仍强制已删除、替代或收窄的路径、入口、生命周期或文档职责，
记录“结构机械断言漂移”：列出当前结构决定、精确断言、直接影响和结构实施交接。此兜底不触发搜索其他测试、脚本
或 CI，不扩大范围，也不修改断言；证据不足或结构决定不明确时保持待决。

## 交付检查结果

`check` 在对话中依次报告：

1. 活动真源所有者及证据，或所有权不清停点；
2. 模式、冻结范围、直接依赖、排除项和覆盖／残余矩阵；
3. 按影响合并的内容问题；
4. 适用时的测试设计模式、范围与发现；
5. 结构机械断言漂移交接；
6. 一致项、无法验证、需要决策、未覆盖和未获授权操作；
7. 建议方案目标、路径、动作边界、完成条件、验证要求与最终范围和漂移复核边界。

每个发现包含声明与位置、直接证据与位置、结论、影响、推荐承接和最小动作。报告后询问是否保存方案并停止。

## 保存一份可独立实施的综合方案

方案至少写明：

- 活动真源、模式、冻结范围、直接依赖、排除项、未覆盖边界和覆盖／残余矩阵；
- 初始证据、各类内容问题、无法验证和需要决策；适用时写明测试设计模式及其参考要求的结果；
- 每项发现的影响、选项、推荐理由、用户决定和最小补证条件；
- 确定修改路径、可能修改路径、明确不修改范围、允许与禁止动作及重新冻结触发条件；
- 每个确定切片的责任与契约、精确路径或受控候选、一层修改链和直接消费者、验证义务、副作用、授权、完成条件和
  残余；未收敛候选保持待决；
- 每项列明验证的证明目标、入口或工作目录、可预见落盘或外部副作用，以及无落盘调用、受控输出或精确清理办法；
  直接证据声称验证只读而默认调用会生成缓存、报告或快照时，作为事实不一致在本方案内解决，不能留到最终复核才发现；
- 完成条件、验证要求、未运行项目、生命周期证明和关闭边界，但不写执行者、临时 Git 技巧或不必要的精确命令；
  只有副作用边界依赖调用方式时才记录必要参数；
- 目标项目授权语义及差额停止条件，只引用或实例化当前规则；
- **最终范围与漂移复核**：实施后确认最终活动入口和所有者，复核方案确定切片、已列直接消费者，以及修改路径新引入
  或改变的一跳直接链接／消费者。不得递归展开、扫描整个工作区，或重跑本 Skill 的 `full`、双遍审计、测试设计
  审计和 Registry 全局审计。发现范围外新问题时记录残余、保持方案活动，并按差额规则处理。

同一审计目标只保存一份综合方案。通过上述切片就绪条件的跨职责改动都可成为确定切片，不要求普通任务再次调用本
Skill、另起审计或按职责拆分子方案；未通过的保留为待决项或精确交接。普通任务取得实施授权后，应能仅凭目标项目
规则和该方案完成确定切片、列明验证、最终范围与漂移复核及满足条件后的生命周期关闭。

项目已有生命周期真源时只实例化任务值，不复制模板全文。缺少收尾契约时填写最小字段并形成骨架治理交接，不创建
结构入口。关联方案未完成时只报告本方案主责，不能继承授权、结论或自动关闭。

保存后静态自审证据、矩阵、切片就绪、范围、路径、授权、完成条件、验证及其可预见副作用处理、最终复核和收尾字段
是否一致，并确认普通任务无需补写方案即可执行。完成条件不冒充结果，未运行验证保持 `not_run`。随后立即停止。
