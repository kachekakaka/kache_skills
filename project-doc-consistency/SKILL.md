# 项目文档一致性建议审计

## 职责

只核对活动文档中的事实、规则、契约、决定、状态和所有者声明是否与当前直接事实一致。测试、CI、配置、schema、帮助和
源码可以是证据或消费者，但不会因此取得业务合同所有权。

本 Skill 不判断文档是否太长，也不形成删除、迁移、合并或简化动作。语义相同的重复或实现镜像可以注明“可另做收缩
检查”，但不在一致性结论中处置。

本 Skill 只读并只交付报告。即使用户同时要求同步、修复、形成方案或实施，也不写文件、不修改产品代码、不保存方案、
不登记待办、不改变生命周期、不运行测试或构建；报告后说明建议可由普通任务另行决定和实施并停止。不要调用或假定
其他 Skill 已安装，也不要检查本 Skill 的安装 provenance 作为审计前置。

## 范围与证据

1. 先读取目标路径适用的项目规则和当前文档入口。用户指定文件、主题或声明时只检查该范围；未指定时，从项目自己的
   入口和活动声明识别并完整读取全部活动文档。
2. 当前入口不足以可靠界定活动范围时，报告范围不明、已有证据和未覆盖内容；不要退化为全仓扫描，也不要自行规定标准
   文件或生命周期。
3. 对范围内文档逐份核对实质声明，不抽样。表格或清单中含义独立的值、状态、所有者、前提或例外分别判断，但不为此
   生成审计编号、覆盖矩阵或过程日志。
4. 每条声明最多展开一层直接证据：读取直接拥有、实现或消费该声明的文档、源码、配置、schema、测试或 CI 入口后停止。
   不从命中继续递归，不自动扫描全部源码、测试、workflow、历史或归档。
5. 历史材料默认只提供语境；动态状态没有实际运行证据时保持未知，不把静态存在写成已经通过。

当前权威可以唯一裁决时，直接报告一致或差额。当前权威留白或同级权威冲突时，展示冲突双方、影响和可选处理方向，
交给后续普通任务决定；不要在本次审计内持续访谈，也不要自行选择正确一方。

## 反过度治理门

建议新增规则、文档或测试前，先确认：

- 它保护的具体行为或合同是什么；
- 谁会实际消费它；
- 已发生或合理预期的失败是什么；
- 为什么现有测试或直接证据不能证明；
- 什么条件下可以删除。

任一项没有答案，只把想法标为可选建议，不建议形成长期项目资产。同一行为已有一项直接证据充分证明时，不要求 CI、
另一套 suite 或新证据格式重复证明。安全、协议、合规、架构或测试体系风险只建议对应专业审查，不扩大本次范围。

## 报告

保持简短，包含：

- 实际检查的活动文档范围和一层证据边界；
- 每个不一致的声明位置、直接事实、影响和最小建议；
- 无法裁决的冲突、可选方向及未覆盖边界；
- 若无问题，明确“在已检查范围内未发现事实不一致”。

不要输出长审计协议、评审轮次、方案候选、验证规划或实施就绪结论。建议不等于修改授权。
