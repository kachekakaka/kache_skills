# 一致性反证与跨载体扫描参考

本文只扩展 `project-doc-consistency` 的 `full` 审计方法，用来主动寻找“初审看起来一致”背后的跨载体矛盾。
它不建立新的业务权威，不做内容收缩，也不要求全仓两两比较。

## 使用条件

- `full` 审计必须完整读取本文，并在普通自然契约单元审计后完成四类扫描。
- `incremental` 只有在内容种子涉及时间状态、允许／禁止合同、聚合入口或操作粒度时读取相应小节。
- 扫描只沿已冻结文档和一轮直接证据工作；发现新的活动文档范围问题时按主 Skill 记录 `未覆盖`，不得静默扩张。

## 四类跨载体扫描

### 1. 初始状态与运行时转换

检查“启动时、初始、当前、阶段性、永久、仅在某阶段”等限定，是否与状态机、切换 API、代际、租约、恢复路径或
直接消费者的运行期转换相冲突。至少记录初始态、允许转换、失败态、终态和是否持久化。

### 2. 允许、禁止、退役合同与夹具

当当前权威已经禁止、退役或收窄依赖、字段、路径、身份或状态时，检查正向／允许夹具是否仍把它作为合法输入；同时检查
负向夹具是否仍拒绝当前已经允许的行为。测试和实现共同接受旧行为时，不能以“测试通过”证明一致。

### 3. 聚合入口与成员闭包

对 `all`、`run-all`、suite、manifest、expected、Registry 汇总或“顺序跑以上”等声明，分别列出文档宣称的成员和
实际调度／选择成员，比较遗漏、多余、顺序或条件差异。数量相同不能代替成员闭包。

### 4. 身份与操作粒度

“同一 source／lease／snapshot”不自动等于“同一请求／响应／调用”。检查普通操作与独立精确操作、可选字段与显式
查询、共享身份与独立生命周期是否被文档错误合并。必须点名实际调用边界和直接消费者。

## 正式证据

每类扫描都在一个或多个正式 `Axxx` 中记录：

1. 被挑战的具体声明和路径锚点；
2. 当前权威与初审正向证据；
3. 不同角色的相反证据或邻接消费者；
4. 结论、发现或明确残余。

没有适用候选时，也要写明检查过的限定词／聚合入口／夹具／操作边界和“不适用”的具体理由；“已搜索、未发现问题”
或文件数量对账不能算完成。

## 第一轮反证式查漏

进入第一轮时，对每份文档级 `一致` 结论独立记录：

- 可证伪主张；
- 初审正向证据；
- 与正向证据不同角色的相反证据或邻接消费者；
- `改变`／`未改变`；
- 反证为何推翻或未推翻原结论。

只有主张、证据角色和结论完全相同，才可显式分组；即使分组，每条路径仍要独立命名并给出锚点。
`N/N 不变`、`同前`、`原证据仍成立` 或按职责类别列名单都不能替代上述记录。

## 第二轮防语义误改

每项拟议修正必须分别回答：产品语义、权限／安全边界、测试选择／分类／覆盖义务、运行行为、历史决定和一层直接消费者
是否改变，并给出 `通过`、`修改` 或 `撤销`。一段综合说明不能代替逐轴结论。

## 失败关闭

任一四类扫描缺少正式记录、第一轮缺少不同角色反证、第二轮缺少逐轴结论，或正式记录在保存前已无法从当前线程或经
用户授权的仓库外轨迹中取得时，完整性门失败；只能报告 `未覆盖`，不得询问保存完整方案。
