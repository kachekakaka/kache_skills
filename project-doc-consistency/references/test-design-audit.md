# 测试契约一致性参考

本文只扩展 `project-doc-consistency` 已冻结的声明范围，用来核对测试治理和可执行证据是否仍忠实消费当前契约。
它不评价测试数量是否足够，不做覆盖率、重复测试经济性或测试资产内容收缩，也不形成删除、合并或精简测试的动作。

## 触发条件

只有以下情况才读取本文：

- 用户明确要求核对 Registry、manifest、suite、CTest／等价注册、CI 或测试安全声明的一致性；
- 某项已冻结产品或治理契约，必须检查测试义务、选择、核心断言或安全实现才能裁决。

`full`、测试文档进入活动集合，以及仓库中存在测试目录、workflow 或 SAFETY 文件都不会自动触发本文。

## 审计模式

触发后选择且只选择一种模式。

### 声明绑定模式

围绕精确文档声明或测试身份建立有界证据链：

```text
当前权威契约
→ 当前实现／配置
→ 被声明的测试义务
→ Registry／manifest／suite／选择器
→ 实际入口和一处核心断言
→ 直接相关的 CI 或安全调用方
```

只读取能够回答当前声明的节点和一轮直接依赖。缺少锚点时使用 `无法核验`，不得递归扫描其他测试寻找替代证据。

### Registry 全局一致性模式

只有用户明确要求核对全部 Registry、suite 身份或正式选择清单时使用。先从当前测试入口冻结精确活动身份集合、
expected／正式清单、分组依据和排除项；入口不能形成完整集合时停止并报告所有权不清，不用目录遍历猜 Registry。

对每个活动身份记录：当前权威义务、Registry 声明、执行类别、入口、实际注册、正式选择范围和一处核心断言。只比较
身份缺失、多余、重复登记、分类、入口、声明、选择范围和断言是否与当前契约一致；不根据测试之间相似度建议删除或合并。

## 身份与所有权

分别核对：

1. 业务或治理权威及其拥有的契约；
2. Registry 或等价活动身份集合；
3. manifest、expected、Release 或正式选择清单；
4. 实际注册的 CTest、target、workflow job 或等价入口；
5. suite 文档声明的触发、输入、边界和直接命令；
6. 核心断言实际约束的行为或结构；
7. 当前协议版本和直接消费者。

不得从“仍在 Registry”“存在 target／CTest”“出现在 expected 清单”反向推导业务契约、实现存在、普通活动身份或
正式认证身份。测试和实现共同接受权威契约禁止的行为时，报告“实现与测试共同偏离契约”。

## 声明、入口与断言

对精确测试项检查：

- 声称的义务是否来自当前权威契约；
- 执行类别、触发和副作用是否与项目协议一致；
- 文档入口、实际命令和注册身份是否指向同一测试；
- manifest／expected／正式清单是否遗漏、多记或错误选择该身份；
- 核心断言是否真正验证所声明的值、前提、例外、失败关闭或结构边界；
- 失败信息和结果语义是否与实际断言一致；
- 已经删除、替代或收窄的旧行为、路径、生命周期或职责是否仍被强制。

结论只使用：`一致`、`身份漂移`、`声明错位`、`结构机械断言漂移`、`实现与测试共同偏离契约`、`无法核验` 或
`需要决策`。这些结论进入纯一致性方案时只能修正声明、身份、分类、入口、选择或断言与当前契约的偏差；不能以
“重复”“成本过高”或“测试太多”为由删除测试。

## 合成夹具和状态转换

精确入口使用合成账号、配置、路径、协议载荷或持久结构时，检查：

- 在目标失败点之前满足当前语法、必填字段和最低输入合同；
- 输入保持虚构、离线，不读取真实用户数据或凭据；
- 故障注入实际到达目标阶段，而不是被更早预检截断；
- 产品会加载、迁移或重建的持久结构使用当前权威 schema／构造入口，或明确固定旧版本及预期迁移、重建或失败结果。

场景存在中间态、未就绪态或最终一致状态时，确认正式转换和可观察就绪条件；故意不转换时明确预期失败关闭。不得用任意
固定等待掩盖未知转换。

## 源码文字提取证据

通过正则、字符串切片或源码搜索证明结构时，提取器必须唯一定位预期实现。零匹配、多次歧义、只命中声明、范围未闭合
或选中错误实现时失败关闭。能使用项目现有解析器且成本合适时优先使用；手写提取器只检查当前语言和目标结构实际存在的
风险，不把某种语法硬编码成跨语言规则。

## CI、安全、GUI 与真实输入

只有冻结声明精确涉及这些调用方时，才检查一份直接 CI、helper 或 GUI／真实输入入口：

- 实际触发器、路径过滤和默认输入是否符合执行类别；
- 认证、上传、费用、真实数据、破坏性动作或外部写入是否被错误默认触发；
- 输出根、所有权、containment、保留、清理和进程停止是否与声明一致；
- GUI 场景的启动、readiness、当前可用退出和外部安全界面阻断是否被准确描述。

不遍历全部 workflow 或安全脚本，不选择新的自动化框架，不点击、绕过或关闭系统安全提示，也不宣称全项目测试或安全
已经认证。

## 静态结论与交接

静态读取可以证明身份、入口、选择、断言形态和声明冲突；故障捕获能力、flaky、性能成本和恢复效果通常需要运行。
未获授权时保持 `无法核验`，对应验证为 `not_run`。

每项发现记录当前权威、错误声明／身份／入口／断言、直接影响、纯一致性修正和最小验证。测试内容去重、矩阵缩减、命令
摘要化或文档删除不在本参考职责内，只能作为 `后续收缩候选` 交给显式的内容收缩任务。
