# 测试设计一致性审计

## 1. 守住范围

审计测试治理和设计是否与当前权威契约、实现风险及文档声明一致。静态审计不能冒充测试有效性认证，也不
修改、创建或删除可执行测试代码。

仅在 `full` 内容审计、用户明确要求测试审计，或当前范围涉及测试、Registry、suite、CI、安全触发和测试脚本时使用本文。

## 2. 冻结测试锚点并建立权威证据链

只为主 Skill C 阶段已经冻结的声明组建立测试链。不得把 Registry 的全部行、suite 目录或 workflow 目录另行
展开为新声明组。每组依次冻结：

1. 冻结活动文档中直接承担该义务的需求、设计或字段契约；ADR 只有被该契约明确声明为当前约束时才读取。
2. 使用契约写出的精确路径/标识符，或在已命名的最小当前源码/配置根中做一次只返回文件路径的精确标识符
   搜索，选定最多一份当前实现/配置锚点；不得把 archive/history 或仓库根交给搜索。
3. 从当前测试索引选定稳定 Registry/选择器中对应的一项，或一组已经精确命名的重复/过度候选对。
4. 只读取该测试项或候选对直接链接的 suite README 或稳定入口。
5. 只读取 suite 精确命名的测试入口、规范命令和一处核心断言。suite 没有给出可定位入口时，报告
   `声明错位` 或 `无法验证`，不得递归扫描测试目录猜测实现。
6. 只读取 Registry/选择器为该项精确命名的 CI 调用方、默认参数和路径过滤。
7. 安全范围只读取 SAFETY/协作规则，以及由 SAFETY、suite 或选择器直接链接的一份中央输出、进程或清理 helper。

缺少任一锚点时在该处停止链路并作出结论。只有两份已冻结锚点直接冲突时，才允许增加一份由冲突内容精确
链接的来源；不得枚举全部实现、测试、workflow、ADR 或发布入口寻找替代证据。

Registry/选择器只能整体读取一次，用于查找冻结契约精确引用的测试项，或比较其文本中已经显露相同稳定命令、
输入和 CI 调用的候选对。没有在这一遍形成候选，就报告本次未覆盖总体重复/过度判断；不得逐行打开 suite
README 来制造候选。任何只声明目录而未直接链接索引文件的测试入口都按范围证据不足处理，不列举目录。

形成以下链路：

```text
权威需求/设计契约
→ 一份当前实现/配置锚点
→ 测试义务
→ Registry 或等价选择机制
→ suite、精确测试入口与核心断言
→ CI 调用方和一份安全 helper
```

不要求每个实现分支都有文档或独立测试。只有当前契约、可观察行为、重要不变量、风险边界或明确覆盖声明
形成测试义务时，才把缺失列为问题。

## 3. 权威契约优先于现状自证

测试通过不能反向证明当前实现正确。存在明确权威契约时：

- 实现偏离契约，报告实现侧不一致；
- 测试断言偏离契约，报告测试声明错位；
- 实现和测试共同固化错误行为，报告“实现与测试共同偏离契约”，并识别应有断言是否形成覆盖缺口；
- 只有行为已由权威来源明确移除、替代或不再支持，原测试才可判为失效测试。

不得因为代码和测试互相一致，就把相反的需求或设计文档简单认定为过时。多个同等级权威来源冲突或优先级
未定义时使用“需要决策”。

## 4. 判断测试项的独立价值

先比较 Registry/选择器中稳定命令、输入、执行环境和 CI 调用。只有这些锚点形成了精确候选对，才读取候选对
各自已经命名的测试入口，并记录：

- 测试义务：证明哪个契约、不变量或风险；
- 测试层级：单元、集成、端到端、人工或正式认证；
- 运行边界：是否跨模块、进程、数据库、容器、网络、设备或真实服务；
- 故障信号：失败时独立暴露或定位什么问题；
- 核心断言：代码实际检查什么，而不是名称或注释声称什么；
- 成本与触发：运行环境、耗时、副作用、执行类别和触发范围。

多个层级覆盖同一业务行为不自动重复。单元证明局部逻辑、集成证明边界、端到端证明交付路径时，是有意重叠。
只有上述维度基本相同、后一项没有新增独有证据时，才是冗余候选。

不得通过阅读全部测试来证明“没有其他重复”或“没有过度测试”。冻结范围没有形成精确候选对时，只汇总已
比较的选择项；不能作整套测试无重复、无过度的结论。

## 5. 使用测试发现子类型

- `覆盖缺口`：存在明确测试义务，但没有可信测试或核心断言；
- `声明错位`：选择清单、suite、CI 或文档声称的覆盖与实际命令、实现或断言不符；
- `有意重叠`：覆盖相同能力，但层级、边界、故障信号或证据价值不同；
- `冗余候选`：义务、层级、边界、断言与触发基本相同，没有新增独有价值；
- `过度候选`：矩阵、环境或触发范围超出支持契约，成本明显增加且没有风险依据；
- `失效测试`：只验证已明确移除、替代或不再支持的当前行为。

这些子类型附着在主 Skill 的五种内容结论下。没有直接证据时使用“无法验证”或“需要决策”，不能用“候选”
措辞暗示已经证明应当删除。

## 6. 审计 CI 选择和路径过滤

只比较冻结测试项由 Registry、suite 或当前选择器精确命名的 CI 调用方；不得逐个遍历仓库中的 workflow、
计划任务和发布入口。对冻结调用方检查：

- push、PR、schedule、workflow_dispatch 及其他触发器实际纳入哪些测试；
- 默认输入是否会把受限或高成本测试从 opt-in 变成自动执行；
- `paths`、`paths-ignore` 或等价过滤是否覆盖会改变测试输入和交付结果的文件；
- Dockerfile、容器编排、依赖锁文件、构建脚本、运行脚本、字段契约、suite 文档和 fixture 改动是否漏触发；
- 文档、静态规则或局部逻辑变更是否无条件触发昂贵 E2E、联网、破坏性或真实数据测试；
- 多个 CI 步骤是否在相同环境和候选上重复执行同一规范命令。

路径过滤没有列出某文件不自动构成漏触发；必须先由契约、Registry、suite 或规范入口证明该文件类别是测试
或交付结果的真实输入。单轮直接依赖仍无法建立闭包时报告范围证据不足，不扩大到其他 workflow。

## 7. 审计安全声明与实际实现

把冻结的 SAFETY/协作规则逐项对照已选 CI 调用方、命令默认值和一份中央 helper：

1. `explicit`、真实数据、真实账号、联网费用和破坏性测试不得被 push、PR、schedule 或默认参数意外触发；
2. 只允许管理当前任务创建并记录所有权的产品进程，不能按名称批量结束；
3. 输出解析后必须位于声明的测试根和本次直接 run，符号链接、junction、reparse point 和路径逃逸失败关闭；
4. 测试根和 run 使用可验证的 owner marker 或等价所有权证明；
5. 默认保留、自动清理和人工删除行为必须与文档一致；删除必须重新验证所有权和 containment；
6. 日志、fixture、摘要和归档不得包含凭据、真实用户数据或原始运行现场。

只有安全声明而没有默认触发或中央 helper 接线证据时使用“无法验证”或治理属性“证据不足”，不能判安全
等价，也不能继续搜索其他脚本补证。

## 8. 识别过度而不误判

重点检查：

- 相同命令、环境和候选是否由多个测试项或 CI 步骤重复执行；
- 兼容矩阵是否包含项目未支持、未交付或没有契约依据的版本和平台；
- 完整、受影响和显式执行语义是否与成本、副作用及真实触发需要相符；
- 大而全测试项是否掩盖不同依赖、失败语义或影响域，妨碍最小验证选择。

受支持运行时矩阵、不同交付环境和安全关键路径的防御性重复不自动算过度。缺少耗时、失败定位、触发频率、
维护成本或独有风险证据时，只报告需要补充的证据。

过度判断只覆盖冻结的选择项和精确候选对；不得为证明总体测试经济性而展开全部测试矩阵或源码。

## 9. 静态审计与动态验证

静态读取可以证明入口、映射、断言形态、重复命令和声明冲突。是否真的捕获缺陷、是否 flaky、性能成本和
故障恢复通常需要运行、故障注入、mutation testing 或历史数据；未获命令或数据授权时使用“无法验证”。

运行授权不包含修改测试。补充、删除、合并、拆分或重构测试代码属于独立实现任务，必须另行形成方案和授权。

## 10. 报告与同步

每个测试发现报告：测试义务、权威契约、选择清单/suite 声明、实际实现/断言/CI 证据、六维比较、主结论、
子类型、影响和建议动作。一致项只汇总映射覆盖范围。

`sync` 只能在现有长期文档、待办和满足主 Skill 受限规则的 Registry 中修订可证明事实。缺少 suite、需要调整
测试代码、改变测试层级或涉及成本取舍时，输出精确实现或结构交接，不自行实施。
