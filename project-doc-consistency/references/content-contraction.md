# 内容收缩审计

本参考承接职责／删除优先遍的详细方法。活动路径、事实／契约证据规则、报告／方案分流、保存停点和动作授权以主
`SKILL.md` 为准。

## 自然审计单元

内容覆盖图必须覆盖每份长期文档的全部实质正文，但不建立固定逐段、逐行或项目级持久账本。为支持一次用户任务内的
长审计，可以维护当前任务的紧凑续跑清单，并把详细证据交付为编号报告分片；二者都不得变成目标项目的长期运行资产。

- 只有正文整体由同一角色、所有者和契约承接，且没有两个及以上稳定一级职责章节时，才可只有一个覆盖全部正文的单元。
- 有两个及以上稳定一级职责章节（通常是文档标题下的 `##`）时，每个一级职责章节至少一个单元，不得跨一级职责章节合并。
- 同一一级章节内若角色、所有者或契约发生变化，继续拆分；只有相邻内容已经分别检查且三者和处置均相同，才可合并；
  合并后仍列出全部锚点。
- 没有稳定标题时，在角色、所有者或契约发生变化的位置分单元。
- 内容较多时，在完整文档边界组成连续批次；单个文档较大时，只在自然单元边界拆成同一文档的连续子分片。每个分片
  交付后在同一任务内自动继续，不得因预计上下文或输出不足把剩余内容标为 `未覆盖` 或要求用户另发“继续”。

每个单元在某个编号报告分片或最终报告中记录：

1. 具体声明或当前职责；
2. 当前所有者，以及命名的直接证据、直接消费者或明确残余；
3. 事实／契约结论与理由或残余；
4. 收缩风险与最小处置，或保留的具体依据。

下面这些表述可以作摘要，但单独出现时均为无效证据：

- “源码、配置和测试静态吻合”；
- “职责清楚”或“属于核心真源”；
- “已完整读取”；
- “删除会损失能力”但未说明损失什么；
- 只列大段章节范围后给出统一结论。

## 分片续跑与完整性

编号报告分片是完整审计报告的一部分，不是临时进度摘要。每个分片至少记录分片编号、精确路径、自然单元锚点、四项证据、
文档级处置是否已经完成，以及新增或改变的发现与残余。

当前任务只需在活跃上下文保留紧凑续跑清单：冻结路径、已交付分片、已完成路径及处置、有效发现、残余和下一批路径。
接近上下文边界时可以压缩会话状态；恢复后先核对冻结路径与续跑清单，再从下一未完成文档继续。已经交付的详细证据不必
重复塞回活跃上下文，但评审时仍须按主 Skill 重新查看相应原始正文和报告分片。

一个文档可以跨多个连续子分片，但只有全部自然单元完成后才能给出文档级 `需要收缩`、`无需收缩`、`无法核验`、
`需要决策` 或 `未覆盖`。预计篇幅不是 `未覆盖` 理由；只有源文件或直接证据实际不可读取、所有权无法裁决、证据仍不足，
或宿主实际中断任务时，才形成相应残余。

最终总索引必须列出每个分片覆盖的路径、文档处置和发现标识，并证明冻结路径无缺口、无重复完成、无跳号续跑。最终回复
不必复制全部自然单元证据，但不能用最终摘要替代已经要求交付的编号分片。

## 按角色检查内容

对每个自然单元检查：

- 同一当前事实、规则、决定或状态被完整重复，形成竞争真源；
- 所有者与直接消费者对值、前提、例外、生命周期或适用范围的表述不同并改变含义；
- 逐段复制源码、配置、schema、测试实现或构建细节，使长期文档成为实现镜像；
- 一次性设计讨论、施工步骤、排障过程、迁移轨迹或评审对话继续留在活动真源；
- 带日期的运行结果、快照、阶段证据或已经完成／失效的历史结论冒充当前状态；
- 需求、设计、测试、运维、待办或方案内容由错误所有者承接；
- 导航摘要扩写成另一份正文，或默认入口复制直接链接目标的细节；
- 重复限定、嵌套说明、模糊指代、未定义术语或混合职责造成理解困难、歧义或声明漂移。

措辞不同但含义、前提、例外和消费者义务相同不算漂移。复杂度不按篇幅处罚；只有它造成重复、职责负担、理解困难、
歧义或契约漂移时才形成发现。源码存在细节不等于长期文档必须记录它。

只对职责、链接、引用或正文复述已经表明直接相关的所有者与消费者进行对照，不做全部活动文档的两两比较。

## 删除优先的最小处置

按以下顺序选择处置：

1. 删除已经失效、重复、一次性或不再承担当前契约的内容；
2. 内容需要可达但不应重复时，只保留职责明确的短摘要和唯一所有者链接；
3. 内容仍有长期价值但所有者错误时，迁移到唯一所有者并删除原位置竞争正文；
4. 必要合同表达重复、含混或过度复杂时，在不改变值、前提、例外和义务的条件下合并或简化；
5. 只有当前职责需要、没有等价真源且删除会损害用户合同或实施闭环时，才有证据保留；
6. 所有权冲突或真实语义取舍无法裁决时保持待决，不用搬迁掩盖冲突。

加目录、拆文件、换文件名或把正文搬到另一活动文档本身不构成收缩。处置必须说明退出或澄清了哪些重复、漂移、镜像、
过程、快照、复杂表达或错误所有权。

## 证明无需收缩

判为 `无需收缩` 时，文档记录必须承接全部自然单元，且任何单元都没有未解除残余，并说明：

- 文档角色、允许内容和相关事实的唯一所有者；
- 每个单元的直接证据或消费者；
- 重复、漂移、镜像、过程／历史、错位和表达风险为何没有命中；
- 当前细节为何属于用户可观察契约、实现结构闭环、稳定测试职责或必要操作合同；
- 删除、迁移、只留链接或简化会损失的具体当前能力。

“文档都重要”“职责就是承接这些内容”“已经分文件”“暂时不长”或“以后可能需要”不是充分依据。证据不足时使用
`无法核验`、`需要决策` 或 `未覆盖`，不要默认通过。

## 分开两种足迹

分别报告：

- **活动真源总内容足迹**：全部活动真源中需要长期维护的唯一正文总量；只有删除重复、实现镜像、过程、快照或错位
  正文，才证明这一足迹下降；
- **默认入口加载量**：从默认入口理解项目时首先需要读取的内容；路由、短摘要和按需 reference 可以降低这一负担，
  但不能证明总内容足迹已经下降。

不要把第二种收益描述成第一种，也不要为了追求总量删除唯一且必要的当前契约。

## 复核收缩候选

### 查漏轮

进入评审时固定全部 `无需收缩` 文档为复核集合，但不冻结其结论。逐份回看原始正文和原报告证据，每份记录：

- 路径；
- `改变` 或 `未改变`；
- 本轮复核的自然单元锚点和至少一个命名原始证据；
- 改变后的发现与处置，或未改变的具体理由。

记录较多时可以按完整文档边界形成编号查漏分片，并在同一任务内自动续跑。只列新增发现、只补已有发现的路径、只报告
文档／发现数量，或因预计输出不足提前结束，都不能证明查漏完成。评审不得新增活动文档路径，但可以在冻结路径内新增、
删除、拆分、合并或改变发现。

### 防误伤轮

对当前候选中的每一项删除、迁移、摘要加链接、合并和简化动作建立动作记录，包括查漏轮后的变化：

- 动作和目标内容；
- 保留唯一事实的位置；
- 直接消费者仍保留的必要义务；
- 是否产生新的漂移或职责缺口；
- `通过`、`修改` 或 `撤销`。

动作较多时可以按完整动作边界形成编号防误伤分片并自动续跑。没有动作的文档不需要进入防误伤清单，但第一轮改变后新增
的所有动作必须进入。

任一轮发现遗漏、依据不足或误伤时，先修订候选并重做受影响记录；修订前结论不计数。发现清单、残余和候选的一一归宿
只能防止已有发现丢失，不能证明没有漏项，不作为两轮通过的摘要证据。

## 收缩完成条件

收缩完成至少证明：

- 每份长期文档的全部自然单元都有四项证据；
- 全部编号报告分片与最终索引覆盖冻结路径且续跑无缺口；
- 每类当前事实、规则、决定和状态有明确所有者；
- 直接消费者只保留职责所需摘要、链接和特定义务；
- 一次性过程、动态快照和历史结果退出活动真源；
- 必要入口仍能到达唯一所有者；
- 总内容足迹和默认入口加载量分别陈述；
- 适用的查漏与防误伤分片完整且不存在未修正失败。

不得使用统一行数、字数、页数、缩减百分比或集合数量作为跨项目完成门槛。
