# 内容收缩审计

本参考承接职责／删除优先遍和逐文档内容覆盖图的详细方法；覆盖图只记录事实／契约遍的既有结论，不改写其证据规则。
活动路径集合、双遍完整性门、报告／方案分流、保存停点和动作授权仍以主 `SKILL.md` 为准。

## 覆盖全部实质内容

对每份长期文档，在形成文档级结论前建立仅用于当前调用的内容覆盖图，纳入全部实质性标题内容和有意义的无标题正文。
可以使用标题、稳定内容锚点或分块范围标识；较长文件可以稳定分块。只有相邻内容已经分别检查且职责、所有者和处置相同
时，才可合并说明。不得抽样，也不得用“主要职责”“主要章节”“代表性片段”或文件级概括代表余下正文。

内容覆盖图必须进入对话报告；方案路线还须把最终有效覆盖依据带入候选。每个内容组记录角色和所有者、事实／契约结论与
证据或残余、职责／删除优先风险，以及保留或收缩归宿。每份长期文档保留独立命名条目；只允许在同一文档内紧凑合并已
分别检查且结论相同的相邻内容组，不隐藏稳定锚点，不跨文档合并处置，也不建立固定逐标题、逐段落或逐行的持久账本。
任一实质内容组没有双遍结果或缺少可见条目时，该文档为 `未覆盖`，不能形成 `一致` 或 `无需收缩` 结论。

## 逐文档输出合同

对每份适用活动文档记录：

1. 文档当前角色和它应当承接的事实类别；
2. 所检查事实的唯一当前所有者，以及该文档是所有者、摘要入口还是直接消费者；
3. 内容覆盖图所含全部实质内容组的稳定锚点及其双遍结论、直接证据或残余；
4. 每项命中的删除、引用、迁移、合并、简化、有证据保留或待决归宿；
5. 没有命中时，针对全部实质内容和适用风险的文档特定保留依据、唯一所有者、消费者义务，以及删除、迁移、只留链接或简化会损失的当前能力；
6. `需要收缩`、`无需收缩`、`无法核验`、`需要决策` 或 `未覆盖` 之一的文档级处置。

“其余 N 份无需收缩”“核心真源天然无需收缩”“已完整读取所以无需收缩”均为无效结论。内容正确、文档较短、已经拆分、
带有目录、职责名称看似匹配或以后可能有用，也不能单独证明任一遍通过。

## 按角色检查内容

先从活动入口和职责声明确认文档角色，再对每个实质内容组检查：

- 同一当前事实、规则、决定或状态在多个活动文档中被完整重复，形成竞争真源；
- 所有者与直接消费者对同一声明的措辞、值、前提、例外、生命周期或适用范围不同，已经改变含义或造成声明漂移；
- 逐段复制源码、配置、schema、测试实现或构建细节，使长期文档成为实现镜像；
- 一次性设计讨论、施工步骤、排障过程、迁移轨迹或评审对话继续留在活动真源；
- 带日期的运行结果、快照、阶段证据或已经完成／失效的历史结论仍冒充当前状态；
- 需求、设计、测试、运维、待办或方案内容由错误的长期所有者承接；
- 为导航所需的简短摘要扩写成另一份正文，或默认入口复制其直接链接目标的细节；
- 重复限定、嵌套说明、模糊指代、未定义术语或混合职责使合同更难理解、不够精准或产生歧义。

非穷举摘要只有在遗漏改变含义或违反职责时才形成问题；措辞不同但含义和消费者义务相同不算漂移。复杂度也不按篇幅
处罚，只有它造成重复、职责负担、理解困难、歧义或契约漂移时才形成发现；不要因为源码存在细节就要求长期文档记录它。

只对已有职责、链接、引用或正文复述证据表明直接相关的所有者与消费者进行对照，不做全部活动文档的两两比较。处置
重复、漂移、复杂或错位内容时，保留所有者的唯一事实、消费者履行自身职责所需的特定义务和必要短摘要。

## 使用删除优先的处置顺序

按以下顺序选择最小处置：

1. 删除已经失效、重复、一次性或不再承担当前契约的内容；
2. 需要可达但不应重复时，保留一句职责明确的摘要并链接唯一所有者；
3. 当前内容仍有长期价值但所有者错误时，收敛到唯一所有者，并删除原位置的竞争正文；
4. 内容承担必要合同但表达重复、含混或过度复杂时，在不改变值、前提、例外和义务的条件下合并或简化；
5. 只有当前职责确实需要、没有等价真源且删除会损害用户可观察契约或实施闭环时，才有证据保留；
6. 所有权冲突或真实语义取舍无法裁决时保持待决，记录最小补证或用户决定，不用搬迁掩盖冲突。

加目录、拆文件、换文件名或把正文搬到另一个活动文档本身不构成内容收缩。处置必须说明退出或澄清了哪些重复、漂移、
镜像、过程、快照、复杂表达或错误所有权。

## 分开两种足迹

分别报告：

- **活动真源总内容足迹**：全部活动真源中需要长期维护和加载的唯一正文总量；只有删除重复、实现镜像、过程、快照或
  错位正文，才证明这一足迹收缩；
- **默认入口加载量**：用户或代理从默认入口理解当前项目时首先需要读取的内容；路由、短摘要和按需 reference 可以
  降低这一负担，但不能证明总内容足迹已经下降。

不要把第二种收益描述成第一种，也不要为了追求总量而删除唯一且必要的当前契约。

## 证明无需收缩

判为无需收缩时，至少绑定当前文档记录：全部实质内容组已完成双遍检查；角色、允许内容和相关事实的唯一所有者；上述
风险逐项没有命中的文档特定依据；当前细节为何属于用户可观察契约、实现结构闭环、稳定测试职责或必要操作合同；删除、
迁移、仅保留链接或简化会损失什么当前能力。

通用的“模型完整”“文档都重要”“职责就是承接这些内容”“已经分文件”“暂时不长”或“以后可能需要”不是充分依据。
证据无法支持负向证明时，使用 `无法核验`、`需要决策` 或 `未覆盖`，不要默认通过。

## 复核收缩候选

- 用户只选择一轮 review 时，同一轮同时查漏和防误伤；选择两轮及以上时，第一轮先查漏，第二轮再防误伤，后续轮次复核前轮修订影响。
- 查漏轮逐份回看全部 `无需收缩` 文档的可见条目和原始证据，检查低显著度内容、重复、声明漂移、职责错位、复杂或
  不精准表达是否漏报；最终交付至少列明本轮改变的处置，以及未改变处置由哪些逐文档条目支撑。路径、发现或集合数量
  对账无效，不能只给已有发现补路径或落点。
- 防误伤轮逐项复核全部删除、迁移、摘要加链接、合并和简化动作，包括查漏轮后新增、删除或改变的动作；确认唯一事实、
  用户合同、决定、字段约束、消费者特定义务、测试职责和操作闭环仍被明确保留，并检查是否产生新的漂移或职责缺口。
- 任一轮发现条目缺失、依据不足或处置错误时，该轮结论作废；先修订候选并重做受影响复核才可计数。最终报告和候选只
  保留当前有效的逐文档证据、处置变化和 review 结论，不保存逐轮推理日志。

每轮还必须完成主 `SKILL.md` 规定的证据、矩阵、切片、路径、验证、副作用、授权、完成条件和生命周期检查。

## 收缩完成条件

收缩切片至少证明：每份长期文档的全部实质内容均已完成双遍检查；每类当前事实、规则、决定和状态只有一个明确所有者；直接消费者只保留职责所需摘要、链接和特定义务；一次性过程、动态快照和历史结果退出活动真源；必要入口仍能到达唯一所有者；总内容足迹和默认入口加载量分别陈述；收缩候选完成适用的查漏与防误伤 review。不得使用统一行数、字数、页数或收缩百分比作为跨项目门槛。
