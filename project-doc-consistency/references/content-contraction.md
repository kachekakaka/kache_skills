# 内容收缩审计

本参考只承接职责／删除优先遍的详细方法。活动路径集合、双遍完整性门、报告／方案分流、保存停点和动作授权仍以
主 `SKILL.md` 为准。

## 逐文档输出合同

对每份适用活动文档记录：

1. 文档当前角色和它应当承接的事实类别；
2. 所检查事实的唯一当前所有者，以及该文档是所有者、摘要入口还是直接消费者；
3. 本遍实际检查到的风险类别和直接位置；
4. 每项命中的删除、引用、收敛、有证据保留或待决归宿；
5. 没有命中时的文档特定保留依据，或者证据不足残余。

内容正确、文档较短、已经拆分、带有目录或以后可能有用，都不能单独证明职责／删除优先遍通过。

## 按角色检查内容

先从活动入口和职责声明确认文档角色，再检查以下内容是否超出该角色：

- 同一当前事实、规则、决定或状态在多个活动文档中被完整重复，形成竞争真源；
- 逐段复制源码、配置、schema、测试实现或构建细节，使长期文档成为实现镜像；
- 一次性设计讨论、施工步骤、排障过程、迁移轨迹或评审对话继续留在活动真源；
- 带日期的运行结果、快照、阶段证据或已经完成／失效的历史结论仍冒充当前状态；
- 需求、设计、测试、运维、待办或方案内容由错误的长期所有者承接；
- 为导航所需的简短摘要扩写成另一份正文，或默认入口复制其直接链接目标的细节。

非穷举摘要只在遗漏改变含义或违反职责时形成问题。不要因为源码存在细节，就要求长期文档同步记录该细节。

## 使用删除优先的处置顺序

按以下顺序选择最小处置：

1. 删除已经失效、重复、一次性或不再承担当前契约的内容；
2. 需要可达但不应重复时，保留一句职责明确的摘要并链接唯一所有者；
3. 当前内容仍有长期价值但所有者错误时，收敛到唯一所有者，并删除原位置的竞争正文；
4. 只有当前职责确实需要、没有等价真源且删除会损害用户可观察契约或实施闭环时，才有证据保留；
5. 所有权冲突或真实语义取舍无法裁决时保持待决，记录最小补证或用户决定，不用搬迁掩盖冲突。

加目录、拆文件、换文件名或把正文搬到另一个活动文档本身不构成内容收缩。处置必须说明退出了哪些重复、镜像、过程、
快照或错误所有权。

## 分开两种足迹

分别报告：

- **活动真源总内容足迹**：全部活动真源中需要长期维护和加载的唯一正文总量；只有删除重复、实现镜像、过程、快照或
  错位正文，才证明这一足迹收缩；
- **默认入口加载量**：用户或代理从默认入口理解当前项目时首先需要读取的内容；路由、短摘要和按需 reference 可以
  降低这一负担，但不能证明总内容足迹已经下降。

不要把第二种收益描述成第一种，也不要为了追求总量而删除唯一且必要的当前契约。

## 证明无需收缩

判为无需收缩时，至少绑定当前文档记录：

- 角色与允许承接的内容类别；
- 已检查的上述风险类别；
- 相关事实的唯一所有者；
- 当前细节为何是用户可观察契约、实现结构闭环、稳定测试职责或必要操作合同的一部分；
- 删除或仅保留链接会损失什么当前能力。

通用的“模型完整”“文档都重要”“已经分文件”“暂时不长”或“以后可能需要”不是充分依据。证据无法支持保留时，
结论使用 `无法验证`、`需要决策` 或 `未覆盖`，不要默认通过。

## 收缩完成条件

收缩切片至少证明：

- 每类当前事实、规则、决定和状态只有一个明确所有者；
- 直接消费者只保留其职责所需的摘要和链接，不复制竞争正文；
- 一次性过程、动态快照和历史结果退出活动真源并进入项目已有承接位置，或在无需保留时删除；
- 必要入口仍能通过直接链接到达唯一所有者；
- 总内容足迹和默认入口加载量的变化分别陈述，没有使用统一行数、字数、页数或收缩百分比作为跨项目门槛。
