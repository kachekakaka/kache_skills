## 1. 适用条件与边界

综合方案包含动态验证、分阶段或昂贵验证、实施期消费者漂移、产品／GUI／外部环境前提、证据复用或技术／认证终态
任一项时读取本文。本文只规定静态方案如何让普通任务安全实施和验证；`project-doc-consistency` 自身仍不运行测试、
产品、门禁或外部操作。

按目标项目自己的验证层级、Registry 等价物和授权规则实例化。不要引入持久执行 manifest、逐次失败日志、固定状态机
或 F2 专用字段，也不要把“测试失败”写成可以修改任意文件的开放授权。

## 2. 分流实施期漂移与新问题

普通任务实施和验证时，把后来事实分为：

- **原范围消费者漂移**：旧测试、夹具、选择器、文档或生命周期声明直接消费方案已经确定的不变量，且当前权威唯一
  裁决正确结果。普通任务可以在原切片及一层直接依赖内做最小修复，记录直接证据、修改范围和重验义务；
- **临时环境阻断**：源码和断言没有被证明错误，环境、工具或外部输入暂时使验证无法进入可判定阶段。安全保留现场
  证据、恢复条件和当前状态，不把它改写成内容发现；
- **新的范围问题**：不能由原权威和已列一跳消费者唯一裁决，或需要新产品语义、新权限、新副作用或确定路径外修改。
  保持方案活动并申请最小决定或授权差额。

只有阻断当前目标、出现新语义或需要新权限时立即询问用户。普通任务自行修复方案范围内唯一可裁决的问题，并自行
处理不会改变语义或副作用的短暂环境问题。与当前完成不相干的独立非阻断问题先去重，收尾前只统一询问一次是否登记
到目标项目已有的已知问题／待办位置；用户不选择登记时不写入。

不得把实施期漂移并回静态发现集合假装已在候选阶段评审，也不因一个消费者漂移重跑完整内容审计。最终归档方案只
总结已经形成结论、实际修改并完成相应重验的漂移，不保存逐次尝试日志或原始运行现场。

## 3. 声明输入、失效与复用

分阶段、全量或明显昂贵的验证为每个阶段记录：

1. 证明目标和当前候选身份；
2. 绑定的输入类别和快照证据；
3. 哪些变化使证据失效；
4. 允许复用的最低证明；
5. 复用后仍必须重跑的下游项目。

按当前项目实际情况至少区分：

- 产品构建输入；
- 产品二进制及 runtime closure；
- 验证实现、夹具、选择器和 expected／正式清单；
- 活动文档与机械门禁；
- 外部环境、真实输入或人工前提。

“产品源码未改”“二进制看起来相同”“只改测试”或“上一轮通过”都不能单独证明可以复用。最低证明应绑定项目当前
协议，例如输入集合身份、产品字节或等价不可变身份、验证输入差异和候选未变证据。任一必要输入、协议或快照身份
证据不足时不复用；按当前候选重新运行受影响阶段。

验证实现、夹具或选择清单变化通常使相应静态检查和动态项失效，即使产品构建可以复用。活动待办、方案、长期文档或
归档状态变化会使先前文档门禁失效。技术阶段通过后发生 source refresh 时，必须重新判断各阶段失效，不以禁止覆盖
既有最终证据为由跳过合法刷新证明。

## 4. 暴露动态预算与产品所有权

在请求动态验证授权或成本选择前，根据冻结入口和当前清单尽量自行计算并披露：

- suite、profile、场景或等价工作单元数量；
- 预计受管产品启动次数；
- 单次自然退出或自动退出上限、保守总耗时区间和主要不确定性；
- GUI、网络、Docker、浏览器、桌面、设备或前台占用；
- 负责启动、readiness、退出、返回码、配置零写回和残留检查的公共 owner；
- 强制清理是否允许、失败清理如何不掩盖首要断言；
- 可以暂停、恢复或安全复用的阶段。

能从直接入口、清单和配置查明的数量由 Skill 自行估算，不把纯算术交给用户。只有时长、前台占用、外部副作用或
验证层级形成真实成本选择时才询问；证据不完整时给保守区间和缺口，不伪造精确时长。

产品进程、真实数据、全量测试、正式认证或其他受限副作用仍按目标项目规则取得明确授权。预算披露帮助用户理解授权，
不自行扩大当前验证层级。

## 5. 处理环境阻断与恢复停点

动态方案说明每个产品或外部输入阶段的启动、readiness、正常退出、返回码、失败清理、owner marker 和恢复停点。只
管理本次启动且所有权明确的进程；不得按名称批量结束，也不得让清理错误覆盖首要失败。

GUI 或真实输入未被消费时，保留当前前台目标、命中对象和外部拦截证据。系统对话框、安全桌面、设备权限提示或其他
不属于产品的输入拦截通常是 `blocked`，不是产品 `failed`；不点击、绕过或伪造外部安全输入。环境恢复后沿原合同从
最近仍有效停点重跑，先按第 3 节重新确认上游证据是否仍可复用。

环境阻断只有在持续阻止当前目标且无法安全恢复时才立即询问。可以安全重试、切换到方案已列等价入口或等待当前受管
进程自然退出时，由普通任务在既有权限内处理并据实记录。

## 6. 区分技术终态与正式终态

方案同时写明：

- 当前验证范围完成后预期达到的技术证据状态；
- 正式认证、签名、发布、部署、Registry／索引回写或其他外部写入是否获授权；
- 未运行阶段在最终记录中使用 `not_run` 或项目等价状态；
- 最终报告不得使用哪些更强结论。

普通验证、全量测试或技术证据完整都不自动等于正式认证、Release、签名、部署或外部回写完成。未授权阶段保持为空
或 `not_run` 是边界证据，不是待普通任务顺手补齐的遗漏。

## 7. 方案最小交接字段

适用时，综合方案至少实例化：

- 原范围消费者漂移、环境阻断和新范围问题的分流规则；
- 独立非阻断问题的去重与收尾批量登记停点；
- 各验证阶段的输入、当前身份、失效条件、最低复用证明和下游重跑项；
- 动态数量、启动次数、退出上限、时长区间、环境占用、owner、清理和恢复停点；
- 技术终态、正式终态、未授权阶段和禁止升级的结论；
- 触发新语义、权限、副作用或确定范围漂移时的差额停止条件。

这些字段记录规则和当前计划值，不预写运行结果。实施完成后只据实更新实际结果与已经处理的漂移；未执行项目继续
保持 `not_run`。
