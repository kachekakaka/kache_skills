# 实施期验证规划参考

本参考由 `project-doc-consistency` 与 `project-doc-contraction` 在方案包含动态验证、昂贵阶段、产品／GUI／
外部环境、实施期消费者漂移、证据复用或认证终态时按需读取。它只帮助只读 Skill 形成可由普通任务实施的
验证交接；调用 Skill 自身仍不运行测试、构建、产品、门禁或外部操作。

## 实施期事实分流

普通任务后来发现的事实分为：

- **原范围消费者漂移**：直接消费已确定结论，且当前权威能唯一裁决。普通任务可在原切片及一层直接依赖内
  做最小修复并重验；
- **临时环境阻断**：源码与方案未被证明错误，环境或工具使验证无法进入可判定阶段。保留现场、恢复条件和
  当前状态，不把它改写成新发现；
- **新的范围问题**：需要新产品语义、新权限、新副作用、确定范围外路径，或不能由现有权威唯一裁决。保持
  方案活动并申请最小决定或授权差额。

不得因一个消费者漂移重跑完整审计，也不得把实施期新发现伪装成候选阶段已经评审过的内容。

## 输入、失效与复用

分阶段或昂贵验证逐阶段记录：

1. 证明目标和当前候选身份；
2. 绑定的输入类别与快照证据；
3. 哪些变化使结果失效；
4. 允许复用的最低证明；
5. 复用后仍需重跑的下游项。

按项目实际情况区分产品源码、二进制与 runtime closure、验证实现／夹具／选择清单、活动文档与机械门禁、
外部环境和人工前提。“上次通过”“产品源码未改”或“二进制看起来相同”都不能单独证明可复用。活动待办、
方案、长期文档或归档状态变化会使先前文档门禁失效。

## 动态预算与所有权

请求动态验证授权或成本选择前，尽量从当前入口自行计算并披露：

- suite、profile、场景或等价工作单元数量；
- 预计受管产品启动次数、单次退出上限和保守耗时区间；
- GUI、网络、Docker、浏览器、设备或前台占用；
- 启动、readiness、退出、返回码、配置零写回和残留检查的 owner；
- 失败清理如何不掩盖首要断言；
- 可以暂停、恢复或安全复用的阶段。

产品进程、真实数据、全量测试、正式认证和其他受限副作用仍按目标项目规则取得明确授权；预算披露不扩大
当前验证层级。

## 阻断、恢复与终态

动态方案说明启动、readiness、自然退出、失败清理、owner marker 和恢复停点。只管理本次启动且所有权明确
的进程，不按名称批量结束。系统对话框、安全桌面、设备权限或其他外部输入拦截通常是 `blocked`，不是产品
`failed`；不得点击、绕过或伪造输入。

方案同时区分：

- 当前验证范围完成后的技术证据状态；
- 正式认证、签名、发布、部署、Registry／索引回写是否获授权；
- 未运行阶段的 `not_run` 或项目等价状态；
- 最终报告禁止使用的更强结论。

普通验证或技术证据完整不自动等于正式认证、Release、部署或外部回写。

## 最小交接字段

适用时，方案至少实例化：

- 原范围消费者漂移、环境阻断和新范围问题的分流；
- 各验证阶段的输入、候选身份、失效条件、最低复用证明和下游重跑项；
- 动态数量、启动次数、耗时、环境占用、owner、清理和恢复停点；
- 技术终态、正式终态、未授权阶段和禁止升级的结论；
- 触发新语义、权限、副作用或确定范围漂移时的差额停止条件。

这些字段记录规则和计划值，不预写运行结果。实施完成后只据实更新实际结果和已经处理的漂移。
