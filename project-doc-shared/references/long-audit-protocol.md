# 项目文档长审计分片协议

本参考只定义 `project-doc-consistency` 与 `project-doc-contraction` 共用的长任务运输、恢复和纠正规则。
它不定义事实如何裁决、什么内容应收缩，也不允许一个 Skill 自动调用另一个 Skill；各 Skill 在自己的
`SKILL.md` 中定义审计单元、证据字段、文档处置和评审目标。

## 范围分片 `S000`

在读取实现证据或跨文档比较前，先交付 `S000`，记录：

- 调用的 Skill、审计模式和当前交付路线；
- 按顺序编号的精确冻结路径或内容种子；
- 一轮直接依赖规则；
- 排除项、基线身份和已经存在的残余；
- 第一份正式审计分片、下一路径和下一审计单元。

后续分片只引用 `S000` 的范围序号。范围确需改变时使用纠正分片追加、移除或重新解释成员；不得静默
重排或重新编号已经交付的成员。

## 正式分片 `Axxx`

- 按冻结顺序在完整文档边界组成批次；单个文档过大时，只在该 Skill 定义的自然审计单元边界拆成连续子分片。
- 每个 `Axxx` 都是正式报告的一部分，不是可以被最终摘要替代的进度消息。
- 分片必须列出精确范围序号、已完成审计单元、该 Skill 要求的证据、文档处置是否已完成，以及新增或改变的
  发现、决定与残余。
- 分片交付后自动继续下一批，不等待用户回复“继续”，也不把剩余范围转交给另一项审计任务。

一个文档可以跨多个连续分片；只有该文档全部审计单元完成后，才能给出文档级处置。

## 正式评审分片 `Rxxx`

- 每轮评审按调用 Skill 定义的固定文档集合或动作集合形成一个或多个连续 `Rxxx`。
- 每个 `Rxxx` 必须在正文中实际列出本轮负责的成员、原始证据和对应结论；不能只报告新增发现、数量或整体摘要。
- 只有全部固定成员在正式 `Rxxx` 中有归宿，该轮才可计为完成。方案正文、最终索引、审阅包或任务结束后的事后重建不能补记缺失的评审记录。
- 评审导致结论或动作变化时，先交付 `Cnnn`，再在后续 `Rxxx` 中重做受影响记录。

## 累计可恢复尾部

每个审计、纠正和评审分片末尾都必须有累计可恢复尾部。最近一个可见尾部本身就是检查点，至少包含：

- 当前及前一分片编号；
- 按当前文档处置分组的全部已完成范围序号；
- 进行中文档和最后完成的审计单元；
- 当前有效发现、待决项和残余；
- 全部被替代记录；
- 精确的下一分片、下一范围序号／路径和下一审计单元。

连续范围序号可写区间，异常项单列；尾部不重复详细证据。活跃上下文只镜像最近一个可见尾部。上下文
压缩后，以 `S000` 和最近尾部恢复，先核对范围、完成状态和下一指针，再继续工作；不能只依赖不可见内部记忆。尾部与正文冲突时，先从可见分片重建状态并交付纠正分片，不猜测下一步。

## 可选仓库外正式轨迹

只有用户明确授权时，内容 Skill 才可在目标仓库外创建一份本任务专用的 append-only 正式轨迹。`S000` 必须记录轨迹
绝对路径；之后每个正式 `S000`、`Axxx`、`Cnnn`、`Rxxx` 和累计可恢复尾部都逐字追加，不能只写摘要或事后回填。

轨迹不进入目标仓库、不加入 Git、不包含凭据、真实用户数据或原始运行现场，也不供另一任务继续审计。它只解决长任务
上下文压缩后正式记录不可检索的问题，不证明语义正确。未获授权时保持纯对话只读；保存方案前若正式记录既不在当前
线程可取得，也不在经授权的仓库外正式轨迹中，必须标为缺失，不得事后补造、不得把该轮计为完成。

## 纠正分片 `Cnnn`

已交付分片不可改写。后续取证或评审改变旧结论时，使用 `Cnnn`：

- 精确点名被替代的分片、路径、审计单元、发现、决定或动作；
- 给出新证据、当前结论和新处置；
- 更新累计可恢复尾部中的有效记录与替代关系。

旧记录继续作为历史交付存在，但不再是当前结论。最终索引只指向最新有效记录，不允许两个互相冲突的
结论同时有效。

## 完整性与最终索引

最终索引必须核对：

1. `S000` 的范围序号没有缺口、重复完成或静默跳过；
2. 每个成员满足调用 Skill 的审计单元、证据和文档处置要求；
3. 分片及累计尾部连续，下一指针可复原；
4. 每项纠正只有一个当前有效结论；
5. 所选评审轮次已经覆盖对应 Skill 规定的固定复核集合或动作集合。

最终回复可以只给出分片索引、综合发现、残余和下一停点，不重复全部审计单元证据；但不能用最终摘要
替代尚未交付的正式分片。

## 规模与中断

“一次调用”指一个用户任务线程，不等于一个模型上下文或一个最终回复。`full` 不得因为预计上下文、
输出篇幅或文件数量较大而主动停止、要求用户另发“继续”或降低证据密度。

只有源文件或必要直接证据实际不可读取、当前所有权无法裁决、证据仍不足，或宿主实际中断任务时，才记录
`未覆盖` 或外部中断残余。恢复条件成立后仍在同一任务线程按最近可见尾部继续。
