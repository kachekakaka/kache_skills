# 独立方案审阅协议

本参考只在用户显式要求于新上下文中审阅一份已经保存的一致性或收缩方案、判断是否可实施时使用。它不重跑原 `full`
审计，不自动实施或保存，也不允许原审计任务自我认证。

## 输入与信任边界

- 固定方案路径、方案记录的不可变基线、当前 Git 状态和 Skill provenance；
- 读取方案、可取得的正式轨迹／审阅记录，以及裁决方案动作所需的一轮当前直接证据；
- 不继承原任务的完整性或防误伤结论；“完整性门通过”“两轮通过”“无新发现”只作为待验证主张；
- 缺少方案、基线、必要正式记录或直接证据时返回 `blocked`，不得补造。

独立审阅只核对方案及其声称的闭包，不重新冻结全部活动文档，也不把结果描述成一次新的 `full` 审计。

## 共同步骤

1. 核对方案绑定的基线、生命周期、修改范围、明确不修改范围和验证选择。
2. 提取全部发现、确定动作、阻断、待决项和“不改”结论；每项必须有唯一归宿。
3. 读取所有 `Cnnn` 的失效集合，检查当前方案、A/R 记录是否静默复用失效证据。
4. 挑战方案声称“无漏项”的高风险关系和每项动作的唯一性；发现新差额时只形成修订建议，不扩写为完整审计。
5. 输出以下之一：
   - `implementation_ready`：方案自包含、动作唯一、边界清楚、无未解除阻断；
   - `needs_revision`：可由有界修订关闭；
   - `blocked`：基线、证据或所有权不足。

## 一致性方案审阅

- 对方案涉及的领域重新形成四类双向清单，并检查所有 `CExx` 候选均有归宿；
- 挑战原任务判为一致、但直接支撑当前动作闭包的文档和消费者；
- 确认每项修正只有一个最小动作，不把现场语义选择留给实施者；
- 确认没有删除重复正文、迁移、摘要加链接、合并、简化或降低默认加载量的收缩动作；
- 确认验证能够证明文字／合同闭环，且不会借测试扩大产品语义或授权。

## 收缩方案审阅

- 对所有删除、迁移、摘要、合并和简化动作应用“过时事实删除门”；依赖未裁决当前事实的动作必须改为
  `consistency_blocked`；
- 确认所有阻断单元完全退出确定修改范围、评审和完成条件；
- 检查唯一事实、用户合同、必要决定理由、字段合同、测试特定义务和运维步骤仍有明确所有者与消费者；
- 检查 `Cnnn` 已宣布失效的证据没有在后续 review 中重新出现；
- 确认总内容足迹与默认入口加载量没有混写。

## 修订与保存

独立审阅始终只读。`needs_revision` 时给出精确差额、受影响动作和需要重做的 review；只有用户随后单独确认，才允许
修订原方案。修订后必须重新执行受影响的独立审阅，不能沿用旧 `implementation_ready`。
