# 一致性 Skill 在方案交接后退出执行链

`project-doc-consistency` 的稳定价值是核对活动文档与当前事实、识别职责不清和内容膨胀，并生成可裁决的修订方案。
把 `sync`、验证命令账本和施工后交接继续放在 Skill 中，会重复目标项目的协作与生命周期规则，也与用户只在生成
方案时调用该 Skill 的实际用法不符。

现决定 consistency 只保留两个阶段：对新内容问题进行只读检查；用户明确授权后保存一份可裁决、可实施且可关闭
的主责方案并做静态自审。保存后 Skill 立即停止，不再提供 `sync`、验证、Git、归档、删除或关闭能力。后续普通
实施任务依据目标项目规则和方案，在当轮授权下完成内容修订、验证、独立验收与关闭。

内容审计能力保持不变：活动真源所有权不清时先停止，未限定范围默认 `full`，精确种子使用一轮直接依赖的
`incremental`，测试设计只在显式请求或作为当前声明直接证据时进入范围。结构、产品实现和测试实现问题继续形成
精确交接，不并入内容方案施工。

本决定替代 ADR-0003 中允许 consistency 在授权后直接修订文档内容，以及 ADR-0004 中允许原 consistency 在方案
保存后继续 `sync` 的部分。两份 ADR 关于结构与内容职责分离、检查与保存分离、保存不构成施工授权和活动方案
完成后退出入口的决定继续有效；skeleton 的职责由 ADR-0005 独立规定。
