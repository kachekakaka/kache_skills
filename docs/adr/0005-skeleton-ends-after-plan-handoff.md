# 骨架 Skill 在方案交接后退出执行链

`project-doc-skeleton` 的实际使用场景是完整检查项目文档结构并生成后续实施依据。把施工、验证授权包、重试、
验收和生命周期关闭继续放在 Skill 运行时，会让一次方案工具长期留在执行链中，并重复目标项目已经拥有的协作与
生命周期规则。

现决定 skeleton 只保留两个阶段：首次对新骨架问题进行完整只读检查；用户明确授权后保存一份可裁决、可实施且
可关闭的主责方案并做静态自审。保存后 Skill 立即停止，不再提供 `apply`、验证、Git、归档、删除或关闭能力。
后续由普通实施任务读取目标项目规则和已保存方案，在当轮授权下完成裁决、施工、验证、独立验收与关闭。

职责收缩不删除生命周期闭环。保存的方案必须实例化目标项目当前收尾契约，明确完成证明、状态消费者、关联方案、
验收停点、关闭动作、最终状态门禁和未运行验证；文件修改或中途门禁通过不能代替活动待办退出和方案归档。

本决定替代 ADR-0002 中允许 `project-doc-skeleton apply` 执行结构迁移，以及 ADR-0004 中允许原 skeleton 在方案
保存后继续施工的部分。ADR-0004 关于检查与保存分离、保存不构成施工授权、同一待办最多一份活动方案及完成后
退出活动入口的决定继续有效；`project-doc-consistency` 的 `sync` 边界不在本 ADR 中改变。
