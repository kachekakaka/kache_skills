# 裸调用或意图不清时先确认交付路线

> 状态：现行。

两个项目文档 Skill 已经区分只报告与形成方案，但 ADR-0010 把无法可靠证明方案意图的请求直接归入报告路线。用户只在
提示中显式调用 Skill、没有补充自然语言请求时，运行时因此会替用户选择报告并开始项目检查；这掩盖了交付路线选择，
也使用户直到检查结束才发现没有进入方案流程。

现决定保留明确请求的快速分流，并为裸调用或意图不清增加前置停点：

1. 用户只要求检查、审计、review 或报告且没有同时要求方案时，直接进入只报告路线；用户明确要求形成、保存或修订方案时，
   直接进入方案路线，不额外询问已经明确的路线。
2. 请求只有 `$project-doc-skeleton`、`$project-doc-consistency`，或内容不足以可靠区分两条路线时，先用一个白话问题询问
   “这次只要检查报告，还是检查后形成方案”。推荐先只要报告，并说明形成方案会继续取得自查轮数和反哺报告选择。
3. 用户可以回复“按推荐”或“只要报告”、“形成方案”或“暂缓”。“按推荐”只接受问题中已经展示的报告路线；沉默、
   模糊回复或其他问题的历史推荐都不能替代当前选择。
4. 取得回答前，只能读取 Skill 自身和为遵守安全边界所必需的适用 `AGENTS.md`；不得读取活动文档入口、枚举项目文档、
   搜索实现、检查 Git 或联网取证。选择报告后才开始对应检查；选择方案后先联合取得交付前自查轮数与实施后反哺报告
   选择，再开始实质检查。
5. 路线选择只决定本次交付形式，不授权写文件、登记待办、保存方案、转换状态、实施、安装或 Git 写操作。两个 Skill
   继续只允许显式调用、保持各自职责和只读边界，并在最终保存方案后退出执行链。

考虑过继续默认报告：回合最少，但会重现本次未确认即开查的问题。考虑过默认进入方案：能够保留方案能力，却让只想获取
报告的用户承担轮次与保存流程。采用前置路线问题只给裸调用和真实歧义增加一个回合，同时保留明确请求的直接路径。

本决定只替代 ADR-0010 中“意图不能可靠证明时默认报告”的部分。ADR-0010 关于明确请求分流、方案路线联合首问、
反哺报告、语义确认与动作授权分离的决定继续有效。
