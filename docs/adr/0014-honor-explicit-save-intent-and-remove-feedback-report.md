# 尊重明确保存意图并取消反哺报告

项目文档 Skill 原先无论用户是否已明确要求保存，都在候选评审后再次询问；还预先询问固定评审轮数和是否生成实施后的反哺报告。这些交互不能增加方案证明力，却让明确请求重复停顿并扩张交付物。现决定：用户在当前请求中已明确要求“检查并保存”或等价结果，且评审没有产生新的范围、语义决定或授权差额时，Skill 完成评审后直接一次性保存并报告结果，不重复确认；只有定稿、自包含、验证规划和必要就绪条件全部满足时使用 `待实施`，仍待独立审阅或其他必要就绪条件时使用 `待确认`。只要求形成方案但未授权保存时，仍进入保存确认停点。保存仍不构成实施授权。

方案默认进行一次有界评审；只有发现会改变结论的问题才修订并追加一轮，最多两轮，仍不稳定就不保存并交回用户，不再预先询问轮数。Skeleton、Consistency 和 Contraction 三个项目文档 Skill 及其活动直接消费者完全取消反哺报告概念、选项和交付物，而不是仅把它设为默认关闭；这项同步不读取、修改或验证其他项目。本决定替代 ADR-0009 的固定轮数与无条件最终保存确认、ADR-0010 的方案路线联合首问和全部反哺报告规则，以及 ADR-0011 中选择方案后的联合首问；报告／方案分流、裸调用时的路线确认、语义确认与动作授权分离、候选先评审后一次性持久化继续有效。
