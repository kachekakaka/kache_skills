# 标准骨架采用最小充分的方案与验证治理

标准骨架原有的生命周期把“待实施”解释成不得存在方案，固定九项收尾又要求无关任务填写“不适用”；验证选择只缩小了运行集合，却没有同时约束重复项、不可达场景、专为骨架制造的合成夹具和输出长期堆积。我们决定以最小充分治理取代这些固定重量：`待确认` 表示仍有语义未决，`待实施` 表示已有且只有一份定稿、自包含、验证规划齐备但尚未取得施工授权的活动方案，`实施中` 表示该方案已取得本次明确施工授权并开始实施；标准方案只固定完成证据、覆盖与残余、验证结果或未运行原因、生命周期关闭四类收尾信息，其余仅在任务真实触发时出现，不填写占位的“不适用”。

普通验证、用户明确选择的完整测试和正式认证都必须保持各自证明目标，但运行集合应复用候选、输入和失效条件未变的既有证据，优先现有的最小输入和最低副作用检查。只有证明目标被另一项完整覆盖时才删除重复测试，只有受支持入口、配置和消费者均无法到达时才删除场景；一次运行未覆盖不足以证明不可达，也不为满足骨架形式单独制造没有真实消费者的合成夹具。成功关闭时精确清理本任务拥有的临时测试输出；失败、阻断或结论不明的现场只有记录所有者和复查日期才可暂存，历史留存必须显式指定，不引入后台自动删除。

活动文档检查与归档检查继续共用一个 T-DOC 身份，但作为两个可独立选择的部分：只修改活动文档时不扫描归档；归档、恢复归档或修改归档路径／索引时才追加归档规则。该选择只约束当前目标项目，不会让骨架检查其他项目。
