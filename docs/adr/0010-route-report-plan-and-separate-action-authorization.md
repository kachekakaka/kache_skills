# 按请求分流报告与方案并分离语义确认和动作授权

> 状态：部分被替代。明确报告／明确方案的快速分流及语义确认与动作授权分离继续有效；“意图不能可靠证明时默认报告”
> 由 [ADR-0011](0011-ask-delivery-route-before-auditing-ambiguous-invocations.md) 替代，固定联合首问、反哺报告以及无条件再次
> 确认保存由 [ADR-0014](0014-honor-explicit-save-intent-and-remove-feedback-report.md) 替代。

两个项目文档 Skill 原先把每次新检查都导向方案候选：实质检查前询问评审轮数，检查后形成候选并进入最终保存停点。
这会让只想获得检查报告的用户承担无用询问，也容易把用户对某项语义结论的“确认”误解为保存、登记、转换状态或施工
授权。施工后是否形成可迁移经验报告也没有独立入口，容易与实施方案或 Skill 本体修改混在一起。

本决定原先规定按当前明确请求选择交付路线：用户只要求检查、审计、review 或报告时，完整只读检查并在对话中交付结果后
停止，不询问评审轮数，不形成方案候选，也不询问保存；意图不能可靠证明要形成方案时同样采用报告路线。后者现已由
ADR-0011 替代。用户明确要求形成、保存或修订方案时进入方案路线；方案路线在实质检查前用同一个白话问题取得“交付前自查轮数”和
“实施完成后是否生成反哺报告”，推荐“两轮、不生成”；用户在该问题回复“按推荐”时同时接受这两项推荐。选择生成
反哺报告只会把它登记为普通实施任务完成项目修改和验证后的独立历史交付物，两个文档 Skill 自身不施工、不生成报告，
也不修改用户级或已安装 Skill。

语义确认与动作授权始终分离。用户回复“确认”“接受”“按推荐”“就这样”，只确认当前问题明确展示的结果；当前问题
没有明确询问写文件、登记待办、保存方案、转换生命周期状态或开始实施时，不产生这些动作授权。先前授权只绑定当时
明确范围，不能扩展到后来出现的新需求。项目当前待办状态、该状态是否允许方案、是否已经取得实施授权，以及方案存在
能否证明已经开工必须分别由当前规则和证据判断，不能相互推导。

除 ADR-0011 和 ADR-0014 已替代的部分外，明确交付路线以及语义决定与动作授权分离继续有效。方案路线的候选评审、
逐项语义决定、一次性持久化及保存后退出仍继续有效；评审默认值和保存停点按 ADR-0014 执行，反哺报告入口退出。
ADR-0004 至 ADR-0006 关于检查、保存与施工分离，以及两个 Skill 不进入施工、验证和关闭阶段的决定继续有效。
