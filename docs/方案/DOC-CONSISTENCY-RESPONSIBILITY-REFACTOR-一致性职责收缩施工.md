# 一致性 Skill 职责收缩施工方案

- 待办：[`DOC-CONSISTENCY-RESPONSIBILITY-REFACTOR`](../已知问题与待做需求.md#doc-consistency-responsibility-refactor收缩一致性-skill-职责)
- 状态：待确认
- 性质：由原职责收缩总待办拆出的 consistency 独立待确认方案，不构成施工授权
- 决策依据：[ADR-0003](../adr/0003-separate-structure-governance-from-content-consistency.md)、[ADR-0004](../adr/0004-separate-review-plan-and-construction.md) 与 [`CONTEXT.md`](../../CONTEXT.md)

## 拆分结论

- 按 D-09 至 D-12，本方案拥有独立待办、施工、复核和验收；它排在 skeleton 阶段之后，且不继承前一阶段授权。
- 原总待办及总方案被两份独立方案共同替代并退出活动入口。
- 按 D-07，旧 `VALIDATION-EQUIVALENT-GOVERNANCE` 待办退出活动列表；其 consistency 验证责任由本待办承接。
- 本方案保持 `待确认`，直到 skeleton 验收后用户另行选择 consistency 施工。
- 本方案只记录 consistency 主责范围内的目标、目标路径、动作边界、完成条件和验证要求，不预写脚本或命令，
  也不与 skeleton 合并；用户可以选择 `sync` 或其他施工方式。
- skeleton 阶段只建立职责、入口和承接位置，仍含未同步事实的旧真源保持为临时材料；本方案完成内容同步后，
  如需退出这些材料，由用户重新发起独立 skeleton 检查、保存和施工周期。

## 已确认目标

1. `project-doc-consistency` 只核对活动文档与当前代码事实，并识别职责不清、内容膨胀和位置不当。
2. 未限定范围的项目文档审计默认 `full`；明确文件、功能或差异时使用 `incremental`，只展开一轮直接依赖。
3. 测试、CI 和安全实现仅在它们是当前声明的直接证据，或用户明确要求测试设计审计时进入范围。
4. 首次运行只检查并报告，随后询问是否保存；保存、差异裁决和再次施工授权彼此分离。
5. 结构入口阶段只读取足以识别活动真源所有者的当前入口和职责声明，不重新认证结构治理；所有权不清时停止并形成 skeleton
   交接，不猜测真源或继续扩张内容审计。
6. 后续 `sync` 只按已保存、已裁决且无漂移的方案，在现有拓扑内修订内容；它不是默认施工方式，用户可以选择
   其他实现者或机制，结构职责冲突保持待决并交接。
7. 主责方案只记录目标、目标路径、动作边界、完成条件和验证要求，不写具体脚本、命令或自动实施计划。
8. 需要命令才能形成证据时，先建立临时验证执行账本并单独申请授权；未运行的原验证保持 `not_run`，替代证据
   不能把它改写为通过。

## 明确不在当前 skeleton 阶段实施

- 不改写 consistency Skill、参考、默认提示或测试设计审计文件。
- 不运行 consistency 的普通门禁或前向试用，不把 skeleton review 当作 consistency 验收。
- 不在本方案写入精确命令或绑定某个环境的脚本设计，不把保存方案解释为 `sync` 授权。
- 不安装 Skill，不执行 commit、push、PR、发布、真实数据或产品进程操作。

## 验证安排

- 测试层级：普通验证
- 验证影响域：后续 consistency 主契约、参考、默认提示、长期文档一致性与代表性前向试用协议
- 具体验证项：证明 consistency 不再认证六项结构治理、不再直接进入 `sync`、能够在所有权不清时停止交接，
  并在已授权代表性样本中区分 `full` 与 `incremental` 内容边界；本方案不记录精确命令，本阶段全部不运行。

后续申请命令授权前，临时账本必须列出实际运行器、工作目录、现有依赖、输出位置及可预见的 Git、联网、产品
进程、真实数据、安装或其他嵌套副作用；不自动安装依赖。涉及外部副作用或授权取舍时，先说明会发生、不会
发生和既有状态。原验证未执行时记为 `not_run`，替代静态证据单独报告。

## 启动条件

只有 skeleton 阶段完成独立验收，且用户再次明确选择 consistency 施工后，才把本待办转为 `实施中` 并开始
修改。届时先复核 skeleton 提供的共享生命周期契约是否漂移；漂移只形成新差异，不自动重做已验收阶段。

## 完成条件与停点

1. consistency 不再建立、短路或报告六项结构治理账本；结构入口阶段只读取识别活动真源所有者所需的最小入口和职责证据。
2. `check → 保存主责方案 → 用户选择施工` 三个阶段可观察；“审计并修复”不能跳过保存停点，`sync` 不再被默认授权。
3. 所有权不清、结构职责冲突或需要移动、归档和退出入口时形成精确 skeleton 交接，不自行解决结构问题。
4. 测试设计参考只在直接证据或显式审计范围内生效，前向协议和契约夹具不再恢复双 Skill 治理认证。
5. 方案与 Skill 均不预写脚本、命令或固定施工机制；执行账本只存在于当次对话，未运行验证使用准确结果语义。
6. 普通验证和静态 review 没有发现 consistency 范围内的阻断问题后暂停等待用户验收；不自动调用 skeleton，
   不继承 skeleton 授权，也不在同一方案中处理后续结构归档。
