## 1. 初始检查证据（历史快照）

- [`project-doc-consistency/SKILL.md`](../../project-doc-consistency/SKILL.md) 的内容审计主责仍清楚：核对文档事实、职责、膨胀和位置，使用 `full` 或一轮直接依赖的 `incremental`，结构所有权不清时停止交接。
- 同一文件仍有“检查 → 保存方案 → 施工”三阶段，并在后半部定义 `sync`、文档写入、验证执行账本和验收前交接；这些内容服务方案后的执行，不符合用户只在生成方案时调用 Skill 的实际用法。
- [`test-design-audit.md`](../../project-doc-consistency/references/test-design-audit.md) 的按需触发、精确证据链和测试经济性分类仍属于必要审计判据；只有末节把 consistency 当作施工者，需要改为方案交接边界。
- 旧职责收缩方案已经独立验收并归档；本方案不否定当时结论，只用新的用户决定替代其中允许 `sync` 和 Skill 继续施工的部分。
- 当前 [`SKELETON-PLAN-ONLY-20260804`](SKELETON-PLAN-ONLY-20260804-骨架Skill仅检查与落方案职责收缩方案.md) 为 `实施中`，两份方案将共享根 README、需求、设计和前向契约；双方验证、验收和授权不得继承。
- 保存前在当前仓库可读文件中未发现本待办 ID 复用；Git 历史没有核对，状态为 `not_run`。

## 2. 已确认决定

1. consistency 只执行内容检查，以及用户明确授权后的方案保存与静态自审；保存后停止。
2. 删除 `sync`、施工、验证执行账本和生命周期关闭的运行时职责。
3. 保留内容审计、所有权停点、`full`/`incremental`、声明分类、问题分类和按需测试设计审计。
4. 保存方案必须让普通实施任务能够独立裁决、修改文档、验证、验收和关闭；执行规则不再复制进 Skill。

## 3. 目标与非目标

### 3.1 目标

- 把 consistency 收缩为“完整内容检查 → 保存并自审方案 → 停止”。
- 让主入口只保留审计流程、硬边界和方案最低完备性，领域测试判据继续由现有 reference 按需承接。
- 让公开文档、默认提示和前向夹具只承诺检查与方案交付。
- 保留项目级收尾契约，使方案在普通任务实施后仍能退出待办、归档并验证最终状态。

### 3.2 非目标

- 不修改 skeleton Skill、其参考、资产或默认提示。
- 不改变 `full`、`incremental`、一轮直接依赖、内容问题分类或测试设计审计判据。
- 不改变标准骨架、T-DOC、Registry schema、项目级生命周期或 consistency 与 skeleton 的职责分界。
- 不运行内容同步、测试、命令、Git、安装、联网、产品进程或生命周期关闭。

## 5. 拟定职责结果

1. 新问题检查始终只读；完成所有权、范围、声明证据、内容问题和适用测试设计判断后询问是否保存。
2. 用户明确保存后，只写一份主责方案及必要活动待办，静态自审后停止；已有活动方案时默认交给普通任务。
3. 方案至少包含初始证据、范围、发现、决定、确定与可能路径、动作边界、完成条件、验证要求、未覆盖范围和任务特定收尾字段。
4. 除经授权保存主责方案及必要待办外，consistency 不再修改既有活动文档内容，不运行验证，也不处理 `sync`、
   Git、归档、删除或关闭。
5. 普通实施任务按项目规则和当轮授权修改方案列出的现有文档内容；结构、产品或测试实现问题继续精确交接。
