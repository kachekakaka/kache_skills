# 需求文档

本文件承接当前已交付、用户可观察且可验收的行为和支持边界。尚未实现的事项登记到
[已知问题与待做需求](已知问题与待做需求.md)。

## 产品范围

本项目交付三个只能显式调用、不会自动互相调用的项目文档 Skill：

- `project-doc-skeleton`：检查项目文档结构、入口、职责、生命周期、测试治理和机械门禁。
- `project-doc-consistency`：只检查活动文档的事实、契约、状态、所有权、Registry／入口和直接消费者一致性。
- `project-doc-contraction`：只在用户确认当前或指定的不可变提交已经完成一致性整改并做过一致性验证后，检查重复、
  镜像、过程快照、内容错位、摘要膨胀和复杂或不精准表达。

三个 Skill 不自动调用对方，也不要求另一个 Skill 已安装；consistency 与 contraction 共同读取
[非可调用共享参考](../project-doc-shared/README.md)。当前架构理由和替代关系从
[设计文档的架构决策记录](设计文档.md#架构决策记录)进入。

## 共同交付合同

- 先按当前明确请求选择交付路线：只要求检查、审计、review 或报告且没有同时要求方案时，在对话中交付只读结果后
  停止；明确要求形成、保存或修订方案时进入方案路线。Skeleton／Consistency 只显式调用或意图不足以可靠分流时，
  先询问只要报告还是形成方案；Contraction 裸调用则默认 `full + 只读报告`，只问一次当前 `HEAD` 的一致性前置确认。
- 检查和未保存候选评审只读取文件、搜索结果和只读 Git 等静态证据，不运行测试、构建、产品或门禁；动态验证留给
  后续普通任务并保持 `not_run`。
- 方案路线使用用户已经给出的自查轮数和反哺报告选择；Skeleton／Consistency 缺失时一次询问，Contraction 缺失时
  默认“两轮、不生成”且不额外提问。检查结束后只在当前调用内形成候选，完成所选轮次后展示范围、决定和残余，
  并单独询问是否只保存方案、不开始实施。
- 能由当前活动权威、项目规则或已有决定唯一裁决的事实由 Skill 自行查明；只有权威留白、同级权威冲突或新增授权
  差额才逐项请用户决定。问题须说明实际结果、代价和可回退性，技术标识不能代替用户可理解的选项。
- 用户对语义结果的确认不自动授权写文件、登记待办、保存方案、转换状态或实施。最终保存确认只允许一次写入方案及
  必要待办；保存后 Skill 停止。
- 保存的方案必须自包含活动所有者、范围、真实发现、决定、确定与待决路径、验证及副作用边界、完成条件、最终复核和
  生命周期收尾，使全新普通任务不依赖原审计对话即可接手。
- 内容 Skill 的内部完整性门只产生 `audit_complete`，不自动表示可实施；只有新上下文中的显式独立方案审阅可以给出
  `implementation_ready`。未通过时返回 `needs_revision` 或 `blocked`，不得由原任务自我升级。
- 三个 Skill 不施工、不运行验证、不安装资产、不使用非只读 Git，也不归档、删除或关闭目标项目生命周期。
- 一致性方案和收缩方案必须分离；一个活动方案不得同时承接两类动作，也不得因一项审计完成自动启动另一项 Skill。

## 共用长任务合同

- consistency 与 contraction 的 `full` 都可以在一个用户任务线程内跨多个模型上下文运行。
- 开始时交付 `S000` 有序范围分片，后续按完整文档或各 Skill 定义的自然单元交付 `Axxx` 正式报告分片。
- 每个审计、纠正和评审分片末尾都带累计可恢复尾部，记录全部完成状态、当前发现／阻断、替代关系和精确下一步。
- 上下文压缩后只从 `S000` 和最近一个可见累计尾部恢复，不依赖不可见内部记忆或猜测。
- 用户明确授权时，可把正式 `S000/Axxx/Cnnn/Rxxx` 逐字追加到目标仓库外的任务轨迹；未授权时不写文件。无论是否
  使用轨迹，保存方案前全部最终有效正式记录都必须可取得，缺失时不得事后补造或宣称完整。
- 已交付分片不可改写；后续结论变化使用 `Cnnn` 纠正分片，最终索引只保留一个当前有效结论。
- `full` 不得因预计上下文、输出篇幅或文件数量较大而主动停止、要求用户另发“继续”或降低证据密度。

## `project-doc-skeleton`

- 支持采用标准骨架的新项目、明确迁移，以及保留成熟既有治理的等价路线；路径或 schema 不同本身不构成迁移理由。
- 一次检查覆盖上下文与路线、结构职责、入口导航、活动／历史生命周期、待办／方案／记录、测试治理和机械门禁等
  全部适用结构维度，并以已填写的覆盖／残余矩阵限制结论范围。
- 存在测试治理入口或测试根时，可以有界调查当前测试资产、生命周期、执行暴露、身份、所有者、直接消费者、执行
  入口和正式选择；不评价测试覆盖、断言质量或经济性。
- 标准完整测试只选择没有等价替代的最小核心能力、本候选实际影响项和用户明确加入项；正式认证不自动扩展到项目未
  声明、未交付或没有直接敏感性证据的平台与环境。Skeleton 只检查这项选择治理，不逐测试审计或生成删除动作。
- 拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，方案只展开一层会改变退出结论的直接消费者；证据
  不足时保持待决。
- 不持续核对产品事实，不审计测试设计，不执行全项目安全认证；超出结构职责的问题形成精确交接。

## `project-doc-consistency`

- 先校验安装目录的 `SOURCE-PROVENANCE.json`，记录 `verified`、`missing` 或 `mismatch`；只有 `verified` 才能把
  实仓结果归因到某个源提交。随后从当前入口确认活动真源所有者；所有权不清时停止内容审计并形成结构治理交接。
- 未限定文件、功能或差异时使用完整活动文档范围；明确种子时只展开一轮直接依赖。增量边界不能可靠形成时报告
  残余，不静默扩大。
- 对范围内每份活动文档完整核对事实、规则、契约、状态、所有权和直接消费者，不得抽查。自然契约单元至少按稳定
  一级职责章节划分，不得跨章用一句“静态吻合”代表未检查内容。
- 表格、清单、矩阵或映射中分别声明不同值、所有者、状态、前提、例外或消费者的行／项必须分别核对；章节级结论不能覆盖独立成员。
- 每个单元必须展示具体声明、命名所有者和直接证据／消费者，以及 `一致`、`需要修正`、`无法核验`、
  `需要决策` 或 `未覆盖` 的结论与理由。
- 必检需求、设计、字段契约、ADR、运维、待办、Registry、manifest、测试入口、实际注册、帮助／注释／配置和直接
  消费者之间的当前含义与状态。
- `full` 还必须完成四类跨载体反证：初始状态与运行时转换、允许／禁止／退役合同与正负夹具、聚合入口与实际成员
  闭包、共享 source／lease 与请求／响应及普通／独立精确操作的粒度差异。每类先列文档／权威侧与实现／消费者侧
  双向清单，再为差额建立候选并逐项归宿；不能只写“无新发现”。
- 疑似重复、实现镜像、过程快照或内容错位但没有改变含义时，只记录 `后续收缩候选`；不得判断文档篇幅、默认加载量，
  不得形成删除、迁移、摘要加链接、合并或简化动作，也不输出 `无需收缩`。动作按实际效果分类：语义已一致而只为减少副本、恢复 README 分层或只留链接的动作仍属于收缩。
- 第一轮评审逐份挑战全部文档级 `一致` 结论，每份必须记录可证伪主张、初审正向证据、不同角色的相反证据／邻接
  消费者及改变理由；`N/N 不变` 或职责分组名单不能替代。第二轮逐项显式记录产品语义、权限／安全、测试选择、运行
  行为、历史决定和直接消费者是否改变。两轮必须在正式 `Rxxx` 中交付，不能由最终摘要或事后审阅包补记。
- 条件测试契约审计只在用户明确要求，或某项冻结契约必须核对测试义务、选择、核心断言、CI 或安全声明才能裁决时
  加载；测试文档自身点名的一处入口可作普通事实证据。
- 一致性方案只能包含事实、契约、状态、所有权、Registry／入口或直接消费者的修正、校准和澄清，以及相应验证与
  生命周期动作；纯收缩候选不进入实施范围。
- 显式独立审阅已有一致性方案时，不重跑 `full`，但必须重新检查四类双向清单的候选闭环、动作唯一性和方案纯度，
  只有无未解除差额时才标记 `implementation_ready`。

## `project-doc-contraction`

- 实质调查前必须固定不可变 SHA，并由用户确认该提交已经完成一致性整改且做过一致性验证。用户未给 SHA 时，Skill
  用只读 Git 识别当前 `HEAD`；裸调用默认 `full + 只读报告`，只问一次是否确认。用户回复“确认”即可，不要求粘贴
  验证日志、命令输出或 `not_run` 清单。
- 用户否认前置、活动文档相对候选基线有未提交修改、生命周期仍显示未关闭一致性事项，或活动所有者／当前合同不足时，
  标记 `consistency_blocked`，报告精确一致性交接种子并停止对应单元；不得自行选择正确一方，也不得自动调用
  consistency。缺少验证证据文本本身不是阻断理由。
- 未限定文件、章节或重复关系时使用完整活动文档范围；明确种子时只展开一轮直接所有者／消费者。范围内长期文档
  必须完整读取，不得抽查。
- 每个自然收缩单元展示当前内容与角色、唯一所有者／消费者或基线锚点、收缩风险或阻断，以及最小动作或保留依据。
- 检查完全重复或换措辞重复、竞争真源、实现／配置／schema／算法／测试镜像、施工过程、单次 PASS、日期化结果、
  历史快照、错误所有者、聚合入口复制下级命令／矩阵、摘要膨胀、默认入口负担和复杂或不精准表达。
- 篇幅只触发深入检查，不单独构成问题；每组细节都要能说明其对当前文档角色和直接消费者的必要性，并专项识别需求
  夹带设计、术语表夹带规格／实现或保留不合适术语，以及测试类长期文档残留已退役说明。当前含义或测试义务是否
  已失效无法由基线唯一裁决时使用 `consistency_blocked`，不得借收缩改写事实或撤销义务。
- 文档级处置为 `需要收缩`、`无需收缩`、`consistency_blocked`、`需要决策` 或 `未覆盖`。
- 只要动作理由依赖“已经过时、当前已不是这样或事实已经错误”，默认 `consistency_blocked`；只有一致性基线已明确
  裁决当前事实，且目标只是重复历史说明时，才可继续纯收缩。
- 第一轮评审逐份挑战全部 `无需收缩` 文档；第二轮逐项检查全部删除、迁移、摘要加链接、合并和简化动作，确认没有
  误删唯一事实、用户合同、必要决定理由、字段合同、测试特定义务或运维步骤。
- 收缩方案只能包含内容删除、迁移、摘要加链接、合并或简化，以及相应验证与生命周期动作；不得修正事实、默认值、
  业务规则、状态、所有权决定、Registry 分类、测试义务、运行行为或安全边界。
- 活动真源总内容足迹与默认入口加载量必须分别报告；拆文件、加索引或单纯减少默认加载量不能冒充总足迹已经下降。
- 显式独立审阅已有收缩方案时，不重跑 `full`，但必须检查过时事实删除门、全部阻断隔离、唯一事实／消费者和
  `Cnnn` 失效证据复用，只有无未解除风险时才标记 `implementation_ready`。

## 支持边界

- Skeleton 只支持单一上下文项目；成熟项目可以保留自己的路径、状态词、Registry schema 和门禁。
- 已知标准项目级 Agent Skill 根默认是工具资产，不是活动项目文档；精确活动声明仍可把必要 Skill 文件作为实现证据。
- 三个 Skill 不在目标项目创建 profile、版本号、持久评审日志或运行账本。安装器可在可调用 Skill 目录生成
  `SOURCE-PROVENANCE.json`；用户明确授权时可在目标仓库外保存本任务正式分片轨迹，但它不供另一任务续跑。
- `project-doc-shared` 不是第四个 Skill，不可显式调用；安装任一内容 Skill 时需按同级路径安装该共享支持目录。
- 项目协作、动作授权和生命周期以目标项目当前规则为准；本项目的规则入口见 [AGENTS.md](../AGENTS.md) 和
  [项目文档入口](README.md)。
