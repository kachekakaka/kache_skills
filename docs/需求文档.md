# 需求文档

本文件承接当前已交付、用户可观察且可验收的行为和支持边界。尚未实现的事项登记到
[已知问题与待做需求](已知问题与待做需求.md)。

## 产品范围

本项目交付两个只能显式调用、运行时互不依赖的项目文档 Skill：

- `project-doc-skeleton`：检查项目文档结构、入口、职责、生命周期、测试治理和机械门禁。
- `project-doc-consistency`：核对活动文档与当前事实，识别事实不一致、职责不清、内容膨胀和位置不当。

两个 Skill 不自动调用对方，也不要求另一个已经安装。当前架构理由和替代关系从
[设计文档的架构决策记录](设计文档.md#架构决策记录)进入。

## 共同交付合同

- 先按当前明确请求选择交付路线：只要求检查、审计、review 或报告且没有同时要求方案时，在对话中交付只读结果后
  停止；明确要求形成、保存或修订方案时进入方案路线。只显式调用 Skill 或意图不足以可靠分流时，必须先询问只要
  报告还是形成方案，回答前不得开始实质项目检查。
- 检查和未保存候选评审只读取文件、搜索结果和只读 Git 等静态证据，不运行测试、构建、产品或门禁；动态验证留给
  后续普通任务并保持 `not_run`。
- 方案路线在实质检查前一次取得交付前自查轮数和实施后是否生成反哺报告。检查结束后只在当前调用内形成候选，完成
  所选轮次后展示范围、决定和残余，并单独询问是否只保存方案、不开始实施。
- 能由当前活动权威、项目规则或已有决定唯一裁决的事实由 Skill 自行查明；只有权威留白、同级权威冲突或新增授权
  差额才逐项请用户决定。问题须说明实际结果、代价和可回退性，技术标识不能代替用户可理解的选项。
- 用户对语义结果的确认不自动授权写文件、登记待办、保存方案、转换状态或实施。最终保存确认只允许一次写入方案及
  必要待办；保存后 Skill 停止。
- 保存的方案必须自包含活动所有者、范围、真实发现、决定、确定与待决路径、验证及副作用边界、完成条件、最终复核和
  生命周期收尾，使全新普通任务不依赖原审计对话即可接手；无需复制全部无需修改文档的审计证据。
- 两个 Skill 不施工、不运行验证、不安装资产、不使用非只读 Git，也不归档、删除或关闭目标项目生命周期。

## `project-doc-skeleton`

- 支持采用标准骨架的新项目、明确迁移，以及保留成熟既有治理的等价路线；路径或 schema 不同本身不构成迁移理由。
- 一次检查覆盖上下文与路线、结构职责、入口导航、活动／历史生命周期、待办／方案／记录、测试治理和机械门禁等
  全部适用结构维度，并以已填写的覆盖／残余矩阵限制结论范围。
- 存在测试治理入口或测试根时，可以有界调查当前测试资产、生命周期、执行暴露、身份、所有者、直接消费者、执行
  入口和正式选择；不评价测试覆盖、断言质量或经济性。
- 拟删除、替代或收窄既有路径、入口、生命周期或文档职责时，方案只展开一层会改变退出结论的直接消费者；证据
  不足时保持待决。
- 不持续核对产品事实，不审计测试设计，不执行全项目安全认证；超出结构职责的问题形成精确交接。

## `project-doc-consistency`

- 先从当前入口确认活动真源所有者；所有权不清时停止内容审计并形成结构治理交接，不猜测真源。
- 未限定文件、功能或差异时使用完整活动文档范围；明确种子时只展开一轮直接依赖。增量边界不能可靠形成时报告
  残余，不静默扩大。
- 对范围内每份活动文档分别完成事实／契约遍和职责／删除优先遍；长期文档必须覆盖全部实质正文，不得抽查。
- 文档按自然职责单元审计：只有正文整体由同一角色、所有者和契约承接，且没有两个及以上稳定一级职责章节时，才可
  用一个单元覆盖全文；有两个及以上一级职责章节时，每章至少一个单元，不得跨章合并。章节内职责变化时继续拆分。
- 每个自然单元必须展示具体声明或职责、命名的所有者和直接证据、事实／契约结论，以及收缩风险与处置或具体保留
  依据。章节范围加“静态吻合”“职责清楚”等统一结论不能证明该范围已经完成双遍审计。
- 一次 `full` 可以在同一用户任务内按完整文档或自然单元边界交付编号报告分片并自动续跑，允许跨上下文压缩；最终
  回复提供分片总索引和综合结论。预计上下文或输出空间不足不能把剩余内容标为 `未覆盖`、要求用户另发“继续”或转交
  新审计任务；只有源文件／证据实际不可读、所有权无法裁决、证据仍不足或宿主实际中断时才形成相应残余。
- 长审计开始时必须交付按顺序编号精确路径的范围分片；每个审计、纠正和评审分片末尾都必须带一个**累计可恢复尾部**，
  以范围序号紧凑承接全部已完成处置、进行中单元、当前发现／残余、替代关系和精确下一步。上下文压缩后只从范围分片和
  最近一个可见累计尾部恢复，不依赖不可见内部记忆或猜测下一步。
- 已交付分片不可改写；后续取证或 review 改变旧结论时，必须用编号纠正分片点名被替代的文档、自然单元或动作。最终
  索引只把最新记录作为当前结论，并列出被替代记录，不能让冲突结论同时有效。
- 任一自然单元或四项证据缺失时，对应文档为 `未覆盖`；完整性门跨范围分片、全部编号审计／纠正／评审分片、累计尾部
  和最终索引核对，不得降低证据密度换取完整数量结论。
- 完整范围必须为每份活动长期文档给出需要收缩、无需收缩、无法核验、需要决策或未覆盖之一及文档特定依据；
  `无需收缩` 必须承接全部自然单元且没有未解除残余。增量范围只给出冻结范围内的逐文档处置，不得宣称项目级完成。
- 内容收缩按文档角色和唯一所有者删除重复、实现镜像、过程、快照和错位正文，或在不改变合同的前提下合并、简化
  复杂和不精准表达；拆文件、加索引或单纯减少默认加载量不能冒充活动真源总足迹已经收缩。
- 冻结的是活动文档路径和一轮依赖边界，不是问题发现集合。候选评审可以在冻结路径内新增、删除、拆分、合并或改变
  发现，但不得静默扩大文档范围。
- 只 review 一轮时同时查漏和防误伤；两轮及以上时，第一轮逐份复核进入评审时全部 `无需收缩` 文档并记录改变／
  未改变及原始证据，第二轮逐项复核全部删除、迁移、摘要加链接、合并和简化动作。两轮都使用同一累计尾部与纠正规则
  自动续跑；纯数量或集合对账不能证明通过。
- 测试设计 reference 只在用户明确要求，或产品／治理契约必须评估测试义务、选择、核心断言、CI 或安全设计才能裁决
  时加载。测试文档自身点名的路径、命令、入口、分类或一处实现可按普通事实精确核对，不因此扩大成测试设计审计。
- 条件测试设计审计遇到产品会加载、迁移或重建的持久结构时，使用权威构造入口或明确版本与预期结果；遇到中间态、
  未就绪态或最终一致状态时，使用正式转换、可观察就绪条件或预期失败关闭，不用任意固定等待掩盖未知转换。
- 综合方案只承接真实发现、待决事项、确定动作、直接消费者、验证、副作用和完成条件，不复制全部无需修改文档的内容
  覆盖图，也不能把应在保存前完成的全面审计推迟给实施任务。
- 实施后只要求普通任务复核最终活动入口和所有者、确定切片、已列消费者及修改路径新产生的一跳关系；不把最终复核
  变成第二次完整审计。

## 支持边界

- Skeleton 只支持单一上下文项目；成熟项目可以保留自己的路径、状态词、Registry schema 和门禁。
- 已知标准项目级 Agent Skill 根默认是工具资产，不是活动项目文档；精确活动声明仍可把必要 Skill 文件作为实现证据。
- 两个 Skill 不创建项目级 profile、manifest、版本号、持久评审日志或运行账本；Consistency 的范围、累计尾部、纠正和
  编号报告分片只存在于当前任务的可见交付，不写入目标仓库，也不供另一个任务续跑。
- 项目协作、动作授权和生命周期以目标项目当前规则为准；本项目的规则入口见 [AGENTS.md](../AGENTS.md) 和
  [项目文档入口](README.md)。
