# 需求文档

本文件承接当前已交付、用户可观察且可验收的行为和支持边界。尚未实现的事项登记到
[已知问题与待做需求](已知问题与待做需求.md)。

## 产品范围

本项目交付三个只能显式调用、不会自动互相调用的建议型审计 Skill：

- `project-doc-skeleton`：发现入口、导航、所有者及活动／历史边界中的真实结构问题。
- `project-doc-consistency`：核对活动文档声明与当前一层直接事实是否一致。
- `project-doc-contraction`：识别有证据支持的内容收缩机会，证据不足时保留内容。

三个 Skill 保留独立名称和职责，不需要共享运行目录，也不要求另一个 Skill 已安装。

## 共同合同

- 只在用户显式调用对应 `$skill-name` 时使用；界面策略保持 `allow_implicit_invocation: false`。
- 始终只读。即使请求同时包含修复、落方案或实施，也只交付报告，不写目标项目、不修改产品代码、不保存方案、不登记
  待办、不改变生命周期、不运行测试或构建。
- 用户未指定文件或主题时，从目标项目自己的入口识别并完整检查全部活动文档；指定范围时只检查该范围。入口不足以可靠
  界定活动集合时报告范围不明和未覆盖，不全仓扫描，不自造标准路径。
- 源码、配置、schema、测试和 CI 只在裁决具体声明、所有者或消费者时作为一层直接证据；不从命中递归，也不自动扫描
  全部实现、workflow、历史或归档。
- 报告保持简短：列出实际范围、每个问题的证据／影响／最小建议，以及无法判断或未覆盖的边界；不生成编号分片、覆盖
  矩阵、评审日志、方案候选、验证规划或实施就绪结论。
- 当前权威无法裁决的语义冲突只展示证据、影响和可选方向，交给后续普通任务决定；审计本身不持续访谈。
- 高风险发现只建议对应安全、协议、合规、架构或测试专业审查，不把普通文档审计扩张为专项治理。

## 反过度治理门

三个 Skill 建议新增规则、文档或测试前，都要确认保护的具体行为或合同、真实消费者、已经发生或合理预期的失败、现有
证据为何不足，以及删除条件。任一项没有答案，只给可选建议，不建议形成长期资产。同一行为已有直接证据充分证明时，
不要求 CI、另一套 suite 或新证据格式重复证明；治理设施明显重于被治理内容时优先建议收缩。

## 各 Skill 边界

### `project-doc-skeleton`

- 只把失效入口／链接、竞争所有者、活动与历史混淆，以及当前项目已声明但无人承接的结构职责视为问题。
- 成熟项目已有等价入口、命名、生命周期或测试治理时直接复用。缺少标准文件、路径不同、没有 Registry 或自动门禁本身
  不是失败。
- 不携带、不安装、不要求通用 T-DOC、标准骨架、测试套件或证据工具。

### `project-doc-consistency`

- 逐份核对范围内活动文档的事实、规则、决定、状态、所有者、前提和例外，不以抽样或固定 Token 代替正文。
- 测试、CI 和源码只作为直接证据或消费者，不取得业务合同所有权，也不触发架构、安全或测试体系治理。
- 语义相同的重复只提示可另做收缩检查，不形成删除或简化动作。

### `project-doc-contraction`

- 检查重复、竞争真源、实现镜像、过程／快照残留、内容错位、摘要膨胀和非必要复杂度；篇幅大本身不是问题。
- 直接使用当前工作状态，不要求不可变 SHA、干净工作树、事先完成一致性整改或验证。
- 事实、所有者或消费者不清时列为保留项，不借收缩改写事实；一个保留项不阻断其他独立内容继续检查。

## 支持与交付边界

- 三个 Skill 包都只包含自身 `SKILL.md` 和 `agents/openai.yaml`，不携带目标项目资产或共享运行协议。
- 显式安装器可以独立镜像所选 Skill 并生成来源清单。Skill 运行时不校验 provenance，来源清单也不认证审计质量。
- 本仓库保留自己的轻量 Markdown 链接检查和方案生命周期；这些是本项目自用设施，不成为其他项目的合规条件。
