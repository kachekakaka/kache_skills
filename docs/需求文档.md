# 需求文档

本文件承接当前已交付、用户可观察且可验收的行为和支持边界。尚未实现的事项登记到
[已知问题与待做需求](已知问题与待做需求.md)。

## 当前阶段与职责分界

本项目交付两个只能显式调用、运行时互不依赖的 Skill。ADR-0003 已把骨架、入口、职责、生命周期、结构等价和
机械门禁治理收归 `project-doc-skeleton`；文档与代码事实核对、职责不清、内容膨胀和位置不当归
`project-doc-consistency`。ADR-0004 要求检查与方案保存分离；ADR-0005 和 ADR-0006 进一步规定两个 Skill 都在
各自主责方案交接后退出，不再承担施工、验证或关闭；ADR-0007 将标准授权改为按实际副作用分级；ADR-0008 允许
consistency 的一份自包含方案统一协调同一审计目标中已经就绪的跨职责实施切片，但不恢复 Skill 的执行阶段。

`project-doc-skeleton` 与 `project-doc-consistency` 的“只检查与落方案”职责收缩均已完成，并由各自当前 Skill
承接；历史施工、验证、验收与关闭结果由归档方案承接，不作为另一项任务的可继承结论。

## `project-doc-skeleton`

- 开始处理一个新骨架问题且尚无对应活动方案时只执行只读检查；`apply` 或修复措辞不能跳过检查停点。
- 先冻结有限的结构维度和本轮文件集合，再在范围内充分读取；一次检查覆盖全部适用结构维度，不在首个缺口停止。
- 检查结论和保存方案都包含本次实际填充的覆盖／残余矩阵；项目级结论只限矩阵中的冻结范围。
- 新项目或用户明确选择迁移时规划标准骨架；成熟既有项目按结构职责和必要安全结果判断等价，不因存在文档或测试
  目录加载标准路线参考。
- 已证明等价时保留现有目录、入口、Registry schema、类别词汇和项目专用门禁；未证明时保留现状并列出全部
  已发现结构缺口，不自动迁移。
- 检查文件、目录、入口、链接可达性、职责归属、待办/方案/记录/归档生命周期、测试治理结构、适用测试资产
  信息架构和机械门禁；集中测试治理根列完整路径，模块内测试根只核对边界和映射，未被入口或所有者承接的顶层
  测试目录列为待裁决候选，具体目标和例外由当前证据形成并写入项目方案。
- 七类标准项目级 Agent Skill 根，以及由用户、适用项目规则或冻结范围内精确配置声明的其他 Skill 根，默认不进入
  活动文档、导航、历史分类或矩阵；精确结构声明可以读取必要文件作为一轮实现证据，但不为发现自定义根扫描配置，
  也不能宽泛排除整个工具目录或其他位置的 `SKILL.md`。
- 检查后询问是否保存方案；明确保存后写入并静态自审一份 `待确认` 方案，然后停止。
- 不提供 `apply`、施工、命令验证、重试、验收或生命周期关闭能力；已有活动方案时由普通任务接手，只有用户
  明确授权“仅修订方案”时才修改方案本身。
- 没有可施工问题时可以保存检查记录，但只使用项目现有承接位置；缺少位置时保存前询问，不创建固定目录。
- 只在标准路线的方案中要求后续任务从 Skill 资产逐字节安装通用 T-DOC；等价路线保留项目门禁。
- 不修改产品代码、产品行为断言、`CONTEXT.md`、ADR 正文或方案目标文件；只在方案中记录结构目标、实施边界、
  直接消费者闭包和需要后续裁决的产品行为选择。
- 方案把施工前状态标为初始检查证据（历史快照），把完成条件与实际实施、关闭结果分开，不以条件冒充结果。
- 方案必须让普通任务能够独立识别确定与可能路径、验证要求、可预见副作用及其无落盘调用／受控输出／精确清理
  办法、状态消费者和验收停点，并在完成条件及方案列明的验收要求满足后退出待办、归档方案、更新索引和验证最终
  状态；施工中途通过不能替代生命周期关闭。
- 标准路线中，用户明确授权普通任务“按已确认方案实施”时，该次授权覆盖确定文件变更、方案列明的普通验证、
  结果记录和满足条件后的生命周期关闭；验证升级、新增副作用、候选实质漂移或新的语义决定只申请差额，不因此
  恢复 skeleton 的执行阶段。
- 不核对产品事实、审计测试设计经济性或执行全项目安全认证。

## `project-doc-consistency`

- 新问题始终只读检查；“检查并修复”、`sync` 或同义表达不能跳过检查停点。
- 检查后询问是否保存主责方案；明确保存后写入并静态自审一份 `待确认` 方案，然后停止。
- 不提供 `sync`、施工、命令验证、验收或生命周期关闭能力；已有活动方案时由普通任务接手，只有用户明确授权
  “仅修订方案”时才修改方案本身。
- 保存的一份主责方案必须自包含任务特定活动真源及所有者、冻结范围、已填写矩阵、决定、确定与可能路径、切片
  就绪证据、验证、可预见副作用处理、授权边界和最终范围与漂移复核入口；不复制项目级模板，不自动调用其他
  Skill、继承授权或关闭生命周期。
- 方案保留目标项目当前实施授权语义；目标规则明确将确定文件变更、方案列明的普通验证、结果记录和满足条件后
  的关闭合并授权时，普通任务按该规则执行，目标规则更严格时不得由 consistency 放宽。
- 结构入口只读取足以识别活动真源所有者的当前入口和职责声明，不建立六项治理账本或认证结构等价。
- 所有权不清时停止内容审计，形成精确 skeleton 交接，不猜测真源或继续扩张。
- 按文档职责区分当前事实、规则与决定、历史结果、待办状态和非穷举摘要，再对照代码、配置、构建和可观察行为。
- 对每份 `full` 活动文档或每个 `incremental` 受影响种子分别完成事实／契约遍和职责／删除优先遍，并把覆盖与
  残余写入矩阵；不能用充分读取代替任一遍。
- 识别事实不一致、职责不清、内容膨胀和位置不当；内容正确但属于其他职责或生命周期时不静默搬迁。
- 测试、Registry、suite、CI 和安全实现只在它们是当前声明的直接证据，或用户明确要求测试设计审计时进入范围；
  显式的测试体系、全部 Registry 或全局覆盖请求使用有边界的 Registry 全局模式。
- 测试审计区分覆盖缺口、声明错位、有意重叠、冗余候选、过度候选和失效测试；测试通过不能反向证明契约正确。
- 同一审计目标中通过就绪检查的现有文档内容、文档结构、产品、构建、测试、CI 和安全切片可以进入一份综合方案
  的确定范围；未收敛候选留在同一方案待决并列最小补证条件。
- 普通任务只凭目标项目、方案和实施授权即可完成全部确定切片、列明验证，并核对最终入口和所有者、确定切片、
  已列直接消费者及修改路径新产生的一跳直接链接／消费者；不递归、不扫描整个工作区、不重跑完整审计，再按项目
  规则关闭。无需再次调用审计或为已收敛切片另起方案。
- 七类标准项目级 Agent Skill 根，以及由用户、适用项目规则或冻结范围内精确配置声明的其他 Skill 根，默认不是
  活动项目文档；只在精确声明需要时作为一轮实现证据，或由显式 Skill 专项任务审查。

## Consistency 当前范围与收敛

- 未限定文件、功能或差异的项目文档审计默认 `full`，完整处理由当前活动入口识别的活动文档集合。
- 明确文件、功能、声明、标识符或当前差异时使用 `incremental`，只展开一轮直接依赖。
- `full` 不自动遍历全部源码、测试、CI、安全实现、历史或归档；活动集合不完整时明确报告未覆盖边界。
- `incremental` 无法可靠界定边界时询问是否升级；不得猜测、递归展开或静默转为 `full`。
- 范围内文档充分读取，不使用固定 token、标题 token 或固定行数代替内容理解。
- `full` 逐份、`incremental` 逐种子填充事实／契约与职责／删除优先两遍矩阵；未执行、证据不足或需要决定的项
  保留残余，不能宣称对应范围已经一致。

## 共同授权边界

- 两个 Skill 的检查都保持只读；本地读取、搜索和只读 Git 查询默认允许。保存授权只覆盖方案及必要活动待办，
  随后退出；普通任务施工仍须在方案保存、决定确认、证据无漂移后另行明确授权。
- 标准路线的一次明确实施授权覆盖确定文件变更、列明普通验证、结果记录，以及完成条件满足后的状态更新、方案
  归档、索引更新和精确任务清理；关闭不以 commit、push 或 PR 为前提，也不推定这些操作。
- 公开、无需认证、纯读取、不上传本地或非公开内容、不收费且不改变外部状态的联网默认允许；已确认方案列明的
  普通下载和公开资源获取随实施授权覆盖，来源、用途、目标、规模和副作用不变时不重复申请。
- commit、push、PR、发布、安装、破坏工作区或改写历史的 Git 操作，以及认证或私有访问、上传、外部写入、付费
  或明显大规模联网、产品进程、真实数据、全量测试和正式认证须明确授权。方案未列明、超出确定范围、使用宽泛
  匹配或未解析路径、仓库外非任务产物、所有权不明或涉及真实数据的删除仍须授权。
- 两个 Skill 不自动调用对方，也不依赖对方已经安装。
- 术语、`CONTEXT.md`、ADR 和无法由证据直接裁决的价值取舍由用户另行决定。
- 凭据、真实用户数据和原始运行现场不得写入仓库或交接。
