# 需求文档

本文件承接当前已交付、用户可观察且可验收的行为和支持边界。尚未实现的事项登记到
[已知问题与待做需求](已知问题与待做需求.md)。

## 当前阶段与职责分界

本项目交付两个只能显式调用、运行时互不依赖的 Skill。ADR-0003 已把骨架、入口、职责、生命周期、结构等价和
机械门禁治理收归 `project-doc-skeleton`；文档与代码事实核对、职责不清、内容膨胀和位置不当归
`project-doc-consistency`。ADR-0004 要求检查、保存方案和施工分别授权。

当前 skeleton 第一阶段施工候选已落地并处于独立验收前停点；consistency 候选仍保留旧契约，后续由独立待办
收敛。长期文档不得把 skeleton 阶段授权或验收解释为 consistency 已完成。

## `project-doc-skeleton`

- 新一轮首次调用只执行只读检查；没有已保存、已裁决且无漂移的方案时，`apply` 或修复措辞不能跳过检查停点。
- 先冻结有限的结构维度和本轮文件集合，再在范围内充分读取；一次检查覆盖全部适用结构维度，不在首个缺口停止。
- 新项目或用户明确选择迁移时建立标准骨架；成熟既有项目按结构职责和必要安全结果判断等价。
- 已证明等价时保留现有目录、入口、Registry schema、类别词汇和项目专用门禁；未证明时保留现状并列出全部
  已发现结构缺口，不自动迁移。
- 管理文件、目录、入口、链接可达性、职责归属、待办/方案/记录/归档生命周期、测试治理结构和机械门禁。
- 检查后询问是否保存方案；保存后的 `待确认` 方案不授权施工，完成裁决且再次选择施工后才转为 `实施中`。
- 没有可施工问题时可以保存检查记录，但只使用项目现有承接位置；缺少位置时保存前询问，不创建固定目录。
- 只在标准路线从自身资产逐字节安装通用 T-DOC；等价路线保留项目门禁。
- 不修改产品代码、产品行为断言、`CONTEXT.md` 或 ADR 正文；施工授权内只最小修改可明确分离的路径、入口、
  生命周期或自动化副作用结构断言，职责无法可靠分离时停止交接。
- 退出旧入口前核对引用、默认配置、启动接线、自动化触发、运维入口和结构机械断言组成的直接消费者闭包；
  直接证据出现部署或产品行为选择时保留上游入口并停止裁决。
- 申请验证命令授权前在对话中建立临时执行账本；涉及自动化、外部副作用或授权选择时，先说明会发生、不会
  发生和既有状态。规范验证未运行时保持 `not_run`，静态证据不能替代原验证。
- 用户验收并授权关闭后，按验证记录、待办退出、方案归档与索引、精确空目录清理、最终状态 T-DOC 的顺序
  关闭生命周期；施工中途通过不能替代最终状态门禁。
- 不核对产品事实、审计测试设计经济性或执行全项目安全认证。

## `project-doc-consistency` 当前候选（待独立收敛）

- 提供只读 `check` 和最小事实同步 `sync`；“检查并修复”等明确表达可直接授权边界内的集中修订。
- 每次重新建立六项整体治理账本，不读取或保存过去的等价声明。
- `full` 建立项目范围内容覆盖账本；`incremental` 只覆盖当前变更及其可证明依赖闭包，不夸大全项目结论。
- 按文档职责区分当前事实、规则与决定、历史结果、待办状态和非穷举摘要，再对照代码、配置、构建、测试和可观察行为。
- 测试相关审计建立权威契约、实现、测试义务、Registry/suite、实际断言和 CI 的证据链。
- 区分覆盖缺口、声明错位、有意重叠、冗余候选、过度候选和失效测试；测试通过不能反向证明实现符合契约。
- 核对 SAFETY 与实际 CI 触发、默认输入、路径过滤、输出 containment、owner marker、保留和删除行为。
- `sync` 只最小修订现有活动长期文档，以及满足严格证据边界的待办和 Registry；不创建、移动、重命名或删除文件，不改变结构或修改可执行测试代码。
- 测试实现缺口、结构问题和语义取舍形成精确交接，不自动调用其他 Skill。

## Consistency 当前范围与收敛

- 每次检查先建立范围账本，只沿会改变结论的直接证据读取；证据不足时明确报告，不无限扩张源码或历史。
- `full` 必须分别交付治理证据账本、内容覆盖账本、未检查范围和原因。
- `incremental` 无法可靠界定依赖闭包时判为范围证据不足，并询问是否升级；不得猜测或静默扩大范围。
- 事实性修复在已有 `sync` 授权时不逐文件重复询问；只有真实语义取舍才逐项确认。

## 共同授权边界

- skeleton 新一轮显式调用只授权只读检查；只有活动方案已保存、裁决且无漂移，并再次明确选择施工时，`apply`
  才授权方案边界内的文件修改。consistency 的新阶段授权规则由其独立待办落地。
- 文件修改、构建或测试命令、commit、push、PR、发布和安装分别授权，不得互相推定。
- 两个 Skill 不自动调用对方，也不依赖对方已经安装。
- 术语、`CONTEXT.md`、ADR 和无法由证据直接裁决的价值取舍由用户另行决定。
- 凭据、真实用户数据和原始运行现场不得写入仓库或交接。
