# 项目文档

本文件是活动项目文档的统一入口。当前事实分别由对应长期文档承接；未完成事项进入待办，历史材料进入归档。

## 核心文档

- [需求文档](需求文档.md)：当前已交付、用户可观察且可验收的行为和支持边界。
- [设计文档](设计文档.md)：当前实现结构、入口、引用路由、调用关系和验证拓扑。
- [已知问题与待做需求](已知问题与待做需求.md)：只登记未完成事项及其机械状态。
- [软件测试](软件测试.md)：保存稳定的活动测试项 Registry。

协作与动作授权以根 [AGENTS.md](../AGENTS.md) 为准；项目术语见 [CONTEXT.md](../CONTEXT.md)；完整 Skill 运行规则由
各自 `SKILL.md` 及 references 承接，不在本入口重复。

## 条件文档

- 架构决策从[设计文档的架构决策记录](设计文档.md#架构决策记录)进入；索引同时标明现行与部分替代状态。
- 方案、字段契约和运维文档仅在适用条件满足并确认后创建；活动方案只从对应待办进入。
- 历史 Markdown 由[文档归档](../archive/docs/README.md)登记，活动导航不直接链接归档正文。

## 生命周期

| 待办状态 | 活动方案数量 | 约束 |
| --- | --- | --- |
| `待确认` | 0 或 1 | 仍有未决语义或必要就绪条件；用户明确保存后允许链接一份方案，但保存不授权实施 |
| `待实施` | 恰好 1 | 方案已定稿、自包含、验证规划齐备且必要就绪条件满足，但尚未取得实施授权 |
| `实施中` | 恰好 1 | 已取得本次普通任务实施授权，方案必须由待办实际链接 |
| `暂缓` | 0 | 方案必须退出活动目录和入口 |

- 同一待办最多一份活动方案；没有可施工问题时不创建空方案。
- 新增或修订方案只有在当前请求明确授权保存后才写入；请求已经明确要求保存且最终候选没有漂移时不重复确认。仍有未决
  语义或必要就绪条件时使用 `待确认`，定稿且就绪时使用 `待实施`；保存和实施是两个独立动作。
- 普通任务取得按已确认方案实施的授权后，按方案完成确定修改、列明普通验证和结果记录；新增语义、权限、副作用或
  范围漂移只申请差额。
- 完成条件和验收要求满足后，退出活动待办、归档方案、更新索引、清理方案列明且所有权明确的精确条件目录，并对
  最终状态运行适用机械门禁。中途结果不能替代最终状态。
- 方案关闭与 commit、push 或 PR 相互独立。

### 收尾模板

每份主责方案只实例化当前任务的值：

- 完成证明：
- 覆盖与残余：
- 验证结果或未运行原因：
- 生命周期关闭：

确定切片就绪、状态消费者、关联方案、联合复核、最终范围漂移或验收停点等信息只在当前任务真实触发时作为条件模块
出现；没有触发就省略，不填写“不适用”占位。最终范围与漂移复核只确认最终入口与所有者、确定切片、已列直接消费者，
以及修改路径新产生或改变的一跳链接／消费者；不递归、不扫描整个工作区，也不重跑完整审计。关联方案未完成时只
报告本方案主责结果，不能自动调用其他 Skill、继承授权或关闭。
