# 项目文档

本文件是活动项目文档的统一入口。项目事实分别由对应长期文档承接；未完成事项进入待办，历史材料进入归档。

## 核心文档

- [需求文档](需求文档.md)：承接当前已交付、用户可观察且可验收的行为和支持边界。
- [设计文档](设计文档.md)：承接当前实现结构、入口、调用链、数据流和适配边界。
- [已知问题与待做需求](已知问题与待做需求.md)：只登记未完成事项及其机械状态。
- [软件测试](软件测试.md)：保存稳定的活动测试项 Registry。

## 条件文档

- 当前架构决策记录从[设计文档的架构决策记录](设计文档.md#架构决策记录)进入。
- 方案、字段契约和运维文档仅在适用条件满足并确认后创建；活动方案只从对应待办进入。

## 生命周期

- 状态为“待确认”的待办可以没有方案，也可以链接一份用户明确保存的活动方案；保存不构成施工授权。
- 状态为“实施中”的待办必须链接一份活动方案；“待实施”或“暂缓”待办不得保留活动方案。
- 同一待办始终最多一份活动方案。完成、取消、暂缓、被替代或退出活动列表后，方案退出活动目录和入口。
- 检查没有可施工问题但用户选择保存记录时，优先使用项目现有检查、工作或历史记录位置；缺少承接位置时
  保存前询问，不创建固定记录目录，也不使用空方案。
- 施工完成后仍等待独立验收。取得关闭授权后，依次记录验证结果、退出活动待办、归档方案并更新索引、确认并
  精确清理已预授权的空条件目录，再对最终状态运行适用机械门禁；中途结果不能替代最终状态门禁。
- 历史文档通过[文档归档](../archive/docs/README.md)登记，活动导航不直接链接归档正文。
