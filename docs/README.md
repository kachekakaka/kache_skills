# 项目文档

本文件是活动项目文档的统一入口。当前事实分别由对应长期文档承接；未完成事项进入待办，历史材料进入归档。

## 核心文档

- [需求文档](需求文档.md)：三个建议型审计 Skill 的用户可观察行为和支持边界。
- [设计文档](设计文档.md)：当前包结构、调用关系、取证边界和验证入口。
- [已知问题与待做需求](已知问题与待做需求.md)：只登记未完成事项及其状态。
- [软件测试](软件测试.md)：当前稳定验证入口，不定义目标项目必须复制的测试治理。

协作与动作授权以根 [AGENTS.md](../AGENTS.md) 为准；项目术语见 [CONTEXT.md](../CONTEXT.md)；每个 Skill 的完整运行合同
只由其 `SKILL.md` 承接。

## 条件文档与历史

- 架构决定从[设计文档的架构决策记录](设计文档.md#架构决策记录)进入。
- 方案、字段契约和运维文档只在当前任务真实需要并获授权时创建；活动方案只从对应待办进入。
- 历史 Markdown 由[文档归档](../archive/docs/README.md)登记，活动导航不把历史正文当成当前合同。

## 本项目方案生命周期

下表只服务本仓库的协作流程，不是三个审计 Skill 对其他项目施加的标准。

| 待办状态 | 活动方案数量 | 约束 |
| --- | --- | --- |
| `待确认` | 0 或 1 | 仍有未决语义或必要就绪条件；保存不授权实施 |
| `待实施` | 恰好 1 | 方案已定稿且普通验证规划齐备，但尚未取得实施授权 |
| `实施中` | 恰好 1 | 已取得当前方案范围的实施授权 |
| `暂缓` | 0 | 方案退出活动目录和入口 |

同一待办最多一份活动方案。保存和实施是两个动作；实施出现新语义、权限、副作用或范围漂移时只申请差额。完成条件满足
后退出活动待办、归档方案、更新索引，并仅在确认 `docs/方案/` 为空时删除该条件目录。关闭不依赖 commit、push 或 PR。

每份方案的收尾只记录：完成证明、覆盖与残余、验证结果或未运行原因、生命周期关闭。最终复核只检查本次修改路径及其
一层直接关系，不重跑完整审计。
