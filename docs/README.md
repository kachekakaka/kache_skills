# 项目文档

本文件是活动项目文档的统一入口。项目事实分别由对应长期文档承接；未完成事项进入待办，历史材料进入归档。

## 核心文档

- [需求文档](需求文档.md)：承接当前已交付、用户可观察且可验收的行为和支持边界。
- [设计文档](设计文档.md)：承接当前实现结构、入口、调用链、数据流和适配边界。
- [已知问题与待做需求](已知问题与待做需求.md)：只登记未完成事项及其机械状态。
- [软件测试](软件测试.md)：保存稳定的活动测试项 Registry。

## 条件文档

- 当前架构决策记录从[设计文档的架构决策记录](设计文档.md#架构决策记录)进入。
- 方案、字段契约和运维文档仅在适用条件满足并确认后创建；活动方案只从对应待办进入。

## 生命周期

- 新增或修订方案先停留在本次调用内的未保存候选：开始实质检查前取得用户选择的正整数评审轮数，完成对应轮次的
  自评审和自修订，并在最终摘要后单独取得保存确认。事实由检查补证；需要用户决定的语义选择或新增授权差额逐项
  询问。标为“待确认”的内容可以留在候选中，但受影响切片不得作为确定实施范围或已完成评审。
- 最终保存确认之前不写方案或必要待办；确认后只写一次，再做链接、状态和内容落盘的机械核对。没有可施工问题时
  不创建空方案；检查记录也须先完成结果候选评审并取得最终保存确认，且只进入项目已有承接位置。
- 最终保存确认前，调用内冻结发现、覆盖／残余矩阵和候选处置必须完成成员与数量完全一致的集合对账；缺失、重复或
  无归宿时作废受影响评审并回到候选修订，不得提出保存问题。临时标识和对账过程不写入独立持久日志。
- 状态为“待确认”的待办可以没有方案，也可以链接一份用户明确保存的活动方案；保存不构成施工授权。
- 项目没有为新保存候选定义更精确状态时，方案和必要待办使用“待确认”，不创建“待确认实施”等近义机械状态。
- 状态为“实施中”的待办必须链接一份活动方案；“待实施”或“暂缓”待办不得保留活动方案。
- 同一待办始终最多一份活动方案。完成、取消、暂缓、被替代或退出活动列表后，方案退出活动目录和入口。
- 活动方案必须物化本次已经填充的覆盖／残余矩阵、任务特定范围和所有者；确定修改切片要有就绪证据，列明验证要
  包含可预见落盘或外部副作用及无落盘调用、受控输出或精确清理办法，未收敛候选留在同一方案待决。Consistency
  对同一审计目标使用一份综合方案协调已就绪切片，不为每种职责另起子方案。
- 检查没有可施工问题但用户选择保存记录时，优先使用项目现有检查、工作或历史记录位置；缺少承接位置时
  保存前询问，不创建固定记录目录，也不使用空方案。
- 施工完成后按方案要求完成验收。完成条件和方案列明的验收要求满足且没有授权差额时，同一次实施授权覆盖记录
  验证结果、退出活动待办、归档方案、更新索引、清理方案列明且所有权明确的精确条件目录，以及对最终状态运行
  适用机械门禁；需要新的语义决定、用户明确验收或高风险清理时才停下。中途结果不能替代最终状态门禁。
- 方案关闭与 commit、push、PR 相互独立；未执行 Git 交付不阻止关闭，关闭也不推定任何 Git 操作。
- 历史文档通过[文档归档](../archive/docs/README.md)登记，活动导航不直接链接归档正文。

### 收尾与联合复核模板

每份主责方案都实例化本节字段，只填写当前任务的值，不复制两个 Skill 的详细规则：

- 本方案主责与完成证明：
- 覆盖与残余：
- 确定切片与就绪证明：
- 关闭时的状态消费者：
- 关联方案、共享文件与对方职责状态：
- 联合只读复核触发条件：
- 最终范围与漂移复核：
- 验收停点：
- 关闭边界与未运行验证：

没有关联职责或某项复核不适用时写“不适用”及当前依据。最终范围与漂移复核确认最终入口和所有者，核对确定切片、
已列直接消费者及修改路径新产生的一跳直接链接／消费者；不递归、不扫描整个工作区，也不重跑完整审计。关联方案
未完成时只能报告本方案主责结果；最后一个关联方案只能触发联合只读复核，不能自动调用其他 Skill、继承授权或
结论、宣称全项目闭环或自动关闭。
