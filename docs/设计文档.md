# 设计文档

本文件承接当前实现结构、入口、引用路由、调用关系和验证拓扑。用户可观察合同见
[需求文档](需求文档.md)；完整运行规则由各 Skill 入口及其 references 唯一实现。

每个 `SKILL.md` 是对应运行时流程和授权边界的主入口；`agents/openai.yaml` 只提供显示信息、默认提示和显式调用策略。
两个 Skill 分别携带自身所需规则，运行时不互相调用。

## 高层调用关系

```text
显式用户请求
→ 对应 SKILL.md 判断请求是否已经给出交付路线
├─ 裸调用或意图不清：先询问只报告还是形成方案 → 用户选择
├─ 明确只报告：直接选择报告路线
└─ 明确形成方案：直接选择方案路线
→ 路线确定后读取目标项目规则与有限当前证据
→ Consistency full：冻结精确路径 → 按文档／自然单元边界交付编号报告分片
   → 维护紧凑续跑清单 → 需要时压缩上下文 → 自动继续下一批 → 最终总索引
→ 按条件加载一项或多项 reference
├─ 只报告：输出完整报告与总索引 → 停止
└─ 形成方案：联合取得自查轮数与反哺报告选择 → 内存候选与用户决定
   → 编号评审分片自动续跑 → 最终保存确认 → 保存一份待确认方案 → 停止
   → 全新普通任务按目标项目规则实施、验证和关闭
```

裸调用停点前只允许读取 Skill 自身和遵守安全边界所必需的适用 `AGENTS.md`；图中的目标项目规则与当前证据步骤承接
路线确定后的其余调查。

Skeleton 在核心流程内选择标准骨架或成熟等价治理，并在需要时调查测试资产结构。Consistency 在核心流程内选择完整
活动集合或一轮直接依赖；冻结的是文档路径和依赖边界，后续评审仍可在冻结路径内改变问题发现。

Consistency 为每份长期文档建立自然职责单元。只有正文整体由同一角色、所有者和契约承接，且没有两个及以上稳定一级
职责章节时，才可用一个单元覆盖全文；有两个及以上一级职责章节时，每章至少一个单元，不得跨章合并。每个单元记录具体声明、
所有者与直接证据、事实／契约结论、收缩风险与处置。

`full` 可以在一个用户任务线程内跨多个模型上下文运行。完整文档构成普通批次，单个大文档只在自然单元边界形成连续
子分片；每个编号分片都是正式报告的一部分，交付后自动继续。活跃上下文只保留冻结路径、已完成分片和路径、文档处置、
有效发现、残余及下一批路径的紧凑续跑清单。上下文压缩后先核对该清单再继续，不因预计篇幅主动停止或要求用户另发
“继续”。

完整性门跨全部编号分片、续跑清单和最终总索引核对。缺少任一自然单元或四项证据时仍按证据问题标为 `未覆盖`；预计
上下文或输出空间不足本身不是 `未覆盖` 理由。最终回复只索引分片并综合发现，无需重复全部自然单元证据。

收缩候选的一轮 review 同时查漏和防误伤；两轮及以上时，第一轮固定进入评审时全部 `无需收缩` 文档并逐份记录改变／
未改变，第二轮逐项复核当前全部收缩动作。两轮均可按完整文档或动作边界形成编号评审分片并自动续跑。发现数或集合相等
只用于防止已有发现丢失，不能作为 review 通过证据。

普通测试文档的路径、命令、入口、分类或一处实现按事实一致性精确核对；只有评估测试义务、选择、核心断言、CI 或安全
设计时才加载完整测试设计 reference。

完整逐文档证据由同一任务的全部编号报告分片共同承接；综合方案只承接真实发现、决定、动作、直接消费者、验证和残余，
不复制全部无需修改文档的内容覆盖图，也不把全面审计交给实施任务。详细检查轴、分片续跑、无效证据和动作记录由
`content-contraction.md` 唯一维护。

## 适配边界

- 需求文档是用户可观察合同所有者；Skill 是运行实现；测试入口和夹具是消费者，不能反向定义产品合同。
- 目标项目的 `AGENTS.md`、活动入口、生命周期和授权规则在运行时优先；标准 references 不能覆盖成熟项目的明确规则。
- 项目级 Agent Skill 工具资产按 `SKILL.md` 的精确路径语义排除；其他同名目录和非标准位置的 `SKILL.md` 不被宽泛忽略。
- 两个 Skill 不保存 profile、manifest、版本号、持久评审日志或上次运行结论；Consistency 的续跑清单只存在于当前任务，
  编号报告分片只构成当前对话交付，不写入目标仓库。
- Consistency 综合方案可以协调已经就绪的跨职责切片，但 Skill 本身仍不施工；Skeleton 仍只拥有结构治理。

## 验证拓扑

当前验证分两层：

1. `SoftwareTesting/doc_consistency/` 的 `T-DOC` 和规则夹具检查本仓库及标准骨架的机械规则，包括活动入口、链接、
   生命周期、Registry、归档和顶层 Markdown 根所有权。
2. `SoftwareTesting/manual/project_doc_skills/` 的 `T-PROJECT-DOC-FORWARD` 是 `explicit` 前向试用，使用仓库外隔离
   目标和全新任务验证两个 Skill 的可观察合同及普通任务独立接手；详细样本与评估者预期由该 suite README 和
   `contract-cases.md` 承接。

动态结果只由对应活动方案或归档记录承接，不在本设计文档维护。
