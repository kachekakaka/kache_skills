# 设计文档

本文件承接当前包结构、调用关系、证据边界和验证入口。用户可观察合同见[需求文档](需求文档.md)。

## 模块结构

```text
project-doc-skeleton/
├── SKILL.md
└── agents/openai.yaml

project-doc-consistency/
├── SKILL.md
└── agents/openai.yaml

project-doc-contraction/
├── SKILL.md
└── agents/openai.yaml

SoftwareTesting/doc_consistency/
├── README.md
├── install_project_doc_skills.py
├── test_markdown_links.py
├── test_project_doc_skill_responsibilities.py
└── test_project_doc_skill_installer.py

SoftwareTesting/manual/project_doc_skills/
├── README.md
└── contract-cases.md
```

每个 Skill 都是自包含包。`SKILL.md` 是唯一运行合同；`agents/openai.yaml` 只提供界面信息和显式调用策略。不存在第四个共享
Skill、共享长审计协议、随附 T-DOC 或目标项目模板。

## 调用与退出

```text
用户显式调用对应 Skill
→ 读取适用项目规则与当前文档入口
→ 指定范围：只检查指定活动文档
  未指定范围：从项目入口识别并检查全部活动文档
  范围无法可靠形成：报告未覆盖，不全仓扫描
→ 每个问题最多读取一层直接证据
→ 输出简短问题清单、建议和未覆盖边界
→ 停止，不写文件、不形成方案、不实施
```

三个 Skill 不自动调用彼此。普通任务可以根据报告另行讨论、形成方案或实施，但不能继承审计请求的写入授权。

## 三类判断

- Skeleton 只判断入口／导航是否有效、所有者是否竞争、活动与历史是否混淆，以及本项目明确声明的结构职责是否无人承接。
- Consistency 只判断活动声明与一层直接事实是否一致；无法由当前权威裁决时保留冲突和选项。
- Contraction 只判断是否有证据支持删除、迁移、合并、摘要或简化；事实、所有者或消费者不清时保留内容。

三者都使用相同反过度治理门。新增长期资产必须有具体保护对象、真实消费者、合理失败、现有证据缺口和删除条件，否则
只能作为可选建议。

## 安装设计

`install_project_doc_skills.py` 只在明确安装请求下使用。每个 Skill 的安装根就是自身目录；安装器精确镜像目标目录并在
其中生成 `SOURCE-PROVENANCE.json`。`--verify-only` 可以检查清单和文件 SHA-256，但该机制只证明安装来源与漂移，不是
Skill 运行前置，也不证明报告正确。

## 验证设计

普通验证只包含三个直接能力：

1. `test_markdown_links.py` 以小型自测试证明链接判断，再检查本仓库 `archive/` 历史根以外 Markdown 的本地相对链接和
   标题锚点；外链不联网验证，也不要求固定文件、目录、Registry 或生命周期。
2. `test_project_doc_skill_responsibilities.py` 检查三个包名称、显式调用元数据、自包含结构和无共享运行包，不匹配生成文案。
3. `test_project_doc_skill_installer.py` 检查独立镜像以及来源清单的 `verified`、`mismatch` 和 `missing` 结果。

[可选行为样例](../SoftwareTesting/manual/project_doc_skills/README.md)只在用户显式授权时运行；未运行时，普通验证只能证明
源码合同和包装边界，不能声称真实模型行为已经通过前向试用。
