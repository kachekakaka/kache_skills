# 设计文档

本文件承接当前实现结构、入口、调用链、数据流和适配边界。目标结构和一次性实施步骤不在此维护。

## 模块结构

```text
project-doc-skeleton/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── skeleton-rules.md
│   └── testing-baseline.md
└── assets/SoftwareTesting/doc_consistency/
    ├── README.md
    ├── test_doc_consistency.py
    └── test_doc_consistency_rules.py

project-doc-consistency/
├── SKILL.md
├── agents/openai.yaml
└── references/
    └── test-design-audit.md

SoftwareTesting/manual/project_doc_skills/
├── README.md
└── contract-cases.md
```

每个 `SKILL.md` 是对应工作流和授权边界的主入口；`agents/openai.yaml` 提供显示信息、默认提示并关闭隐式调用。
两个 Skill 分别携带自身所需判据，运行时不互相调用，也不要求另一个 Skill 已安装。

## 当前阶段模型

ADR-0003 将结构治理与内容一致性重新分开，ADR-0005 和 ADR-0006 让两个 Skill 都在各自主责方案交接后退出
执行链，ADR-0008 让 consistency 的一份自包含方案可以协调同一审计目标中已经就绪的跨职责实施切片，而不恢复
Skill 的执行阶段；ADR-0009 把方案自评审前移到未保存候选，最终确认后才一次落盘。两者不保存 profile、manifest、
版本号、评审日志或上次运行结论。

```text
skeleton 新问题
→ 取得用户选择的方案评审轮数
→ 完整只读结构检查
→ 在内存候选中自评审并自修订指定轮数（必要的用户决定逐项停问）
→ 展示最终摘要并询问是否保存
→ 一次保存待确认方案并机械核对
→ skeleton 停止，普通实施任务接手

consistency 新问题
→ 取得用户选择的方案评审轮数
→ 双遍只读内容检查（按需进入 Registry 全局模式）
→ 在内存候选中自评审并自修订指定轮数（必要的用户决定逐项停问）
→ 展示最终摘要并询问是否保存
→ 一次保存待确认的自包含综合方案并机械核对
→ consistency 停止，普通实施任务统一实施、最终复核并关闭
```

## 骨架处理流

1. 显式调用先取得用户选择的正整数方案评审轮数；未提供时推荐 `2` 并询问，不静默选择。随后进入只读 `check`
   并完整读取适用协作规则。采用标准骨架的项目检查、明确迁移或标准结构比较才加载
   `skeleton-rules.md`；标准测试治理、标准 T-DOC 或标准验证规划适用时才加载 `testing-baseline.md`。
2. 冻结有限结构维度和本轮文件集合，在范围内充分读取；完成上下文、结构职责、入口导航、活动/历史、待办/
   方案/记录、测试治理、适用测试资产信息架构、机械门禁与授权边界全部适用维度，不在首个缺口短路，并填充
   覆盖／残余矩阵。检查只使用静态读取、搜索和只读 Git，不执行测试、构建、产品、门禁或其他验证命令。
3. 全部维度满足时保留等价既有结构；否则保留现状并列出全部已发现结构缺口。标准化迁移只是一个候选处理。
4. 检查结束先形成未保存方案候选。方案区分事实、推断、决定、确定与可能路径、完成条件和验证结果，并实例化目标
   项目当前收尾字段；列明可预见
   验证副作用及无落盘调用、受控输出或精确清理办法，不写不必要的精确命令、临时 Git 技巧或绑定施工者；活动
   清单、所有者、排除项和已填矩阵直接物化在方案中。调用内发现清单使用稳定临时标识，并在最终保存前对账报告与
   候选处置的成员和数量；不相等时作废受影响评审并回到候选修订。
5. 按冻结证据自评审并自修订用户指定轮数；每轮检查目标、路径、决定、确定范围、残余和轮次状态。事实缺口继续
   只读补证；语义决定或授权差额逐项询问并给出建议。待确认项可以保留，但其受影响切片不能进入确定范围，也不能
   计为完成对应评审。改变自定义 Skill 根、工具可发现性、所有者或路径职责等治理结果不能由标准路线替用户选择；
   识别决定后在当前轮计数前停下。逐轮评语和修订轨迹不进入持久方案。
6. 完成指定轮数后展示最终摘要并单独询问是否保存。最终确认前不写方案或必要待办；确认后只写一次并机械核对
   落盘内容、链接和状态，然后 skeleton 停止。既有方案的修订候选遵守同一边界，原件在最终确认前不变。
7. 普通实施任务读取目标项目规则和方案；用户明确授权按已确认方案实施时，在同一批次完成确定文件变更、方案
   列明的普通验证、结果记录和满足条件后的生命周期关闭，出现验证升级、新副作用、候选实质漂移或新的语义决定
   时只申请差额；关闭与 Git 交付相互独立，不需要再次调用 skeleton。

第 4 至 5 步把验证入口调用方式纳入候选就绪检查：会读取文本的新增 Python 验证入口记录 `-X utf8` 或有证据的
等价显式 UTF-8 模式，并把 `-B` 作为独立的无字节码参数。缺少运行模式时 skeleton 先自修订候选，修订前不计受影响
评审轮次；正确模式下的严格解码错误进入失败语义。候选只记录必要参数，不预写完整命令或绑定施工者，不改外部脚本、
不扩大 T-DOC，也不自动迁移成熟项目已有的权威命令；后者只记录 locale 依赖残余、影响和可能修订路径。

骨架只读取直接相关的治理证据，不持续核对产品事实，不评价测试设计经济性，也不认证全项目安全。内容问题、
语义取舍和测试实现缺口形成自包含交接包，不产生运行时 Skill 依赖。公开只读联网仅在用户指定或已冻结结构
声明直接需要公开证据时使用，不以外部资料替代项目当前证据。

七类标准项目级 Agent Skill 根，以及由用户、适用项目规则或冻结范围内精确配置声明的其他 Skill 根，按路径语义
属于项目级 Skill 工具资产，默认不进入 skeleton 的活动文档枚举、导航、历史分类和矩阵；只有精确结构声明需要时
读取必要文件作为一轮实现证据。不为发现自定义根扫描配置，该排除也不扩大到相邻工具目录内容或其他位置的
`SKILL.md`。

通用 T-DOC 从活动 Markdown 集合识别非标准顶层目录，并以 `README.md`、`docs/README.md` 和
`SoftwareTesting/README.md` 的一层直接 Markdown 目标判断所有权。标准根、归档、缓存和七类标准项目级 Skill 根不进入
该判断；规则只验证目录内是否有直接所有者入口，不解析正文语义，也不把检查扩大为全局两跳导航。

测试资产信息架构调查从测试入口和 Registry 或等价选择入口建立活动项入口、所有者与实现根映射；集中治理根列
完整路径，模块内根只核对边界，未接线顶层测试目录成为所有权候选。目录混放、导航、命名和跨职责依赖只是调查
信号，最终目标、例外与残余按项目证据进入方案，不在 Skill 中固定目录结果或审计测试覆盖。

skeleton 不修改方案目标文件。需要调整路径、入口、生命周期或结构机械断言时，方案要求普通实施任务先核对
引用、默认配置、启动接线、自动化触发、运维入口和结构断言组成的直接消费者闭包；出现部署或产品行为选择时
保持待决，不在骨架方案中猜测。

## 内容一致性处理流

1. 显式调用后先取得用户选择的正整数方案评审轮数；未提供时推荐 `2` 并询问，不静默选择。随后读取适用规则，
   以及足以识别活动真源所有者的当前入口和职责声明；不认证结构治理。
2. 所有权不清时停止并形成 skeleton 交接；所有权明确后再冻结内容范围。
3. 未限定范围的项目文档审计默认 `full`，完整处理当前活动集合；明确文件、功能、声明或差异时使用
   `incremental`，只展开一轮直接依赖。
4. 增量边界无法证明时报告范围证据不足并询问是否升级，不猜测或静默转为 `full`。
5. 对每份 `full` 活动文档或每个 `incremental` 受影响种子分别执行事实／契约遍和职责／删除优先遍，把结果写入
   已填充的覆盖／残余矩阵；项目级 Skill 工具资产默认不进入活动集合，只能按精确声明作为一轮实现证据。
6. 区分当前事实、规则与决定、历史结果、待办状态和非穷举摘要，再按职责映射权威来源、实现和可观察证据。审计只
   使用静态读取、搜索和只读 Git，不执行测试、构建、产品、门禁或其他验证命令；动态验证保持 `not_run`。
7. 报告事实不一致、职责不清、内容膨胀、位置不当、无法验证和未覆盖范围，并形成未保存主责方案候选。候选物化
   活动真源及所有者、已填矩阵、决定、确定与可能路径、切片就绪证据、动作边界、验证、
   可预见副作用处理与授权要求、最终范围与漂移复核入口和任务特定收尾字段；调用内发现清单使用稳定临时标识，最终
   保存前核对清单、矩阵和候选处置的成员与数量完全一致，保证全部冻结发现都有已决定、确定、待决、交接、不适用或
   排除归宿。
8. 同一审计目标中通过就绪检查的文档、结构、产品、构建、测试、CI 和安全改动统一进入一份综合方案；未收敛项
   留在同一方案待决，不为每类职责另起方案。
9. 按冻结证据自评审并自修订用户指定轮数；每轮检查目标、路径、决定、确定范围、残余和轮次状态。事实缺口继续
   只读补证；语义决定或授权差额逐项询问并给出建议。待确认项可以保留，但其受影响切片不能进入确定范围，也不能
   计为完成对应评审。自定义 Skill 根、工具可发现性、所有者或路径职责等治理结果不能由测试差异替用户选择；逐轮
   决定出现时在当前轮计数前停下，评语和修订轨迹不进入持久方案。
10. 完成指定轮数后展示最终摘要并单独询问是否保存。最终确认前不写方案或必要待办；确认后只写一次并机械核对
    落盘内容、链接和状态，然后 consistency 停止。既有方案的修订候选遵守同一边界，原件在最终确认前不变。
11. 普通实施任务遵守目标项目授权规则，一次完成确定切片和列明验证，再确认最终入口
    与所有者，核对确定切片、已列直接消费者及修改路径新产生的一跳直接链接／消费者；不递归、不扫描整个工作区、
    不重跑双遍或测试设计审计。满足条件后关闭，不需要再次调用 consistency。

公开只读联网只有在用户指定或已冻结声明直接需要公开证据时才进入内容证据链；先固定声明和来源，不进行无边界
浏览，也不让公开资料覆盖目标项目自己的当前契约。是否需要授权继续由目标项目按实际副作用判断。

除经明确授权保存一份主责方案及必要待办外，consistency 自身不创建、移动、重命名、归档或删除目标项目的既有
活动文档，不改变入口、导航、路径职责、生命周期规则、Registry schema、`CONTEXT.md` 或 ADR，也不修改产品
代码、可执行测试代码、CI 或安全实现；已经就绪的这些改动可以由后续普通任务按同一综合方案实施。

## 测试设计审计流

```text
权威需求/设计契约
→ 当前实现与风险
→ 测试义务
→ Registry 或等价选择机制
→ suite 与实际断言
→ CI 选择和安全触发
```

该流程只在测试、CI 或安全实现是已冻结声明的直接证据，或用户明确要求测试设计审计时启用；`full` 本身不
触发。具体声明使用声明绑定模式；显式测试体系、全部 Registry、suite 组织或全局覆盖请求使用 Registry 全局模式，
先从权威入口冻结每个活动 ID，再按测试义务、层级、运行边界、故障信号、核心断言、成本与触发形成有证据的职责
分组。两种模式互斥，并区分覆盖缺口、声明错位、有意重叠、冗余候选、过度候选和失效测试。

测试通过不能反向证明实现符合权威契约；实现和测试共同固化错误行为时报告共同偏离。只有相关声明直接涉及
选择、触发或安全行为时，才在一轮直接证据内比较：

- SAFETY 中 `explicit`、认证或私有资源、上传、外部写入、联网费用、明显大规模下载、真实数据和进程约束与
  CI push、PR、schedule、手动入口及默认输入；公开只读联网不能只因使用网络就被判为受限；
- workflow 路径过滤与 Dockerfile、锁文件、脚本、契约、suite 文档和 fixture 等真实输入；
- 实际输出根、owner marker、containment、保留和删除实现与安全声明。

这类检查不能宣称全项目 CI 完整或安全等价。静态证据不足时使用“无法验证”；运行、故障注入或 mutation
testing 仍按目标项目另行授权，已就绪的测试代码改动则可进入同一综合方案供普通任务实施。

## 验证结构

当前验证分两层：

1. `SoftwareTesting/doc_consistency/` 的 T-DOC 与规则夹具只验证本仓库及标准骨架的机械规则，包括顶层 Markdown
   根所有权；
2. `SoftwareTesting/manual/project_doc_skills/` 是 `explicit` 前向试用入口，验证两个 Skill 的主责、阶段和范围收敛、
   Skeleton 测试资产信息架构调查，并验证全新普通任务只凭目标夹具、自包含方案和实施授权即可完成跨职责切片、
   最终复核与关闭，以及项目级 Skill 资产隔离；它不属于普通门禁，也不把真实项目变成自动路径依赖。

动态普通验证、独立验收和关闭结果由对应活动方案及归档记录承接，不在本设计文档重复维护。代表性前向试用保持
`explicit`，只有另行满足明确授权、全新任务和隔离目标条件时执行。
