# 设计文档

本文件承接当前实现结构、入口、调用链、数据流和适配边界。目标结构和一次性实施步骤不在此维护。

## 模块结构

项目由两个独立 Skill 包组成：

```text
project-doc-skeleton/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── skeleton-rules.md
│   └── testing-baseline.md
└── assets/SoftwareTesting/doc_consistency/
    ├── test_doc_consistency.py
    └── test_doc_consistency_rules.py

project-doc-consistency/
├── SKILL.md
└── agents/openai.yaml
```

每个 `SKILL.md` 是对应工作流和授权边界的主入口；`agents/openai.yaml` 提供显示信息、默认提示并关闭隐式调用。`project-doc-consistency` 不携带脚本、模板或持久化报告资产。

## 骨架处理流

1. 显式调用后读取目标项目适用的协作规则，以及当前场景所需的骨架规则和测试基线。
2. 只读调查项目入口、活动 Markdown、测试目录、归档和工作区修改，并确认项目适用性。
3. 集中确认互不依赖的未知项；存在依赖或冲突时逐个澄清，并对最终变更清单、修改和命令分别取得授权。
4. 先建立承接位置与入口，再实施已确认的迁移或机械修复。
5. 需要安装或更新文档门禁时，将 `assets/SoftwareTesting/doc_consistency/` 下的两个 Python 源码逐字节复制到目标项目，不在目标项目内制作分叉。
6. 取得命令授权后，使用规则夹具验证门禁自身，再由目标项目中的 `T-DOC` 只读检查当前文档骨架；未运行适用验证项时只报告静态审查范围，不给出总体通过结论。

`test_doc_consistency_rules.py` 使用系统临时目录构造隔离正反夹具；`test_doc_consistency.py` 从安装位置定位目标项目根目录，读取 Markdown 和固定路径并返回机械检查结果。两个脚本只依赖 Python 标准库，不负责判断正文事实。

## 内容一致性处理流

1. 显式调用后读取目标项目协作规则；未指定模式且没有修订意图时使用只读 `check`，出现同步、修订或修复
   意图时进入 `sync`，“检查并修复”等组合表达不视为模式冲突。
2. 按增量或用户明确要求的全量范围，先区分当前事实、规则与决定、历史结果、待办状态和非穷举摘要，再将需要核验的声明映射到代码、配置、构建、测试、用户确认和可观察行为证据。
3. `check` 在交流中按五种结论报告问题和未覆盖范围，对一致项只做范围摘要，不写文件。
4. `sync` 只保留符合现有文档职责与抽象级别、不会制造重复真源的最小事实修订；当前请求已明确要求直接
   修复时，说明集中清单后实施，否则取得一次集中确认，只修改清单内现有活动长期文档的事实正文。
5. 需要运行命令时另行列出命令、验证层级、输出和副作用，并取得独立命令授权。

内容一致性处理不改变目录、导航、待办与方案生命周期、Registry 或归档关系。结构变化交回显式调用的骨架 Skill；术语、`CONTEXT.md`、ADR 和语义取舍由用户另行显式处理。
